## v1.32 — Braintree Production Parity

**Goal:** Close the gaps identified in the Braintree thin slice (v1.31) to bring it to the "same level of support as Stripe" for real-world production usage.

### Subscription Mutation Lifecycle

- [x] **PROC-14**: Implement subscription upgrades, downgrades (plan swaps), quantity changes, and pause/resume logic for Braintree adapters. — _Shipped in Phase 97 (`097-01-PLAN.md`). Unsupported semantics return typed errors instead of falling through to Stripe-shaped behavior. See `accrue/lib/accrue/processor/braintree.ex`, `accrue/lib/accrue/billing/subscription_actions.ex`._
- [x] **PROC-15**: Implement Braintree webhook event parsing to converge subscription mutation changes (swaps, quantity, pause, resume) locally. — _Shipped in Phase 97 (`097-02-PLAN.md`). Lifecycle notifications normalize through the shared reducer; canonical refetch drives convergence rather than payload snapshots. See `accrue/lib/accrue/webhook/default_handler.ex`, `accrue/lib/accrue/billing/subscription_projection.ex`._

### Payment Method Management

- [x] **PROC-16**: Extend the `Accrue.Billing` facade to provide full CRUD parity for Braintree `payment_methods` (adding new vaulted methods, deleting, setting default). — _Shipped in Phase 98 (`098-01-PLAN.md`). Canonical `add/update/delete/list/sync_payment_methods` verbs with projection-first reads, write-through resync, and guarded deletes. Compatibility wrappers preserve `attach/detach`._
- [x] **PROC-17**: Extend the `AccrueAdmin` UI customer payment methods tab to handle Braintree operator surfaces for payment method updates. — _Shipped in Phase 98 (`098-02-PLAN.md`, `098-03-PLAN.md`). Admin exposes sync/set-default/guarded-delete only; host owns add/replace through vault-reference wrappers. VERIFY-01 browser proof passes. See `098-VERIFICATION.md` (7/7)._

### Refunds & Prorations

- [x] **PROC-18**: Implement the Braintree `charge.refund` flow with parity to the Stripe implementation. — _Shipped in Phase 99 (`099-01-PLAN.md`). Canonical `Accrue.Billing.refund/2` + `refund!/2`; Braintree adapter callbacks; additive `processor_id` schema._
- [x] **PROC-19**: Implement Braintree webhook convergence for refunds, ensuring local `Invoice` and `Charge` records correctly project Braintree's transaction statuses. — _Shipped in Phase 99 (`099-02-PLAN.md`). Immediate-retrieve convergence on write, `ReconcileRefundFees` Oban backstop, derived refund rollups on invoices preserving sale-truth amounts. Verification reconstructed from per-plan self-checks; see `099-VERIFICATION.md`._

### Billing Portal Parity

- [x] **PROC-20**: Address `create_billing_portal_session/2` parity for Braintree by either providing a unified local portal or explicitly documenting the Braintree local-portal alternative. — _Shipped in Phase 100 (`100-01-PLAN.md`). Braintree `billing_portal: %{create: false}` capability; facade raises `%Accrue.APIError{code: :unsupported_by_gateway}`; new `accrue/guides/braintree-local-portal.md` provides LiveView copy-paste recipe._

## Out of Scope

- **FIN-03**: App-owned finance exports remain out of scope.
- Stripe Connect parity (Braintree equivalent) — carried to v1.33 spike.
- Stripe Checkout parity (Braintree Drop-in UI equivalent) — carried to v1.33 (Accrue Portal foundation).

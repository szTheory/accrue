## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**

- Keep Braintree mutation support honest by rejecting unsupported quantity, pause, and resume semantics with typed errors instead of Stripe-shaped fallthrough.
- Webhook payload snapshots are not trusted; Braintree lifecycle notifications normalize to the shared reducer event families and trigger a canonical refetch.
- Payment-method writes follow `provider call → explicit sync → local projection lookup`; admin stays projection-first and server-driven (sync, set default, guarded delete only). Host owns add/replace through vault-reference wrappers.
- Refunds use immediate post-write `retrieve_refund` for deterministic convergence; `ReconcileRefundFees` is the idempotent backstop. Invoices retain sale truth and surface refund rollups rather than mutating parent amounts.
- Braintree `swap_plan` proration is restricted to `:none` and `:create_prorations` only; other Stripe-centric knobs fail explicitly.
- Braintree billing-portal capability is explicitly **disabled**, not implicitly absent. The facade raises a typed `:unsupported_by_gateway` error pointing to the local portal guide instead of silently routing to Stripe-shaped behavior.

**Issues Resolved:**

- Closed PROC-14..PROC-20 — Braintree production-parity gaps from the v1.31 thin slice.
- Established the host-owned vault-reference seam for Braintree add/replace flows.
- Centralized Braintree-specific refund copy in `AccrueAdmin.Copy`.

**Issues Deferred:**

- No live re-run of the Phase 99 Nyquist test bundle at milestone close — verification was reconstructed from per-plan self-checks (all PASSED). Re-run `099-VALIDATION.md` commands before any production cut that depends solely on Phase 99. See `099-VERIFICATION.md`.
- Stripe Checkout / Connect Braintree parity (Drop-in UI, Hyperwallet) — out of scope for v1.32; carried into v1.33.
- App-owned finance exports (FIN-03) remain out of scope.

**Technical Debt Incurred:**

- Per-task atomic commits were not produced for Phases 97–99 because the working tree was a shared dirty main with overlapping work. Phase commits exist as feature-grouped commits rather than per-task.
- Host proof in Phase 97 logs transient `too_many_connections` Postgres errors from background processes; required hermetic test suite still completes 0-failures. Worth a future Postgres pool cleanup.

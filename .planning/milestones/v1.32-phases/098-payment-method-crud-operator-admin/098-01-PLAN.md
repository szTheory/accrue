<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host browser -> billing facade | Untrusted browser input may cross only as a narrow vault reference, never raw card data. |
| Billing facade -> Braintree gateway | Provider writes can mutate funding state and must be guarded before destructive calls. |
| Braintree canonical state -> local projection | Refetched provider truth must be reconciled transactionally so stale rows do not mislead later reads. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-98-01 | T | `Accrue.Billing.PaymentMethodActions.delete_payment_method/2` | mitigate | Query projected active Braintree subscriptions by `Subscription.data["payment_method_token"]`, require explicit replacement when needed, and refuse raw passthrough deletes. |
| T-98-02 | I | `Accrue.Processor.Braintree` payment-method callbacks | mitigate | Accept only narrow vault reference attrs and avoid logging raw provider payloads or browser-originated card data. |
| T-98-03 | D | Projection sync path | mitigate | Refetch provider truth after add/update/delete/default writes and expose explicit `sync_payment_methods/2` recovery for drift. |
</threat_model>

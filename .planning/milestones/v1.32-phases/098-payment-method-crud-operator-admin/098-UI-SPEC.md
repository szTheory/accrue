# Phase 98 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — preserve the existing Phoenix LiveView `ax-*` admin system (`customer_live.ex`, `accrue_admin.css`) |
| Preset | not applicable |
| Component library | custom AccrueAdmin HEEx components: `AppShell`, `Tabs`, `Button`, `DropdownMenu`, `DetailDrawer`, `FlashGroup`, `StatusBadge`, `DataTable` |
| Icon library | none — prefer text labels and badges over introducing icon-only actions in this phase |
| Font | `system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |

## Surface

- Route: `GET /customers/:id?tab=payment_methods&org=<slug>` (source: Phase 77 VERIFY route contract).
- LiveView: `AccrueAdmin.Live.CustomerLive`, `payment_methods` branch only.
- Operator scope: inventory, explicit `set default`, guarded delete, explicit reconcile/sync, and host-assisted add/replace handoff.
- Hard boundary: no raw card capture, no embedded Braintree Drop-in, no fake “edit card in place” UI for Braintree.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Status-dot gaps, inline badge spacing |
| sm | 8px | Row metadata gaps, compact action spacing |
| md | 16px | Default row padding, body spacing |
| lg | 24px | Card padding, confirmation-body sections |
| xl | 32px | Tab-panel section gaps |
| 2xl | 48px | Major state breaks inside empty and destructive surfaces |
| 3xl | 64px | Not used inside the tab; reserved for page-level spacing only |

Exceptions: 44px minimum touch target for any row action trigger or confirmation CTA; keep existing `ax-button`/`ax-icon-button` minimums rather than inventing smaller controls.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--accrue-paper)` in light mode / `#0f1318` in dark mode | Page background and tab canvas; do not replace with a phase-specific backdrop |
| Secondary (30%) | `#FFFFFF` in light mode / `#171d24` in dark mode | `ax-card` surfaces, table shell, confirmation drawer, dropdown panel |
| Accent (10%) | `#5D79F6` default brand accent, host-overridable via `brand[:accent_hex]` | Primary CTA, active tab underline, default-status emphasis, focus ring, sync affordance |
| Destructive | `var(--ax-primary)` via existing `ax-button-danger`, paired with warning copy | Final destructive action only; do not introduce ad-hoc red tokens in this phase |

Accent reserved for: `Set default payment method`, `Sync payment methods`, active tab chrome, `Default` status badge, and focus-visible states. Do not use accent for delete actions, passive metadata, or every row link.

## Component Inventory

- On first load, the primary focal point is the payment-method inventory card header with its `Sync payment methods` action and the visible `Default` status row, so operators can orient on current truth before choosing a mutation.
- Use a single `ax-card` tab panel with a heading, short operator-boundary explainer, and the inventory surface below it.
- Inventory must use the responsive table/card pattern already established by `AccrueAdmin.Components.DataTable`:
  desktop `>=1024px`: table layout
  mobile `<1024px`: stacked cards
- Each payment-method row/card must show, in this order:
  1. payment method label: `brand/type + masked last4`
  2. expiry
  3. default state
  4. dependency state: whether the method is funding an active subscription or otherwise blocked
  5. available actions
- Use `StatusBadge` tone mapping:
  `cobalt` for `Default`
  `amber` for `In use` / `Replacement required`
  `slate` for neutral projected methods
- Use `DropdownMenu` or equivalent disclosed action group for secondary row actions. Do not place multiple destructive buttons inline on every row.
- Use `DetailDrawer` for the delete confirmation surface so impact copy, dependency summary, and final confirmation live in one server-rendered, auditable place.

## Interaction Contract

- First-class operator action: `Set default payment method` for any non-default, eligible row. This is the primary row action.
- High-risk action: `Delete payment method` is never immediate. First click opens a confirmation surface with:
  payment-method summary,
  current default/non-default state,
  active-subscription dependency summary,
  exact next-step guidance.
- If deletion is blocked because the method funds an active subscription, the confirmation surface must not render an enabled destructive CTA. Show the blocking reason and the replacement path instead.
- If the row is the current default and another usable method exists, the confirmation surface must require replacement/default reassignment first. Do not silently pick a fallback default.
- If the row is the last method and deletion is allowed, the confirmation copy must state that the customer will be left with no default payment method.
- Add/replace for Braintree is a host-assisted handoff, not an admin-side form. Render a secondary action or explanatory link to the host billing flow when the host provides one; otherwise show explanatory copy only.
- Include an explicit `Sync payment methods` action near the section header. This is the operator-visible reconcile path for local/provider drift.
- All mutations are server-driven LiveView actions. Disable the triggering control while the request is in flight and resolve with a flash plus refreshed local projection.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Set default payment method` |
| Empty state heading | `No payment methods on file` |
| Empty state body | `This customer has no vaulted payment methods yet. Add or replace one in the host billing flow, then sync this view.` |
| Error state | `We couldn't update the payment-method projection. Refresh or sync payment methods, then try again. If the problem persists, inspect the processor response.` |
| Destructive confirmation | `Delete payment method`: `Deleting this method can disrupt active subscriptions. Review dependencies before you continue.` |

Additional copy rules:

- Keep Tier A operator English through `AccrueAdmin.Copy`; update `export_copy_strings` allowlist and generated host JSON when visible strings change.
- Explain the operator/customer boundary in plain language: admin can review, set default, sync, and guarded-delete; card entry or replacement happens in the host billing flow.
- For Braintree replacement-oriented flows, prefer `Replace payment method` over `Edit card`.
- Use provider-honest copy. Never imply that changing the customer default automatically moves existing subscriptions to the new funding source.

## States

- Has methods: show rows/cards with row actions and status badges.
- Empty: show the empty-state heading/body above plus the host-handoff guidance.
- Syncing: keep inventory visible, disable sync trigger, and preserve current rows until the refreshed projection lands.
- Success: flash in the existing notifications region with the changed outcome (`default updated`, `payment method deleted`, `payment methods synced`).
- Blocked delete: use warning tone and explanatory copy, not a generic provider failure message.
- Provider/API failure: use error flash plus the error-state copy above.

## Accessibility

- Keep one `h3` section heading for the tab panel.
- Every interactive row action must have an accessible name that includes the action and the masked method identifier, for example: `Set default payment method for Visa ending 4242`.
- Confirmation drawer title must name the exact method being acted on.
- Preserve the Phase 77 VERIFY posture on this route: host Playwright path, full-page axe, light and dark theme coverage, and no new token bypasses unless documented in `theme-exceptions.md`.
- Do not rely on color alone for default/in-use status. Status text must be visible in badges and confirmation copy.

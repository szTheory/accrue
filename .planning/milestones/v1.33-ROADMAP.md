# Milestone v1.33: Braintree Full Maturity

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 101–104
**Total Plans:** 20

## Overview

Achieve honest Braintree first-party maturity for hosted checkout, self-serve billing portal, local promotion-code discounts, local metered billing, and a written Connect/Hyperwallet boundary without drifting into unsupported marketplace parity.

**Requirements:** **BT-01..BT-09** — see [v1.33-REQUIREMENTS.md](v1.33-REQUIREMENTS.md). **Strategic parent:** [STRATEGY.md](../STRATEGY.md).

| # | Phase | Goal | Requirements |
|---|-------|------|--------------|
| 101 | Accrue Portal Foundation & Checkout | First-party LiveView checkout + customer portal scaffolding wrapping Braintree Hosted Fields. | BT-01, BT-02, BT-03 |
| 102 | Coupon / Discount Mapping | Local promotion-code resolution mapping to Braintree Discount IDs at subscription time. | BT-04, BT-05 |
| 103 | Metering Engine | Custom local aggregation engine for metered usage and Braintree renewal settlement. | BT-06, BT-07 |
| 104 | Connect Spike / Decision | Investigate Hyperwallet for Braintree marketplace parity and record the go/no-go boundary. | BT-08, BT-09 |

**Success criteria (milestone):**

1. Host apps can mount `Accrue.Portal` and route customers through a first-party hosted checkout + self-serve portal on Braintree.
2. Promotion codes entered in the portal correctly apply Braintree Discount IDs to subscriptions.
3. Metered usage is locally aggregated and billed through Braintree without implying a native Braintree-side meter.
4. A documented decision exists on Connect/Hyperwallet parity for Braintree marketplaces.

## Milestone Summary

**Decimal Phases:** none.

**Key Decisions:**

- Braintree checkout and billing-portal support are part of the first-party surface, but remain provider-honest: Stripe returns upstream hosted pages while Braintree returns mounted local UI.
- Promotion-code support on Braintree is explicitly local-first: stored mappings resolve to Braintree discounts, and stale or invalid mappings fail clearly instead of silently degrading.
- Braintree metering stays local-ledger-first: renewal windows, invoice authoring, settlement, repair, and telemetry all live in Accrue rather than pretending native Braintree meter parity.
- Hyperwallet is a hard no-go for the current strategy; marketplace parity for Braintree remains out of scope unless the strategy changes and a new milestone reopens it explicitly.

**Issues Resolved:**

- Closed BT-01..BT-09 with verification artifacts for all four phases.
- Restored the example-host `/app/billing` proof lane that had drifted during portal and metering work.
- Reconciled processor-support wording so strategy, support matrix, docs, and verifier needles now tell the same Braintree story.

**Issues Deferred:**

- No next milestone is defined yet; fresh requirements and roadmap scope are required before continuing the PROC-08 track.
- Marketplace Connect parity for Braintree via Hyperwallet remains explicitly rejected for the current direct-gateway strategy.
- FIN-03 remains out of scope.

**Technical Debt Incurred:**

- The milestone close depended on a dedicated closeout pass to backfill `101` / `103` / `104` verification artifacts and reconcile `102-VALIDATION.md`; future milestones should keep phase-level verification artifacts current earlier.
- The archive reflects a repo that no longer uses a top-level active `.planning/REQUIREMENTS.md`; the milestone-scoped requirements file under `.planning/milestones/` is now the operational pattern.

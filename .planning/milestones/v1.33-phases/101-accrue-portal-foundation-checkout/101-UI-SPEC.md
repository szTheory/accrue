# Phase 101 — UI Design Contract

> Visual and interaction contract for the **end-customer-facing** `accrue_portal` package: hosted checkout (Braintree Hosted Fields) + customer portal (subs, PMs, invoices, cancel). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Provenance:** This contract is heavily pre-populated from `101-CONTEXT.md` (cohesive synthesis from 4 advisor agents) and the existing locked Accrue brand tokens (`accrue/priv/static/brand.css`, FND-07, Phase 1). No new aesthetic decisions — Claude's Discretion line in 101-CONTEXT.md mandates "HEEx + tailwind classes match `accrue_admin`'s look-and-feel for visual consistency when both packages are mounted in the same host."

## Design System

| Property | Value |
|----------|-------|

### Themability contract (NON-NEGOTIABLE — OSS library audience)

`accrue_portal` is shipped to third-party Phoenix SaaS hosts. Every visible color MUST be a CSS variable, never a hard-coded hex inside HEEx or Tailwind utilities. Hosts override by setting `--accrue-cobalt`, `--accrue-moss`, etc. on `:root` in their own stylesheet, OR by configuring `Accrue.Config :branding.accent_color` (already wired through `BrandPlug`). **Failure mode the contract prevents:** "I can't make Accrue Portal match my brand" — the #1 OSS adoption blocker.

## Layout Strategy: host-aware vs. shipped shell

Phase 101 ships **one rendering posture**, with a documented opt-in for hosts that want the in-host shell:

### Default (shipped): standalone "billing portal" layout

`Accrue.Portal.Layouts.root/1` and `Accrue.Portal.Layouts.app/1` render a self-contained portal shell:
- Top bar: brand logo (host-supplied via `BrandPlug`), business name, theme toggle, "Sign out" link (host-controlled URL, surfaced via `:unauthenticated_path` config sibling)
- Left rail: portal nav (Dashboard / Subscriptions / Payment methods / Invoices) — **only on `>=md` (768px)**; below that, top bar exposes a hamburger
- Main content area: scoped to viewport, max-width `1120px` centered
- No host chrome injected

Rationale: customers visiting `/billing` should feel they are on a **dedicated billing surface**, not a half-styled iframe inside the marketing site. This matches Stripe Hosted Checkout's standalone posture (the comparison customers will draw).

### Opt-in: embed in host layout (`:layout` option on `accrue_portal/2`)

The `accrue_portal/2` macro accepts `layout: {MyAppWeb.Layouts, :app}` (mirroring how `accrue_admin/2` already works). When set, Portal LVs render their content slot inside the host's layout — host owns sidebar, top bar, footer; Portal owns only the central content card.

**Out of scope for v1.33:** sidecar-mounted-iframe deployment (e.g., `<iframe src="/billing" />` embedded in the host's own page). The portal works that way today (no hostile headers), but no first-class API guarantees it.

### Full-bleed checkout exception (Hosted Fields)

The checkout LV (`Accrue.Portal.Live.CheckoutLive`) uses a **single-column centered layout** — no sidebar even on desktop. Reasoning: payment-form abandonment correlates inversely with on-screen distractions. Mirror Stripe Hosted Checkout's column.

## Spacing Scale

Declared values (must be multiples of 4). **Source:** `accrue_admin/assets/css/theme.css:9-14` (mirrored exactly to keep operator and customer surfaces visually consistent in hosts that mount both).

| Token | rem | px | Usage |
|-------|-----|-----|-------|
| `--ap-space-xs` | 0.25rem | 4px | Icon-to-text gaps, badge inner padding |
| `--ap-space-sm` | 0.5rem | 8px | Compact element spacing, form field internal padding |
| `--ap-space-md` | 1rem | 16px | Default element spacing, card body padding |
| `--ap-space-lg` | 1.5rem | 24px | Section padding, card-to-card gap |
| `--ap-space-xl` | 2rem | 32px | Layout gaps, page padding desktop |
| `--ap-space-2xl` | 3rem | 48px | Major section breaks (e.g., between hero CTA and supporting copy) |

Exceptions (touch-target compliance — WCAG 2.2 SC 2.5.8):
- Interactive controls (buttons, links serving as buttons, form inputs, toggle switches, payment-method "set default" / "delete" affordances) MUST have a minimum hit area of **44×44 px** even if their visible glyph is smaller. Implement via padding, not via `min-height` alone, so disabled-state `cursor` and click semantics still work.
- Hosted Fields iframe wrappers (`<div class="ap-hf-field">`) — fixed **48px** min-height to match Braintree's recommended host-element height (under 48 the iframe content can clip on Mobile Safari).

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (1rem) | 400 (regular) | 1.5 | Default paragraph text, form descriptions, card body |
| Label | 14px (0.875rem) | 600 (semibold) | 1.4 | Form labels, table headers, small KPI labels |
| Heading | 20px (1.25rem) | 600 (semibold) | 1.2 | Card titles, section headings (`<h2>`) |
| Display | 28px (1.75rem) | 600 (semibold) | 1.2 | Page hero headline (`<h1>`), checkout total amount |

**Font weight discipline:** EXACTLY 2 weights — 400 (regular) and 600 (semibold). No 500, no 700. Reasoning: system stack on macOS/Windows/Linux renders 600 distinctly; 500 is muddy on Windows ClearType, 700 on macOS Retina is heavier than design intent.

**Numeric tabular alignment (REQUIRED):** All money amounts (subscription price, invoice totals, line-item amounts) MUST use `font-variant-numeric: tabular-nums` so digits align in vertical lists. Class `.ap-num-tabular` exposes this; apply on every `<td>` showing a money value.

**Mono usage:** Reserved for one purpose only — the Braintree transaction ID / processor reference shown on receipts. Do not use mono for prices, dates, or other "data-y" content. **Source:** `theme.css:8`.

### Accent reserved for (EXPLICIT LIST — never "all interactive elements")

The `--ap-accent` (cobalt) color may appear on:

1. **Primary CTA button** — exactly one per page: "Subscribe", "Add payment method", "Save changes" (only the action that completes the page's purpose)
2. **Active nav item indicator** — left rail current page (background tint, not text color)
3. **Focus ring** — `:focus-visible` only, never on `:hover`
4. **Hosted Fields focus border** — when a card-number/CVV/expiry iframe is focused, the wrapping `<div>` border shifts to accent (drives Hosted Fields' iframe-content focus styling — see "Braintree Hosted Fields Visual Contract" below)
5. **Selected item state** — e.g., the chosen plan card on a multi-plan checkout (subtle accent border + 12% accent background tint)

**Accent is NOT used for:**
- Body links inside paragraph copy (use `--ap-primary` underlined)
- Secondary buttons (e.g., "Leave checkout", "Discard card", "Keep subscription", "Back")
- Inactive nav items
- Form field borders (default `--ap-border`)
- Table row hover (`color-mix(--ap-base 84%, --ap-elevated)`)
- Success/warning/error states (those have their own tokens)

### Destructive confirmation discipline

Three destructive actions exist in this phase: **Cancel subscription**, **Delete payment method**, **Cancel checkout in progress** (abandon flow with unsaved nonce).

For each: **two-step confirmation** — clicking the destructive button opens an inline confirm panel (NOT a modal — modals are reserved for step-up auth) with explicit verb-noun confirm copy and a "Keep" escape hatch. The confirm button uses `bg: #B42318 / color: #FFFFFF`, never the cobalt accent.

## Braintree Hosted Fields Visual Contract

Hosted Fields renders three iframes (card number, expiration, CVV) inside `<div>` placeholders we control. Braintree's `styles` option controls the **content of the iframe** (font, color, padding); we control the wrapping `<div>` (border, focus ring, error state). The split is non-negotiable — Braintree owns iframe inner styling for security/PCI reasons.

### Iframe content styles (passed to Braintree's `client.create({styles: ...})`)

```js
{
  "input": {
    "font-family": "system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif",
    "font-size": "16px",          // matches our --ap-body size; >=16px prevents iOS Safari zoom
    "font-weight": "400",
    "color": "#111418",            // hard-coded — Hosted Fields cannot read CSS vars
    "line-height": "1.5"
  },
  "input.invalid": {
    "color": "#B42318"
  },
  "input.valid": {
    "color": "#111418"
  },
  ":-webkit-autofill": {
    "color": "#111418"
  },
  "::placeholder": {
    "color": "#5D6A73"             // matches --ap-muted
  }
}
```

**Dark mode:** Hosted Fields supports a `styles` overrides object. The CheckoutLive JS hook reads `data-theme` from `<html>` and re-initializes (or, if Braintree SDK supports it on this version, calls `instance.setAttribute({styles: ...})`) with dark-mode hex values: `color: #F4F7FA`, placeholder `#A8B2BC`, invalid `#FDA29B`. Verify SDK API at implementation time.

### Wrapper `<div>` (host-element) styles

| State | Border | Background | Notes |
|-------|--------|------------|-------|
| Default | `1px solid var(--ap-border)` | `var(--ap-sunken)` | min-height 48px, padding 12px 16px, radius `var(--ap-radius-sm)` |
| Focus | `2px solid var(--ap-accent)` | `var(--ap-elevated)` | Focus is propagated by Braintree via class `braintree-hosted-fields-focused` on the host element |
| Invalid | `2px solid #B42318` | `color-mix(in srgb, #B42318 6%, var(--ap-elevated))` | Class `braintree-hosted-fields-invalid` |
| Valid (touched + valid) | `1px solid var(--ap-success)` | `var(--ap-elevated)` | Class `braintree-hosted-fields-valid` |

**Layout:** Card number occupies a single full-width row; expiration + CVV share a row below at 50/50 (or stack on `<sm` viewports). Cardholder name field is a normal LV-rendered `<input>`, not a Hosted Field (Braintree only requires number/expiry/CVV in iframes; name is non-PCI).

### Required loading states

- **iframes-loading:** while Braintree SDK boots (1-3s on cold cache), show skeleton boxes matching the iframe wrapper dimensions exactly. Never show empty white space — perceived load time matters on a money page.
- **submit-pending:** after the user clicks "Pay $X", disable the button, swap label to "Processing payment…", show a spinner glyph LEFT of the label. Hosted Fields' tokenize call is async (~200-500ms) followed by our subscription create (~1-2s on Braintree). DO NOT use a full-page overlay — keep the form visible so the user knows where their attention is.
- **submit-error:** show the error message inline above the submit button using the destructive color, NOT in a flash region. Flashes are too easy to miss after the user has scrolled past.

All portal-facing copy lives in `accrue_portal/lib/accrue_portal/copy.ex` (mirror of `accrue_admin/lib/accrue_admin/copy.ex` — single source of truth, no inline strings in HEEx). i18n is out of scope for v1.33; English-only with the strings below.

| Page | Primary CTA Label | Secondary CTA Label |
|------|-------------------|----------------------|

### Brand voice rules

- **Second person, active voice:** "You can update your card" not "The user may update their card"
- **No exclamation points** except in the welcome toast ("Welcome!") and one-time success congratulations ("Subscribed to Pro. Welcome!"). Anything else feels desperate.
- **Money formatting:** Always show currency code OR symbol — never bare numbers. Use `Accrue.Money.format/2` (already in core). Examples: "$29.00", "€29,00", "$29.00 USD" (when ambiguity matters, e.g., multi-currency hosts).
- **Time formatting:** Relative for short ranges ("in 3 days", "yesterday"), absolute for ≥7 days ("on May 8, 2026"). Always include the year for invoice dates.
- **Don't apologize for the host's policies:** "Your subscription ends at period end" not "Sorry, your subscription will sadly end at period end."
- **Never use the word "simply":** if the action were simple, we wouldn't need copy explaining it.

## Interaction Patterns

### Loading states (REQUIRED on every async surface)

- LV mount: skeleton blocks at component level, NEVER a global spinner. Skeleton has the exact dimensions of the loaded content (no layout shift).
- Form submit: button-level pending state — disabled, label swap to gerund ("Saving…", "Processing payment…"), spinner glyph 16px to the LEFT of label.
- Hosted Fields boot: skeleton boxes inside the wrapper divs while SDK loads.

### Empty states (REQUIRED — no "blank table")

Every list view (subscriptions, payment methods, invoices) MUST render the empty-state copy from the contract above when no rows. Empty state always includes a forward path (link or CTA), never a dead end.

### Error states

- **Field-level:** Hosted Fields invalid → red border on the wrapper + inline error text below the row, 14px.
- **Form-level:** form submit error → destructive-color text region directly above the submit button. Stays until next form interaction (don't auto-clear on keystroke — user might be reading).
- **Page-level:** LV crash → flash region top of page; offer "Refresh" button. Don't redirect to a separate /error page — context loss.

### Focus management

- Modal focus trap: only on step-up auth modal (mirror admin's `StepUpAuthModal`); not used elsewhere in v1.33 since destructive confirms are inline.
- Skip-link: top of every page — `<a href="#main">Skip to content</a>` (screen-reader/keyboard nav users skip the nav rail).
- After LV `push_patch` to a new view, focus moves to the page's `<h1>` (programmatic `focus()` via JS hook).
- Form submit success (e.g., "Card saved") with redirect: focus moves to the toast region for SR announcement; visual focus moves to the page's primary CTA on the new page.

### Keyboard

- Every interactive control reachable by Tab in document order
- Destructive actions: `Esc` cancels the inline confirm panel
- Form submit: `Enter` in any field submits (default browser); Hosted Fields iframes require Braintree's bridged Enter handling (already supported by SDK)
- Tab order on checkout: Cardholder name → Card number → Expiry → CVV → Pay button → "Leave checkout" link

### Animations / motion

- All transitions: `180ms ease` (matches admin's `--ax-theme-transition`)
- `prefers-reduced-motion: reduce` → all transitions become `0ms`. Theme.css already implements this for `--ap-theme-transition`. Do NOT use motion to convey meaning (e.g., shake-to-indicate-error) — it must work as still UI for the reduced-motion user.

### Responsive breakpoints (Tailwind defaults; mirror admin)

| Breakpoint | Width | Behavior shift |
|------------|-------|----------------|
| `sm` | 640px | Two-column form rows (expiry/CVV) un-stack |
| `md` | 768px | Nav rail appears; mobile hamburger disappears |

## CSP Allowlist for Hosted Fields (D-22 — already locked in CONTEXT.md)

`Accrue.Portal.CSPPlug` MUST emit:

```
default-src 'self';
base-uri 'self';
connect-src 'self' wss: https://*.braintreegateway.com https://*.braintree-api.com https://api.braintreegateway.com;
font-src 'self' data:;
img-src 'self' data: https:;
object-src 'none';
script-src 'self' 'nonce-{nonce}' https://js.braintreegateway.com https://assets.braintreegateway.com;
style-src 'self' 'nonce-{nonce}' 'unsafe-inline';
frame-src 'self' https://assets.braintreegateway.com https://*.braintreegateway.com;
frame-ancestors 'self'
```

**Source for allowlisted hosts:** Braintree Hosted Fields v3 documentation (canonical hosts list as of 2025-Q4). The `'unsafe-inline'` on `style-src` is required by Hosted Fields' iframe-content styling (the SDK injects style tags); we cannot eliminate it without breaking the integration. Document this trade-off in the install guide. We compensate by keeping `script-src` strict-nonce and `frame-src` to a tight allowlist.

**Subresource Integrity (SRI):** Per CONTEXT.md Discretion, the `js.braintreegateway.com/.../client.min.js` and Hosted Fields module `<script>` tags MUST include an `integrity` attribute pinning a known-good hash. SRI hash for the SDK version is a planning-phase concern — record in PLAN.md, surface in the install guide, document the upgrade procedure (when Braintree releases new SDK, hash must rotate).

## Security Visual Contract (Phase 101–specific)

Defense-in-depth from D-19 has visual implications:

| Surface | Behavior on wrong-tenant access |
|---------|----------------------------------|
| `/subscriptions/:id` where `:id` not owned by `current_customer` | Render the standard 404 page with copy "Page not found" — DO NOT render "You don't have access to this subscription" (information leakage). LV halts mount. |
| `/payment-methods/:id` same | Same 404. |
| `/invoices/:id` same | Same 404. |

This is not just an engineering rule — it's a UI rule, because "different copy on different failures" is itself a side channel. The portal must look identical between "doesn't exist" and "exists but not yours."

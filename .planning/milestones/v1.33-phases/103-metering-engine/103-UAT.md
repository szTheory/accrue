## Verification Approach

Phase 103 ships the local Braintree metering engine — meter definitions,
webhook-anchored renewal windows, replay-safe settlement, stale-window
reconciliation, and durable ops telemetry. Every user-observable behavior
below was test-driven during the four plan executions and lives under
`accrue/test/`, which runs in full on every `release-gate` matrix cell.

CI gates that must be green to merge:

- `release-gate (accrue × Floor | Primary | Forward-compat)` — runs the
  complete `cd accrue && mix test --warnings-as-errors` suite, which
  includes every metering test below

No phase-named gate (e.g. `phase103-metering-gate` mirroring
`phase18-tax-gate`) was added — it would duplicate the metering coverage
that `release-gate` already runs, slowing CI without adding signal. Phase
18 has a focused gate because tax tests run against external Stripe
sandbox state; Phase 103 tests are pure Ecto + Fake processor and are
fast enough to live in the main suite.

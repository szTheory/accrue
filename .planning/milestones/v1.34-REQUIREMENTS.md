# Requirements: v1.34 Rendro Native Invoice PDF Default

**Archived:** 2026-05-06
**Status:** ✅ Complete

## Overview

Make Rendro the default invoice PDF path in Accrue so Chrome is no longer required for the primary install story, while preserving the existing invoice-facing APIs, lazy render semantics, and an explicit optional ChromicPDF fallback.

## Final Requirement Outcomes

- [x] **PDF-01** — Introduced an invoice-specific PDF renderer seam separate from the existing HTML-oriented `Accrue.PDF.render/2` contract.
- [x] **PDF-02** — Routed `Accrue.Invoices.render_invoice_pdf/2` through the invoice renderer seam without changing the public billing and invoice API surface.
- [x] **PDF-03** — Preserved lazy render and storage semantics for `render/store/fetch_invoice_pdf` flows when the default renderer changed.
- [x] **PDF-04** — Made Rendro the default invoice PDF renderer and generated valid invoice PDFs without requiring Chrome.
- [x] **PDF-05** — Preserved invoice content and layout intent parity for branding, totals, line items, dates, footer semantics, email attachments, and admin download flows.
- [x] **PDF-06** — Kept ChromicPDF available as an explicit optional fallback path with clear configuration and failure messaging.
- [x] **PDF-07** — Published the required Rendro version to Hex and replaced the temporary local path dependency before milestone close.
- [x] **PDF-08** — Updated Accrue’s install and PDF docs so Rendro is the default recommendation and ChromicPDF is documented as an optional fallback.
- [x] **PDF-09** — Documented the migration posture for hosts currently using the legacy `:pdf_adapter` or ChromicPDF-based invoice path.

# Milestone v1.34: Rendro Native Invoice PDF Default

**Status:** ✅ SHIPPED 2026-05-06
**Phases:** 106-108
**Total Plans:** 6

## Overview

Made Rendro the default invoice PDF path in Accrue so the normal install story no longer depends on Chrome, while preserving invoice-facing public APIs, lazy render and storage semantics, an explicit optional ChromicPDF compatibility path, and a published Hex-backed Rendro dependency handoff.

## Phases

### Phase 106: Invoice Renderer Seam & Rendro Default

**Goal**: Introduce the invoice-specific renderer seam, route invoice PDFs through Rendro by default, and preserve lazy render/storage behavior plus billing, mailer, and admin parity.
**Depends on**: v1.33 shipped
**Plans**: 2 plans

Plans:

- [x] 106-01: Correct invoice proof lanes and contract docs to use the invoice renderer seam
- [x] 106-02: Strengthen Rendro semantic parity proof while preserving the public billing facade

**Details:**
Phase 106 split invoice rendering from the legacy HTML `Accrue.PDF` seam, established `Accrue.InvoiceRenderer` as the invoice-facing path, kept `Accrue.Billing.render_invoice_pdf/2`, `store_invoice_pdf/2`, and `fetch_invoice_pdf/1` stable, and proved the Rendro default across billing, mailer, and admin flows without requiring Chrome.

### Phase 107: Rendro Release & Optional Chromic Path

**Goal**: Keep ChromicPDF as an explicit compatibility path, harden runtime/config/error behavior, and replace the local Rendro path dependency with a published Hex release.
**Depends on**: Phase 106
**Plans**: 2 plans

Plans:

- [x] 107-01: Typed explicit-Chromic compatibility contract, migration warnings, and invoice-path-wide telemetry
- [x] 107-02: Rendro Hex cutover and clean-checkout release proof

**Details:**
Phase 107 introduced `%Accrue.Error.InvoiceRendererUnavailable{}` for explicit Chromic misconfiguration, kept the Rendro path as the default with no implicit fallback chain, added narrow boot warnings for legacy `:pdf_adapter` drift, expanded invoice-path unavailable telemetry, switched `accrue` to `{:rendro, "~> 0.1.0"}`, and added `scripts/ci/verify_rendro_hex_resolution.sh` plus the release-order runbook updates.

### Phase 108: Docs, Migration, and Proof Closeout

**Goal**: Update install and PDF docs around Rendro-first defaults, document migration for legacy `:pdf_adapter` / Chromic hosts, and revalidate final billing/admin/email proof lanes.
**Depends on**: Phase 107
**Plans**: 2 plans

Plans:

- [x] 108-01: Front-door docs, operational guidance, and canonical migration section
- [x] 108-02: Advanced guide cleanup and behavior-first closeout proof

**Details:**
Phase 108 rewrote package and guide surfaces to describe Rendro-first defaults honestly, documented the three-state migration contract for legacy hosts, aligned advanced custom-PDF/email/branding guides to the seam split, and revalidated the billing PDF, mailer attachment/fallback, admin invoice flow, package-doc verifier, HexDocs build, and Rendro Hex-resolution proof.

## Milestone Summary

**Decimal Phases:**

- None

**Key Decisions:**

- Decision: Invoice rendering now belongs to `:invoice_pdf_adapter` and `Accrue.InvoiceRenderer`, while `:pdf_adapter` remains the lower-level HTML seam.
- Decision: Rendro is the default invoice renderer and ChromicPDF is only an explicit compatibility path, never an inferred fallback.
- Decision: Release truth for Rendro must come from Hex-backed resolution plus a clean-checkout proof script, not a maintainer-local sibling repository.

**Issues Resolved:**

- Removed proof-lane drift that still configured invoice behavior through the legacy HTML seam.
- Replaced bare `:chromic_pdf_not_started` invoice failures with a typed host-matchable error contract.
- Eliminated the local `../../rendro` dependency requirement from `accrue`.
- Cleared stale package-doc and HexDocs warnings during milestone closeout.

**Issues Deferred:**

- None

**Technical Debt Incurred:**

- None recorded in the milestone audit.

# Requirements: v1.35 Dual-Provider Supportability Closure

**Archived:** 2026-05-07
**Status:** ✅ Complete

## Overview

Close the supportability gap between Accrue's shipped Stripe + Braintree capabilities and the repo's public/operator-facing truth by aligning support-contract docs, lifecycle semantics, and webhook/operator recovery guidance.

## Final Requirement Outcomes

- [x] **SUP-01** — Public package docs, support matrix, and planning mirrors now state one provider-honest contract for checkout, billing portal, and the official Stripe + Braintree facade surface.
- [x] **SUP-02** — First-hour and host-facing guidance now document the mounted Braintree portal/checkout setup contract, including `portal_base_url`, `portal_mount_path`, auth/CSP expectations, and sharp failure modes.
- [x] **LIF-01** — Accrue now publishes one canonical lifecycle semantics guide covering cancel, cancel-at-period-end, resume, pause/unpause, lifecycle labels, and post-action convergence across Stripe, Fake, and Braintree with explicit native/host-owned/unsupported labeling.
- [x] **LIF-02** — Touched lifecycle copy and UI now prefer least-surprise subscription behavior, distinguish `active`, `canceling`, `paused`, `past_due`, and `ended`, and avoid implying Stripe-only semantics on Braintree.
- [x] **OPS-01** — Webhook docs, operator runbooks, and telemetry references are now processor-aware for the shipped Braintree slice, including replay/recovery, drift diagnosis, checkout completion ambiguity, and metered-renewal recovery.
- [x] **OPS-02** — Deterministic proof and verifier coverage now guard the support contract and exercise the Braintree recovery/documentation paths formalized in this milestone.

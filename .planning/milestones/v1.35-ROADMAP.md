# Milestone v1.35: Dual-Provider Supportability Closure

**Status:** ✅ SHIPPED 2026-05-07
**Phases:** 109-111
**Total Plans:** 9

## Overview

Closed the supportability gap between Accrue's shipped Stripe + Braintree core and the repo's public/operator-facing truth by aligning the support contract, mounted Braintree onboarding, lifecycle semantics, and webhook/replay/operator recovery guidance around one provider-honest story.

## Phases

### Phase 109: Support Contract Truth

**Goal**: Align package docs, planning mirrors, onboarding docs, example-host proof docs, and drift gates around one provider-honest checkout and billing-portal contract.
**Depends on**: v1.34 shipped
**Plans**: 3 plans

Plans:

- [x] 109-01: Normalize the support SSOT and package-facing front doors
- [x] 109-02: Branch mounted Braintree onboarding and operator guidance from the same contract
- [x] 109-03: Align example-host mirrors and shift-left bash gates to the shipped support truth

**Details:**
Phase 109 made the public contract explicit: Stripe returns upstream hosted checkout and billing-portal URLs, while Braintree returns mounted first-party local URLs on the same facade. The same wording now appears in the processor support matrix, root/package READMEs, active planning mirrors, First Hour, `accrue_portal` docs, example-host proof docs, and the merge-blocking bash verifiers that protect those mirrors.

### Phase 110: Lifecycle Semantics & Self-Serve Clarity

**Goal**: Publish one canonical lifecycle semantics guide and propagate least-surprise renewal/cancellation wording into touched portal, admin, and example-host surfaces with proof.
**Depends on**: Phase 109
**Plans**: 3 plans

Plans:

- [x] 110-01: Publish lifecycle semantics SSOT and link adjacent guides back to it
- [x] 110-02: Rewrite portal, admin, and host lifecycle wording around least-surprise semantics
- [x] 110-03: Add targeted proof for the lifecycle SSOT and touched LiveView copy

**Details:**
Phase 110 introduced `accrue/guides/lifecycle_semantics.md` as the canonical glossary for cancel, cancel-at-period-end, resume, pause, state labels, and convergence expectations across Stripe, Fake, and Braintree. It then updated the portal, admin, and example-host UI copy to prefer "cancel renewal" and explicit access timing over vague status strings, and locked that wording down with focused docs and LiveView tests.

### Phase 111: Webhook & Operator Closure

**Goal**: Make webhook, replay, telemetry, and operator recovery guidance processor-aware for the shipped Braintree slice and prove the recovery path deterministically.
**Depends on**: Phase 110
**Plans**: 3 plans

Plans:

- [x] 111-01: Rewrite webhook, telemetry, and operator guides around shared boundary plus processor deltas
- [x] 111-02: Name and guard the deterministic replay/recovery proof bundle
- [x] 111-03: Harden replay, DLQ, and local portal-completion idempotency proof

**Details:**
Phase 111 rewrote the webhook and operator story so Stripe hosted flow semantics and Braintree local checkout/replay semantics are described together without parity theater. It added explicit replay and supportability proof coverage in docs and tests, strengthened DLQ and CLI replay coverage for Braintree portal-completion rows, and finished with a passed milestone audit after the bounded host verifier and the library-side replay/idempotency bundle reran green.

**Key Decisions:**

- Decision: Checkout and billing portal remain a single public facade, but support surfaces must explicitly distinguish Stripe-hosted URLs from Braintree-mounted local URLs.

- Decision: Braintree supportability closes on deterministic replay/idempotency proof and operator runbooks, not on new processor breadth or new billing primitives.

- Replaced vague cancellation/lifecycle copy with explicit end-of-period, hard-stop, paused, past-due, and ended semantics across touched surfaces.
- Hardened webhook replay and local portal-completion proof so the operator recovery story is both documented and test-backed.
- Backfilled phase verification artifacts and refreshed the milestone audit to a passing closeout state.

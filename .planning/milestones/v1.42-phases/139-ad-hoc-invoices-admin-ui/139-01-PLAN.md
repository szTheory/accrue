# Phase 139: Ad-hoc Invoices - Admin UI

## Objective
Add operator controls to the existing invoice detail page in `accrue_admin` to allow adding and removing ad-hoc (manual) line items on draft invoices. This fulfills the visual and behavioral contracts defined in `139-UI-SPEC.md`.

## Key Files & Context
- `accrue_admin/lib/accrue_admin/live/invoice_live.ex`: The primary LiveView to modify.
- `accrue_admin/lib/accrue_admin/copy.ex`: Centralized copy text for the admin interface.
- `accrue/lib/accrue/billing.ex`: Backend API providing `add_invoice_item/2` and `remove_invoice_item/2`.
- `accrue_admin/test/accrue_admin_web/live/invoice_live_test.exs`: Test suite for the invoice detail LiveView.

## Implementation Steps

### 1. Update Copy Functions
Add the required copywriting from the UI-SPEC to `AccrueAdmin.Copy`:
- `invoice_add_manual_item_cta/0`: "Add manual line item"
- `invoice_empty_manual_items_heading/0`: "No manual adjustments yet"
- `invoice_empty_manual_items_body/0`: "Draft invoices can include one-off charges or credits here..."
- `invoice_add_manual_item_error/0`: "We couldn’t save this invoice adjustment..."
- `invoice_remove_manual_item_confirm/0`: "Remove manual line item: This removes the adjustment from the draft invoice..."
- `invoice_add_manual_item_success/0`: "Manual line item saved. It will appear on the finalized invoice."
- `invoice_remove_manual_item_success/0`: "Manual line item removed from the draft invoice."
- `invoice_draft_locked_guidance/0`: "Only draft invoices can be adjusted from admin."
- `invoice_manual_row_badge/0`: "Manual adjustment"

### 2. State Management in `InvoiceLive`
- Add `:pending_remove_item` and `:new_item_form` assigns to `mount/3` and `assign_invoice/2`.
- Initialize `:new_item_form` as a changeset or schemaless map for `%{"description" => "", "amount_minor" => "", "currency" => "@invoice.currency"}`.
- Ensure the state is reset appropriately on successful add/remove operations.

### 3. Add Line Item Workflow
- Render a new form card inside `<section class="ax-card">` immediately preceding or adjacent to the existing line items list.
- Only render the actionable form if `@invoice.status == :draft`. If not draft, render the passive `invoice_draft_locked_guidance/0`.
- The form should include inputs for `description`, `amount_minor`, and a locked or default `currency` select.
- Implement `handle_event("add_manual_item", %{"invoice_item" => params}, socket)`:
  - Cast `params` and call `Accrue.Billing.add_invoice_item(@invoice, attrs)`.
  - On success: push success flash, clear form, and call `refresh_invoice/2`.
  - On failure: push error flash.

### 4. Remove Line Item Workflow
- In the line items list, distinguish manual items (e.g., items without a `price_ref` or generated by the ad-hoc API).
- Render the `invoice_manual_row_badge/0` label next to manual items.
- If `@invoice.status == :draft`, render a "Remove" button for these items.
- Clicking "Remove" stages the item by sending `phx-click="stage_remove_item" phx-value-id={item.id}` and updating the `:pending_remove_item` assign.
- Conditionally render an inline confirmation block for the staged item with a primary "Confirm" and ghost "Cancel" button.
- Implement `handle_event("confirm_remove_item", _, socket)`:
  - Call `Accrue.Billing.remove_invoice_item(@invoice, socket.assigns.pending_remove_item)`.
  - On success: push success flash, clear `:pending_remove_item`, and call `refresh_invoice/2`.

## Verification & Testing
- **UI Checks:** Verify the UI strictly follows `139-UI-SPEC.md` colors, spacing (`ax-*` classes), and copy text.
- **Unit/Integration Tests:** Update `invoice_live_test.exs` to simulate a user filling out the ad-hoc line item form on a draft invoice and successfully submitting it. Verify the item appears in the list.
- **Remove Test:** Simulate clicking the remove button, confirming the inline dialog, and verifying the item is removed from the DOM and backend.
- **Status Gating Test:** Assert that a finalized invoice does not render the add form or remove buttons.

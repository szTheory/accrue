<objective>
Integrate E2E testing into GitHub Actions CI to ensure production-readiness, prevent regressions, and enforce a shift-left testing culture.

Purpose: Implement the Hybrid Model (D-01) with both native Playwright testing for speed/sharding and a Docker boot check to protect local DX. Implement D-03 by promoting the live-Stripe check to be mandatory periodically.
Output: Updated `ci.yml` with native Playwright jobs, a Docker smoke job, and a modified live-stripe job.
</objective>

<task type="auto">
  <name>Task 1: Add Native Playwright CI Job (Sharded)</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Update `.github/workflows/ci.yml` to add a new `playwright-e2e` job.
    This job should run on `ubuntu-24.04`, setup Elixir/Node natively for speed, install dependencies, compile the app with `MIX_ENV=test`, run database migrations/seeds, install Playwright browsers, and run `npx playwright test`.
    Configure it as a matrix job to support Playwright sharding (e.g., `shard: [1, 2, 3]`, `npx playwright test --shard=${{ matrix.shard }}/${{ strategy.job-total }}`) to maximize parallelization (per D-04).
  </action>

  <done>CI contains a natively running, sharded Playwright E2E job.</done>

  <name>Task 2: Add Docker Smoke Job to CI</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Update `.github/workflows/ci.yml` to add a new job `host-docker-smoke`.

  </verify>
  <done>CI contains a job that runs the Docker Compose setup to prevent dev UX regressions.</done>
</task>

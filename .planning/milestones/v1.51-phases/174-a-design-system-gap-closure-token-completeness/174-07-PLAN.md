<objective>
Resolve the stale deferral comment in .ax-search-trigger and formally document it as an intentional exception to the "all transitions use a single bundle var()" must_have (DSY-01, Gap 3).

Decision chosen: option (c) — document .ax-search-trigger as an intentional exception and remove the "collapse pending" comment. Rationale: the .ax-search-trigger transition intentionally uses two different named token variables to achieve asymmetric enter/exit timing. --ax-theme-transition (180ms ease-out) drives the color/border/background changes; --ax-motion-fast (120ms ease-out via the back-compat alias) drives the transform snap. These two durations are brand-meaningful — collapsing them into a single bundle would require a new --ax-transition-focus token that is functionally identical to --ax-transition-base with one property at a different duration, adding complexity with no DX benefit. The 4 collapsed sites all had identical per-property durations, making a single bundle a lossless simplification. The .ax-search-trigger site is not lossy-collapsible without a new token.

No CSS behavioral change is made. Only the stale comment is replaced with an exception comment. The asset bundle must still be rebuilt (even comment-only changes to app.css require a rebuild to reflect in accrue_admin.css).

Output: app.css .ax-search-trigger comment resolved. accrue_admin.css rebuilt. grep for "collapse pending" returns 0.
</objective>

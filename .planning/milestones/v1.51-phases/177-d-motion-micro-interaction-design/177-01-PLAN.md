Create a new guide at accrue_admin/guides/motion.md. This is the authoritative motion spec
for the Phase 177 depth pass. Produce it as a human-readable Markdown document suitable for
ExDoc. Do NOT include fenced code blocks with implementation samples — the guide contains
specification prose, tables, and references to token names, not code.

Structure the document with these sections in order:

1. A title "# Motion & Micro-interaction Design" and a brief intro paragraph: "Accrue Admin
   applies restrained, purposeful, token-based motion to interactive surfaces. Every
   animation serves a functional role (feedback, continuity, or affordance) and honors
   `prefers-reduced-motion`. Decorative motion is inadmissible."

2. "## Motion Vocabulary" — reproduce the token table from 177-UI-SPEC.md §Motion Vocabulary:
   duration atoms (--ax-dur-instant through --ax-dur-exit), easing atoms (--ax-ease-out
   through --ax-ease-emphasis), travel/scale atoms (--ax-rise-sm/md, --ax-press-scale), and
   property bundles (--ax-transition-colors/transform/shadow/base). Include a note: "All new
   motion composes from these atoms only. Raw `ms`, `s`, or `cubic-bezier()` literals in
   app.css are banned (see Enforcement Guard below)."

3. "## The Motion Contract" — reproduce the full 9-surface table from 177-UI-SPEC.md
   §The Motion Contract, with columns: Surface (file) | Trigger | Animated property | Enter
   token | Exit token | Reduced-motion fallback | Justification. Use the exact surface names,
   triggers, tokens, and justifications from the UI-SPEC. All 9 rows (detail_drawer,
   detail_drawer-backdrop, dropdown_menu, More ▾ overflow, collapsible nav group,
   global_search palette, palette backdrop, tabs active indicator, flash/toasts,
   skeleton→content, badge/state change) must appear. Include the enter/exit asymmetry note
   below the table.

4. "## Antipattern List" — reproduce the 8-row antipattern table from 177-UI-SPEC.md
   §Antipattern List: ID | Antipattern | Rule for accrue_admin. Cover A1 (transition:all),
   A2 (layout-thrashing props), A3 (raw literals), A4 (decorative/infinite loops), A5
   (duration range 150–300ms), A6 (ignoring reduced-motion), A7 (frequent/keyboard actions),
   A8 (decorative "looks nicer" motion). Note the shimmer exception (A4).

5. "## Enforcement Guard" — short section noting: "The CI script
   `scripts/ci/verify_package_docs.sh` contains motion antipattern guards (Phase 177,
   MOT-01) that ban `transition: all`, raw `cubic-bezier()` literals, raw `ms`/`s` duration
   literals in transition/animation rules (except `ax-skeleton-shimmer 1.4s`), and
   layout-thrashing properties in transition lists. These guards are paired with negative
   tests in `package_docs_verifier_test.exs`. Any new CSS rule violating these patterns
   will fail CI."

6. "## Reduced-motion" — short section: "All transitions route through `--ax-transition-*`
   bundles or individual `--ax-dur-*`/`--ax-ease-*` atoms. The `@media
   (prefers-reduced-motion: reduce)` block in `theme.css` collapses these bundles to
   `--ax-dur-instant` (0ms), removing travel and overshoot while retaining opacity
   crossfades. No JS code should check `matchMedia` — the token override handles it. The
   reduced-motion behavior is verified by an automated Playwright check in
   `e2e/reduced-motion.spec.js`."

The guide must be specific enough that a developer can look up any animated surface and
see which token drives it and why it animates at all. Per D-01 (CONTEXT §Motion spec doc):
the functional justification column IS the justification record — no entry means no
animation is permitted.

### `artifacts/contrast.js` (utility/script, batch-transform)

**Analog:** `accrue_admin/e2e/score-visuals.mjs` (lines 1–51)

The `score-visuals.mjs` file is the repo's only standalone Node CLI script with no external dependencies beyond its explicit opt-in imports. It establishes three conventions that `contrast.js` should copy:

**Script header comment pattern** (`score-visuals.mjs` lines 1–22):
```javascript
/**
 * <filename> — <one-line description>
 *
 * <what it reads>
 * <what it emits>
 *
 * Usage: node <path>/<filename>
 * Output: <where output goes>
 */
```

**ESM import block pattern** (`score-visuals.mjs` lines 24–27):
```javascript
import fs from "fs";
import path from "path";
import { fileURLToPath } from "url";

const __dirname = path.dirname(fileURLToPath(import.meta.url));
```

Note: `contrast.js` does NOT need `fs` or `path` — it takes no file inputs and emits to stdout. The ESM header and `__dirname` lines can be omitted if the script is CJS (`// Usage: node contrast.js`). The RESEARCH.md canonical script is a clean CJS script with no imports at all — prefer that simpler form.

**Zero-dependency script structure** — the full commit-ready script from `180-RESEARCH.md` lines 582–629:
```javascript
// Source: W3C WCAG 2.0 Techniques G17 + WCAG 2.1 Understanding SC 1.4.3
// artifacts/contrast.js — zero external dependencies
// Run: node artifacts/contrast.js > artifacts/contrast-table.txt

function linearize(v) {
  const s = v / 255;
  return s <= 0.03928 ? s / 12.92 : Math.pow((s + 0.055) / 1.055, 2.4);
}
function luminance(r, g, b) {
  return 0.2126 * linearize(r) + 0.7152 * linearize(g) + 0.0722 * linearize(b);
}
function contrastRatio(l1, l2) {
  const [hi, lo] = l1 > l2 ? [l1, l2] : [l2, l1];
  return (hi + 0.05) / (lo + 0.05);
}
function parseHex(h) {
  const c = h.replace('#', '');
  return [parseInt(c.slice(0,2),16), parseInt(c.slice(2,4),16), parseInt(c.slice(4,6),16)];
}

const PALETTE = {
  Ink:    '#111418',
  Slate:  '#24303B',
  Fog:    '#E9EEF2',
  Paper:  '#FAFBFC',
  Moss:   '#5E9E84',
  Cobalt: '#5D79F6',
  Amber:  '#C8923B',
};

const lums = Object.fromEntries(
  Object.entries(PALETTE).map(([name, hex]) => [name, luminance(...parseHex(hex))])
);

const names = Object.keys(PALETTE);
const header = 'Accrue palette WCAG 2.x contrast ratios (threshold: 0.03928)';
const divider = '='.repeat(60);
console.log(header);
console.log(divider);
for (let i = 0; i < names.length; i++) {
  for (let j = i + 1; j < names.length; j++) {
    const [a, b] = [names[i], names[j]];
    const r = contrastRatio(lums[a], lums[b]);
    const level = r >= 7.0 ? 'AAA' : r >= 4.5 ? 'AA-body' : r >= 3.0 ? 'AA-large' : 'FAIL';
    console.log(`${a} vs ${b}: ${r.toFixed(2)}:1  [${level}]`);
  }
}
```

**Script-header comment style** (`scripts/ci/verify_package_docs.sh` lines 1–12):
```bash
#!/usr/bin/env bash
set -euo pipefail
ROOT_DIR=${ROOT_DIR:-$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)}
fail() {
  echo "[verify_package_docs] package docs verification failed: $*" >&2

}
```
The `verify_package_docs.sh` pattern: lead with a `[script-name]` prefix in all output messages, exit non-zero on failure. Copy this convention for any error output `contrast.js` might emit (though the happy path is pure stdout).

## Shared Patterns

### Verdict Tag Vocabulary
**Source:** CONTEXT.md decisions block; RESEARCH.md Pattern 1
**Apply to:** `BRAND-AUDIT.md` — every section that passes judgment

The five tags and when to use each:
```
KEEP    — no change needed; cited evidence confirms it is correct
TIGHTEN — correct concept, but usage rules must be more restrictive (contrast rows drive this)
REWORK  — concept must change; requires cited failure AND user ratification at checkpoint
ADD     — a missing element that should exist; requires ratified justification
REMOVE  — an existing element that should not; requires cited reason AND user ratification
```
**Enforcement rule:** KEEP/TIGHTEN verdicts are batch-approved at checkpoint. Every REWORK/ADD/REMOVE is an explicit accept/reject item. No verdict proposes a palette hex change unless the failure cannot be resolved by a usage-rule restriction alone.

### Evidence Citation Format
**Source:** RESEARCH.md Pattern 1 (evidence-gated verdict structure, lines 178–199)
**Apply to:** Every TIGHTEN, REWORK, ADD, REMOVE verdict in `BRAND-AUDIT.md`

```markdown
<Token/Topic> on <Surface> = <ratio>:1 (see `artifacts/contrast-table.txt` row "<Token> vs <Surface>").
Passes <level> (≥ <threshold>:1) but fails <level> (< <threshold>:1).
```

### Section Back-Reference Pointer
**Source:** RESEARCH.md Pattern 2 (BRAND-DNA.md structure, lines 204–248)
**Apply to:** Every section of `BRAND-DNA.md`

```markdown
→ BRAND-AUDIT.md §N
```
This is the only rationale carrier in the DNA. The pointer is mandatory — it means "the argument for this value is in the audit at that section." Without it, downstream agents cannot verify the rationale without loading the full audit.

### Rendering-Evidence Deferral Marker
**Source:** CONTEXT.md D-05; RESEARCH.md Pitfall 4
**Apply to:** Any verdict site in `BRAND-AUDIT.md` §4 (stress tests) and §8 (logo-system spec) that touches legibility at small sizes

```markdown
*[DEFERRED: Phase 181 screenshot pipeline — legibility at 16px not asserted here]*
```
Never substitute an asserted verdict for this placeholder. If the item is specifically about rendering quality (not contrast math), this marker is mandatory.

### Checkpoint Task Type
**Source:** RESEARCH.md Pattern 3 (checkpoint task structure, lines 253–288)
**Apply to:** Plan 4 (ratification plan)

The ratification gate is `checkpoint:decision` (not `checkpoint:human-verify`). In `end-of-phase` mode (`human_verify_mode` implied by `auto_advance: false` in `.planning/config.json`), `checkpoint:decision` tasks ARE emitted; `checkpoint:human-verify` tasks are suppressed. Using the wrong type would silently skip the ratification gate.

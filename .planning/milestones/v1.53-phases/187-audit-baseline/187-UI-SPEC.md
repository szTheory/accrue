| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, tight table-cell affordance gaps |
| sm | 8px | Compact element spacing, icon/text gap, form-control internal rhythm |
| md | 16px | Default element spacing, field groups, card internal rhythm |
| lg | 24px | Section padding, grouped toolbar/table spacing |
| xl | 32px | Page and panel gaps, major page-header spacing |
| 2xl | 48px | Major section breaks in readable artifacts |
| 3xl | 64px | Page-level spacing only |

Exceptions: none for new Phase 187 UI/spec artifacts.

Phase 187 rules:
- Do not introduce new spacing values in admin UI code or planning artifacts.
- Audit tables and ledgers should prefer dense but scannable rhythm: `sm` inside rows, `md` between row groups, `lg` around section headers.
- Baseline artifact tables must not rely on horizontal scrolling as the only way to read critical fields; use wrapped cells or detail rows for long reproduction paths.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Typography rules:
- Use Geist for all normal UI and artifact prose.
- Use Geist Mono only for stable IDs, code symbols, JSON/NDJSON snippets, file paths, commands, and checksum-like values.
- Do not add a fifth size or a third weight. If a surface needs more hierarchy, use spacing, section order, muted color, or table grouping.
- Long prose in `187-RUBRIC.md` and `187-BASELINE.md` should stay within the reading measure inherited from `--ax-measure` where rendered in the admin/dev UI.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` / `--accrue-paper` `#fafbfc` in light; `#0f1318` in dark | Main canvas, page background, full-page artifact surfaces |
| Secondary (30%) | `--ax-elevated` `#ffffff` in light; `#171d24` in dark | Cards, tables, sidebars, nav regions, artifact summary panels |
| Accent (10%) | `--ax-accent` / `--accrue-cobalt` `#5d79f6`; filled controls use `--ax-accent-strong` | Primary CTA, active nav/tab/filter state, focus ring, selected cell, one primary inline action per region |
| Destructive | `--ax-danger` `#d64b4b`; readable text via `--ax-danger-readable` | Defect severity markers, destructive confirmation copy, failed parse/error states |

Accent reserved for: primary CTA, active navigation/tab/filter state, visible focus ring, selected baseline cell, and one primary inline action in a region.

Color rules:
- Never reserve accent for every control or every clickable element.
- Use `--ax-info`, `--ax-success`, `--ax-warning`, and `--ax-danger` only for semantic evidence states, not decoration.
- Layer/z-index defects must use overlay tags in the ledger; do not create a decorative layer color scheme.
- Dark-mode findings should be scored against semantic role correctness, not generic preference.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Run baseline audit |
| Empty state heading | No baseline cells recorded |
| Empty state body | Create the Phase 187 manifest, then run the baseline audit to record covered, gap, and n/a cells. |
| Error state | Baseline artifact could not be parsed. Fix the JSON or NDJSON line shown in the error output, then rerun the artifact parser. |
| Destructive confirmation | Replace Phase 187 baseline: This overwrites the current baseline artifacts for comparison. Confirm only after the new audit run has trace and screenshot evidence. |

Copywriting rules:
- Use measured, exact, native, durable Accrue voice from `brandbook/voice.md`.
- Findings must name the object and mechanism: surface, state, evidence path, failed dimension, and recovery step.
- Empty, error, permission-denied, and disconnected/reconnecting states must tell the operator what happened, what object/process is affected, and the next useful action when one exists.
- Avoid generic form labels, bare negative empty states, and problem-only errors.
- Destructive-action findings must name the specific object and consequence. If no product action is being performed, say that the phase records evidence only.

## Visual Hierarchy Contract

Primary screen focal point: the severity-ranked defect ledger and scored baseline summary. The first thing a maintainer should see is whether the baseline is complete, what the worst defects are, and which owner phase receives each defect.

Hierarchy order:
1. Baseline completeness status and score summary.
2. Severity-ranked defects grouped by owner phase.
3. Matrix coverage by surface type: component, component group, page/flow.
4. Evidence manifest links for screenshots, traces, axe output, and optional vision findings.
5. Schema and rerun instructions.

Visual rules:
- Keep artifact UIs work-focused and dense. Do not add a marketing hero, decorative cards, large illustration, or brand-heavy treatment.
- Repeated ledger entries may use cards only when a table becomes unreadable on mobile; otherwise prefer tables with stable columns.
- Icon-only controls require accessible labels. Planning artifacts should prefer visible text labels for audit actions.
- Focal color belongs to severity and current selection, not to every link or button.

## Interaction Contract

Phase 187 does not fix the admin UI; it records trustworthy evidence. Interaction probes must observe these contracts and write defects when the current UI fails them:

| Interaction | Passing Contract | Evidence |
|-------------|------------------|----------|
| Modal/drawer layering | Dialog or drawer appears above scrim, is fully visible, and receives pointer events | Playwright trace plus screenshot reference |
| Focus trap | Tab and Shift+Tab remain inside the open dialog/drawer where the pattern requires trapping | Playwright trace and active-element assertion |
| Focus restore | Closing an overlay restores focus to its trigger | Playwright trace and active-element assertion |
| Dismissal | Escape and click-outside behavior match the component contract | Playwright trace |
| Dropdown/popover/toast position | Floating element appears near its trigger and does not obscure the related control | Screenshot plus trace |
| Scroll reachability | Bottom content is reachable; sticky regions do not hide required actions | Trace plus scroll assertion |
| Disabled/read-only affordance | Disabled controls look disabled and are not actionable | Actionability assertion |
| LiveView patch focus | Focus is not lost or hidden after DOM patching | Trace plus active-element assertion |
| Empty/error/permission/disconnected states | State is reachable, named, and contains the next useful operator action where applicable | Screenshot, axe where relevant, and ledger row |

Ledger requirements:
- Defect rows must include `id`, `severity`, `surface`, `surface_type`, `persona_job`, `reproduction`, `expected`, `actual`, `rubric_dimension`, `overlay_tags`, `cell_id`, `evidence_refs`, `owner_phase`, `status`, and `notes`.
- Defect IDs use the `AX187-001` pattern.
- `layer/z-index` is an overlay tag, not a thirteenth rubric dimension.
- Structured artifacts win over markdown if they disagree.

## Phase 187 Artifact Contract

Required artifacts in `.planning/phases/187-audit-baseline/`:

| Artifact | UI/UX Contract |
|----------|----------------|
| `187-RUBRIC.md` | Defines the carried 10 dimensions plus `interaction-integrity` and `microcopy`; includes scoring anchors and overlay tag examples. |
| `187-BASELINE.md` | Maintainer-readable summary with baseline completeness, score summaries, severity-ranked defects, and downstream handoff notes. |
| `baseline.cells.json` | Canonical scored cell data for every audited surface/mode/theme/state/dimension. |
| `defects.ndjson` | One defect per line with stable IDs and owner-phase routing. |
| `artifacts.manifest.json` | References generated screenshots, traces, axe output, and optional vision findings without committing bulky evidence files. |
| `schemas/*.schema.json` | Optional if cheap; otherwise document schemas in `187-RUBRIC.md` and make extraction a Phase 192 guardrail. |

Matrix contract:
- Use a representative manifest, not a literal Cartesian product.
- Include component, component-group, and page/flow rows.
- Canonical modes are `chromium-desktop` and `chromium-mobile`, with light and dark themes.
- State taxonomy: `default-populated`, `empty`, `loading`, `error`, `permission-denied`, `disconnected-reconnecting`, `overflow`, `long-content`, `disabled-readonly`, and `interactive-open`.
- Every cell is explicitly `covered`, `gap`, or `n/a`; `gap` cells become defects or seed/tooling gaps.

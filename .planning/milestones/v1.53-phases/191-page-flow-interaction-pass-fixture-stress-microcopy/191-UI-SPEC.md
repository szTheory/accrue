## Spacing Scale

Declared values for Phase 191 page and flow work (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-xs` | 4px | Icon-to-label gaps, close icon optical gaps, status/meta micro-gaps |
| `--ax-space-sm` | 8px | Button groups, filter chips, compact inline state labels |
| `--ax-space-md` | 16px | Default field stacks, overlay form rows, state copy spacing |
| `--ax-space-lg` | 24px | Overlay panel padding, page-section rhythm, drawer header/body/footer gaps |
| `--ax-space-xl` | 32px | Page-flow group gaps, recovery/error sections, major responsive wraps |
| `--ax-space-2xl` | 48px | Empty/error state vertical padding and proof-surface breaks |
| `--ax-space-3xl` | 64px | Rare page-level separations only; never inside dense operator groups |

Exceptions:
- `--ax-space-2xs` (2px) is a frozen pre-existing foundation token for dense micro-gaps. Phase 191 may consume it only where the current component already uses it; do not promote it into new page, overlay, or fixture-layout spacing.
- Icon-only controls, overlay close controls, dropdown triggers, drawer actions, row actions, pagination/load-more controls, and mobile nav toggles must reach a 44px minimum touch target at 320px and 375px.
- Overlay panels must keep footer actions reachable without hidden fixed-footer overlap. If the body scrolls, use the existing drawer/modal header/body/footer rhythm instead of local padding hacks.

Page rhythm:
- Top-level page flow stacks use `--ax-space-xl` between major groups.
- State surfaces inside existing groups use `--ax-space-lg` padding and `--ax-space-md` internal gaps.
- Dense tables/cards inherit the Phase 190 group rhythm; Phase 191 must not reintroduce card-in-card "box prison" layouts while adding state fixtures.

## Typography

Use only the existing composed role tokens. Phase 191 introduces no new type tokens, no fifth size, and no third weight. Only weights 400 and 600 are allowed.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display | 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Required usage:
- Page headings, dialog titles, drawer titles, and primary state headings use the heading role.
- Empty, error, permission, disconnected, and recovery body copy use body or body-sm plus `--ax-measure`; long explanatory copy may use `--ax-type-body-relaxed-font` for 1.5 line-height.
- Field labels, filter labels, status labels, and action group labels use label role.
- IDs, event IDs, processor IDs, route fixture keys, payload snippets, and ledger references use code role with `overflow-wrap: anywhere` when multi-line.

Text-fitting contract:
- Button labels must wrap or shrink through layout before they collide with icon or background. Do not reduce font size with viewport units.
- Long names, non-ASCII names, IDs, URLs, failure reasons, and raw payload snippets must wrap intentionally. Use ellipsis only when the full value is available in adjacent text, a title, or an accessible name.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` light `#fafbfc`, dark `#0f1318` | Page canvas, unframed flow background, true-empty/error canvas |
| Secondary (30%) | `--ax-elevated` light `#ffffff`, dark `#171d24`; `--ax-sunken` light `#f1f5f8`, dark `#0b1015` | Cards, tables, drawers, modals, popovers, state panels, recessed code/payload wells |
| Accent (10%) | runtime `--ax-accent` default Cobalt `#5d79f6`; `--ax-accent-strong`, `--ax-accent-readable`, `--ax-accent-subtle`, `--ax-accent-border` | Primary action, active nav/tab/filter, selected row, focus ring source, command/search selection, current-step emphasis |
| Destructive | `--ax-danger` `#d64b4b`; danger surfaces through `--ax-status-danger-*` | Destructive actions, destructive confirmations, unrecoverable error emphasis only |

Accent reserved for: primary CTA, active navigation, active tab/window selector, active filter chip, selected row/card, visible focus ring, command palette active result, link text, and current-step/progress emphasis.

Color rules:
- Do not use accent as a decorative wash for every card, every heading, empty-state art, inactive control, KPI card, or fixture marker.
- Error, warning, success, info, and neutral state colors must use the existing `--ax-status-{success,warning,danger,info,neutral}-{bg,border,text,solid,on-solid}` pairs in both themes.
- Disabled and read-only states use `--ax-disabled-*` and `--ax-readonly-*`; disabled controls must not show hover, active, selected, or pointer affordances.
- Disconnected/reconnecting state uses warning or info semantics plus text and disabled action state. Color alone is never the state.
- Overlay stack order remains: dropdown 200, popover 300, drawer 400, modal 500, toast 600. No ad-hoc z-index literals.

## Copywriting Contract

Use Accrue voice: measured, exact, native, durable. Copy must name the object, process, route, event, invoice, subscription, customer, owner scope, config key, or action being affected. Do not use "oops", "failed", "forbidden", "invalid", or "are you sure?" without the specific object and recovery path.

| Element | Copy |
|---------|------|
| Primary CTA | Run interaction audit |
| True empty heading | No billing records yet |
| True empty body | Records appear here after Accrue records activity for this organization. If you expected rows, confirm owner scope or seed state. |
| Filtered empty heading | No records match these filters |
| Filtered empty body | Clear filters or adjust owner scope to review matching billing records. |
| Permission denied heading | Access restricted |
| Permission denied body | This admin account cannot view {object}. Switch organization scope or ask an administrator to grant billing admin access. |
| Error state | This {resource} could not load. Retry the request; if it persists, inspect logs for owner scope {scope}. |
| Disconnected state | Connection lost. Reconnecting before actions can run. |
| Reconnected state | Connection restored. Review the current state before running an action. |
| Loading state | Loading {resource} |
| Destructive confirmation | {Action} {object}: This will {specific consequence}. Continue? |

Required destructive/consequential confirmation coverage:

| Action family | Confirmation contract |
|---------------|-----------------------|
| Subscription cancel, resume, swap plan, pause collection, comp replacement | Button label names verb + subscription action. Confirmation names subscription/customer, billing effect, and audit consequence. |
| Invoice finalize, void, mark uncollectible, manual pay, remove line item | Confirmation names invoice number/ID, resulting status, and whether processor or local billing state is affected. |
| Charge refund | Confirmation names charge ID, amount/currency, and that a refund/audit row will be recorded. |
| Customer payment-method delete/default/sync | Confirmation or warning names the payment method/customer and blocked reason when the action cannot run. |
| Webhook replay and bulk replay | Confirmation names one webhook ID or the exact failed/dead row count and the active organization scope. |

Microcopy patterns:
- Empty states distinguish true empty, filtered empty, data unavailable, permission denied, and disconnected/reconnecting.
- Error copy states what happened and what to do next. If the next action is not in the UI, name the evidence location: logs, owner scope, webhook endpoint, processor fixture, or config key.
- Button labels are verb + noun: `Replay webhook`, `Refund charge`, `Void invoice`, `Clear filters`, `Load more`.
- Accessible names add object context when visible text is short: `Close invoice action dialog`, `Select invoice in_showcase_open`, `Replay webhook wh_e2e_dead`.
- Domain vocabulary must be consistent across headings, tabs, filters, buttons, alerts, and table/card labels: use customer, subscription, invoice, charge/payment, coupon, promotion code, Connect account, event, webhook, recovery, owner scope, and Fake processor.

## Interaction Contract

Phase 191 closes the Phase 187 interaction defects and the Phase 190 D-30 handoff categories. Passing behavior is the corrected regression target; do not encode broken Phase 187 observations as permanent expected behavior.

### Modal And Drawer Layering

- Drawer root uses `--ax-z-drawer`; modal/step-up/command-palette root uses `--ax-z-modal`; toast remains above both at `--ax-z-toast`.
- Backdrop/scrim is below the panel and `aria-hidden="true"`. The panel is the top pointer target at its center and at primary controls.
- Dialog/drawer root uses `role="dialog"`, `aria-modal="true"`, `aria-labelledby`, and `aria-describedby` when descriptive copy exists.
- Panel width remains `min(42rem, calc(100vw - 2rem))` for modal-like surfaces unless an existing drawer contract requires a full-screen mobile sheet. Mobile drawers are full-screen sheets.
- The first visual focus after open is the first meaningful control, or the dialog heading with `tabindex="-1"` when no immediate control should receive focus.

### Focus Trap And Restore

- `Tab` and `Shift+Tab` stay inside the active modal, drawer, command palette, or protected confirmation until the overlay is dismissed.
- Background page controls are not reachable while a modal/drawer is active.
- Closing by Escape, click outside, Cancel, Close, successful submit, or LiveView patch restores focus to the invoking control. If the trigger no longer exists, focus moves to the nearest stable page heading or state alert, not to `body`.
- Nested/transient overlays close from innermost to outermost. Closing a dropdown inside a drawer must not close the drawer unless the action explicitly submits/dismisses the drawer.

### Dismissal

- Escape closes the active overlay and preserves page context. It must not submit a form, trigger navigation, or run a destructive action.
- Click outside dismisses only overlay state and is equivalent to Cancel/Close. It never confirms, submits, deletes, refunds, voids, replays, or mutates billing state.
- Protected destructive confirmations may require explicit Cancel for dirty or sensitive input, but outside-click handling must be deterministic, tested, and must leave focus in a known location with no partially hidden overlay.
- Dropdowns and popovers close on outside click and Escape, then restore focus to their trigger.

### Scroll Reachability

- Page body, drawer body, modal panel, dropdown panel, command palette, tables/cards, and long detail sections must be scrollable by wheel, touch, keyboard, and programmatic scroll where applicable.
- No primary or recovery action may be hidden behind a sticky header, sticky footer, viewport edge, or nested scroll dead-end.
- Overlay body scroll does not scroll the background page. Background scroll state is restored after close.
- Long overlay content keeps header context and footer actions reachable; if the body scrolls, the footer remains visible or immediately reachable without hidden content.

### LiveView Patch Focus

- Any `push_patch`, filter submit, pagination/load-more, row selection, tab/window change, optimistic update, reconnect, or async action completion must leave focus on the retained control, an updated state alert, or the page heading.
- Focus must never disappear, land on `body`, or move behind an overlay after a LiveView patch.
- New alerts, validation errors, disconnected/reconnecting notices, and action results use an announced region (`aria-live="polite"` for status, assertive only for blocking errors).

### Floating Elements

- Dropdowns, popovers, tooltips, command palette, and toasts position relative to the trigger or intended viewport region and do not obscure the control they describe.
- Floating panels flip or constrain when near viewport edges; they must not clip actionable content at 320px or 375px.
- Tooltips remain descriptive only. They do not replace accessible names or required inline error/help text.
- Toasts/flash messages do not cover the next useful action in the active flow.

### Disconnected/Reconnecting

- Every page exposes a visible and programmatic disconnected/reconnecting state when the LiveView client is stale.
- Mutating actions are disabled while stale. Read-only navigation may remain available if it does not imply fresh data.
- Copy states the stale condition and recovery: `Connection lost. Reconnecting before actions can run.`
- Reconnected state clears stale disabled affordances and announces restoration without moving focus unexpectedly.

### Keyboard Completion

- Keyboard-only operation completes each primary flow: search/filter/apply/clear, tab/window navigation, load more, row select/deselect, open/close overlays, confirm/cancel sensitive actions, command palette search/select, drawer close, and mobile nav open/close.
- Visible focus uses the existing 2px `--ax-focus-ring`, offset, and `--ax-focus-shadow`.
- Non-interactive empty states, status badges, and display-only metadata expose no hover pointer, `role="button"`, or fake focus target.

## Fixture Stress Contract

Fixture work extends `examples/accrue_host` seeds and E2E forcing helpers only. Do not redesign host chrome and do not create new product features to satisfy a state.

Required fixture states:

| Fixture state | Contract |
|---------------|----------|
| Null/missing optional fields | Detail and list pages render absent optional fields with explicit labels or omitted rows, not blank punctuation or layout gaps. |
| Permission-denied | Authenticated non-admin or wrong-owner-scope user reaches a stable denial state with `Access restricted` copy and no misleading primary action. |
| Boundary pagination | List pages expose exactly none, one page, and next-page states so `Load more` appears only when more data exists. |
| High counts | KPI, table, sidebar badge, and pagination counts handle large values without clipping or tone drift. |
| Non-ASCII names | Customer/org/coupon/promotion/event metadata supports names with accents, CJK, emoji-safe truncation, and long Unicode strings without overlap. |
| Disconnected/reconnecting | Test-only LiveView disconnect/reconnect forcing exposes stale UI, disabled mutating actions, and restoration copy. |
| Existing edge states | Long-name customer, multi-currency/JPY, dunning/at-risk, canceling subscription, and webhook failure rows remain intact. |
| Error/loading | Stable test-only forcing exposes loading holds and recoverable query/action errors long enough for visual, keyboard, and copy assertions. |

Seed implementation rules:
- Use deterministic namespaces such as `e2e_phase191_*` for processor IDs, idempotency keys, slugs, emails, and route params.
- Follow the existing get-or-insert / `on_conflict: :nothing` pattern. Re-running seeds must not duplicate rows or mutate append-only event history.
- One-click reachability means each matrix cell can be reached from a deterministic route, dashboard launcher, filter chip, query param, component kitchen proof link, or E2E fixture endpoint without manual database editing.
- Generated traces/screenshots stay under ignored Playwright output paths. Planning artifacts cite references only.

## Page State Matrix Contract

Every canonical page flow must define and verify these states when applicable:

| State | Passing contract |
|-------|------------------|
| Happy/default | Primary page task is clear; first useful action is visible; keyboard reaches it in logical order. |
| Empty | Explains when records appear; no hover/focus affordance on the empty container; optional CTA is specific. |
| Filtered empty | Shows active constraints and makes `Clear filters` the next useful action. |
| Loading | Skeleton/spinner preserves layout size and is announced as loading; loading never looks like a disabled final state. |
| Error | Names failed object/process and recovery path; retry or evidence location is visible. |
| Permission denied | Names access boundary; no hidden or disabled destructive action is advertised as available. |
| Boundary | Pagination, high counts, zero counts, one-row lists, long names, null fields, and non-ASCII values render without clipping. |
| Advanced | Filter/sort/search/tab/window/action combinations keep state visible after LiveView patch. |
| Disconnected/reconnecting | Stale state visible; mutating actions disabled; reconnected state announced without focus loss. |
| Interactive-open | Overlay/dropdown/drawer/modal/tooltip/toast is layered, positioned, keyboard-safe, and dismissible. |

Phase 191 must preserve the Phase 190 group contract while adding page-flow evidence. If a defect is caused by a shared primitive or component group, fix the shared root and cite the owning contract rather than adding page-specific CSS.

# Phase 197 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 197 is LIST propagation, not new list design. Preserve the Phase 196 Subscriptions exemplar structure and apply it to the eight remaining `accrue_admin` list pages: customers, invoices, payments, coupons, promotion codes, webhooks, events, and connect accounts.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - custom `ax-*` admin design system |
| Preset | not applicable |
| Component library | Phoenix LiveView components: `PageHeader`, `DataTable`, `FilterChipBar`, `StatStrip`, `Breadcrumbs` |
| Icon library | Heroicons via `AccrueAdmin.Components.Icon` |
| Font | `--ax-font-sans`: Geist, system-ui, Segoe UI, sans-serif; `--ax-font-mono`: Geist Mono stack |

Source decisions:

- `components.json` is absent and `npx shadcn info` reports no shadcn configuration or installed components. Do not initialize shadcn for this Phoenix/LiveView phase.
- `accrue_admin/assets/css/theme.css` is the implementation SSOT for admin tokens. `brandbook/tokens/README.md` documents the brand layer, but Phase 197 must use the admin `--ax-*` tokens.
- No Tailwind migration, no Radix/shadcn blocks, no third-party registry blocks.

---

## Phase Scope Contract

| Area | Contract |
|------|----------|
| In scope | Conform all eight target list pages to SPEC-LIST and the Phase 196 Subscriptions exemplar. |
| Out of scope | New billing primitives, new routes, breaking public APIs, `accrue_portal`, Tailwind migration, overlay sweep, Storybook breadth, final zero-regression sign-off. |
| Runtime abstraction | Do not create a generic `ListPage` DSL or attr-heavy resource facade. Narrow pure helpers are allowed only after repeated duplication is proven. |
| State ownership | Each LiveView owns URL/query/default/filter/bulk/action state. `PageHeader` remains stateless and owns only page orientation. |
| Copy ownership | New or touched page copy belongs in `AccrueAdmin.Copy` or existing copy modules, not inline HEEx strings except unavoidable narrow migration labels. |

Required page composition for every target page:

1. `PageHeader.page_header/1` with breadcrumbs, one title, description, stat strip, optional actions, and `:filter_toolbar`.
2. `FlashGroup` if the page already renders flashes.
3. `DataTable` with `render_filter_toolbar={false}` and `list_id` matching the resource.
4. `FilterChipBar.filter_chip_bar/1` rendered in the `DataTable` `:list_status` slot.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip internals, inline control spacing |
| sm | 8px | Compact row/cell gaps, label/value spacing |
| md | 16px | Default element spacing, table toolbar gaps |
| lg | 24px | Page header and section padding |
| xl | 32px | Layout gaps between major list bands |
| 2xl | 48px | Major section breaks when inherited from page shell |
| 3xl | 64px | Page-level layout spacing only |

Exceptions: existing `--ax-space-2xs` (2px) may remain for inherited dense-table and chip micro spacing. Do not introduce new 2px spacing in Phase 197 except through existing component classes. 1px borders/hairlines and existing mobile 44px touch-target accommodations remain allowed.

LIST rhythm:

- PageHeader to list-status band: `--ax-space-lg`.
- Filter toolbar controls: compact, single-row where space allows, wrapping without overlap on mobile.
- Dense rows must keep at least 8 full populated rows visible above the fold at 1280x800 when data allows.
- Mobile row cards use card rhythm, but desktop table rows stay compact.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 20px (`--ax-type-lg`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display | 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Typography contract:

- Use only 400 and 600 weights for newly touched LIST hierarchy.
- Page titles render through `PageHeader` as one `.ax-display` content `<h1>`.
- Table cells use Body/Label roles only; do not promote plumbing IDs or raw backend flags to Heading/Display.
- Monospace is reserved for secondary IDs and code-like values; it must not become the primary scan label.
- Body descriptions may use the existing relaxed 1.5 line-height only for multi-line explanatory copy.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` = `--accrue-paper` `#fafbfc`; dark `#0f1318` | Page background and dominant admin surface |
| Secondary (30%) | `--ax-elevated` `#ffffff` / dark `#171d24`; `--ax-sunken` `#f1f5f8` | PageHeader bands, table shells, toolbar fields, mobile row cards |
| Accent (10%) | host `--ax-accent`, brand Cobalt reference `#5d79f6`; readable `--ax-accent-readable` | Active links, primary buttons, selected/default filter chips, focus rings, active segmented controls |
| Destructive | `--ax-danger` `#d64b4b`; readable `--ax-danger-readable` | Destructive actions only; none newly introduced in Phase 197 |

Accent reserved for: selected/default filter chips, "All" or queue lens activation links, primary action buttons when an existing page already has one, accessible focus rings, and stat-strip values that intentionally signal actionability. Do not use accent as generic decoration or for static page headings.

Semantic colors:

- `--ax-warning` / amber: queue attention states such as needs collection, failed payments, needs replay, and connect attention.
- `--ax-success` / moss: valid/active/healthy states, but not as a generic positive wash.
- `--ax-info`: informational status only.
- `--ax-danger`: destructive or failed terminal states only.

## Page-Level LIST Contract

| Requirement | Contract |
|-------------|----------|
| Header | Every target page adopts `PageHeader.page_header/1` and renders exactly one content `<h1>`. Preserve `data-ax-page-header`, `data-ax-page-title`, `data-ax-page-actions`, and `data-ax-page-filter-toolbar`. |
| Breadcrumbs | Breadcrumbs are passed to `PageHeader`; current page crumb has no href and carries `aria-current` through `Breadcrumbs`. |
| Filter toolbar | `DataTable.filter_toolbar/1` renders in the `PageHeader` `:filter_toolbar` slot. `DataTable` must receive `render_filter_toolbar={false}`. |
| Filter state | URL-backed only. Parent LiveViews handle `data_table_filter` with `AccrueAdmin.DataTableNav.patch_with_filters/3` and `handle_params/3`. |
| Chips/count/clear | `FilterChipBar` in `:list_status` must render `[data-ax-filter-chips]`, `[data-ax-result-count]`, and `[data-ax-clear-all]` whenever a default lens or user filter is active/removable. |
| Counts | Counts must be honest visible-row counts unless a page implements a scoped exact-count query. Use "Showing N invoices", not "N total invoices" unless total is true. |
| Table priority | Desktop columns and mobile card fields prioritize identity, state, money/value, time, then signals. Plumbing IDs are secondary text or detail-page material. |
| Mobile | Keep `DataTable` row-to-card degradation. No shrunken desktop grids, no horizontal clipping, and no overlapping toolbar controls. |
| Pagination | Do not render pagination/load-more controls when there is no next cursor or only one page of results. |

## Per-Page Contract

| Page | Default lens | Header title | Description direction | Required chips |
|------|--------------|--------------|-----------------------|----------------|
| Customers | All customers | Find a customer | Look up a customer and inspect their billing state. | Active "All customers"; quick chip "Missing payment method"; clear-all returns to all customers preserving owner scope. |
| Invoices | Needs collection (`status=open,uncollectible`) | Clear open receivables | Work invoices that need collection. | Active "Needs collection"; "All invoices" one chip away; clear-all routes to `view=all`. |
| Payments (`ChargesLive`) | Failed payments (`status=failed`) | Recover failed payments | Inspect charges that need follow-up. | Active "Failed payments"; "All payments" one chip away; do not mention `/charges` in UI/test copy. |
| Coupons | Valid coupons (`valid=true`) | Review usable discounts | Check which coupon definitions can still be applied. | Active "Valid coupons"; "All coupons" one chip away. |
| Promotion codes | Active codes (`active=true`) | Find active codes | Review customer-facing codes tied to coupons. | Active "Active codes"; "All promotion codes" one chip away. |
| Webhooks | Needs replay (`status=failed,dead`) | Replay failed deliveries | Inspect webhook deliveries that need operator action. | Active "Needs replay"; "All deliveries" one chip away; preserve bulk retry selection/confirmation. |
| Events | All ledger | Trace billing activity | Read the append-only billing event ledger. | Active "All ledger"; quick chip "Admin changes"; do not hide ledger rows by default. |
| Connect accounts | Needs attention (`needs_attention=true`, OR lens) | Finish account readiness | Find connected accounts that need onboarding or capability work. | Active "Needs attention"; "All accounts" one chip away; OR predicate is query-owned. |

Implementation notes:

- Webhooks needs safe multi-status decode for failed/dead rather than UI-only copy.
- Connect needs a named OR lens instead of AND-ing existing readiness booleans.
- Customers and Events are reference/ledger defaults. Do not manufacture weak exception queues that hide expected rows.
- Clear-all always preserves `org` / owner scope and must not create blank-URL redirect loops.

## Four-State Contract

Every target page must expose four visually distinct LIST states:

| State | Visual/interaction contract | Copy contract |
|-------|-----------------------------|---------------|
| Populated | Dense table rows on desktop; card rows on mobile; list-status row visible with active chip(s) and visible count. | Row labels prioritize operator nouns; no raw backend flag as the primary text. |
| First-run empty | `DataTable` empty card with `data-ax-state="first-run-empty"` and no clear-filters affordance. | Explain how rows arrive for that resource. |
| Filtered empty | `DataTable` empty card with `data-ax-state="filtered-empty"` and a clear-filters affordance. | "No [resource] match these filters." Body tells operator to clear filters or adjust search/scope. |
| Loading skeleton | Table-shaped desktop skeleton and card-shaped mobile skeleton with `aria-busy`, one status label, and decorative skeleton cells hidden from assistive tech. | Loading label names the resource, e.g. "Loading invoices." |

Queue-empty is a filtered/default-lens empty state when underlying resource data exists but the default queue is clear. It may use positive copy such as "Nothing needs replay." First-run empty and filtered-empty must never share the same heading/body.

Recommended state copy seeds:

| Page | First-run empty | Queue/default empty | Filtered empty | Loading |
|------|-----------------|---------------------|----------------|---------|
| Customers | "No customers yet." Customers appear after checkout or imported billing activity. | Not applicable for All default. | "No customers match these filters." Clear filters or adjust the search. | "Loading customers." |
| Invoices | "No invoices yet." Invoices appear when subscriptions activate or renew. | "No invoices need collection." View all invoices to review the ledger. | "No invoices match these filters." Clear filters or adjust the search. | "Loading invoices." |
| Payments | "No payments yet." Payments appear after charges are recorded. | "No failed payments." View all payments to inspect settled and pending charges. | "No payments match these filters." Clear filters or adjust the search. | "Loading payments." |
| Coupons | "No coupons yet." Coupons appear after discount definitions sync locally. | "No valid coupons." View all coupons to inspect invalid or expired definitions. | "No coupons match these filters." Clear filters or adjust the search. | "Loading coupons." |
| Promotion codes | "No promotion codes yet." Codes appear after customer-facing discounts sync locally. | "No active codes." View all promotion codes to inspect inactive or expired codes. | "No promotion codes match these filters." Clear filters or adjust the search. | "Loading promotion codes." |
| Webhooks | "No webhook deliveries yet." Deliveries appear after signed processor events are recorded. | "Nothing needs replay." View all deliveries to inspect the full delivery log. | "No webhook deliveries match these filters." Clear filters or adjust status/type filters. | "Loading webhook deliveries." |
| Events | "No billing events yet." Events appear when billing state changes are recorded. | Not applicable for All ledger default. | "No ledger rows match these filters." Clear filters or adjust actor/source filters. | "Loading billing events." |
| Connect accounts | "No connected accounts yet." Accounts appear after onboarding starts. | "No accounts need attention." View all accounts to inspect onboarded accounts. | "No connected accounts match these filters." Clear filters or adjust readiness filters. | "Loading connected accounts." |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Clear filters` for filtered-empty recovery and list clear-all. Preserve `Retry selected` on Webhooks bulk retry. |
| Empty state heading | Page-specific first-run, queue-empty, and filtered-empty headings from the four-state table above. |
| Empty state body | State the mechanism by which rows arrive, or the next recovery action: clear filters, adjust search, or view all. |
| Error state | "List could not be loaded. Retry, or check owner scope before continuing." Page-specific variants may name the resource and query seam. |
| Destructive confirmation | None newly introduced. Phase 197 must not add destructive actions. Preserve existing Webhooks retry confirmation copy and behavior. |

Voice rules:

- Measured, exact, native, durable. No sales copy, no fintech posturing, no vague "seamless"/"powerful"/"robust" claims.
- Page titles name the operator job, not backend structure.
- Action labels use verbs and affected nouns: "Clear filters", "View all invoices", "Retry selected".
- Visually-hidden context is required where a repeated action label could be ambiguous.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Default load | Bare routes load the page-owned default lens without misleading first paint. Reference defaults (customers/events) show all. Queue defaults use URL/default params with All one chip away. |
| All / clear-all | For narrowed defaults, clear-all routes to `view=all`. For all-default pages, clear-all removes user filters and returns to base/all. Always preserve owner scope. |
| Filter edits | Instant-apply behavior may remain; filters stay URL-backed and parent-targeted. Do not add client-only state. |
| Bulk action | Preserve Webhooks bulk replay selection, confirmation, and flash behavior. Do not generalize bulk behavior across pages. |
| Focus | Newly moved filter controls must retain visible `:focus-visible` rings and predictable tab order: breadcrumbs -> title actions -> filter toolbar -> chip clear/apply links -> table controls. |
| Motion | No per-row stagger. Loading skeletons may shimmer through existing reduced-motion-safe classes. No new motion tokens. |
| Non-interactive states | Empty-state heroes and static state cards must not show hover, pointer cursor, or role/button semantics. |
| Overlays | Do not change overlay architecture in Phase 197. Cross-page overlay correctness remains Phase 199 ownership. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline evidence-path gaps, compact label gaps |
| sm | 8px | Table cell breathing room, compact list spacing |
| md | 16px | Default spacing between headings, tables, and paragraphs |
| lg | 24px | Major subsection breaks inside the audit |
| xl | 32px | Breaks between top-level audit sections |
| 2xl | 48px | Executive summary to ranking-table separation if rendered as a web page |
| 3xl | 64px | Page-level spacing only; do not use inside dense score tables |

Exceptions: 44px minimum touch target for any rendered link/button control in a browser surface. Existing admin `--ax-space-2xs` (2px) may be cited as existing design-system evidence but must not be introduced into Phase 201 deliverables.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Contract: use only weights 400 and 600. Keep audit prose body-sized and evidence tables label-sized; do not use hero-scale display type for score rows, warnings, or appendix sections. Letter spacing is `0` except existing admin token evidence quoted from source files.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#fafbfc` | Background and page surface when the audit is rendered outside plain Markdown |
| Secondary (30%) | `#ffffff` | Tables, evidence cards, and callout surfaces when a rendered preview needs framed content |
| Accent (10%) | `#5d79f6` | Evidence links, focus rings, one primary CTA if a rendered audit preview exists, and selected section anchors only |
| Destructive | `#d64b4b` | Destructive actions only; Phase 201 has no allowed destructive action |

Accent reserved for: evidence-path links, focus-visible outlines, the single `Review quality audit` CTA in a rendered preview, and active section anchors. Do not use accent for every interactive element, every score, or decorative emphasis.

Additional semantic color rule: score/risk language in the Markdown audit should rely on text, rank, score, confidence, and priority labels first. If rendered with color, use existing Accrue feedback tokens (`--accrue-feedback-success`, `--accrue-feedback-warning`, `--accrue-feedback-danger`, `--accrue-feedback-info`) only as secondary reinforcement.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Review quality audit |
| Empty state heading | No audit evidence yet |
| Empty state body | Run the Phase 201 evidence pass before scoring weak dimensions. |
| Error state | Audit evidence is incomplete. Add a local path or mark the claim as an assumption before ranking it. |
| Destructive confirmation | none - Phase 201 must not expose destructive actions |

Voice rules: measured, exact, Phoenix-native, durable, mechanism-led, and proof-checkable. Preserve blunt scored-core language, but frame it as release-readiness triage rather than a public report card. Avoid hype, generic adjectives, and public shaming.

## Interaction Contract

| Interaction | Contract |
|-------------|----------|
| Evidence links | Local paths must be written inline as code and should remain clickable in Markdown-capable renderers where possible. |
| Section navigation | Use stable Markdown headings for Executive Summary, Dimension Ranking, Top 5 Weakness Deep Dives, Journey Audits, Missing Dimensions, Evidence Appendix, and Phase 204 Handoff. |
| Score reading | Scores must be readable without color. Every low score needs score, confidence, practical consequence, highest-leverage fix, and evidence path. |
| Handoffs | CI/CD details link or refer to Phase 202; DB schema details link or refer to Phase 203; ranked follow-up work links or refers to Phase 204. |
| Hover/focus | Do not rely on hover-only disclosure. If the audit is rendered as HTML later, focus-visible outlines must use the accent focus color and all controls must be keyboard reachable. |
| Motion | None. This phase must not add animation, drawers, modals, popovers, sort controls, filters, or generated interactive score widgets. |

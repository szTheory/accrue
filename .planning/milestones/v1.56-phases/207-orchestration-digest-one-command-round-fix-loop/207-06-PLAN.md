<objective>
Implement the ORCH-03/ORCH-04 mutation half of the loop: a new node script `ratchet-fix.mjs` (two CLI modes — `--apply-decisions` and `--finalize-fixes`), a scoped per-resolved-finding probe spec `ratchet-fix-probe.spec.js`, plus the thin `mix accrue_admin.ui.fix` orchestrator that sequences apply → rebuild+commit CSS → re-capture → scoped probe → finalize (guard-mint + verify-close promotion). `ui.fix` never generates a CSS fix itself — the maintainer (or their coding assistant) has ALREADY hand-edited the CSS/component files between `ui.round` and `ui.fix`, guided by the digest; this task automates "rebuild it, prove it, lock it in."

**D-50 boundary (hard constraint):** `ui.fix` is the MUTATION command and must create ZERO net-new `open` rows. It therefore NEVER runs `ratchet-propose.mjs` or `ratchet-verify.mjs` (the evaluator fan-out that discovers AND `appendOpen()`-writes findings — that belongs to `ui.round` only, per D-50: `ui.fix` "does NOT propose net-new findings"). The "did the fix stick?" decision is made ONLY by a scoped, per-resolved-finding DOM/computed-style probe (`ratchet-fix-probe.spec.js` writes `probe-results.json`; `ratchet-fix.mjs --finalize-fixes` reads it), which observes ONLY the specific resolved findings and can never raise a new `open` row for an unrelated candidate.

Purpose: this is the maintainer's second and final formal interaction per round (after batch-approve/reject) — apply the batch, prove each fix stuck via a genuine scoped probe of the re-captured DOM (never guessed, never a fresh fan-out), and mint a guard so a fixed defect cannot silently reopen.
Output: `mix accrue_admin.ui.fix [--round N] [--dry-run]`, backed by a fully self-tested `ratchet-fix.mjs`, a scoped probe spec, and a FakeRunner ExUnit test.
</objective>

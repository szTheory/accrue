# Phase 208 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope

Phase 208 creates no new adopter-facing or operator-facing admin screen. Its user-facing surfaces are maintainer-facing evidence artifacts and status readbacks:

1. The already-built Phase 207 ratchet digest, which remains governed by `207-UI-SPEC.md`.
2. The Phase 208 sign-off artifact: `UI-RATCHET-SIGN-OFF.md`.
3. The follow-on runbook for graduating the remaining admin surfaces under the ratchet.
4. CI and terminal status copy around the deterministic-only `admin-ui-ratchet-guardrails` job.

If this phase changes `accrue_admin` UI while fixing representative-slice findings, those edits must stay inside the existing `ax-*` token/component system in `accrue_admin/assets/css/theme.css`, `accrue_admin/assets/css/app.css`, and `accrue_admin/lib/accrue_admin/components/*`. Do not introduce new visual primitives, Tailwind, shadcn, external registries, or runtime dependencies.

Representative slice is locked by `accrue_admin/e2e/baseline-manifest.js` `SLICES.foundation`: `component-kitchen`, `dashboard`, `subscription-detail`, and `subscriptions`.

Sources: `.planning/ROADMAP.md` Phase 208 details, `.planning/REQUIREMENTS.md` CONV-01..07, `207-UI-SPEC.md`, `baseline-manifest.js`, `theme.css`, `app.css`, and the Phase 200 sign-off/verifier pattern.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Phoenix/LiveView admin UI uses the existing hand-authored `ax-*` CSS system; Phase 208 artifacts are Markdown/CI text plus the existing Phase 207 static digest |
| Preset | not applicable; codebase scan found no `components.json`, no Tailwind config, and the project is not React/Next/Vite |
| Component library | AccrueAdmin Phoenix function components for any incidental admin UI edits; Markdown tables/sections for sign-off and runbook artifacts |
| Icon library | Heroicons through `AccrueAdmin.Components.Icon` for admin UI only; Phase 208 Markdown artifacts use text labels, not decorative icons |
| Font | Existing admin system: Geist and Geist Mono via `--ax-font-sans` / `--ax-font-mono`; Markdown artifacts must use renderer defaults but preserve mono formatting for commands, paths, ids, and status constants |

Binding boundaries:

- `accrue_admin/priv/static/accrue_admin.css` must stay fresh after any source CSS/component changes.
- The Phase 207 digest visual contract is not reopened. Phase 208 only verifies it reaches `CONVERGED (2 dry rounds)` for the representative slice.
- CI guardrail output is deterministic text only and must not require `ANTHROPIC_API_KEY`.

## Phase 208 Interaction Contract

Primary maintainer flow, in order:

1. Run `mix accrue_admin.ui.round --slice foundation` until the digest reports `CONVERGED (2 dry rounds)`.
2. Confirm every representative-slice cell scores at least `2`, `regressions.ndjson` is 0 bytes, and `finding-regressions.ndjson` is 0 bytes.
3. Freeze `accrue_admin/e2e/ratchet/ledger.baseline.json` as the slice high-water mark with an explicit freeze command/flag; freezing must never be hidden behind a generic guardrail command.
4. Run the deterministic local guardrail and independent verifier.
5. Prove the synthetic ledger count-increase failure and the persona-regression failure with automated tests.
6. Keep `admin-hardening-guardrails`, `admin-phase200-guardrails`, and asset-drift green.
7. Write `UI-RATCHET-SIGN-OFF.md` and require exactly one final maintainer decision line beginning with `Final maintainer decision: ACCEPT`.

No in-browser approve/reject controls are introduced in this phase. Existing approval/suppression behavior remains file/CLI-driven through Phase 207 `decisions.json` and `mix accrue_admin.ui.fix`.

## Sign-Off Artifact Contract

`UI-RATCHET-SIGN-OFF.md` is the sole Phase 208 maintainer decision surface. It must be a Markdown evidence summary, not a marketing page.

Required sections, in this order:

1. `## Executive Status`
2. `## Representative Slice Evidence`
3. `## Ledger Baseline Summary`
4. `## Regression Files`
5. `## CI Gate Evidence`
6. `## Persona Regression Proof`
7. `## Existing UI Gate Status`
8. `## Follow-On Runbook`
9. `## Maintainer Checkpoint`

Required final line format:

`Final maintainer decision: ACCEPT (maintainer approved {YYYY-MM-DD}). Evidence source: accrue_admin/e2e/ratchet/ledger.baseline.json and .planning/phases/208-prove-convergence-on-the-representative-slice-wire-ci-accept/UI-RATCHET-SIGN-OFF.md.`

Evidence tables must use `Status` values from this closed set only: `PASS`, `BLOCKED`, `PENDING`, `N/A`. Do not use color words as status values.

## Runbook Contract

The runbook may live inside `UI-RATCHET-SIGN-OFF.md` or as a linked Markdown file in the Phase 208 directory. It must be executable by a maintainer without rediscovering the Phase 207 implementation.

Required headings:

1. `## Run The Representative Slice`
2. `## Read The Digest`
3. `## Apply Fixes And Mint Guards`
4. `## Freeze The Baseline`
5. `## Run Deterministic Guardrails`
6. `## Graduate Another Surface`
7. `## Recover From A Regression`

The runbook must name `SLICES.foundation` as the proven slice and must describe follow-on graduation as a bounded surface/slice run, not a broad full-surface mandate.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, small chip insets |
| sm | 8px | Compact row gaps, table cell breathing room |
| md | 16px | Default element spacing, Markdown table-to-copy rhythm in generated HTML |
| lg | 24px | Section padding and section-to-section gaps |
| xl | 32px | Major evidence block separation |
| 2xl | 48px | Empty/complete state padding if a generated HTML status page is added |
| 3xl | 64px | Page-level spacing only; avoid in dense CI/sign-off artifacts |

Exceptions:

- 2px is allowed only for borders, focus outlines, and structural separators; it is not a layout spacing token.
- Existing mobile touch targets remain at 44px minimum where `app.css` already applies them. Do not shrink controls to fit dense status output.
- Markdown artifacts have no custom layout engine; if rendered to HTML, use this scale exactly.

---

## Typography

Use exactly these four size roles for any Phase 208 generated HTML/status artifact. Markdown source should express hierarchy through headings and tables that map cleanly to these roles.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label / table status | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display / convergence summary | 28px | 600 | 1.2 |

Only weights `400` and `600` are allowed. Commands, file paths, hashes, job names, `finding_id`, `claim_key`, and `ledger_sha256` use Geist Mono / monospace at the Body or Label size, never a separate type scale.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` / `--accrue-paper` `#FAFBFC`; dark `#0F1318` | Page/report background, Markdown renderer canvas if HTML is generated |
| Secondary (30%) | `--ax-elevated` `#FFFFFF`; dark `#171D24` | Evidence tables, sign-off summary panels, digest cards inherited from Phase 207 |
| Accent (10%) | `--ax-accent-strong` / `--accrue-cobalt` `#5D79F6`; readable link color `#174EA6`; dark readable `#9BB5FF` | Reserved elements listed below only |
| Destructive | `--ax-danger` `#D64B4B`; status danger text `#9B1C1C` on light; dark readable `#FFAAAA` | Failed guardrails, count-increase/regression rows, destructive/freeze warnings only |

Accent reserved for: `CONVERGED (2 dry rounds)` badge, evidence links, focus rings, the primary `Run ratchet guardrails` action if an HTML status page is added, and Phase 207 digest region overlays. Do not use accent for every status badge or generic emphasis.

Status semantics:

- `PASS` may use existing success token `--ax-success` / `#5E9E84` when color is available, but the word `PASS` is mandatory.
- `PENDING` may use existing warning token `--ax-warning` / `#C8923B`, with the word `PENDING`.
- `BLOCKED` uses Destructive and must include the failing artifact or command.
- Status must never be conveyed by color alone.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Run ratchet guardrails` |
| Empty state heading | `No open findings in the representative slice` |
| Empty state body | `The foundation slice reached 2 dry rounds and both regression files are empty. Freeze the baseline and collect maintainer ACCEPT.` |
| Error state | `Ratchet guardrails failed. Review finding-regressions.ndjson and regressions.ndjson, repair the named regression, then rerun npm run ratchet:ledger and the existing UI guardrails.` |
| Destructive confirmation | `Freeze ledger baseline`: `Freezing ledger.baseline.json sets the slice high-water mark. Continue only after CONVERGED (2 dry rounds), a non-empty baseline, and empty regression files.` |

Additional exact labels:

- CI job id: `admin-ui-ratchet-guardrails`
- CI job display name: `Admin UI ratchet guardrails`
- Convergence status: `CONVERGED (2 dry rounds)`
- Gate pass copy: `PASS - deterministic ratchet guardrails are clean`
- Gate blocked copy: `BLOCKED - finding-regressions.ndjson is not empty`
- Missing sign-off copy: `PENDING - maintainer ACCEPT line is not present`

Voice: direct, operational, and evidence-first. Avoid celebratory copy, marketing claims, and vague adjectives like "beautiful" or "award-winning" in sign-off/runbook artifacts; those claims belong in the ratchet evaluator rubric, not the final evidence surface.

## CI Status Contract

`admin-ui-ratchet-guardrails` must read as a deterministic sibling to the existing UI gates.

Required visible checks:

| Check | Required Copy | Source |
|-------|---------------|--------|
| No LLM key | `PASS - ANTHROPIC_API_KEY is not required for this job` | CI environment / workflow contract |
| Ledger reducer | `PASS - finding-regressions.ndjson is 0 bytes` | `accrue_admin/e2e/ratchet/finding-regressions.ndjson` |
| Independent verifier | `PASS - independent recompute matches ledger.baseline.json` | `scripts/ci/verify_ratchet_ledger.mjs` |
| Synthetic count increase | `PASS - synthetic count increase blocks the gate` | automated test evidence |
| Persona regression | `PASS - regressed lens count increase blocks the gate` | automated test evidence |
| Existing UI gates | `PASS - admin-hardening-guardrails, admin-phase200-guardrails, and asset-drift are green` | CI evidence |
| Bundle freshness | `PASS - accrue_admin.css is fresh` | asset-drift / bundle check |

Failure copy must name the exact artifact to inspect and the command to rerun. Do not emit a generic "UI failed" message.

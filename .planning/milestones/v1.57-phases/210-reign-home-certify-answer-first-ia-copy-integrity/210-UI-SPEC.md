# Phase 210 — UI Design Contract

> Visual and interaction contract for reigning the **Home** page (`dashboard_live.ex`) onto the canonical shared component vocabulary + answer-first IA, and certifying cross-page (Home + Subscriptions) IA/copy integrity. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a REIGN, not a redesign.** The `accrue_admin` design system, tokens, brand, and shared components already exist and are locked (v1.50–v1.54). Phase 210 introduces **no new tokens, no new palette, no new deps, and zero new shared components** (COMP-01 resolved to "keep both inline" in 209/210-CONTEXT D-01 — Home's ranked-exception attention rail and Subscriptions' at-risk callout do not converge enough to justify `WorkQueueCallout`). The job is to compose Home from the same primitives the reference pages (Payments/Customers/Invoices) and the just-reigned Subscriptions page already use, collapse the triplicated verdict and triplicated customer-search entry points to one each, and remove the bespoke `.ax-home-*`/`.ax-launcher*`/`.ax-attention*` markup — while preserving console density. **Cross-page parity with Phase 209's reigned Subscriptions header grammar is the through-line of this contract**; where this spec says "mirror Subscriptions," treat `209-UI-SPEC.md` as load-bearing precedent, not a suggestion.

## Spacing Scale

Use the existing `--ax-space-*` scale only. **No new spacing values.** Density is the point — do not over-air.

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-2xs` | 2px | Dense rail-row/stack rungs (`.ax-stack-xs`), chip gaps |
| `--ax-space-xs` | 4px | Icon gaps, inline padding, tight chip rows |
| `--ax-space-sm` | 8px | Compact element spacing, badge/label gaps |
| `--ax-space-md` | 16px | Default element spacing, card padding |
| `--ax-space-lg` | 24px | Section padding, card gaps |
| `--ax-space-xl` | 32px | Layout gaps |
| `--ax-space-2xl` | 48px | Major section breaks |
| `--ax-space-3xl` | 64px | Page-level spacing |

**Exceptions:** none new. The removed bands (`ax-home-header-health`, `ax-attention-summary`, `ax-home-customer-search-strip`) were themselves sources of extra vertical padding pushing content down — their removal is a density *improvement*, not a re-air. The 3-tile launcher grid (down from 4) must **not** widen tile padding/gap to fill the freed column — reuse the existing `.ax-launchers` grid gap token and let tiles size to a 3-up (or auto-fit `minmax()`) track, not a wider 3-of-4 layout with visible dead space. Density-no-regression gate: header-band height and above-the-fold content (attention rail + launcher row) must hold at-or-tighter than the pre-reign screenshot.

## Typography

Use the composed type roles already defined in `theme.css`. **Exactly two weights** in the whole system: `400` (regular) and `600` (semibold).

| Role | Token | Size | Weight | Line Height | Usage on Home |
|------|-------|------|--------|-------------|----------------|
| Display (page title, canonical PageHeader h1) | `--ax-type-display` (`ax-display`) | 36px | 600 | 1.2 | `PageHeader` title only — inherited automatically, not applied elsewhere |
| Body | `--ax-type-body` | 16px (`1rem`) | 400 | 1.4 | `:description` intro copy, launcher body text |
| Body small | `--ax-type-body-sm` | 14px (`0.875rem`) | 400 | 1.4 | Meta lines, `EmptyState` body |
| Label | `--ax-type-label` | 14px (`0.875rem`) | 600 | 1.4 | Stat labels, rail row metric text |
| Eyebrow / section label | `--ax-type-eyebrow` | 12px (`0.75rem`) | 600 | 1.4 (uppercase, `--ax-tracking-caps`) | Zone `<h3>` headings ("Jump to a task", "At a glance") — unchanged |
| Code / ID / amount | `--ax-type-code` | 14px mono | 400 | 1.4 | Money amounts in StatStrip/tiles |

**Removed:** the bespoke verdict-sentence `<h1 class="ax-display">` (`dashboard_health_headline/1`) is retired along with its helper — `PageHeader` supplies the only h1 now, and its content is a short, plain page title (see Copywriting Contract), not a rendered verdict sentence.

## Color

60/30/10 split maps to the established theme tokens. **Keep Cobalt as the ratified interaction accent; Moss is success-only. Fix polish, not palette.**

| Role | Token / Value | Usage |
|------|---------------|-------|
| Dominant (60%) | `--ax-base` (light `var(--accrue-paper)`) | Page background, `section.ax-page` |
| Secondary (30%) | `--ax-elevated` (light `#ffffff`) | `.ax-card` surfaces (rail rows, launcher tiles, empty state), PageHeader band, KpiCard/Timeline surfaces |
| Accent (10%) — Cobalt | `--ax-accent` = `#5D79F6` (+ `--ax-accent-strong` for filled controls) | See reserved-for list below |
| Destructive / danger | `--ax-danger` = `#d64b4b` (status tokens `--ax-status-danger-*`) | **Status semantics only** (webhook dead-letter / at-risk severity where P1 warrants it). Home has **no** destructive *actions*. |

**Accent (Cobalt) reserved for — explicit list, never "all interactive elements":**
1. The **single** primary CTA button (`.ax-button-primary`) — the de-duplicated "Open invoice queue" action in `PageHeader` `:actions`.
2. Inline text links / quiet links (`.ax-link`, `.ax-link-quiet`) — e.g. "Review all signals", customer-name links inside rail rows.
3. Focus rings (`--ax-focus-ring` / `--ax-focus-shadow`) on interactive controls.
4. `StatStrip` stat-value tone `cobalt` (`ax-stat-value--cobalt`) on **one** informational (non-severity) metric — this is an established exception already shipped on Subscriptions (209) for the "Open invoices" count value; it colors a number, not a background or control, and stays consistent across both pages.

Accent is **not** used to fill status strips, KPI backgrounds, launcher-tile backgrounds, or every badge — the round-99 "triple Cobalt CTA + blue banners competing" defect (Subscriptions) has a Home analog (triplicated customer-search CTA, all styled as competing buttons) that this phase collapses the same way. Status/verdict tones use the semantic status tokens (`moss`/success, `amber`/warning-action-required, `slate`/neutral, `--ax-info` teal for informational), never the interaction accent.

**Tone scale:** rail rows, launcher tiles, and `EmptyState` all reuse the existing `moss`/`cobalt`/`amber`/`slate`/`ink` tone scale via `StatusBadge`/`.ax-card` — no new tone, no bespoke `ax-attention-priority-*`/`ax-attention-dot-*`/`ax-launcher-health-*` color classes (those are retired along with the markup that used them; `StatusBadge`'s built-in tone dot replaces the bespoke `ax-attention-dot`).

## Interaction & Structural Contract (phase-specific)

These are the load-bearing "reign" contracts the checker/executor must honor:

1. **`PageHeader` replaces the hand-rolled `<header>`.** Breadcrumbs (single, self-referential-free crumb) + plain title + `:description` (verdict `StatusBadge`) + `:actions` (primary CTA, customer-search control, `Audit ledger` secondary) + `:stat_strip` (4-stat `StatStrip`, exposure-first framing per D-03a). No `:filter_toolbar` slot — Home has no filterable table. Remove the retired `ax-dashboard-title-row`, `ax-home-header-health`, and the sentence-title `<h1>` helper (`dashboard_health_headline/1`) plus its now-dead callers.
2. **Attention rail kept, itemized rows kept, verdict-summary block dropped.** The `ax-attention-summary` block ("Billing status: Unhealthy." + P1/P2/P3 sentence) is removed — its content is now covered by the header `StatusBadge`/`StatStrip`. The ranked per-row list (`.ax-card.ax-attention` with P1/P2/P3 rows) **stays** — this is where `failed_meter_event_count` and the itemized detail for every signal continue to live (content-preservation requirement). Rebuild each row from shared primitives: `StatusBadge` for the priority chip (replaces bespoke `ax-attention-priority-*`/`ax-attention-dot-*` — `StatusBadge`'s built-in dot already gives the tone-dot affordance), `.ax-stack-xs` for the metric+label text, `.ax-chip.ax-label` for the optional pill, and a quiet trailing action (icon-suffixed link or small `Button`) for the row's CTA. Empty branch uses `EmptyState.empty_state` (not the bespoke `.ax-card.ax-empty` markup) with `icon={:check_circle}`.
3. **Customer-search collapses to one control, in the header.** Remove the `ax-home-customer-search-strip` `<section>` entirely and remove the `ax-launcher-customer` tile from the launcher grid. The single surviving control lives in `PageHeader :actions` (`data-command-palette-trigger`) — see Copywriting Contract. This drops the launcher grid from 4 tiles to **3** (ROADMAP SC1's literal "four launcher tiles" phrasing is superseded to three per CONTEXT D-02a — do not flag the count drop as a regression).
4. **Three-tile launcher grid, rebuilt from shared primitives.** Each surviving tile (Invoice queue / Recovery / Developer) is `.ax-card` + `Icon` (lg) + title + `StatusBadge`-or-chip meta (tone-mapped, only rendered when the underlying count is non-zero, matching today's conditional rendering) + `Button`(-styled action, replacing the bespoke `ax-launcher-action`/`ax-launcher-health-*`/`ax-launcher-meta-*` ad hoc spans). The Invoice-queue tile keeps a `primary`-marked variant (stable selector, see §7) since it's the highest-priority task door. Grid CSS shrinks to a 3-up (or `auto-fit`/`minmax()`) track using the **existing** `.ax-launchers` gap token — no new spacing value, no widened tile padding to fill the lost 4th column.
5. **Answer-first order preserved end-to-end:** header verdict (`StatusBadge`+`StatStrip`) → primary action (`:actions`) → attention rail (supporting detail, ranked) → task launchers (next-step doors) → KpiCard "At a glance" (drill-down, unchanged) → Timeline activity (unchanged). Matches the grammar Payments/Customers/Invoices/Subscriptions already exhibit.
6. **No re-duplication between header StatStrip and the kept KpiCard band (D-03a).** The header `StatStrip` is the one-line exposure-first answer; the `KpiCard` "At a glance" band is the detailed metric grid. They must not restate the same number as the same sentence — different framing (StatStrip: money-at-risk lead; KpiCard: neutral metric cards with deltas), same underlying `@stats` assigns. Content-preservation proof required: every datum spread across the three removed verdict renderings (`dashboard_health_headline`, `ax-home-header-health`, `ax-attention-summary`) lands in either the `StatusBadge`/`StatStrip` or the retained rail-row list — nothing lost, nothing silently dropped.
7. **Test/selector migration in-phase (D-05):** migrate `dashboard_live_test.exs` L107 (`ax-home-health-answer`), L130 (`ax-launcher-primary`), L184 (`ax-home-customer-search-cta`) and the `admin-spec-overview-phase194`/`admin-interaction-overlay-phase199` `.ax-attention-rail*` e2e selectors to the new shared-component DOM in this phase — do not leave any gate red across the phase boundary. Keep a stable, intentional selector for "the primary launcher tile" and "the customer-search trigger" (e.g. `data-ax-launcher-primary` / `data-ax-command-palette-trigger`, already present) so the migrated assertions target real markers, not incidental classes. `admin-a11y.spec.js` (axe) must stay green with landmark/heading/visually-hidden semantics preserved — the single `<h1>` (PageHeader's) must remain the page's one top-level heading.
8. **CSS is stop-referencing, not delete, in this phase.** Do not delete any `.ax-home-*`/`.ax-launcher*`/`.ax-attention*`/`.ax-health-summary*` rule from `app.css` — Phase 210 only stops *referencing* the retired classes. Deletion is Phase 211's grep-gated job.
9. **Density-no-regression + PNG parity:** verify against (a) the pre-reign Home screenshot (header-band height, attention-rail + launcher above-the-fold extent held at-or-tighter) and (b) the canonical Payments/Customers/Invoices + reigned-Subscriptions reference, in both light and dark themes.
10. **Scope fence:** diff touches **no** `accrue/lib` (core is M2), adds **no** nav room (M3), introduces **no** "why blocked"/causality/diagnosis synthesis, adds **no** new deps, adds **zero** new shared components (COMP-01 resolved "inline" for both pages).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Persisted Stripe evidence → core diagnostic | Stored provider-shaped evidence is untrusted for authorization and must be normalized before crossing into admin. |
| Core diagnostic → CustomerLive | The admin renderer receives consumer-shaped independent branches, not persistence/provider structures. |
| Advisory observation → local grant/headline | Advisory facts must never cross into resolver, Guard, or summary Access decisions. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-214.2-01-E | Elevation of privilege | `Admin.diagnostic_for_customer/1` and `CustomerLive.access_headline/1` | high | mitigate | Compose but never merge branches; retain local resolver as the only headline/grant input; run the isolation script and contradictory-row invariance test. |
| T-214.2-01-I | Information disclosure | primary advisory disclosure and raw projection | high | mitigate | Normalize to count/time/source/completeness/lookup keys, omit object IDs/watermarks/provider payload from primary UI, and keep raw evidence inside the existing escaped lazy viewer. |
| T-214.2-01-T | Tampering | advisory provenance label | high | mitigate | Emit pull only from exact `_accrue.source == "pull"`; later states use event watermark for webhook and unavailable otherwise. |
| T-214.2-01-A | Tampering | advisory status communication | medium | mitigate | Render explicit state text and boundary copy through StatusBadge; never rely on color or add a static live region. |

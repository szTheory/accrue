<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Authenticated host → Offline.replace_device/3 | Host-owned identity and policy authorize an account-scoped replacement; request, actor, and reason remain untrusted input. |
| Replacement device → PoP verifier | The new public key, challenge response, and signature prove possession without exposing the private key. |
| Replacement transaction → devices/challenge/audit tables | Prior transition, replacement insertion, challenge consumption, and event append must commit or roll back together under database locks. |
| Scenario corpus → executor | Synthetic references select setup only; fixture data cannot authorize, mutate directly, or decide lifecycle outcomes. |
| Durable rows → assertion/public consumers | Only bounded states/counts/correlations leave persistence; secrets, raw evidence, and PII stay behind the boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-220-12-01 | Spoofing | Offline.replace_device/3 | high | mitigate | Require host authorization for `:offline_device_replacement`, bounded actor attribution, one-time challenge, and replacement-key signature bound to account/prior/replacement/operation fields. |
| T-220-12-02 | Tampering | Replacement transaction | high | mitigate | Lock account, prior device, and challenge; validate account ownership and active state under lock; commit prior transition, replacement insert, challenge consumption, and audit atomically. |

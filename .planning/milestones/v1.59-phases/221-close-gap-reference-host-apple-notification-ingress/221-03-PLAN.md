<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Untrusted peer/body → local backpressure and parser | Attackers can spoof content and exhaust per-node resources. |
| Verified/invalid outcome → PostgreSQL | Acknowledgement depends on durable terminal state. |
| Runtime evidence → logs/telemetry/tests | Raw evidence could escape through diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-221-09 | Spoofing | Rate-policy identity | high | mitigate | Key only normalized direct `remote_ip`; ignore untrusted forwarding headers and document edge authority. |
| T-221-10 | Denial of Service | Body/rate admission | high | mitigate | Matching 262,144-byte limits, bounded fixed-window state, 429 temporary denial, and deterministic tests. |
| T-221-11 | Tampering | Concurrent duplicates | high | mitigate | Barrier-controlled router proof asserts PostgreSQL uniqueness/locks converge intake and wakeup state. |
| T-221-12 | Information Disclosure | Responses/logs/telemetry | high | mitigate | Empty bodies plus recursive negative assertions for raw bytes, tokens, signatures, PII, arguments, and exception text. |
| T-221-13 | Repudiation | Quarantine acknowledgement | medium | mitigate | Assert bounded durable quarantine identity/config versions exist before verified-invalid 200. |
</threat_model>

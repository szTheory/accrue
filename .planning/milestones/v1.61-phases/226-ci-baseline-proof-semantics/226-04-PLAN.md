<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Host runtime/tool output → diagnostic | Commands, paths, errors, and environment-backed values may contain sensitive or injection-capable text. |
| Host script → optional NDJSON fact | Local runtime observations become retained machine evidence. |
| CI provisioning → host proof contract | Misclassification could shift responsibility or mask whether tests actually ran. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-226-13 | Information Disclosure | setup facts/diagnostics | high | mitigate | Emit only fixed codes/commands and bounded normalized identities; reject or omit URLs, tokens, env values, payloads, app data, and raw paths. |
| T-226-14 | Tampering | next-command rendering | high | mitigate | Derive owner and next command from a fixed registry, reject unknown codes, and never execute/render caller-supplied command prose. |
| T-226-15 | Spoofing | host-versus-CI ownership | medium | mitigate | Contract-test each code's single owner and reserve Linux dependency provisioning for CI. |
| T-226-16 | Repudiation | setup failure evidence | medium | mitigate | Preserve command identity, classified result, duration, normalized evidence location, and original nonzero status. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| recovery record → live collection | Collection must prove recovery completion before any refresh-capable or remote observation path. |
| Git/GitHub/GSD outputs → canonical JSON | Untrusted command and remote data enter committed evidence. |
| canonical JSON → Markdown | Validated evidence becomes human-consumed release diagnostics. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-229-09 | Spoofing | remote repository/ref facts | high | mitigate | Bind every fact to fixed repository, observation time, full SHA data, and normalized request; reject foreign/missing identity. |
| T-229-10 | Tampering | recovery-to-observation ordering | high | mitigate | Require verified recovery manifest and preservation object resolution before the collector exposes any live/refresh flag. |
| T-229-11 | Information Disclosure | JSON/Markdown evidence | high | mitigate | Recursive field allowlist, relative-path grammar, Markdown escaping, bounded classifications, and negative controls for secret/path/log/payload/actor fields. |
| T-229-12 | Repudiation | unavailable/green evidence | high | mitigate | Explicit unavailable records with provenance and no substitution; separate Actions conclusion from provider-proof state. |
| T-229-13 | Denial of Service | remote pagination and process output | medium | mitigate | Bound page count, item count, buffer size, and command duration; surface a bounded unavailable reason on observation failure. |
</threat_model>

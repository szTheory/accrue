<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| workflow run conclusion -> lane proof | A green conclusion is a workflow's self-report, not evidence that the lane proved anything. |
| committed evidence artifact -> reviewer trust | A committed record verified by nothing is indistinguishable from a record that was verified. |
| mutable branch ref -> CI step subject | A step bound to a moving ref silently changes what it verifies between runs. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-232-10-01 | Tampering (with evidence) | self-test flag short-circuit | high | mitigate | Add a real, non-self-test invocation against the committed pair, assert structurally that the step passes the committed-file arguments and not the self-test flag, and fix the argument-handling order if it would swallow the invocation. |
| T-232-10-02 | Spoofing (of a safety property) | mutable branch binding | high | mitigate | Assert the step contains a full-length literal SHA and does not name the integration branch. |

| T-232-10-04 | Repudiation | conflated concurrent dispatches | medium | mitigate | Run identifier plus observed SHA per row makes two dispatches distinguishable rather than merge-able into one claim. |

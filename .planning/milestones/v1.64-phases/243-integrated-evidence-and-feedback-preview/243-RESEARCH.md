## Common Pitfalls

### Pitfall 1: Local macOS image treated as Linux acceptance

**What goes wrong:** Locally minted images replace OS/font-specific committed Linux baselines.
**Why it happens:** The same test command is runnable on a developer machine, but the snapshots encode runner/font rendering.
**How to avoid:** Use the existing Ubuntu `workflow_dispatch` mint job; review intended changes, commit, then run the blocking normal comparison.
**Warning signs:** Baseline provenance lacks Linux runner, browser and lockfile identity, or a local macOS image appears in the expected Linux directory. `[VERIFIED: .github/workflows/accrue_admin_browser.yml:105-115; .planning/phases/243-integrated-evidence-and-feedback-preview/243-CONTEXT.md, D-03]`

### Pitfall 2: A mask passes without matching, or hides meaningful facts

**What goes wrong:** A broken selector makes volatile content unstable, or a broad selector masks identity/money/state/action/error context.
**Why it happens:** The current mask helper returns locators without explicit positive-count/exclusion assertions; some selectors are positional or whole-fact/text scopes.
**How to avoid:** Confirm matched rendered text per composition; assert nonzero intended target counts and check exposed protected facts remain unmasked. Prefer deterministic fixture time for a new exemplar if that avoids a mask.
**Warning signs:** `td:nth-child(4)`, `.ax-body` filtering, or `.ax-summary-fact` remain broad without label/value boundary proof. `[VERIFIED: accrue_admin/e2e/admin-visual-regression-phase211.spec.js:43-79; .planning/phases/243-integrated-evidence-and-feedback-preview/243-CONTEXT.md, D-04]`

### Pitfall 3: Preview damaged by proof startup or fixture setup

**What goes wrong:** Proof targets the user's persistent preview DB/process, reseeds feedback data, drops test DB unexpectedly or binds the preview port.
**Why it happens:** `mix verify.full` is a wrapper with multiple environment scopes: its browser step drops/creates/migrates/seeds test DB and builds assets, then the dev boot step creates/migrates the dev DB and starts a server. The older Phase 239 handoff described only its test DB segment.
**How to avoid:** Preserve the approved preview DB/container/process; inspect each path's actual host, DB name, Compose instance, port and process before proof/reset/mutation. Use disposable package/host fixtures for mutation assertions. Keep the preview's skip-seed warm recovery command separate from proof.
**Warning signs:** A plan says only “`MIX_ENV=test` means isolated”, invokes `make reset`, assumes no seed because a helper uses a fixture, or checks only an HTTP verb. `[VERIFIED: examples/accrue_host/mix.exs:156-164; scripts/ci/accrue_host_verify_browser.sh:108-126; scripts/ci/accrue_host_verify_dev_boot.sh:60-76; .planning/phases/243-integrated-evidence-and-feedback-preview/243-CONTEXT.md, D-07-D-09]`

### Pitfall 4: Evidence labels collapse across phases or tiers

**What goes wrong:** Historical results or source inspections are represented as current route, rendered, exercised, remote or provider proof.
**Why it happens:** A full suite/regression aggregate looks broad, while the 240 ledger marks many route states source-only and 242 leaves a named CSS HTTP gap.
**How to avoid:** For each final claim link the changed route/state to its owner and record current revision, fixture, command and evidence tier. Mark N/A by route applicability and unobserved when there is no execution evidence.
**Warning signs:** “All routes verified” from an aggregate count; “served” from a bundle hash; “CI passed” from workflow definition; “read-only app” from page-request logs. `[VERIFIED: .planning/phases/240-shared-system-and-real-billing-exemplar/240-COVERAGE.md:1-4; .planning/phases/242-investigations-and-remaining-admin-surfaces/242-EXECUTION-HANDOFF.md:18]`

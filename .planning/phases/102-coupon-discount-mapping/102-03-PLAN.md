<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| customer browser -> LiveView checkout | Promo-code inputs and submit events arrive from an untrusted client |
| LiveView preview state -> final subscription submit | Provisional preview state must not be trusted without revalidation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-102-05 | I | `CheckoutLive` preview messaging | mitigate | Keep user copy generic for invalid codes and drift; do not reveal whether a mapped Braintree discount id is missing or incompatible. |
| T-102-06 | T | `CheckoutLive` preview/submit flow | mitigate | Always pass the selected `promotion_code` through `Billing.subscribe/3` and rely on core revalidation instead of trusting preview state or browser-hidden fields. |
| T-102-03 | R | portal submit UX | mitigate | Translate `%Accrue.Error.DiscountMappingInvalid{}` into safe customer copy and block subscription creation rather than allowing an undiscounted checkout completion. |
</threat_model>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → guard | The incoming `conn`/`socket` is untrusted; only server-side assigns are read for billable (never params/headers). |
| host billable fn → guard | The host-supplied 1-arity fn is untrusted to be total; a raise must fail closed. |
| guard → deny response | The deny body crosses back to the client; must stay opaque. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-04 | Elevation of Privilege | fail-OPEN on resolver/billable-fn error | mitigate | `resolve_billable/3` wraps the host fn in `rescue`/`catch → nil`; nil flows to the Phase 123 gate which fails closed; deny is the only non-`{:ok,true}` path. Tested: raising-fn leg in guard_test.exs Task 2(3). |
| T-124-05 | Spoofing / EoP | billable spoofed via request input | mitigate | Default probe + host fn read ONLY `container.assigns`; the `accept` header is read for content negotiation, never for authz. Source-asserted: no params/headers feed the billable. |
| T-124-06 | Information Disclosure | deny body leaking which tier gates what | mitigate | `deny_plug/4` body is opaque (`{"error":"forbidden"}` / `"Forbidden"`); `ctx.required` goes only to host-owned `on_deny` fns, never auto-serialized. Tested: opacity assertion in guard_test.exs Task 2(4). |
| T-124-07 | Tampering / EoP | stashing the boolean decision (stale grant) | mitigate | Stash `:accrue_billable` (billable term) only; `:accrue_entitled` must be absent. Tested: resolve-once assertion in guard_test.exs Task 2(2). |
</threat_model>

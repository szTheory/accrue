<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → controller pipeline | The HTTP request is untrusted; the plug must enforce server-side, halt on deny, and never trust client-supplied entitlement claims. |
| router DSL → plug | Macro-expanded `plug` registration; bad opts must fail at compile, not silently no-op. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-124-08 | Elevation of Privilege | a misconfigured plug silently allowing | mitigate | `init/1` raises `ArgumentError` at compile time on missing/both/wrong-type `feature:`/`plan:`; the plug cannot register with ambiguous intent. Tested: init-raise legs Task 1. |
| T-124-09 | Information Disclosure | deny response leaking entitlement structure | mitigate | Deny delegates to `Guard.deny_plug/4` opaque body; plug test asserts the body excludes the feature/plan name (D-10). |
| T-124-10 | Denial of Service | open-redirect / redirect loop via `on_deny: {:redirect, _}` | mitigate | Deny target is a host-declared static path (not user input); moduledoc documents it must live outside the gated pipeline (D-13). No redirect default (the default is 403). |
| T-124-SC | Tampering | npm/pip/cargo installs | accept | This phase installs ZERO external packages (all deps pre-locked in mix.lock); no Package Legitimacy Gate applies (RESEARCH §"Package Legitimacy Audit"). |
</threat_model>

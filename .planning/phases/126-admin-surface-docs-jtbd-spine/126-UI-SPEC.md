# Phase 126 — UI Design Contract

> Visual and interaction contract for the **read-only entitlements tab** on `AccrueAdmin.Live.CustomerLive`.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** Only success criterion #1 (the admin entitlements viewer) is UI work. Criteria #2–4
> (`guides/entitlements.md`, the JTBD ⛔→✅ flip, the README/quickstart spine, green doc verifiers) are
> docs/verifier work with **no visual surface** — they are out of this contract's scope.
>
> **This is an EXISTING admin UI with a fully-established design system.** This phase adds **one tab**
> to a tabbed detail view that already exists. The contract below is **reuse-only**: it documents the
> tokens, components, and copy discipline the new tab MUST honor — it introduces **zero new tokens,
> zero new components, and zero new CSS classes**. Source of truth for every value here is the live
> code, not a fresh design exercise.

## Spacing Scale

Declared values are the live `--ax-space-*` tokens (rem-based; root 16px → all multiples of 4). **Do not introduce raw pixel padding/margins — use these tokens or the structural classes that consume them.**

| Token | CSS var | Value | Usage |
|-------|---------|-------|-------|
| xs | `--ax-space-xs` | 4px (0.25rem) | Inline gaps, chip padding, badge dot gap |
| sm | `--ax-space-sm` | 8px (0.5rem) | Compact element spacing, list-row gaps, tab gaps |
| md | `--ax-space-md` | 16px (1rem) | Default element spacing, card gaps, KPI grid gap |
| lg | `--ax-space-lg` | 24px (1.5rem) | Card padding (`ax-card`), section padding |
| xl | `--ax-space-xl` | 32px (2rem) | Page-level stack gap (`ax-page` / `ax-stack-xl`) |
| 2xl | `--ax-space-2xl` | 48px (3rem) | Major section breaks |

Radii (reuse, do not redefine): `--ax-radius-sm` 12px, `--ax-radius-md` 16px, `--ax-radius-lg` 24px (cards). Pills/badges use `999px`.

Exceptions: touch targets — interactive controls use the established `min-height: 2.75rem` (44px) floor from `ax-button` / `ax-field-control` / `ax-icon-button`. The entitlements tab is read-only, so it inherits this only via the tab strip and any links; no new exceptions.

## Typography

The type scale is fixed in `accrue_admin/assets/css/app.css` via named classes — the tab consumes classes, never declares font-size inline. Four roles, two weights (400 implicit body / 600 semibold).

| Role | Class | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Display (KPI value) | `ax-display` / `ax-kpi-value` | 28px (1.75rem) | 600 | 1.2 |
| Heading (section `<h3>`) | `ax-heading` | 20px (1.25rem) | 600 | 1.2 |
| Body | `ax-body` | 16px (1rem) | 400 | 1.5 |
| Label / eyebrow / badge / tab | `ax-label` / `ax-eyebrow` / `ax-status-badge` / `ax-tab` | 14px (0.875rem) | 600 | 1.4 |
| Mono (raw JSON only) | `ax-json-raw` / `ax-json-value` | 14px (0.875rem) | 400 | 1.5 |

Weights: only **400** (body) and **600** (everything emphasized — headings, labels, badges, links). No third weight. The `ax-eyebrow` uppercases via `text-transform`, not a heavier weight.

## Color

The palette is locked in `accrue/priv/static/brand.css` (`--accrue-*`) and bound to semantic `--ax-*` tokens in `theme.css`. Light-mode values shown; dark mode is handled by the token layer automatically (`data-theme`). **The tab MUST reference semantic tokens / component tones — never raw hex.**

| Role | Token (light) | Value | Usage |
|------|---------------|-------|-------|
| Dominant (~60%) | `--ax-base` (`--accrue-paper`) | `#FAFBFC` | Page background |
| Secondary (~30%) | `--ax-elevated` / `--ax-sunken` | `#FFFFFF` / `#F1F5F8` | Cards (`ax-card`), JSON viewer surface, sunken raw-JSON block |
| Accent (~10%) | `--ax-accent` (`--accrue-cobalt`) | `#5D79F6` | Active tab underline, links, KPI sparkline, focus ring — **interactive/navigation affordances only** |
| Success | `--ax-success` (`--accrue-moss`) | `#5E9E84` | Active-plan / granted-feature status badge (`moss` tone), via `StatusBadge` |
| Warning | `--ax-warning` (`--accrue-amber`) | `#C8923B` | **Grace state** badge AND the **"⚠ Unmapped plan"** drift badge (`amber` tone), via `StatusBadge` |
| Neutral | `--ax-subtle` (`--accrue-slate`) / `--ax-muted` | `#24303B` / `#5D6A73` | Expired-grace / canceled / secondary text (`slate` tone, `ax-muted`) |
| Text | `--ax-primary` (`--accrue-ink`) | `#111418` | Primary text, headings |

Accent reserved for: **the active tab underline, hyperlinks (`ax-link`), the focus-visible ring, and KPI sparkline strokes.** Accent is NOT used for the unmapped-drift signal (that is `amber`/warning) and NOT used to fill plan/feature chips.

Destructive: **none — this phase ships zero destructive actions** (read-only viewer; no grant/revoke/edit). The existing `ax-button-danger` token exists but is not used here.

**Drift-signal color rule (load-bearing, from D-03):** unmapped active subscriptions are surfaced with the **`amber`/warning** `StatusBadge` tone (the established "needs attention" tone — same family as grace/dunning), distinguishing them by eye from `moss` active plans without inventing a new color. Use `StatusBadge` (`tone="amber"` or a `:warning`/`:grace_period`-family status) — do not hand-roll a red badge or a new class.

## Copywriting Contract

All operator-facing strings live in a new `AccrueAdmin.Copy.Entitlements` submodule, registered via `defdelegate` in `AccrueAdmin.Copy` and added to the `mix accrue_admin.export_copy_strings` allowlist (CONTEXT D-05 / VERIFY-01). **No string below may be hardcoded in the template.** Phrasing matches the established `customer_detail_*` / `*_empty_*` voice (declarative, lowercase-after-first-word, period-terminated for body copy).

| Element | Copy | Copy fn (proposed) |
|---------|------|--------------------|
| Tab label | `Entitlements` | (tab strip — humanized from `"entitlements"`, matches existing tabs) |
| Section heading — resolved | `Active entitlements` | n/a (`ax-heading` literal acceptable per existing tab pattern, or `entitlements_section_title/0`) |
| Section heading — drift | `Plan mapping` | `entitlements_drift_section_title/0` |
| Active plans label | `Active plans` | `entitlements_active_plans_label/0` |
| Granted features label | `Granted features` | `entitlements_features_label/0` |
| Quantities/limits label | `Seats & limits` | `entitlements_quantities_label/0` |
| Grace state label | `In grace period` | `entitlements_grace_label/0` |
| Unmapped drift badge | `⚠ Unmapped plan` | `entitlements_unmapped_badge/0` |
| Empty state heading | `No active entitlements` | `entitlements_empty_title/0` |
| Empty state body | `This customer has no entitling subscriptions, so no plans or features are currently granted.` | `entitlements_empty_copy/0` |
| Drift "all clear" note (optional) | `All active subscriptions map to a configured plan.` | `entitlements_no_drift_copy/0` |
| Raw map disclosure | `Show resolved map` | `entitlements_raw_map_label/0` |
| Error / resolver-failure state | `Entitlements couldn't be resolved for this customer right now. The gate fails closed, so no access is granted on error — retry shortly.` | `entitlements_error_copy/0` |
| Destructive confirmation | not applicable — no destructive actions in this phase | — |

**Fail-closed honesty in copy (PITFALLS #1):** the error-state string MUST state that resolution failing means **no access is granted** (fail-closed), never imply data is missing in a way that suggests access is silently allowed.

**Drift copy must be self-explaining:** the `⚠ Unmapped plan` badge alone is not enough — pair it with a one-line hint (tooltip or adjacent `ax-muted` text) such as `This subscription's price isn't in your :plans config, so the resolver drops it.` so an operator understands the drift "by eye" without reading source (D-03).

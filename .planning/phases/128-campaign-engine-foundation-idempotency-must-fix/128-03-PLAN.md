<objective>
Create the pure, property-testable `Accrue.Dunning.Campaign` step resolver: given the configured steps, the campaign anchor timestamp, and `now`, return the next step to send (with key/template) and the `schedule_in` delay until it — or a terminal signal when the journey is exhausted. Pure function only; no DB, Oban, Stripe, or clock calls (DUN-02, D-11).

Purpose: The `DunningStep` worker (Plan 05) calls this resolver after delivering each step to decide whether to enqueue the next one and with what delay. Keeping it pure makes the property test trivial (zero-decimal/ordering/boundary edge cases) and makes the Phase-131 `Accrue.Dunning.Engine` behaviour a clean extraction — but this plan does NOT introduce the behaviour.
Output: A new pure module `accrue/lib/accrue/dunning/campaign.ex` and a new property test `accrue/test/property/dunning_campaign_property_test.exs`.
</objective>

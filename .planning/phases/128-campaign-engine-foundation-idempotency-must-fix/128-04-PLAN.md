## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe webhook retry → enqueue | Stripe re-fires `invoice.payment_failed` on every Smart Retry (weeks 1-4); each crosses into Accrue's mailer enqueue. Duplicate/unbounded sends are the threat. |
| email assigns → Oban args (JSONB) | Assigns are persisted to `oban_jobs.args`. Must be scalar-only and PII-free. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-128-07 | DoS / cost (notification spam) | `:invoice_payment_failed` enqueue | mitigate | Duplicate-enqueue-under-retry-storm produces at most one email per invoice via Oban `unique` `keys: [:type, :invoice_id]`, `period: :infinity`, `:completed` in states (D-13) — a week-2 Smart-Retry redelivery returns `{:ok, %Job{conflict?: true}}`, silent, no retry storm. Acceptance criteria prove no second job is created. |
| T-128-08 | Information Disclosure | email assigns in `oban_jobs.args` | mitigate | Assigns carry only `invoice_id`/`subscription_id`/`to` references (IDs, not structs) enforced by `only_scalars!/1`; CTA URLs deep-link the portal but carry no token/secret in the dedup key (keyed on `invoice_id` only). Sensitive Stripe fields never logged (CLAUDE.md). |
| T-128-09 | Tampering | dedup key collision | mitigate | `keys: [:type, :invoice_id]` includes `:type` so a `:receipt` and `:invoice_payment_failed` sharing an id cannot collide; keyed on `invoice_id` (always present) not nullable `invoice_number`. |
| T-128-SC | Tampering | npm/pip/cargo installs | n/a | No package installs (Mailglass/Oban already in mix.lock). |
</threat_model>

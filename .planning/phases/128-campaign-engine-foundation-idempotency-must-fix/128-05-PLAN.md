<objective>
Build the durable, cancel-guarded, Oban-unique `Accrue.Workers.DunningStep` worker that delivers one dunning step email and chains the next, threading a single `campaign_started_at` identity. This is the durable scheduling engine — it runs independent of when/whether the processor re-fires webhooks (DUN-02), it can never double-send a step (DUN-05 via D-16 unique), and it self-cancels on recovery (DUN-05 via D-11 cancel-guard backstop).

Purpose: The webhook reducer (Plan 06) enqueues the day-0 step; from there the chain is self-propelling — each `perform/1` resolves and enqueues the next step via the pure `Accrue.Dunning.Campaign` resolver (Plan 03). The cancel-guard re-checks live subscription state so any step that slips past the proactive cancel (Plan 06) self-cancels with no email.
Output: A new worker module `accrue/lib/accrue/workers/dunning_step.ex` (with `perform_job`-driven tests, since the webhook-path enqueue/keying tests live in Plan 06).
</objective>

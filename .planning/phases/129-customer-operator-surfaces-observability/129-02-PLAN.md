<objective>
Add a named query function that folds the `accrue_events` ledger into a `%{recovered: n, lost: n}` counter, answering the merchant question "how much past-due revenue did dunning recover vs. lose to terminal action?" — with no new table.

Purpose: DUN-08 SC#4 — the recovered-vs-lost signal must be DERIVABLE (a query API, not a dashboard; the full analytics dashboard is milestone Out-of-Scope, carried). It counts the two confirmed-transition lifecycle ledger types created in Plan 01: recovered = count(`dunning.recovered`), lost = count(`dunning.exhausted`). It deliberately excludes the sweeper's request-time `dunning.terminal_action_requested` (request-time intent, sweeper-only, may exist with no campaign) so "lost" can never double-count (D-06).

Output: `Accrue.Billing.Dunning.recovered_vs_lost/1` + unit and property tests proving the type filter, the window filter, and the never-counts-terminal-action-requested invariant.
</objective>

## Component Inventory

### `AccrueAdmin.Components.WindowSelector` (NEW)

**File:** `accrue_admin/lib/accrue_admin/components/window_selector.ex`

**Attrs:**
- `current_window :: String.t()` — required. One of `"7d"`, `"30d"`, `"90d"`.
- `base_path :: String.t()` — required. Clean path with no query params (e.g., `"/billing/analytics/recovery"`).

**Rendered structure:**

```html
<nav class="ax-tabs" aria-label="Time window (UTC)">
  <a class="ax-tab [ax-tab-active]" aria-current="page|nil"
     data-phx-link="patch" data-phx-link-state="push"
     href="{base_path}?window=7d">
    7 days UTC
  </a>
  <a class="ax-tab [ax-tab-active]" aria-current="page|nil"
     data-phx-link="patch" ...
     href="{base_path}?window=30d">
    30 days UTC
  </a>
  <a class="ax-tab [ax-tab-active]" aria-current="page|nil"
     data-phx-link="patch" ...
     href="{base_path}?window=90d">
    90 days UTC
  </a>
</nav>
```

**Active state rule:** The button whose `value` matches `current_window` receives class `ax-tab-active`
and `aria-current="page"`. All others receive neither.

**CSS classes used:** `ax-tabs` (container), `ax-tab` (inactive button), `ax-tab-active` (active button).
No new CSS classes introduced. Reuses the existing tab system verbatim.

**Insertion point in `RecoveryLive` template:**

```heex
<header class="ax-page-header">
  <Breadcrumbs.breadcrumbs ... />
  <p class="ax-eyebrow">Recovery Dashboard</p>
  <h2 class="ax-heading">Revenue Recovery</h2>
  <WindowSelector.window_selector current_window={@window} base_path={@current_path} />
</header>
```

Place `<WindowSelector>` after the `<h2>` heading and before the KPI grid. This positions the
filter above the data it controls, consistent with the "filter then data" reading order.

## Interaction Contract

### URL as Single Source of Truth

| Interaction | Mechanism | Result |
|-------------|-----------|--------|
| User clicks "7 days UTC" button | `<.link patch="…?window=7d">` — LiveView intercepts click, pushes URL | `handle_params/3` fires with `%{"window" => "7d"}`; DOM diff updates KPI cards + funnel; URL bar shows `?window=7d` |
| User clicks "30 days UTC" button | Same — `?window=30d` | Same; `?window=30d` in URL bar |
| User clicks "90 days UTC" button | Same — `?window=90d` | Same |
| User loads page with no `?window=` | `handle_params/3` receives `%{}`; `parse_window(nil)` falls back to `"30d"` | 30-day view renders; "30 days UTC" button is active |
| User loads page with `?window=bad` | `parse_window("bad")` falls back to `"30d"` | 30-day view renders; "30 days UTC" button is active |
| User bookmarks/shares URL | URL contains `?window=7d` etc. | Recipient sees same window on load — URL is SSOT |
| Back/forward browser navigation | LiveView pushState handles history | Correct window restores on back button |

**No full page reload** on window switch. LiveView's `<.link patch>` sends a minimal DOM diff.
No `handle_event` callback. No JavaScript custom code.

### Active State Rendering

The active button is determined server-side from `@window` assign:
- Active: `class="ax-tab ax-tab-active" aria-current="page"` — accent-colored bottom border, `--ax-primary` text
- Inactive: `class="ax-tab" aria-current={nil}` — `--ax-muted` text, transparent bottom border

The `aria-current="page"` attribute is the ARIA affordance for assistive technology. It is set
on the active button and absent (not `aria-current="false"`) on inactive buttons.

### Touch Target

Each `.ax-tab` button renders with `padding: 0.75rem 1rem` and `min-height` inherited from the
containing `.ax-tabs` flow. Effective touch target is approximately 44px tall (0.75rem top +
line-height + 0.75rem bottom at 16px base = ~40px; acceptable for admin tooling used on desktop).
No additional touch target expansion needed — this is an admin dashboard, not a mobile-first UI.

## Copywriting Contract

Source: CONTEXT.md §specifics + REQUIREMENTS.md DAN-10 (HIGH confidence).

| Element | Copy | Notes |
|---------|------|-------|
| Window selector button 1 | `7 days UTC` | UTC suffix is mandatory per DAN-10 — no timezone conversion |
| Window selector button 2 | `30 days UTC` | Default selection |
| Window selector button 3 | `90 days UTC` | |
| `aria-label` on `<nav>` | `Time window (UTC)` | Screen reader context for the button group |
| Empty state (no events in window) | Not applicable in this phase — the KPI cards and funnel already handle zero-data states from Phase 143/144. `recovered_str` renders `$0.00` (or locale equivalent) when `recovered_cents` is 0. | Existing behavior; no new empty state copy needed |
| Error state | Not applicable — `parse_window/1` is a pure whitelist guard with no failure path. Invalid `?window=` silently falls back to `"30d"`. No error is shown to the user. | By design per CONTEXT.md D-03 |
| Destructive actions | None — this phase contains no destructive actions. | No confirmation copy needed |

**UTC label rationale (from DAN-10):** UTC-only labels prevent ambiguity across timezones for
an ops/billing admin dashboard. The "UTC" suffix is not optional. Future phases may add a
"Showing data since YYYY-MM-DD (UTC)" badge — Phase 145 does not ship that badge.

**Label casing:** Title-style not used. Labels are sentence-style: `"7 days UTC"` not `"7 Days UTC"`.
This matches the existing `.ax-eyebrow` / `.ax-label` pattern in the admin UI.

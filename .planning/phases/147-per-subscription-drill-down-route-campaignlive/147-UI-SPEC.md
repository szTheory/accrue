## Component Inventory

New components to build in this phase, following established patterns:

### `AccrueAdmin.Components.CampaignTimeline`

File: `accrue_admin/lib/accrue_admin/components/campaign_timeline.ex`

| Attr | Type | Required | Description |
|------|------|----------|-------------|
| `arcs` | `:list` | yes | `[{anchor :: String.t() \| nil, events :: [Event.t()]}]` from `campaign_timeline_grouped/2` |
| `invoice_map` | `:map` | yes | `%{stripe_invoice_id => %{status:, amount_due_cents:, card_last4:, card_brand:}}` from `invoices_for_campaign/2` |

**Outer shell:** `<section class="ax-campaign-timeline">` wrapping a `for {anchor, events} <- @arcs` comprehension. Each arc is a `<div class="ax-campaign-arc">` using `.ax-timeline-list` layout (grid, `gap: --ax-space-lg`).

**Row variants** (implemented as private component function heads dispatching on `event.type`):

1. **Anchor row** (`dunning.campaign_started`): CSS class `ax-campaign-timeline-anchor`.
   - Dot: `.ax-timeline-dot ax-timeline-dot-cobalt`
   - Card: `.ax-timeline-card` containing date/time (`ax-label`) + failure reason from `@invoice_map[event.data["invoice_id"]]` (`.ax-body`, or "—" if nil) + payment method context (card brand + last4, or "—" if nil)
   - Payment method context shown once here, NOT repeated on step rows

2. **Retry row** (`dunning.step_sent`): CSS class `ax-campaign-timeline-step`.
   - Dot: `.ax-timeline-dot ax-timeline-dot-slate`
   - Card: `.ax-timeline-card` containing "Attempt N" label (`.ax-label`, 1-indexed within arc, counting only `step_sent` events) + timestamp (`.ax-timeline-meta`) + invoice amount via `format_money/3` (`.ax-money`) + `StatusBadge.status_badge/1` for invoice status

3. **Terminal row** (`dunning.recovered` or `dunning.exhausted`): CSS class `ax-campaign-timeline-terminal`.
   - Recovered → Dot: `.ax-timeline-dot ax-timeline-dot-moss`. Outcome badge: `.ax-status-badge ax-status-badge-moss` labelled "Recovered". MRR value from `event.data["mrr_value_cents"]` + `event.data["currency"]` via `format_money/3`.
   - Exhausted → Dot: `.ax-timeline-dot ax-timeline-dot-amber`. Outcome badge: `.ax-status-badge ax-status-badge-amber` labelled "Exhausted". MRR value same pattern.

**Legacy prefix arc** (`anchor == nil`): wrap in a `<div>` with heading `.ax-eyebrow` text "Legacy events" and render rows without a campaign_started row. If `events` is empty, render empty state instead of this section.

**`format_money/3` call pattern** (compute once per component render, thread as assigns):
```
currency = Accrue.Config.get!(:default_currency)
locale   = Accrue.Config.default_locale()
Accrue.Invoices.Render.format_money(amount_due_cents, currency, locale)
```
Guard nil: `if ctx && ctx.amount_due_cents, do: format_money(...), else: "—"`.

## Layout

**Page structure:** Single-column `.ax-page` layout. No sidebar content, no tabs, no window selector. Breadcrumbs above the page header. Page header (`ax-page-header`) contains title + subscription ID as subtitle. CampaignTimeline section occupies the full content width below.

**Responsive:** Inherits the two-column shell layout (sidebar + main) from the AppShell at `min-width: 1024px`. The timeline itself is a single column at all breakpoints — no horizontal scrolling needed.

**Empty state layout:** When `@arcs == []`, the `CampaignTimeline` component renders `.ax-empty-state` (`display: grid; gap: --ax-space-md; max-width: 48rem`) with an `.ax-heading` + `.ax-body` pair. No full-page empty state — it is scoped inside the timeline section.

## Interaction States

| State | Trigger | Treatment |
|-------|---------|-----------|
| Page load | `mount/3` called | Synchronous DB load in mount — no loading skeleton needed (timeline is fast: small event set per subscription) |
| Row hover | Cursor over `ax-at-risk-grid tbody tr` | Inherits `.ax-at-risk-grid tbody tr:hover td` background from `app.css` — no new hover rules needed for CampaignTimeline rows (static timeline, not a table) |
| Breadcrumb back-link | Click "Recovery" breadcrumb | Standard `<a href>` navigation to RecoveryLive — no LiveView patch, full navigation |
| Focus ring on breadcrumb link | Keyboard tab | `border-color: var(--ax-focus-ring)` + `outline: none` — inherits `.ax-link:focus-visible` rule |
| Nil values | `invoice_map` lookup returns nil | Render "—" (em dash) in place of amount, card details, failure reason. No error state. |
| Empty arcs list | Subscription has no dunning events | Render `.ax-empty-state` block inside `.ax-campaign-timeline`. No 404, no redirect. |

## Accessibility

- Page `<h1>` uses `.ax-heading` — single h1 per page, matches established LiveView page structure.
- Breadcrumb `<nav aria-label="Breadcrumb">` pattern from `AccrueAdmin.Components.Breadcrumbs` — inherited unchanged.
- Timeline list uses `<ul class="ax-timeline-list">` (ordered list semantics implied by visual sequence) — use `<ol>` for the `ax-timeline-list` inside each arc to convey chronological ordering to screen readers.
- Status badges carry visible text labels ("Recovered", "Exhausted", "Attempt N") — no icon-only states.
- Timestamps rendered as `<time datetime="{iso8601}">` for machine-readable temporal semantics.
- `ax-visually-hidden` class available for any screen-reader-only context (e.g., aria labels on status dots).
- No interactive controls, no forms — no additional ARIA roles needed.

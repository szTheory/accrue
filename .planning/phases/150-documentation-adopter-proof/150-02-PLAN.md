|----------|-------------|
| client (authenticated browser) → LiveView/layout | The banner is rendered server-side for the current session's scope; it must reveal only the current org's billing status. |
| seed data → demo environment | Seeded demo credentials are committed to the repo; must be dev/demo-scoped, never production-usable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-04 | Information Disclosure | Layouts.app banner customer resolution | mitigate | Resolve the customer strictly from @current_scope via AccrueHost.Billing.customer_for_scope/1 (scope-bound to the active organization). Never accept a customer id from params. ASVS V4 (access control) — no cross-tenant dunning-state leakage; the healthy org sees no banner, the past-due org sees its own. |
| T-150-05 | Tampering / Availability | Side-effecting customer creation on render (Pitfall 1) | mitigate | The dunning_customer/1 resolver returns only a resolved %Accrue.Billing.Customer{} or nil — never a raw Organization billable — so the banner never triggers Accrue.Billing.customer/1 get-or-create on a plain GET/render. |
| T-150-06 | Elevation of Privilege | Seeded demo accounts (healthy@ / past-due@example.com) | mitigate | Demo accounts are non-privileged org owners with a documented demo password, seeded only in the example host (dev/demo). They create no admin/production credentials. Document as demo-only; do not present the hard-coded-password pattern as a production recipe (CLAUDE.md: secrets never committed for real hosts). |
| T-150-07 | Information Disclosure / Logging | Customer/subscription PII at render | mitigate | The layout resolution is a read; the banner shows generic copy only (no payment-method details / Stripe PII). ASVS V7 — do not log customer/subscription fields during resolution. |
| T-150-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan; all modules are first-party (Accrue.*, AccrueAdmin.*, AccrueHost.*) already in the monorepo. No supply-chain surface. |
</threat_model>

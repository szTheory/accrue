<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI-derived identifiers -> GitHub and Hex state | A wrong PR number, target version, or run id can point the proof ledger at the wrong release line. |
| GitHub workflow outputs -> planning ledger | A successful workflow can still be the wrong workflow or wrong run if it is not tied back to the exact PR/version pair. |
| post-publish public surfaces -> completion claim | Tags, GitHub releases, Hex, HexDocs, and release notes can drift or update at different times. |
| core publish success -> downstream package publish success | A partial publish can leave the linked line inconsistent if recovery is not documented precisely. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-159-06 | Spoofing | `PR_NUMBER`, `TARGET_VERSION`, `RUN_ID` derivation | mitigate | Derive identifiers from the GitHub Actions event and validate them with `gh pr view`, `gh run view`, associated-PR lookup, and lockstep manifest checks before writing any success rows. |
| T-159-07 | Tampering | `159-VERIFICATION.md` live proof block | mitigate | Append a new dated block only for the exact validated identifiers; preserve the 2026-05-31 blocker rows and never rewrite them to look successful. |
| T-159-08 | Repudiation | release completion claim | mitigate | Require workflow ordering, tags, GitHub releases, Hex API truth, HexDocs availability, and host Hex smoke in the same ledger before checking REL-01 or REL-03 complete. |
| T-159-09 | Denial of Service | partial linked publish recovery | mitigate | Follow D-10 exactly: retry downstream first, use `publish-hex.yml` only as documented fallback, and record retire-forward recovery if a linked line must be abandoned. |
| T-159-10 | Information Disclosure | release logs and proof capture | mitigate | Keep only URLs, timestamps, package versions, and job conclusions in the ledger; do not copy secret-bearing workflow logs or credentials into planning artifacts. |
</threat_model>

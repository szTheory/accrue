# Phase 174 — UI Design Contract

> Visual and interaction contract for **Design-System Gap Closure & Token Completeness** (DSY-01/02/03).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Phase character note (read first).** This is *pure design-system substrate*, not new
> screens. The contract below is therefore weighted toward **(1) the `--ax-*` token taxonomy
> being added/extended** (the real "design system" artifact of this phase) and **(2) the one
> genuinely user-facing surface: the `/dev/components` variants reference (DSY-03)**. There is
> **no new billing screen, nav, or IA** here — those are Phase B+ and are explicitly out of
> scope. The "Spacing / Typography / Color" sections below document the *existing v1.50 token
> contract being extended*, not net-new visual decisions. Every change carries an anti-churn
> justification token (a literal or bypass eliminated).

## Token Taxonomy (the primary deliverable — DSY-01)

This is the heart of the phase. All values below are **locked in CONTEXT.md (D-01…D-16)** — encode
them verbatim; do not re-derive. New tokens slot into the existing `html.accrue-admin` element in
`theme.css` and follow the house comment / px-annotation style. Migration is a **1:1 literal→token
rename with ZERO value changes** unless noted.

### Line-height (unitless ratio — inherits cleanly through nested type) — `theme.css`

| Token | Value | Role | Replaces literal |
|-------|-------|------|------------------|
| `--ax-leading-tight` | `1.2` | display, headings | `line-height: 1.2` (lines 228, 234, 1190) |
| `--ax-leading-normal` | `1.4` | body, labels — **the default** | `line-height: 1.4` (lines 373, 583, 933, 986, 1266, 1295, 1363, 1394) |
| `--ax-leading-relaxed` | `1.5` | prose / long-form copy only | `line-height: 1.5` (lines 396, 847) |

> **D-09:** Keep body at `1.4`. Do NOT force `1.5` globally — `1.4` is correct for a dense admin;
> `relaxed` (1.5) is reserved for genuine reading regions (settings copy, empty-state descriptions,
> the `.ax-measure` region). WCAG 1.4.12 governs user *override* capability, not the default.

### Letter-spacing (em — scales with font-size) — `theme.css`

| Token | Value | Role | Replaces literal |
|-------|-------|------|------------------|
| `--ax-tracking-tight` | `-0.02em` | large display tightening | `letter-spacing: -0.02em` (line 2159) |
| `--ax-tracking-normal` | `0` | default | — (additive) |
| `--ax-tracking-wide` | `0.04em` | smaller uppercase labels (eyebrow) | `letter-spacing: 0.04em` (lines 389, 2221) |
| `--ax-tracking-caps` | `0.08em` | uppercase eyebrows / section labels | `letter-spacing: 0.08em` (lines 114, 260) |

> **D-10:** Keep BOTH `wide` (0.04em) and `caps` (0.08em) — two optical sizes; merging visually
> regresses one existing use.

### Reading measure (ch ≈ one "0" advance) — `theme.css` + utility in `app.css`

| Token | Value | Role |
|-------|-------|------|
| `--ax-measure` | `68ch` | max line length for prose (≈66 chars; 60–75 sweet spot) — **net-new / additive, no literal to replace** |

Consuming utility (add to `app.css`): `.ax-measure { max-width: var(--ax-measure); }`. Exact
consumption sites left to planner/executor (D-23); dense reading regions only — **not** applied
phase-wide (that is Phase C's reading-measure work, SCR-04).

### Breakpoints (documented constants block + grep-guard — **NO build change**) — `app.css`

CSS `@media` cannot read `var()`, so breakpoints live as a **commented registry block at the top of
`app.css`** plus an **inline token comment on every `@media`** so they are grep-able. (D-01/D-02.)

| Token | Value | Query form | Existing `@media` sites (app.css) |
|-------|-------|------------|-----------------------------------|
| `--ax-bp-content` | `640px` | min-width up-query | 2026, 2231 — `/* --ax-bp-content ↑ */` |
| `--ax-bp-md` | `768px` | min-width up-query | 896, 1620 — `/* --ax-bp-md ↑ */` |
| `--ax-bp-lg` | `1024px` | min-width up-query | 1246, 1637, 2036 — `/* --ax-bp-lg ↑ */` |
| `--ax-bp-sm ↓` | `599.98px` | max-width guard | 1785, 1921 — `/* --ax-bp-sm ↓ */` |
| `--ax-bp-lg ↓` | `1023.98px` | max-width guard | 1655 — `/* --ax-bp-lg ↓ */` |

> **D-03:** Mobile-first up-queries use min-width; max-width uses the existing `-0.02px` guard form.
> The `640px` value is named `--ax-bp-content` (it sits *below* 768; naming it `xl` would break
> monotonic ordering — it is an intrinsic content step, not a layout tier).
> **D-05:** Phase 174 only **names** the existing values — no layout-behavior change. The 600/640
> proximity reconciliation is deferred to Phase C.
> **D-04:** The token-bypass grep guard must flag any `min-width:`/`max-width:` literal in `app.css`
> not in the registry and not carrying an `--ax-bp-*` comment. ⚠️ The new guard needle must be added
> to **BOTH** the guard script AND its negative-test seed fixture (the `verify_package_docs ↔ test`
> coupling) — otherwise the negative tests break.
> **Note:** layout-internal sizing literals (e.g. `min-width: 0`, `max-width: 16rem`, `min-width:
> 2.75rem`) are intrinsic box constraints, NOT breakpoints — the guard targets `@media` conditions only.

### Transition bundles (property-bundles composed from existing dur/ease atoms) — `theme.css`

Exactly **4** bundles (D-13), each composed strictly from the existing `--ax-dur-*` / `--ax-ease-*`
atoms (never hardcoded ms/curves), enter-neutral on `--ax-ease-out`. **No `--ax-transition-all`**
(perf footgun). Use `background-color` (not `background` shorthand) so the skeleton shimmer's
`background-position` is never accidentally animated.

| Token | Properties | Collapses (app.css) |
|-------|-----------|---------------------|
| `--ax-transition-colors` | `color`, `background-color`, `border-color` | 59, 291 |
| `--ax-transition-transform` | `transform` | (transform legs of 270, 992, 1446, 1967) |
| `--ax-transition-shadow` | `box-shadow` | (shadow leg of 1967) |
| `--ax-transition-base` | colors + transform + shadow combo (cards/tiles) | the ~5 multi-line blocks: 270, 992, 1446, 1967, 2077 |

> **D-14:** New `--ax-transition-*` family. **Freeze** the legacy `--ax-motion-*` / `--ax-theme-transition`
> aliases as back-compat — do NOT extend them. Single-property sites already using `--ax-motion-*`
> may stay as-is; only the multi-line blocks are collapse targets.
> **D-15:** Reduced-motion override **at the token level** — inside the existing
> `@media (prefers-reduced-motion: reduce)` block (theme.css ~line 157), redefine the bundles on the
> root using `--ax-dur-instant` so every consumer gets reduced-motion correctness for free.
> **D-16:** Exit-asymmetry / deep motion semantics are **deferred to Phase D** — ship only the neutral
> substrate. Flag any intentionally-snappy transform divergence for Phase D rather than adding a 5th bundle.

## Typography

> Existing v1.50 type scale (`--ax-type-xs … --ax-type-3xl`, Geist). This phase **adds the line-height
> and letter-spacing micro-tokens** above; it does not change sizes or weights. Roles below document the
> already-shipped contract the `/dev/components` gallery and migration must honor.

| Role | Class | Size | Weight | Line height (new token) |
|------|-------|------|--------|-------------------------|
| Display | `.ax-display` / `.ax-kpi-value` | 24px (`1.5rem`, `--ax-type-xl`) | 600 | `--ax-leading-tight` (1.2) |
| Heading | `.ax-heading` / `.ax-sidebar-name` | 20px (`1.25rem`, `--ax-type-lg`) | 600 | `--ax-leading-tight` (1.2) |
| Label / Eyebrow | `.ax-label` / `.ax-eyebrow` | 14px (`0.875rem`, `--ax-type-sm`) | 600 | `--ax-leading-normal` (1.4) |
| Body | `.ax-body` | 16px (`1rem`, `--ax-type-md`) | 400/regular | `--ax-leading-relaxed` (1.5) — prose |

Weights in use: **regular (400)** + **semibold (600)** (group labels use 700 — pre-existing, untouched).
Eyebrow tracking → `--ax-tracking-wide` (0.04em); uppercase group/section labels → `--ax-tracking-caps`
(0.08em); display tightening → `--ax-tracking-tight` (-0.02em).

## Color

> Existing v1.50 semantic token contract (`theme.css`), theme-aware via `data-theme`. **No new color
> tokens this phase.** The single color *action* in Phase 174 is **DSY-02: killing the inline-hex
> bypass** in `dunning_banner.ex` (see Copywriting / Bypass section). 60/30/10 documented for the checker.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (`--accrue-paper` light / `#0f1318` dark) | page background, surfaces |
| Secondary (30%) | `--ax-elevated` / `--ax-sunken` | cards, sidebar, nav, panels |
| Accent (10%) | `--ax-accent` (+ `--ax-accent-strong` / `-subtle` / `-soft` / `-border` / `--ax-focus-ring`) | **see reserved list** |
| Destructive | `--ax-danger` / `--ax-danger-readable` / `--ax-danger-surface` / `--ax-danger-border` | dunning banner, failed/destructive states only |

Accent reserved for: **primary buttons, links, focus rings, and active-state indicators only.** Never
for decorative fills, never "all interactive elements." (Cobalt `#5D79F6` is the brand interactive
accent; Moss `#5E9E84` is the brand accent for positive/money-positive; Amber for warning/pending.)

> **Out of scope (do NOT "fix") — D (Claude's Discretion):** the runtime brand-config hex defaults
> (`accent_hex: "#5D79F6"` etc. in `*_live.ex`, `layouts.ex`, `brand_plug.ex`) and the favicon SVG hex
> are **host-overridable branding config / asset literals at the Elixir layer**, not CSS token bypasses.
> DSY-02 targets the CSS/HEEx **render path** only.

## `/dev/components` Variants Reference (the user-facing surface — DSY-03)

The one genuinely viewable artifact. **Hand-rolled LiveView gallery** extending
`accrue_admin/lib/accrue_admin/dev/component_kitchen_live.ex` — **zero new deps** (D-17). Dev-only
(guarded by `Mix.env() != :prod` + `fake_processor?/0`).

### Scope — exactly four families (D-18)

**button · badge · status · card.** The rest of the kitchen (Detail, RelatedResources, Icon, empty-state)
stays a looser sanity-check, NOT token-mapped reference rows (anti-churn: don't mirror the whole UI).

### Data source (single source of truth — D-19)

New module `AccrueAdmin.Dev.ComponentRegistry` returning rows of:
`%{family, variant, ax_class, tokens: [~w(--ax-...)]}`. The page renders from this list **and** the
drift test asserts against it — one list, two consumers.

### Row anatomy (each reference row shows three things)

| Element | What it shows |
|---------|---------------|
| **Live swatch** | the *real* component rendered (e.g. `<Button.button variant="primary">`) — not a static mock |
| **Copy-paste class** | the `ax-*` class string a maintainer pastes (`ax_class`) |
| **Token map** | a small `<dl>` listing the `--ax-*` tokens that class resolves to |

### Light/dark side-by-side (D-20)

Render **both** themes per row via `data-ax-theme="light|dark"` wrappers (theme tokens cascade from the
wrapper). **The per-theme token-resolution difference is the page's primary reference value** — a
maintainer sees how each variant resolves in both themes at a glance.

### Known variant inventory the registry must enumerate

| Family | Variants (truth lives in each component's `*_class/1` clauses — registry must mirror exactly) |
|--------|-----------------------------------------------------------------------------------------------|
| button | `primary`, `secondary`, `ghost` (`AccrueAdmin.Components.Button`) |
| badge / status | `paid`, `past_due`, `failed`, `active` (and the full `StatusBadge.status_badge` status set) |
| card | KPI card tones (`moss`, `amber`, …) + base `.ax-card` (`AccrueAdmin.Components.KpiCard` / `.ax-card`) |

> Executor: enumerate the *actual* variant set from each component at implementation time — the table
> above is the known floor, not a cap. Adding a variant without a registry entry must fail CI (D-21).

### Drift-prevention test (D-21)

`ComponentRegistryTest` that **(a)** renders the page and asserts every registry variant appears, and
**(b)** asserts the registry's `ax_class` set exactly matches each component's known class outputs — so
adding a 5th variant without a registry entry fails CI.

### Screenshot-ready (D-22 — built now, wired in Phase F)

Build the page so a single screenshot per theme regresses the entire button/badge/status/card token
surface. `/dev/components` is added to `e2e/admin-visuals.spec.js` as a cheap anchor shot across
{light, dark} (mobile not needed for this page) — **the wiring itself lands in Phase F**; build it
screenshot-ready now.

### Page layout

Reuse the existing kitchen scaffold: `AppShell` → `.ax-page` → `.ax-page-header` (breadcrumbs +
`.ax-eyebrow` "Shared primitives" + `.ax-display` heading). Reference rows live in `.ax-card`
sections, one family per section, rows stacked at `--ax-space-lg` gaps, composed entirely from
existing tokens. No new layout primitives.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request to /charges or /charges/:id | User-controlled :id path segment flows into redirect URL |
| Redirect target construction | mount_path derived from request_path; must not accept user-controlled input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-175-03-01 | Elevation of Privilege | /charges redirect bypasses live_session auth | mitigate | Redirect only sends 302; destination /payments is inside live_session which runs AuthHook. No auth state is granted by the redirect itself. |
| T-175-03-02 | Tampering | Open redirect via :id path segment | mitigate | URI.encode/1 applied to id before interpolation in redirect URL; mount_path derived from request_path not from user params; redirect target is always {mount_path}/payments/{id} — fixed prefix, no user-controlled domain |
| T-175-03-03 | Spoofing | Sidebar collapse aria-expanded mismatch between server and client | accept | Server renders initial state from badge count; JS hook overrides from localStorage on mount. No security consequence — purely UI state |
| T-175-03-SC | Tampering | No new npm/pip/cargo installs | accept | No new packages in this plan |
</threat_model>

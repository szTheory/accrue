# Phase 175 — UI Design Contract

> Visual and interaction contract for the **Persona-Driven IA Spine** depth pass. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is NOT a greenfield UI.** It is a depth pass on the already-shipped `accrue_admin` v1.50 admin. The design system is LOCKED: custom `ax-*` BEM-adjacent CSS + tokens in `accrue_admin/assets/css/theme.css` (+ class definitions in `app.css`), Geist sans/mono variable fonts with tabular numerals. **Tailwind is configured but inert — do NOT migrate.** Every visual decision below names an existing `ax-*` token. Genuine token gaps are flagged explicitly in [Token Gaps](#token-gaps) rather than resolved with literals.
>
> **Scope:** IA-spine contracts only (nav tiering + badges, work-queue defaults, Customer-360 tab tiering, bidirectional threading incl. Webhook→Event→entity, visible search, compliance actor-lens). **Out of scope:** new billing primitives, per-screen rubric uplift (Phase C/176), motion work (Phase D/177). Satisfies IA-01 through IA-07.

## Spacing Scale

The phase **reuses** the existing 4px-base `--ax-space-*` scale verbatim. No new spacing values are introduced. Every new gap/padding below MUST name one of these tokens.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| `--ax-space-2xs` | 2px | (existing — dense tables only; not used by new IA chrome) |
| `--ax-space-xs` | 4px | Icon/label gaps in nav links, badge internal gap, related-card icon gap |
| `--ax-space-sm` | 8px | Sidebar link padding gap, collapsible group internal gap, chip-to-chip gap, More-menu item gap |
| `--ax-space-md` | 16px | Nav-link/launcher default spacing, related-card list gap, search-field internal gap |
| `--ax-space-lg` | 24px | Sidebar nav-group separation (`.ax-sidebar-nav` gap — already set), card padding |
| `--ax-space-xl` | 32px | Layout-level gaps (unchanged) |
| `--ax-space-2xl` | 48px | Major section breaks (unchanged) |
| `--ax-space-3xl` | 64px | Page-level rhythm (unchanged) |

**Exceptions:** none. New IA chrome must not introduce literal px/rem spacing. The recessed-zone indentation, the collapsed/expanded group spacing, and the "More ▾" menu padding all resolve from the tokens above. Existing intentional non-token spacing (e.g. `.ax-sidebar-link` `padding: 0.5rem 0.625rem`, `.ax-tab` `padding: 0.75rem 1rem`) is pre-existing v1.50 surface and is **not** re-opened here (anti-churn).

## Typography

The phase **reuses** the existing `--ax-type-*` scale, `--ax-leading-*` line-heights, and `--ax-tracking-*` letter-spacing. No new type steps. New IA text maps to these established roles:

| Role | Size token | Weight | Line-height token | Applied to (this phase) |
|------|-----------|--------|-------------------|--------------------------|
| Group eyebrow / specialist-zone label | `--ax-type-xs` (12px) | 700 | (uppercase, no leading override needed) + `letter-spacing: var(--ax-tracking-caps)`, `text-transform: uppercase` | Recessed specialist-zone collapsible group headers (matches existing `.ax-sidebar-group-label`). The **primary Billing** group label uses the same step but is visually heavier by *color/weight contrast* (see Color), not a new size. |
| Nav link label / tab label | `--ax-type-sm` (14px) | 600 | `--ax-leading-normal` (1.4) | Sidebar link labels, Customer-360 tab labels, "More ▾" trigger + menu items (matches existing `.ax-sidebar-link-label`, `.ax-tab`) |
| Badge / attention count | `--ax-type-sm` (14px) — see gap note | 700 | `--ax-leading-tight` (1.2) | Attention-count badges on Recovery / Developer / Catalog group headers; tab counts (existing `.ax-tab-count`) |
| Body / search placeholder | `--ax-type-md` (16px) | 400 | `--ax-leading-relaxed` (1.5) | Visible search-field input text + placeholder, related-card values |
| Related-card title | `--ax-type-sm` (14px) | 600 | `--ax-leading-normal` (1.4) | `.ax-related-title` (existing) |

**Weights in play:** exactly two — **regular 400** (body, search input) and **semibold 600** (labels, nav, tabs), with **700** reserved as it is today for eyebrows/badges/group-labels (pre-existing v1.50 convention — not introduced here). Letter-spacing only via `--ax-tracking-caps` (uppercase group labels) and `--ax-tracking-wide` (eyebrows); no literal `em` values.

## Color

The phase **reuses** the semantic `--ax-*` palette. No new hues. The 60/30/10 split maps to the existing surface/chrome/accent token roles:

| Role | Token(s) | Usage in this phase |
|------|----------|---------------------|
| Dominant (~60%) | `--ax-base` (page), `--ax-elevated` (cards/sidebar surface) | Page + sidebar + card backgrounds. The recessed specialist zones share the **same** sidebar surface — recession is achieved by *de-emphasizing text*, not a different background fill. |
| Secondary (~30%) | `--ax-muted`, `--ax-subtle`, `--ax-border` | Recessed-zone text + chevrons (`--ax-muted`); group labels (`--ax-muted`); borders (`--ax-border`). The visual "weight" gradient between primary Billing and recessed zones is carried by `--ax-primary` (Billing labels) vs `--ax-muted` (specialist labels). |
| Accent (~10%) | `--ax-accent`, `--ax-accent-readable`, `--ax-accent-subtle`, `--ax-accent-border`, `--ax-focus-ring` | See reserved list below. |
| Semantic — attention badges | `--ax-warning` / `--ax-warning-readable` (Recovery: at-risk), `--ax-danger` / `--ax-danger-readable` (Developer: dead-letter) | Attention-count badges are **status-colored, never accent-colored**, so a count reads as "work needing attention" not "selected." Catalog badge (if ever non-zero) uses the neutral accent badge style. |
| Destructive | `--ax-danger`, `--ax-danger-readable` | No new destructive actions in this phase. Existing destructive flows (e.g. payment-method delete in `customer_live`) are unchanged. |

**Accent reserved for (explicit — never "all interactive elements"):**
1. Active sidebar nav link pill (`.ax-sidebar-link-active` — existing `--ax-accent` 12% surface + `--ax-accent-border`).
2. Active Customer-360 tab underline (`.ax-tab-active` `border-bottom-color: var(--ax-accent)` — existing).
3. Focus rings on the new search field, the collapsible group toggle, the "More ▾" trigger, and chips (`--ax-focus-ring` — existing pattern).
4. Active filter chip + "All"-chip active state (chip `cobalt` tone is the accent-family default in `filter_chip_bar`).
5. Launcher icon tiles + hover border on Home (`--ax-accent-subtle` / `--ax-accent-border` — existing `.ax-launcher`).

**Accent is NOT used for:** attention-count badges (status colors), recessed-zone chrome, related-card chrome, or resting nav links. This keeps "blue = where you are / where focus is," "amber/red = work waiting."

**Color-only status guard (rubric ⑥):** the Recovery (amber) and Developer (red) badges MUST pair the color with a count number and an accessible label (e.g. `aria-label="3 webhooks need attention"`), so status is never conveyed by hue alone.

## Component & Interaction Contracts

This section is the IA-spine heart. Each contract names the component file, the existing classes/tokens it extends, the affordance, the states, and the a11y requirement. **All new classes follow the `ax-*` convention and resolve every value from tokens above.**

### 1. Recessed specialist zones + collapsible group headers (IA-02)
*Files: `nav.ex`, `components/sidebar.ex`, `app.css`. Justification token: persona-job — specialist personas (Recovery/Developer/Compliance) drown in a flat 5-equal-group sidebar.*

- **Primary Billing zone:** always-expanded, **not** collapsible, no chevron. Group label uses `.ax-sidebar-group-label` but its links read at full `--ax-primary` weight. This is the visual "anchor."
- **Specialist zones (Recovery · Developer · Catalog):** render the group label as a **collapsible toggle** — a `<button>` carrying the existing `.ax-sidebar-group-label` styling (`--ax-type-xs`, 700, `--ax-tracking-caps`, uppercase, `--ax-muted`) plus a leading/trailing **chevron** (`Icon.icon name={:chevron_right}` rotating to down on expand; reuse `.ax-related-chevron` rotation pattern or a new `.ax-sidebar-group-chevron`). Recessed feel = `--ax-muted` label + smaller chevron at `--ax-icon-sm`.
- **Connect:** stands alone — a single ungrouped leaf (group label optional/absent), no collapse.
- **Indentation:** recessed-zone links indent by `--ax-space-sm` relative to Billing links (token, not literal).
- **Collapse affordance:** chevron rotates via `--ax-transition-transform`; collapse height change has **no motion contract in this phase** (motion is Phase D) — instant show/hide is acceptable, executor must not add bespoke easing.
- **Default collapse state:** auto-**expand when the zone's badge count > 0, collapse when 0**; persist manual user toggle in `localStorage` (key naming + JS hook is planner/executor discretion per CONTEXT.md).
- **States:** expanded / collapsed / (zone has work → expanded + badge) / (zone empty → collapsed, no badge).
- **A11y:** toggle is a real `<button>` with `aria-expanded`, `aria-controls` pointing at the link list; the link list region is keyboard reachable; focus-visible uses `--ax-focus-ring`.

### 2. Attention-count badges on group headers (IA-02)
*Files: `nav.ex` (add badge field), `sidebar.ex` (render), shared context fn for counts, `app.css`. Justification token: persona-job — "quiet rooms that light up only when they have work."*

- **Visual:** a pill badge on the collapsible group header, right-aligned. Base shape = the existing `.ax-badge` (`--ax-radius-pill`, `--ax-type-sm`/700, `min-height: 1.75rem`, `--ax-space-xs` gap). **Override the accent fill with status fills:**
  - Recovery (at-risk / past-due): background `color-mix(in srgb, var(--ax-warning) 12%, var(--ax-elevated))`, text `--ax-warning-readable`.
  - Developer (dead-letter webhooks): background `color-mix(in srgb, var(--ax-danger) 12%, var(--ax-elevated))`, text `--ax-danger-readable`.
  - Catalog: neutral — default `.ax-badge` accent style (rarely non-zero).
  - *(The `12%` mix step matches the existing accent-badge/`--ax-accent-subtle` convention; if executor prefers, `--ax-danger-surface` already exists for the danger case — see Token Gaps for the missing warning surface token.)*
- **Render rule:** badge renders **only when count > 0** (mirrors `related_resources` "renders nothing when empty"). Zero = no badge, zone collapsed.
- **Data source:** reuse existing dashboard attention queries via a shared context fn computed in `on_mount`/sidebar assigns — **no parallel count queries, no polling/PubSub** (compute once per navigation).
- **A11y:** badge has an `aria-label` describing the count + meaning (e.g. `"2 at-risk subscriptions"`); the bare number is not the only signal.

### 3. Work-queue default + "All" escape-hatch chip (IA-03, IA-07)
*Files: list LiveViews (invoices/subscriptions/charges→payments/customers/events), `filter_chip_bar.ex` (reuse), `router.ex`. Justification token: persona-job — Finance Ops needs a queue, not a raw list.*

- **Default queue filters (apply in LiveView + `push_patch` so URL shows `?status=…`, shareable/bookmarkable):**
  - Invoices → `open + uncollectible`
  - Subscriptions → `past_due + canceling (at-risk)`
  - Payments → `failed`
  - Customers → `all` (Support lookup tool — no queue)
- **"All" chip:** a persistent chip in the existing `filter_chip_bar`. Its active/inactive state uses the existing chip tones — **default persona-queue chips use `cobalt`** (accent family = "this is the active queue"); the **"All" chip uses `slate`** (neutral escape hatch). Clicking "All" clears the persona-queue filter (one click). Use the chip's existing `remove_href`/`active` API — no new chip variant required.
- **Mechanism guard:** do NOT use a hard HTTP redirect for the default filter; do NOT leave the URL unchanged. `push_patch` with the status param is the contract.
- **States:** default-queue active (queue chip cobalt-active, "All" inactive) / All view (queue chip cleared, "All" slate-active) / empty queue (see Copywriting empty states).

### 4. Customer-360 primary tabs + "More ▾" overflow (IA-05)
*Files: `customer_live.ex`, `components/tabs.ex` (extend), `app.css`. Justification token: persona-job — Support needs the three everyday tabs prominent, advanced tabs out of the way; rubric ② visual hierarchy.*

- **Primary visible tabs:** Subscriptions · Invoices · **Payments** (the `charges` tab relabels to "Payments" to match the new route/label). Use existing `.ax-tab` / `.ax-tab-active` / `.ax-tab-count`.
- **"More ▾" overflow:** a trigger at the **end** of the tab strip styled as an `.ax-tab` (same 14px/600, `--ax-leading-normal`) with a trailing chevron-down. Opens a dropdown menu listing the recessed tabs: **Payment methods · Entitlements · Events · Metadata**, each with its existing per-tab count.
- **Menu surface:** `--ax-elevated` background, `--ax-border` 1px, `--ax-radius-md`, `--ax-shadow-md`, `z-index: var(--ax-z-popover)`. Menu item = `--ax-type-sm`/600, `--ax-muted` resting → `--ax-primary` hover, padding via `--ax-space-sm`. When a recessed tab is the active tab, the "More ▾" trigger reflects active state (`.ax-tab-active` underline) so the user isn't lost.
- **Mobile (@360px):** the "More ▾" grouping keeps the primary three on one row; overflow tabs live in the menu (mobile-friendly by design — this is *why* the dropdown was chosen over a wrapping strip).
- **A11y:** trigger is a `<button aria-haspopup="menu" aria-expanded>`; menu items are links/`menuitem`s; Esc closes; focus returns to trigger. Active recessed tab announced via `aria-current` on the menu item.
- **No motion contract** (Phase D) — open/close may be instant; no bespoke easing.

### 5. Bidirectional Related-billing card on all 8 detail screens (IA-04)
*Files: `related_resources.ex` (reuse as-is), 8 detail LiveViews, lightweight `/events/:id`. Justification token: persona-job — no detail page dead-ends; Developer incident path (Webhook→Event→entity) is the weakest thread.*

- **Component contract:** use `related_resources.ex` **unchanged** — `%{icon:, label:, href:, value: (optional)}` items; the card renders nothing when items are `[]`. All chrome (`.ax-related`, `.ax-related-item`, `.ax-related-icon`, `.ax-related-chevron`) already resolves from tokens; **no CSS change needed**.
- **Coverage (all 8 — each MUST render a non-empty card where relationships exist):** customer, subscription, invoice, charge (payment), coupon, promotion_code, connect_account, webhook.
- **Webhook → Event → entity thread (the priority gap):**
  - Webhook detail: Related card links to the **Event(s)** it produced (`label: "Event"`, `value:` event type/id, `href:` `/events/:id`).
  - Add a lightweight **`/events/:id`** destination (full LiveView or focus drawer reusing `detail_drawer.ex` — planner's call) so the event row has a navigable target; from there a Related card links onward to the **affected entity** (customer/subscription/invoice).
  - Thread must be **bidirectional**: the affected entity (or its detail) links back toward its events where relevant.
- **Icon vocabulary:** reuse existing `Icon` names (`:users`, `:invoices`, `:subscriptions`, `:payments`, `:webhooks`, `:events`, `:coupons`, `:promotions`, `:connect`).
- **Empty-state behavior:** if a detail genuinely has zero relationships, the card is omitted (existing `:if={@items != []}`) — that is not a "dead end" because every entity in practice has at least a customer link.

### 6. Visible labeled global-search field (IA-01)
*Files: `dashboard_live.ex` (Home field), topbar layout, `global_search.ex`. Justification token: persona-job — Support's primary entry is currently hidden behind a ⌘K hotkey.*

- **Topbar:** surface `global_search` as a **visible labeled input**, not just the icon trigger. Reuse the existing `.ax-search-trigger` chrome family (pill, `--ax-radius-pill`, `--ax-elevated`, `--ax-border`, `--ax-type-sm`) **or** an `.ax-input`-based field — but it must read as a real search field with visible placeholder text. Placeholder copy: **"Search customers, invoices… ⌘K"** (the ⌘K hint stays; hotkey still works).
- **Home:** render a **prominent** search field in the Home hero/search zone (larger target than the topbar pill) using `.ax-input` (`min-height: 2.75rem`, `--ax-radius-md`) with a leading `:search` icon at `--ax-icon-md` and the same placeholder.
- **Focus:** `--ax-focus-ring` on focus-visible (existing pattern).
- **A11y:** the field has an associated visible/`aria-label` ("Search"); the ⌘K affordance is supplementary, not the only path. Mobile: field is full-width and tappable (no hotkey dependency).
- **Anti-churn:** this is the *only* Home change besides the verb relabels (§7). The attention rail, KPI strip, and recent-activity zones stay **frozen**.

### 7. Home verb-relabeled task launchers (IA-01)
*Files: `dashboard_live.ex`, `Copy` module. Justification token: persona-job — launchers must name the job by verb. (Design-mandated exact strings.)*

- Apply the **exact** design strings to the four `.ax-launcher` titles (CSS unchanged):
  - "Look up a customer" (→ `/customers`)
  - "Clear the invoice queue" (→ `/invoices?status=open`)
  - "Recover at-risk revenue" (→ Recovery)
  - "Investigate an incident" (→ Webhooks)
- Launcher chrome (`.ax-launcher`, `.ax-launcher-icon`, `.ax-launcher-title`, `.ax-launcher-copy`) is unchanged — text-only edit via `Copy`.

### 8. Compliance actor-lens chip on `/events` (IA-07)
*Files: events LiveView, `filter_chip_bar.ex` (reuse). Justification token: persona-job — Compliance ("who did what, when?") is rare → a saved lens, not a nav group.*

- **Affordance:** a labeled quick-filter chip **"By actor"** surfaced in the existing `filter_chip_bar` on `/events`, using the existing filter/URL-param mechanism — **not** a new nav group, **not** new chip CSS.
- **Tone:** `slate` (neutral lens) when inactive; `cobalt` when an actor filter is applied (consistent with §3's active-queue convention).
- **Behavior:** activating the lens applies an actor filter (URL-param synced, shareable); clearing returns to the full ledger. No new visual primitives — chip reuse only.

### Route reshaping with redirects (IA-06)
*File: `router.ex`. Justification token: no-breaking-changes guardrail.*

- Add `/payments` → existing `ChargesLive`/`ChargeLive`; **redirect** `/charges` → `/payments` and `/charges/:id` → `/payments/:id`. Relabel nav leaf + Customer-360 tab "Payments." Existing bookmarks survive. (No visual contract — listed here so the checker knows the "Payments" relabel is intentional and consistent across nav, tab, and route.)

## Token Gaps

Where a needed value has **no existing token**, it is flagged here rather than hardcoded. Planner/executor must either compose from existing atoms (preferred) or add a token in `theme.css` (and note it as a Phase-A-style addition).

| Need | Status | Recommendation |
|------|--------|----------------|
| **Warning surface + border tokens** (for the Recovery amber badge fill) | GAP — only `--ax-danger-surface` / `--ax-danger-border` exist; there is no `--ax-warning-surface` / `--ax-warning-border` | Either compose inline via `color-mix(in srgb, var(--ax-warning) 12%, var(--ax-elevated))` (matches the existing accent-subtle 12% convention, no new token) **or** add `--ax-warning-surface` / `--ax-warning-border` mirroring the danger pair. Composing from `--ax-warning` is token-compliant (rubric ①) since it references a token, not a literal — **preferred**. |
| **Sidebar group chevron rotation class** | minor GAP — `.ax-related-chevron` exists for related cards but not a sidebar-group variant | Add `.ax-sidebar-group-chevron` reusing `--ax-transition-transform` + a `rotate` on `[aria-expanded="true"]`. No new token needed (transform bundle exists). |
| **Status-toned badge variants** (`.ax-badge` is accent-only today) | minor GAP — `.ax-badge` hardcodes the accent mix | Add `.ax-badge-warning` / `.ax-badge-danger` modifiers composing from `--ax-warning`/`--ax-danger` + their `-readable` tokens. Fully token-sourced. |
| **"More ▾" dropdown menu surface class** | GAP — no existing tab-overflow menu | Add `.ax-tab-more-menu` (+ items) composing `--ax-elevated`, `--ax-border`, `--ax-radius-md`, `--ax-shadow-md`, `--ax-z-popover`, `--ax-space-sm`. All tokens exist — no literals. |

**No literal hex or px is permitted in any new rule.** Every gap above resolves from existing token atoms via `color-mix`/`var()`. If a brand-new raw value were ever required it would be a Phase-A token-system change, which is out of scope here — escalate rather than inline.

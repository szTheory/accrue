# Phase 176 — UI Design Contract

> Visual and interaction contract for the systematic per-screen rubric uplift. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a RUBRIC-BASELINE CONTRACT, not a component spec.** Phase 176 adds NO new components and NO new screens. It brings every *existing* admin screen to a uniform ≥2 baseline on all 10 rubric dimensions, in light+dark × desktop+mobile@360px. The design system is **LOCKED** (custom `ax-*` tokens; Tailwind inert; no migration). Everything below is expressed in existing `ax-*` tokens. Genuinely-missing tokens are flagged explicitly in [§ Token Gap Flags](#token-gap-flags) — do **not** invent literals to fill them.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom `ax-*` BEM-adjacent CSS + CSS custom-property tokens) |
| Preset | not applicable — Elixir/Phoenix LiveView, **not** React/Next/Vite, so shadcn gate is N/A |
| Component library | Phoenix.Component + `accrue_admin` shared primitives (`data_table`, `detail` [`detail_section`/`detail_field_list`/`summary_card`], `detail_drawer`, `related_resources`, `json_viewer`, `status_badge`, `kpi_card`, `button`, `tabs`, `filter_chip_bar`) |

**Anti-churn rule (binding on every change this phase):** each edit must cite one justification token — (a) a rubric dimension below bar with a recorded before-score in `176-SCORECARD.md`, (b) a named persona-job miss, or (c) a concrete token bypass eliminated. "Looks nicer / my taste" is inadmissible. Frozen screens (Home/`dashboard_live`, primary nav/`sidebar`+`nav`, global search) and the v1.50-heavily-iterated screens (Customer-360, dashboard) are touched **only on a rubric-flagged miss**.

## Spacing Scale

Declared tokens (all defined in `theme.css`; all multiples of 4 except the intentional 2px dense rung):

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-2xs` | 2px | Dense-table inner gaps, field label→value gap, focus outline-offset (`:focus-visible`) — the one sub-4 exception |
| `--ax-space-xs` | 4px | Icon gaps, inline padding, empty-state row gaps |
| `--ax-space-sm` | 8px | Compact element spacing, chip gaps, card-field gaps |
| `--ax-space-md` | 16px | Default element spacing, card-list gap, field-list gap |
| `--ax-space-lg` | 24px | Card padding (`.ax-card`), section padding |
| `--ax-space-xl` | 32px | Page-level stack gap (`.ax-page`, `.ax-stack-xl`) |
| `--ax-space-2xl` | 48px | Empty-state vertical padding, major section breaks |
| `--ax-space-3xl` | 64px | Page-level / layout rung |

**Spacing-rhythm baseline (rubric ③ ≥2):** every margin/padding/gap touched during uplift resolves to a `--ax-space-*` token. Zero literal `px`/`rem` spacing introduced. Residual literals found in a touched screen (e.g. the `0.25rem 0.625rem` in `.ax-help-link`) are converted to tokens as part of the dimension-① fold-in only when that screen is in scope — do not chase out-of-scope literals.

Exceptions: the 2px `--ax-space-2xs` dense rung is intentional and token-named, not a violation.

## Typography

Type scale (`theme.css`), line-height and tracking micro-tokens (Phase 174):

| Role | Size token | Value | Weight | Line-height token | Tracking token |
|------|-----------|-------|--------|-------------------|----------------|
| Display (hero numbers) | `--ax-type-3xl` | 36px (2.25rem) | 600 | `--ax-leading-tight` (1.2) | `--ax-tracking-tight` (-0.02em) |
| Heading | `--ax-type-lg` / `--ax-type-xl` | 20px / 24px | 600 | `--ax-leading-tight` (1.2) | `--ax-tracking-normal` (0) |
| Body | `--ax-type-md` | 16px (1rem) | 400 | `--ax-leading-normal` (1.4) default; `--ax-leading-relaxed` (1.5) on prose | `--ax-tracking-normal` (0) |
| Label / eyebrow | `--ax-type-xs` / `--ax-type-sm` | 12px / 14px | 600/700 | `--ax-leading-normal` (1.4) | `--ax-tracking-wide` (0.04em) on labels; `--ax-tracking-caps` (0.08em) on uppercase eyebrows |

**Weights:** 400 (regular body) + 600 (semibold headings/labels); 700 reserved for eyebrow/chip uppercase emphasis. Do not introduce new weights.

**Typography baseline (rubric ⑧/④ ≥2):** any prose/long-form region touched this phase uses `--ax-leading-relaxed` (1.5); data tables, KPI grids, and field-lists keep `--ax-leading-normal` (1.4). Tabular figures are inherited globally — do not override.

## Color

The 60/30/10 split maps onto the surface-layer tokens (theme-aware: every value below auto-adapts in `[data-theme="dark"]` and system-dark via `theme.css`):

| Role | Token | Usage |
|------|-------|-------|
| Dominant (≈60%) | `--ax-base` | Page canvas / app background |
| Secondary (≈30%) | `--ax-elevated` (cards/panels), `--ax-sunken` (recessed wells, table-row hover) | Cards, sidebar, drawers, data-table shell |
| Accent (≈10%) | `--ax-accent` family (`--ax-accent-strong` for filled controls, `--ax-accent-subtle`/`-soft`/`-border` for tints, `--ax-accent-readable` for accent text on tint) | **Reserved-for list below only** |
| Destructive | `--ax-danger`, `--ax-danger-readable` (text), `--ax-danger-surface`/`--ax-danger-border` (dunning banner) | Destructive actions + dunning/failure surfaces only |

**Accent reserved for (exhaustive):** primary buttons (`.ax-button-primary`, filled via `--ax-accent-strong`), the active/selected state (active tab `aria-current`, active filter chip, active nav leaf), links (`.ax-link` via `--ax-accent-readable`), and the `:focus-visible` ring (`--ax-focus-ring`). Accent is **never** used for plain body text, decorative borders, or "all interactive elements."

**Other semantic hues (status only, never decorative):** `--ax-success`/`-readable`, `--ax-warning`/`-readable`, `--ax-info`/`-readable` (distinct calm teal-blue — must not read as accent), and the money-state intents `--ax-money-positive`/`-negative`/`-pending`.

**Contrast baseline (rubric ⑥ ≥2 — verified in BOTH themes):**
- Text on a tinted/colored surface uses the `-readable` variant of that hue (`--ax-success-readable` on success tints, `--ax-danger-readable` on danger surfaces, `--ax-accent-readable` on accent tints, `--ax-info-readable` on info tints). Never place a base hue token as text on its own tint.
- **Status is never conveyed by color alone.** Every status/state carries a text label or icon in addition to color (e.g. `status_badge` shows text; money sign shows +/− or a label, not just red/green). This is a hard rubric-⑥ gate.
- Target APCA Lc ≥ 60 for body text / ≥ 45 for large text (AA-equivalent), checked in light AND dark. Dark surfaces avoid pure black (`--ax-base` dark = `#0f1318`, layered `--ax-elevated`/`--ax-sunken`) — do not collapse the elevation layers.

## Responsive / Mobile-First Contract (rubric ⑤ — the core of this phase)

Breakpoint tokens (Phase 174; CSS `@media` cannot read `var()`, so values live in the **AX BREAKPOINT REGISTRY** comment block at the top of `app.css` and every `@media` MUST carry its grep-able token comment — no bare-literal `@media`):

| Token | Value | Role |
|-------|-------|------|
| `--ax-bp-sm` ↓ | 599.98px (max-width guard) | Phone — hide non-essential chrome (search-trigger text, attention pill) |
| `--ax-bp-content` ↑ | 640px (min-width) | **Intrinsic content step** — field-list/launcher 1→2 col. NOT a layout tier. |
| `--ax-bp-md` ↑ | 768px (min-width) | Tablet — detail grids (`.ax-grid-2`/`-3`) promote multi-column; KPI 3-up; drawer side-anchors |
| `--ax-bp-lg` ↑ | 1024px (min-width) / 1023.98px ↓ | Desktop — sidebar shows; shell becomes 2-col; **(currently)** data-table card→table swap |

### Breakpoint behavior contract (what triggers what)

| Layout primitive | Mobile (≤ trigger) | Desktop (≥ trigger) | Trigger token | Status |
|------------------|--------------------|--------------------|---------------|--------|
| `data_table` table ↔ card-collapse (`.ax-data-table-shell` ↔ `.ax-data-table-cards`) | card list | table | **see reconciliation ↓** | wired (CSS exists), breakpoint under review |
| Detail multi-column (`.ax-grid-2`, `.ax-grid-3`) | single column (1fr) | 2/3 col | `--ax-bp-md` (768px) | correct — reuse as-is |
| Field list (`.ax-field-list`) | single column | 2 col | `--ax-bp-content` (640px) | correct — reuse as-is |
| KPI grid (`.ax-kpi-grid`, `.ax-kpi-grid-4`) | 1 col | 3/4 col | `--ax-bp-md` / `--ax-bp-content`+`--ax-bp-lg` | correct — reuse as-is |
| Shell + sidebar | overlay drawer (`.ax-shell-nav-open`) | persistent 15rem rail | `--ax-bp-lg` (1024px) | frozen — touch only on flagged miss |
| Detail drawer | full-width sheet | right-anchored 42rem panel | `--ax-bp-md` (768px) | correct — reuse as-is |

**Mobile-first uplift rule for list screens:** all nine list screens **already set `card_fields`/`card_title`** (audited — none missing). So the list-screen work is NOT wiring new collapse; it is (a) confirming each screen's `card_fields` selection surfaces the operator's decision-critical columns (not all columns) in the card, (b) confirming `card_title` is the human-meaningful identifier, and (c) the breakpoint reconciliation below. Do **not** build a new mobile layout — extend the existing `data_table` contract only.

**Mobile-first uplift rule for detail screens:** stack multi-column detail layouts to a single column below `--ax-bp-md` using the existing `.ax-grid-2`/`.ax-grid-3`/`.ax-stack-*` utilities (which already do this) + `.ax-field-list` (already 1-col below 640px). The executor's job is to ensure dense detail screens actually *use* these grid utilities rather than any ad-hoc layout, and that tap targets and overflow are usable @360px (min interactive height ≥ 2.75rem, already the `.ax-input-search` baseline; no horizontal scroll).

### 600/640 breakpoint reconciliation (Phase 174 D-05 deferred to here — DECIDE from usage sites)

Current state: `--ax-bp-sm ↓` (599.98px) is used only to *hide non-essential chrome* (search-trigger text @1903, attention pill @2076); `--ax-bp-content ↑` (640px) is the *content-promotion* step (field-list/launcher/KPI 1→2col). These serve **different intents** (chrome-hiding vs content-reflow), so they are not a true duplicate.

**Contract decision:** **Document, do not collapse.** Keep both rungs because they express distinct intents (a max-width chrome-hide guard vs a min-width content-promotion step) that happen to sit ~40px apart. The planner records this rationale in `176-SCORECARD.md`. The executor must NOT merge `599.98`→`639.98` or `640`→`600`. If, during the per-screen audit, a screen exhibits a visible reflow seam in the 600–640 gap @360px→wider, that single screen is fixed by moving its rule onto the `--ax-bp-content` step — the registry rungs themselves stay as-is.

### data-table collapse-breakpoint reconciliation (CONTEXT decision vs current CSS)

**Discrepancy flagged:** `176-CONTEXT.md` decides list tables "collapse to cards below `--ax-bp-md`" (768px). Current CSS (`app.css` `.ax-data-table-shell`/`.ax-data-table-cards` @1352–1369) swaps at `--ax-bp-lg` (1024px) — tables show only ≥1024px, cards show below. This means on 768–1023px tablets, users currently get cards where the CONTEXT intends a table.

**Contract decision (executor must apply):** move the data-table table↔card swap from `--ax-bp-lg` (1024px) to `--ax-bp-md` (768px), so tables render at ≥768px and cards below 768px — matching the locked CONTEXT decision and the rest of the detail-grid promotion tier. Update the `@media (min-width: 1024px) /* --ax-bp-lg ↑ */` block governing `.ax-data-table-shell`/`.ax-data-table-cards` to `@media (min-width: 768px) /* --ax-bp-md ↑ */` (keep the grep-able token comment). Re-verify no horizontal overflow at 768px for the widest table (invoices/charges). This is a token-driven change (no literal px outside the registry-documented value), justified by SCR-02 + the CONTEXT decision.

### @360px verification (code-level only; visual proof is Phase 179)

Add cheap structural assertions where they exist (no horizontal scroll, card layout active at mobile width) — the full *visual* @360 sweep is Phase 179. Verify via the existing harness: `cd accrue_admin && npm run e2e:visuals:png-only` (spot checks) and keep `admin-a11y.spec.js` (`verify01-admin-a11y/mobile`) green.

## Reading-Measure Contract (rubric ① + readability; SCR-04)

`--ax-measure` (68ch ≈ 66 chars, the 60–75 sweet spot) and the `.ax-measure` utility (`max-width: var(--ax-measure)`, `app.css:406`) exist but are **applied to NO screen yet**. This phase applies them.

**Application rule — REGION-LEVEL, dense prose ONLY (never whole-page):**

| Apply `.ax-measure` to | Do NOT apply to |
|------------------------|-----------------|
| Settings / configuration descriptions | Data tables (`data_table`) |
| Empty-state body copy (`.ax-empty-copy` already caps at 28rem — leave it) | KPI grids / KPI cards |
| Event / webhook JSON payload **explanatory prose** (the description around `json_viewer`, not the JSON tree itself) | Field lists (`.ax-field-list`) — they are columnar, not prose |
| Invoice / charge detail long-form prose / notes | Summary cards / status rows |
| Metadata-viewer prose descriptions | Anything full-bleed by design |

Wrap the prose/description block (e.g. a `<p class="ax-body ax-measure">…`), never the page container. The JSON tree/raw output inside `json_viewer` stays full-width (it is data, not prose). `.ax-empty-copy`'s existing 28rem cap is intentional and stays — do not double-cap.

## Token-Compliance Fold-In (rubric ① ≥2)

Dimension ① is folded into the per-screen uplift, not run as a separate pass. While a screen is in scope:
- Resolve any residual literal hex/px/em **in CSS/styling** to an `ax-*` token. (Audit confirms the CSS layer is already clean.)
- **Not a violation:** the `accent_hex: "#5D79F6"` / `accent_contrast_hex: "#FAFBFC"` literals in `*_live.ex` are **domain branding-config seed data** (the app's configurable brand color), not CSS bypasses. Leave them. Do not "tokenize" data.
- No inline `style=` attributes introduced; no bare-literal `@media` (every `@media` carries its `--ax-bp-*` token comment).

## Focus & Semantics Baseline (rubric ⑦ ≥2)

- Every interactive element has a visible `:focus-visible` treatment via `--ax-focus-ring` (existing pattern: border-color swap for inputs/buttons/links; 2px outline + `--ax-space-2xs` offset for nav toggles/tab-more items). Touched screens must not strip this.
- Tables use `<th scope="col">`, captions via `.ax-visually-hidden` (`@table_caption`), `<dl>/<dt>/<dd>` for field lists and card fields. Sections that are landmarks carry `aria-label` (e.g. `related_resources`, `json_viewer`). Active tab carries `aria-current="page"`; toggle buttons carry `aria-pressed`.
- Mobile nav overlay (`.ax-shell-nav-open`) and drawers remain keyboard-operable; do not regress `step_up_auth_modal` focus trap.
- axe must pass in light AND dark (`admin-a11y.spec.js`); no new violations introduced by uplift.

## Brand Expression Baseline (rubric ⑧ ≥2)

"Quiet polish, well-made developer tooling, not fintech" (calm, exact, measured). Concretely: Geist display face on hero numbers, tabular figures everywhere (inherited — never override), tightened radii (`--ax-radius-*`, pill reserved for badges only), restrained dual-layer shadows (`--ax-shadow-sm` default; shadow = elevation, resting cards use borders). No decorative gradients beyond the existing body canvas; no finance-cliché imagery. Motion is OUT of scope this phase (Phase 177) — do not add transitions.

## Reuse / DRY Baseline (rubric ⑩ ≥2)

Uplift by **extending shared primitives, never re-implementing**. If a tail screen hand-rolls a card/section/field-list, replace it with `detail_section`/`detail_field_list`/`summary_card`/`data_table`/`related_resources`/`json_viewer`. Component public APIs stay **backward-compatible** (no breaking changes); extend via new optional attrs/slots only. The `data_table` URL-synced filters and Phase 175 work-queue defaults must not regress.

## Token Gap Flags

Tokens genuinely missing for this phase's contract (flag, do not invent literals):

- **None blocking.** Phase 174 shipped the full responsive/type/measure/transition token set this phase needs (`--ax-bp-*`, `--ax-leading-*`, `--ax-tracking-*`, `--ax-measure`/`.ax-measure`, `--ax-transition-*`). The breakpoint *registry* exists; the only adjustments are *which* registered rung a given rule uses (the data-table collapse move from `--ax-bp-lg`→`--ax-bp-md`), which is a usage change, not a new token.
- **Watch (not a gap):** if a touched detail screen needs a tap-target minimum token, reuse the existing `2.75rem` min-height pattern from `.ax-input-search`; if it recurs ≥3 times, the planner MAY propose a `--ax-tap-min` token — but that is a Phase-174-style token addition and should be flagged up, not minted inline.

SUB-CHANGE A — Add ax-collapsed + ax-content-* CSS classes in app.css.

Add a Phase 177 comment section "Phase 177 (v1.51 MOT-02) — Collapsible nav link list
reveal". Add the .ax-collapsed class definition: this class is applied by the JS hook when
collapsing — it sets opacity to 0 and pointer-events to none, with a transition shorthand
for opacity using var(--ax-dur-exit) and var(--ax-ease-in). When the class is absent and
the element is visible (list.hidden = false), the opacity is implicitly 1 (no extra rule
needed). Add the show-direction transition: for the expand side, the element goes from
opacity 0 (immediate — set to 0 before the browser paints via JS) to opacity 1 via the
natural transition. Write only the .ax-collapsed rule; the expand path relies on removing
this class and the browser interpolating from 0 to 1 via any existing transition on the
element. Add "transition: opacity var(--ax-dur-2) var(--ax-ease-out);" to a new
.ax-sidebar-group-links rule so the link list always has a transition to animate against.
The element selector is the div whose id matches the data-controls attr on the
section[data-group]; use the class ax-sidebar-group-links if it exists, or add a comment
for the executor to grep the component. Per sidebar.ex the controlled div is
"sidebar-group-links-{group}" — add ax-sidebar-group-links to that div in sidebar.ex if
the class doesn't exist, so the CSS selector works cleanly.

Add the skeleton content CSS transition class tuple section "Phase 177 (v1.51 MOT-02) —
Skeleton → content fade-in". The data_table.ex component (Plan 03) will use:
  phx-mounted={JS.show(transition: {"ax-content-entering", "ax-content-enter-from", "ax-content-enter-to"}, time: 180)}
on the content container. Define the three CSS classes:
  .ax-content-enter-from: opacity 0
  .ax-content-entering: transition using opacity var(--ax-dur-2) var(--ax-ease-out)
  .ax-content-enter-to: opacity 1
These compose from the atoms; no raw ms literals.

SUB-CHANGE B — Rewrite setExpanded in sidebar_collapse.js.

Replace the setExpanded method body with the transitionend two-step (PATTERNS.md §sidebar
two-step pattern). The new body must:
1. Set aria-expanded attribute (keep this line unchanged from current).
2. Get the list element via document.getElementById(this.el.dataset.controls). If not found, return early.
3. For expand (expanded = true): call list.removeAttribute("hidden") first, then
   list.classList.remove("ax-collapsed"). The CSS transition fires automatically from
   opacity 0 → 1 as the hidden attr is removed and ax-collapsed is absent.
4. For collapse (expanded = false): add the "ax-collapsed" CSS class first (triggers the
   opacity exit transition), then attach a { once: true } transitionend listener. In the
   listener body: set list.hidden = true and remove "ax-collapsed". This preserves the
   accessibility semantics of hidden (screen readers skip it when hidden) while letting the
   CSS transition run before display:none is applied.
5. Keep all other methods unchanged: mounted, destroyed, handleClick, storageKey.

Per RESEARCH §pattern 2: the `hidden` attr must only be set AFTER the exit animation
completes so assistive technology still skips the content when closed. Do not set
list.hidden = false before removeAttribute("hidden") — call removeAttribute("hidden")
directly.

Also check sidebar.ex (accrue_admin/lib/accrue_admin/components/sidebar.ex): if the
controlled div for sidebar group links does NOT already have the class "ax-sidebar-group-links",
add it so the CSS selector in sub-change A can target it. Grep for the div whose id is
"sidebar-group-links-*" and add the class if absent.

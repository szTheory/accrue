<objective>
Refactor global_search / command palette from the class-swap hidden mechanism to a
data-open attribute approach so CSS transitions can fire (class-swap to "hidden" applies
display:none which kills transitions). Wire the palette panel scale-in + backdrop fade via
pure CSS on the data-open attr. Update command_palette.js hook to use the new attr.
(MOT-02 surface #5 / #5b; MOT-03 reduced-motion via bundle override.)

Purpose: This is the last of the JS-coupled surfaces. Plans 02 and 03 covered CSS-only
surfaces and the :if-gated DOM mount/remove surfaces. global_search is in a middle category:
it stays in the DOM but uses a class-swap to "hidden" which is equivalent to display:none
and blocks CSS transitions. The data-open approach is the cleanest solution (PATTERNS.md
§global_search data-open approach).

Output:
- global_search.ex: data-open={to_string(@is_open)} on wrapper, remove the class-swap
- command_palette.js: replace 2 classList.contains("hidden") checks with dataset.open checks
- app.css: CSS transition rules keyed on [data-open="true"] for wrapper, palette panel
  (scale + opacity), and backdrop (opacity)
</objective>

RULE 1 — wrapper closed state (append to the existing .ax-command-palette-wrapper rule):
Add to the .ax-command-palette-wrapper selector: pointer-events: none;
This ensures the closed palette (data-open="false") cannot receive clicks. The wrapper
always stays in the DOM (no display:none), so pointer-events none is the accessibility-safe
closed state.

RULE 2 — wrapper open state:
.ax-command-palette-wrapper[data-open="true"] { pointer-events: auto; }

RULE 3 — backdrop base (closed) state. Append to the existing
.ax-command-palette-backdrop rule:
  opacity: 0;
  transition: opacity var(--ax-dur-2) var(--ax-ease-out);
  (the transition is always present so the browser can interpolate in both directions)

RULE 4 — backdrop open state:
.ax-command-palette-wrapper[data-open="true"] .ax-command-palette-backdrop { opacity: 1; }

Exit backdrop: the transition on the base rule handles exit direction when [data-open]
reverts — it fires with --ax-dur-2 (symmetric, because CSS can't encode asymmetric exit
on a single transition declaration without JS for a pure CSS approach). This is acceptable
for the palette backdrop; the panel gets asymmetric exit behavior below.

RULE 5 — palette panel base (closed) state. Append to the existing .ax-command-palette rule:
  opacity: 0;
  transform: scale(0.98);
  pointer-events: none;
  transition:
    opacity var(--ax-dur-2) var(--ax-ease-out),
    transform var(--ax-dur-2) var(--ax-ease-emphasis);
  (two-property transition; opacity uses ease-out; transform uses --ax-ease-emphasis —
  this is the ONE earned overshoot per motion contract and UI-SPEC)

RULE 6 — palette panel open state:
.ax-command-palette-wrapper[data-open="true"] .ax-command-palette {
  opacity: 1;

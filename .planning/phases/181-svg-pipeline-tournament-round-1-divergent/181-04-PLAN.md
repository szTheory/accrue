  <action>
    Create `harness/dirs/d-typemark.mjs` as a pure ESM module (no main(), exports only).

    The module must export `CONFIGS` and `generate(config, font)`. Unlike Directions A/B/C, `generate` receives the loaded opentype `font` object as its second argument because it calls `extractGlyphs()` to get actual Geist letterform paths. Import `extractGlyphs, getCapHeight` from `'../geist-spine.mjs'`.

    **Design approach:** Direction D produces a complete "accrue" typemark SVG where the mark motif IS part of the letterforms — no separate geometric mark to the left. The full typemark is the logo. All candidates use Geist Regular outlines (from extractGlyphs) as the base; surgery modifies one or more glyphs.

    Implement 3–4 configs covering the three design-source motif examples:

    **D1 — `cc` echoed layers:** Take the two `c` glyphs from "accrue" (positions 1 and 2 in the string). Render the primary `cc` in Ink (#111418). Add an echo layer: duplicate the first `c` path shifted by (+dx, +dy) offsets — creates a shadow/depth effect. Render echo in a lighter value (e.g., Ink at 40% opacity via `opacity="0.4"`, or Fog #E9EEF2 — use opacity since monochrome-derivable check scans hex colors, not opacity). The echoed layer must survive the monochrome-derivable lint: opacity on Ink color is greyscale-mappable, so use `opacity` not a saturated color. Knobs: `echoOffset` (dx, dy pair — e.g., 3, 3), `echoOpacity` (0.3–0.5).

    **D2 — stepped `e` crossbar:** Take the `e` glyph from "accrue" (position 5). The Geist `e` has a horizontal crossbar cutting through the interior counter. Modify the crossbar to have a stepped notch: split the crossbar segment into two horizontal segments with a vertical drop in the middle — creating a staircase profile. Since we have the path data as `d` string (not individual segments), implement this via SVG clip/mask rather than raw path editing: render the `e` glyph normally, then overlay a small stepped mask shape in Paper (#FAFBFC) on top of the crossbar to create the stepped notch appearance. Knobs: `stepDepth` (notch vertical size), `stepWidth` (notch horizontal size), `stepOffset` (horizontal position of the notch).

    **D3 — `u` filling interval:** The `u` glyph counter (interior white space) reads as a vessel. Visualize it as a filling/empty interval: render the `u` as normal Ink, then add an interior fill element in a contrasting lighter tone (Fog #E9EEF2 at partial fill height) creating a liquid/gauge metaphor inside the counter. Knobs: `fillLevel` (0.0–1.0 — fraction of counter height that is "filled"), `fillColor` (use Fog #E9EEF2 — passes monochrome lint since E9EEF2 saturation ≈ 0.06).

    **D4 — full typemark (all three motifs combined):** "accrue" with all three modifications: cc echo + stepped-e crossbar + u filling interval applied simultaneously. Minimal knobs (uses the defaults from D1/D2/D3).

    For each config, `generate(config, font)` must:
    1. Call `extractGlyphs(font, 'accrue', 1000)` to get all 6 glyph paths
    2. Assemble a full `<svg>` with all 6 glyphs placed at correct x-offsets (tracking advance widths)
    3. Apply the motif modifications as described above (overlays, masking elements, or duplicate paths)
    4. Return `{ fullSvg: string, markIsTypemark: true, markWidth: number, markHeight: number, skipGapRatio: true }`

    The `fullSvg` is a complete valid SVG string: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 {totalWidth} {totalHeight}">...</svg>`.

    Total width = sum of all 6 glyph advance widths at fontSize=1000. Total height ≈ capHeight + descenderDepth (estimate: 1100 units at fontSize=1000 covers full ascender+descender). Use `getCapHeight(font)` to set the viewBox reference.

    All configs have `skipGapRatio: true` in their metadata.

    Each config has a `rationale` string (one sentence for gallery display).

    Add a light validation: assert none of the fullSvg strings include 'NaN'. Log `[d-typemark] smoke: OK` if a quick inline check passes when imported (add a module-level smoke that runs on import only in test mode).

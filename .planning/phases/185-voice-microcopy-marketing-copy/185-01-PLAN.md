  Required sections (use these exact heading names):

  ## Voice Principles
  Four principles, one per Brand DNA adjective: measured, exact, native, durable. Each principle is 2-3 sentences: what it means for Accrue specifically, one concrete example of the principle in action. Do not invent new principles — derive from BRAND-DNA.md voice adjectives only.

  Add one memorable north-star sentence (from BRAND-AUDIT.md §2.4): "Sounds like a maintainer you trust."

  ## Do / Don't
  A table with two columns (Do / Don't), 8-10 rows. Derive from BRAND-DNA.md Do/Don't list: direct, calm, precise, practical, literate, generous vs hype, sales language, consumer-finance wording. Make each row a specific writing behavior, not a vague adjective. Examples of row shapes: "State the mechanism" / "Name the benefit without naming the mechanism"; "Use contractions in body copy" / "Force formality ('one may utilize')" — calibrate to Formal↔Casual=3 (professional, contractions allowed, no buddy-speak).

  ## Tone Sliders
  Two labeled 5-point scales with pole names and anchor values (per D-08):

  Scale 1: Formal (1) ↔ Casual (5) — anchor = 3
  Scale 2: Precise (1) ↔ Evocative (5) — anchor = 4

  Explain what each anchor means in practice for Accrue (Formal=3: contractions OK, no slang; Precise=4: literal/exact by default, evocative only when it adds clarity).

  Then the per-surface delta table (per D-09) with three columns: Surface | Formal↔Casual | Precise↔Evocative:
  - API reference (HexDocs): 4 / 5
  - README: 3 (anchor) / 4 (anchor)
  - Landing / marketing: 2 / 3
  - Release notes: 2–3 / 4
  - Error / empty-state microcopy: 3 / 5

  Note the ±1-step cap rule: "Voice adjectives stay fixed; tone shifts within a ±1-step cap so voice never breaks."

  ## Surface Dispatch Rule
  Named rule encoding D-07. Structure as a clear IF/THEN rule, not prose:

  Rule: "Tagline leads when a human is already on the page (README H1, landing hero). Descriptor leads wherever the string is search-indexed or seen out of context (GitHub repo description, Hex.pm, social/OG card)."

  Include an explanation of WHY: search-indexed strings without surrounding context need the concrete category noun first ("Elixir billing library") for both SEO and scan-ability. Engaged readers (already on a README or landing page) can receive the tagline first.

  ## Vocabulary
  Two subsections: "Use" and "Avoid".

  Use (10-14 entries): words and phrases that encode the voice — derive from README prose, BRAND-DNA.md, and BRAND-AUDIT.md. Examples: "billing state", "domain model", "Ecto-native", "append-only", "tamper-evident", "merge-blocking", "idiomatic", "facade", "webhook signature", "context function". Each entry with a one-line rationale.

  Avoid (10-14 entries): words banned by D-10 and the Brand DNA Don't list. Must include all banned adjectives from D-10: "production-grade", "batteries-included", "bank-grade", "modern alternative". Also include: "seamless", "powerful", "robust", "easy", "effortless", "simple", "best-in-class", "world-class", consumer-finance terms ("wallet", "money", "funds" in marketing copy). One-line rationale for each.

  ## Claims Posture
  Encode D-10: "State capability as a mechanism or named artifact, not an adjective."

  Include an explicit YES/NO table with 4-5 pairs drawn directly from the D-10 exemplars in CONTEXT.md:
  - YES: "Every webhook is signature-verified before it touches your database, and can't be bypassed."
  - NO: "bank-grade security"
  - YES: "Ships complete at v1.0: subscriptions, checkout, invoices, coupons, emails, PDFs, admin UI."
  - NO: "batteries-included"
  - YES: "A tamper-evident, append-only event ledger records every billing state change."
  - NO: "production-grade"

  Add one sentence: "Substantiate strong claims with a verifiable mechanism the reader can inspect (VERIFY-01 proof path, merge-blocking CI, named schema field)."

  ## CTAs
  Encode D-11: "CTAs are literal next-actions."

  Approved primary CTAs: "Get started", "Install"
  Approved secondary CTAs: "Read the guide", "View on Hex", "Browse the source"
  Sub-CTA spec string: "MIT · Elixir 1.17+ · Phoenix 1.8+"

  Banned CTA list (verbatim from D-11): "Start free", "Try it now", "Get billing in minutes", exclamation marks in CTAs, "demo".

  Rationale sentence: "Dev-tool norm: 'Get started' reads as docs entry, not a sales funnel. The sub-CTA spec is an honest statement of compatibility, not a teaser."

Tables for structured content. No fenced code blocks — this is prose, not code. Keep the file ≤ 250 lines (Phase 186 inlines it; fat files hurt the 2 MB budget).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Script → fs.readFileSync inputs | Assembly script reads source files from the local repo — all inputs are committed, developer-controlled artifacts |
| Inline SVG → HTML body | SVG content from brandbook/logo/ is embedded directly into HTML; malicious SVG content would need to originate from the repo itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-186-01 | Tampering | Inlined SVG content in index.html | mitigate | assemble.mjs must strip any `<script>` elements inside SVG content before embedding (logo SVGs produced by generate-logo-suite.mjs are path-only, but defensive strip is cheap and correct) |
| T-186-02 | Information Disclosure | External `src`/`href` URLs in index.html | mitigate | verify-brandbook.mjs asserts `(src|href)=["']…https?://` match count === 0; this is the primary automated mitigation and is a blocking gate |
| T-186-03 | Information Disclosure | SVG `xlink:href` to remote URL | mitigate | assemble.mjs reads SVGs as strings; verify-brandbook.mjs no-external-URL assertion covers `href` in SVG namespace; logo SVGs from Phase 183 contain no external references (confirmed — outlined paths only) |
| T-186-SC | Tampering | npm/pip/cargo installs | accept | Phase 186 introduces zero new npm installs; brandbook/harness/ has no dependencies key; no package-manager install tasks exist in this plan |

Note: This phase produces a static, offline, file://-served HTML document. No server, no user input, no auth, no network requests from the committed artifact. ASVS V2/V3/V4/V6 do not apply. The only applicable security concerns are (a) inlined SVG content integrity and (b) absence of external network references — both addressed above.
</threat_model>

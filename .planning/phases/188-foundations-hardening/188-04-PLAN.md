<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Theme preference -> semantic token resolution | Light, dark, and system-dark modes select state colors and focus roles. |
| ARIA state -> browser behavior | `aria-disabled` alone does not disable links unless the component removes activation. |
| Keyboard user -> focus styling | Focus indicator visibility must survive theme and contrast changes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-188-04-01 | Spoofing | disabled controls | mitigate | Tokenized disabled visuals plus `Button.button/1` removing disabled link href and tab stop. |
| T-188-04-02 | Elevation of Privilege | disabled link actions | mitigate | Disabled link-button output omits `href`, sets `aria-disabled="true"`, and uses `tabindex="-1"`. |
| T-188-04-03 | Information Disclosure | status role colors | accept | Status colors expose only UI state already visible to the operator; no new data source is added. |
| T-188-04-04 | Denial of Service | focus visibility | mitigate | Replace border-only focus with 2px outline/offset/halo so keyboard flows remain usable. |
| T-188-SC | Tampering | npm/pip/cargo installs | mitigate | No package-manager install task exists; tests use existing ExUnit/Phoenix component stack. |

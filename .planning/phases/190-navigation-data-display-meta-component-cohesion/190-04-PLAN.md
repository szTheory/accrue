## Scope Rationale

This plan intentionally owns 12 files because GRP-01 and GRP-04 meta-component behavior must keep navigation semantics, dropdown/search/flash layers, and drawer/modal structure aligned in one wave after data-display work settles. The apparent breadth is caused by paired component/test files plus authored and rebuilt CSS; splitting would force sequential edits to `navigation_components_test.exs`, `display_components_test.exs`, and the same CSS bundle without improving parallelism. The plan remains bounded to three tasks and one subsystem: reusable navigation and meta-component roots.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Navigation state to ARIA | Route/patch active state becomes screen-reader and visual state. |
| Dropdown/search user input to rendered UI | Search query and action labels render in command/dropdown surfaces. |
| Overlay structure to interaction model | Dialog/drawer markup implies behavior that Phase 191 completes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-190-14 | Spoofing | Tabs and window selector | mitigate | Keep link semantics with one `aria-current` current page item and visible selected treatment. |
| T-190-15 | Spoofing | DropdownMenu | mitigate | Use disclosure semantics that match native `details` behavior; tests reject overclaimed menu semantics. |
| T-190-16 | Tampering | GlobalSearch | mitigate | Preserve existing query trim and max-length boundary; do not add raw HTML rendering. |
| T-190-17 | Repudiation | Modal-confirm actions | mitigate | Structural contract requires object/action/consequence copy and visible cancel/confirm order; Phase 191 owns keyboard dismissal proof. |

</threat_model>

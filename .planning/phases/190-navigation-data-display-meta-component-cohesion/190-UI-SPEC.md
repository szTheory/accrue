## Spacing Scale

Declared values for Phase 190 group layouts (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-xs` | 4px | Icon-to-label gaps, tab count gaps, chip internals |
| `--ax-space-sm` | 8px | Button/action gaps, filter chips, compact header sub-gaps |
| `--ax-space-md` | 16px | Default group internals, toolbar item gaps, data card fields |
| `--ax-space-lg` | 24px | Card padding, drawer/modal header/body/footer gaps, section gutters |
| `--ax-space-xl` | 32px | Page group gaps, KPI/table cluster gaps, major detail stacks |
| `--ax-space-2xl` | 48px | Empty-state vertical padding and major proof-surface breaks |
| `--ax-space-3xl` | 64px | Rare page-level separations only; do not use inside dense groups |

Exceptions:
- New or changed Phase 190 group-layout CSS, proof specimens, padding, margins,
  and gaps must use 4px as the minimum spacing value and only the declared scale
  above. Existing legacy sub-4px CSS outside touched group layouts is outside
  this contract; do not propagate or reuse it for group-level work.
- Icon-only, tab overflow, filter-clear, drawer-close, pagination/load-more, and
  row-selection controls must reach a 44px minimum touch target at mobile widths
  and must follow the accessible action-label rules in the copywriting contract.

Group rhythm:
- Page-level group stacks use `--ax-space-xl` between siblings.
- Inside a framed group, header to body uses `--ax-space-lg`, and related inline
  controls use `--ax-space-sm` to `--ax-space-md`.
- Avoid "box prison": do not place `.ax-card` inside `.ax-card` unless the inner
  card is a repeated item, a table mobile row card, or a genuinely framed tool.
- Drawers and modals use `--ax-space-lg` panel padding and `--ax-space-md` footer
  separation; body overflow must preserve a visible footer/action area.

## Typography

Use only the existing composed role tokens. Only two weights are allowed:
regular 400 and semibold 600. Do not add raw `font-size`, `font-weight`,
`line-height`, `letter-spacing`, or `font-family` in new group CSS.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display | 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Phase 190 role usage:

| Group element | Required type role |
|---------------|--------------------|
| Page headings, detail object titles | `--ax-type-heading-font` or existing `.ax-heading`/`.ax-summary-title` equivalent |
| KPI metric values | `--ax-type-metric-font`; numeric text keeps tabular figures |
| Group section titles | `--ax-type-title-font` for empty states, `--ax-type-md` semibold for compact section headers |
| Toolbar/filter labels | `--ax-type-label-font` |
| Filter chips, tab counts, metadata labels | `--ax-type-label-sm-font` or `--ax-type-xs` semibold where already established |
| IDs, cursor/debug values, specimen slugs | `--ax-type-code-font` or `--ax-type-code-xs-font` |
| Empty/error/help copy | `--ax-type-body-sm-font`; use `--ax-measure` for explanatory copy |

Long object names, IDs, URLs, customer emails, failure reasons, and raw payload
snippets must wrap or truncate intentionally. Use `overflow-wrap: anywhere` for
multi-line facts and `text-overflow: ellipsis` only where the full value is
available nearby or in a title/accessible label.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` light `#fafbfc`, dark `#0f1318` | Page canvas, unframed group background, empty-state canvas |
| Secondary (30%) | `--ax-elevated` light `#ffffff`, dark `#171d24`; `--ax-sunken` light `#f1f5f8`, dark `#0b1015` | Cards, nav/sidebar, data-table shells, drawers, modals, recessed wells |
| Accent (10%) | `--ax-accent` default Cobalt `#5d79f6`; text/fill through `--ax-accent-readable`, `--ax-accent-strong`, `--ax-accent-subtle`, `--ax-accent-border` | Primary action fill, links, active navigation, selected tabs, active filters, focus ring source, command/search affordances |
| Destructive | `--ax-danger` `#d64b4b`; rendered through `--ax-status-danger-*` for text/bg/border pairs | Destructive actions, error states, danger badges only |

Accent reserved for: primary CTA, active page/sidebar navigation, active tab
indicator, active filter chip, selected row state, focus ring, command-palette
selection, link text, and current-step/progress emphasis. Accent is not a
decorative wash for every card, KPI, header, empty state, or inactive control.

State color contract:
- Filters, sorting, selected rows, selected tabs, current nav, and active windows
  must use `--ax-interactive-selected` plus an additional structural cue
  (`aria-current`, `aria-pressed`, chip label, count, or border).
- Error and failed states use `--ax-status-danger-{bg,border,text}`; warning and
  dunning-risk states use `--ax-status-warning-*`; success/recovered states use
  `--ax-status-success-*`; info states use `--ax-status-info-*`.
- KPI delta tones stay in the existing moss, cobalt, amber, slate, and ink set.
  Do not map unknown status to danger by default.
- Disabled controls use `--ax-disabled-*` and must not advertise hover, active,
  selected, or focus affordance.

## Copywriting Contract

Use Accrue voice: measured, exact, native, durable. Phase 190 may standardize
group-level labels and state copy, but broad page-flow microcopy cleanup belongs
to Phase 191.

| Element | Copy |
|---------|------|
| Primary CTA | Apply filters |
| Empty state heading | Nothing in this list yet |
| Empty state body | Billing records appear here when they match this view. If you expected rows, check filters or organization scope. |
| Filtered-empty CTA | Clear filters |
| Error state | This data display could not load. Retry the query; if it persists, inspect logs for the active owner scope. |
| Loading state | Loading billing records |
| No-pagination state | No pagination control is shown when there is no `next_cursor` or equivalent more-data signal. |
| Destructive confirmation | Modal-confirm must name the object, action, and consequence: "{Action} will execute against {object or projection}. Continue?" Keep object-specific existing copy where it is already more precise. |

Required label vocabulary:
- Filter submit: `Apply filters`.
- Filter reset: `Clear filters`.
- Pagination: `Load more`; render only when more data exists.
- Poll/new rows: `Load newer rows`.
- Selection: `Select`, `Selected`, `Select visible`, `Clear visible`,
  `{N} selected`.
- Tabs and window selectors: use route/navigation nouns, not ARIA tab-panel
  language unless the surface renders same-page panels.
- Drawer close: `Close` unless a more specific object close label exists.
- Destructive primary action: use the literal verb and noun (`Cancel subscription`,
  `Void invoice`, `Replay webhook`) and keep cancel/secondary action visually
  neutral.

Empty-state distinction:
- True empty: explain when records appear.
- Filtered empty: preserve the screen's tailored empty copy and make `Clear filters`
  the next useful action.
- Data unavailable/error: state what failed and how to retry or where to inspect
  evidence. Do not use bare "failed", "forbidden", "invalid", or "oops".

Accessible action labels:
- Single-word visible labels are allowed only when the accessible name supplies
  the object context. Row selection controls that visibly read `Select` or
  `Selected` must expose names such as `Select invoice {id}`, `Select customer
  {name}`, or `Selected subscription {id}`. Bulk controls must expose `Select
  visible {resource plural}` or `Clear visible {resource plural}` when the table
  context is not already programmatic.
- Drawer and modal close controls that visibly read `Close`, or render as an
  icon-only close button, must expose `Close {drawer name}` or `Close {object}
  drawer` unless an associated dialog/drawer title already provides equivalent
  programmatic context.
- Every icon-only action must have an accessible name through `aria-label` or
  `aria-labelledby`. If the icon is not universally understood in this admin
  context, provide a tooltip or adjacent text label with the same action and
  object; do not rely on the `title` attribute alone.

## Group Interaction Contracts

### Page Header + Actions + Breadcrumbs

- Order: breadcrumbs/orientation first, task heading second, descriptive copy
  third, primary action in the same visual band as the task.
- The primary action sits right-aligned on desktop and wraps below the heading on
  mobile without separating from the title by more than `--ax-space-md`.
- Breadcrumb current item uses `aria-current="page"` and muted/non-link styling.
- Header copy uses `--ax-measure` and must not stretch edge-to-edge on wide
  screens.
- Secondary actions stay grouped after the primary action and use neutral button
  variants unless selected/active.

### Toolbar + Search + Filters + Sort

- Filters sit directly above or inside the same group as the table/list they
  constrain.
- Active filters must be visible as chips or selected controls after submission.
- The active chip uses state color plus text (`Clear`) and an accessible remove
  label; color alone is not sufficient.
- Search, filter, sort, and clear actions wrap into a stacked card/list-friendly
  toolbar below 768px.
- Filtered-empty states make `Clear filters` the obvious next action.
- Disabled or unavailable filters use `--ax-disabled-*` and must not look enabled.

### Table + Empty + Loading + Error + Pagination

- `DataTable` remains the canonical entity-queue renderer for customers,
  subscriptions, invoices, charges/payments, webhooks, events, coupons,
  promotion codes, and connect accounts.
- Desktop table appears at `min-width: 768px`; mobile card/list mode appears
  below 768px. Only one layout is accessible/focusable at a time.
- Card fields must be explicit per resource: each card needs an identity title,
  2-5 labeled facts, status/action affordance where applicable, and no loss of
  row action context.
- Horizontal overflow is allowed only for machine-like data that cannot be
  summarized into cards without losing meaning.
- Empty, filtered-empty, loading, error, no-pagination, has-pagination, selected,
  and long-content states must be represented in the lab.
- Pagination/load-more appears only when `next_cursor` or equivalent more-data
  signal exists. If not, omit the control; do not render a disabled primary
  affordance.

### KPI + Chart + Table

- Summary KPIs appear before trend/chart evidence, and chart/table evidence
  appears before row-level drill-down actions.
- KPI cards share one rhythm: label, metric, delta/meta, optional sparkline.
  Use existing `KpiCard` tones and tokenized spacing.
- KPI grids are one column on mobile, two columns at content width, and up to
  four columns only where the existing `ax-kpi-grid-4` pattern applies.
- Do not nest KPI cards inside another decorative card. A surrounding section may
  be unframed; repeated KPI cards may be framed individually.
- `AtRiskTable` is the specialized exemplar that must gain the shared
  data-display contract, including mobile cards/list behavior and state coverage.

### Detail Header + Metadata + Actions

- Detail object identity comes first: eyebrow, title/ID, status, primary facts,
  then actions.
- Actions stay adjacent to the object identity and wrap without pushing metadata
  off screen.
- Metadata uses label/value lists with `overflow-wrap: anywhere` for IDs and
  external identifiers.
- Detail sections use consistent elevation and spacing. Avoid a card inside a
  card unless the inner element is a repeated related-resource item.
- The lab must render this group concretely to close Phase 187 visibility defects
  `AX187-001` and successors for `detail-header/metadata/actions`.

### Modal Confirm

- Phase 190 owns structure, role, IDs, sizing, action order, and visual hierarchy.
  Full focus trap, focus restore, Escape, click-outside, and scroll-lock
  regression coverage are Phase 191 unless a reusable root defect is found.
- Use `role="dialog"`, `aria-labelledby`, and when descriptive copy exists,
  `aria-describedby`.
- Width: `min(42rem, calc(100vw - 2rem))`; panel radius `--ax-radius-lg`;
  layer token `--ax-z-modal`.
- Header contains title and description. Body names the object and consequence.
  Footer actions use neutral cancel first and destructive/primary confirm last on
  desktop; on mobile, actions stack full-width with confirm still visually
  unmistakable.
- Destructive confirm uses `--ax-status-danger-solid` /
  `--ax-status-danger-on-solid` or existing danger button mapping, never raw red.

### Drawer + Form

- Phase 190 owns responsive sizing, header/body/footer rhythm, title/description
  IDs, action grouping, and layer token consumption. Focus trap, focus restore,
  Escape, and click-outside are Phase 191.
- Mobile drawer is a full-screen sheet; desktop may use side-panel sizing, but
  content must not exceed viewport height without scrollable body.
- Footer stays visually attached to the drawer and separated by
  `--ax-space-md` plus border. Primary submit and cancel remain visible after
  body scroll.
- Form fields stack with `--ax-space-md`; errors sit directly under the field
  they describe.
- Loading/disabled submit states must be distinct from a normal disabled form.

### Tabs + Subviews

- Route or patch navigation tabs use link navigation with `aria-current="page"`.
  Do not force APG `tablist` semantics unless same-page tab panels exist.
- Active tab uses text, border, and selected state; color alone is not enough.
- Counts use pill styling and remain readable in light and dark.
- Tab rows may horizontally scroll when labels are long, but the active tab must
  remain discoverable and focusable.
- `window_selector` follows the same navigation contract unless it becomes a
  true same-page segmented control.

### Dropdowns, Search, Flash, and Toasts

- `dropdown_menu` must choose one semantic model. Current native `<details>`
  disclosure should not keep `role="menu"`/`menuitem` unless Phase 191 supplies
  true menu-button keyboard behavior.
- Command/global search uses `--ax-z-modal`, the existing command-palette rhythm,
  and active-result state distinct from hover.
- Flash/toast uses `--ax-z-toast`, semantic status colors, and must not obscure
  the next action in the active group.

## Responsive and State Coverage

Required viewport proof widths: 320, 375, 768, 1024, and 1440 when the existing
test harness supports them. Every group specimen must be checked in light and
dark through the global theme toggle.

| State | Required visual contract |
|-------|--------------------------|
| Long content | Wrap or truncate intentionally; no overlap, clipping, or off-screen actions |
| Empty | Non-interactive empty surface; no hover cursor unless an explicit action is present |
| Filtered empty | Shows active constraints and `Clear filters` |
| Loading | Skeleton/spinner does not shift layout or look like disabled |
| Error | Danger semantic surface with recovery path |
| No pagination | No disabled pager as primary affordance; row count only if useful |
| Has pagination | `Load more` appears in footer rhythm and is reachable on mobile |
| Active filter/sort | Visible chip/control state plus accessible label |
| Selected row | `aria-pressed`/selected count plus visible selected treatment |
| Dark mode | Same semantic hierarchy; no hidden borders, text, focus rings, or disabled states |

## Phase 191 Handoff Boundary

Phase 190 must emit a handoff list for Phase 191 rather than completing these:

- Full modal/drawer focus trap and focus restore.
- Escape and click-outside dismissal regression coverage.
- Page scroll locking and full scroll reachability across every page.
- LiveView patch focus recovery.
- Overlay positioning fixes that depend on page-flow fixtures.
- Disconnected/reconnecting state coverage.
- Broad page-flow microcopy cleanup.
- Fixture expansion for permission-denied, boundary pagination, high counts,
  non-ASCII names, and disconnected/reconnecting states.

If Phase 190 discovers a reusable root issue while building a group contract, it
may fix the root structure/CSS/API and record the remaining behavior in the
handoff list keyed to Phase 187 defect IDs or overlay tags.

> Visual and interaction contract for idempotent verification, final scorecard packaging, CI guardrail status, and maintainer sign-off.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none - custom AccrueAdmin `ax-*` CSS token system |
| Preset | not applicable |
| Component library | Phoenix LiveView function components and LiveComponents; no shadcn, Radix, Base UI, Tailwind authoring, PhoenixStorybook, or third-party UI registry |
| Icon library | Heroicons via `AccrueAdmin.Components.Icon`, sized through `--ax-icon-{sm,md,lg}` |
| Font | Geist Variable for UI text; Geist Mono Variable only for cell IDs, evidence refs, artifact paths, commands, JSON keys, and NDJSON row references |

Sources: `.planning/REQUIREMENTS.md` VER-02..04, `.planning/ROADMAP.md` Phase 192, `192-CONTEXT.md`, Phase 191 UI/verification artifacts, Phase 187 rubric/baseline artifacts, `accrue_admin/assets/css/theme.css`, `accrue_admin/assets/css/app.css`, `accrue_admin/e2e/baseline-manifest.js`, `brandbook/voice.md`, and `brandbook/tokens/README.md`.

Contract:
- `accrue_admin/assets/css/theme.css` remains the implementation token source of truth.
- Structured artifacts are canonical: `final.cells.json`, `scorecard.delta.json`, `regressions.ndjson`, and `artifacts.manifest.json` override markdown summaries when they disagree.
- `192-SCORECARD.md` and `192-SIGN-OFF.md` are maintainer-readable proof surfaces, not independent sources of truth.
- Phase 192 must not introduce new billing primitives, breaking public routes/APIs, a Tailwind migration, PhoenixStorybook, a pixel-diff service, committed bulky screenshots/traces, or `accrue_portal` work.

## Spacing Scale

Declared values for Phase 192 verification and sign-off surfaces (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-xs` | 4px | Icon-to-label gaps, compact status markers, cell result badges |
| `--ax-space-sm` | 8px | Table cell controls, evidence-link groups, checklist item gaps |
| `--ax-space-md` | 16px | Default scorecard row spacing, summary table padding, artifact list spacing |
| `--ax-space-lg` | 24px | Scorecard section padding, sign-off checklist groups, gallery row rhythm |
| `--ax-space-xl` | 32px | Major proof-surface groups: summary, deltas, regressions, CI, gallery, sign-off |
| `--ax-space-2xl` | 48px | Top-level breaks between scorecard and sign-off packages |
| `--ax-space-3xl` | 64px | Rare page-level separation only; do not use inside dense audit tables |

Exceptions:
- Dense pre-existing audit/table affordances inherited from the admin design system must use the declared spacing scale above; do not introduce or rely on sub-4px spacing tokens.
- Scorecard and sign-off rows may use compact density, but every interactive evidence link, disclosure, filter, or checklist control must reach a 44px minimum touch target at 320px and 375px.
- Evidence tables must degrade to stacked rows/cards at 320px and 375px; do not squeeze all artifact columns into a horizontally unreadable table.
- Long artifact paths, cell IDs, command strings, route IDs, checksums, and NDJSON evidence refs must wrap with `overflow-wrap: anywhere`.

## Typography

Use only the existing composed role tokens. Phase 192 introduces no new type tokens, no fifth size, and no third weight. Only weights 400 and 600 are allowed.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display | 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Required usage:
- `192-SCORECARD.md` headings use heading role for phase status, section names, and blocking regression groups.
- Summary counts, baseline/final deltas, and CI pass/fail totals may use display or metric role only when they are the primary read in a summary band.
- Checklist labels, evidence lens labels, coverage status, and pass/block badges use label role.
- Cell IDs, dimension names, artifact paths, commands, JSON keys, SHA-256 values, and trace refs use code role with wrapping. Never use viewport-scaled type.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` light `#fafbfc`, dark `#0f1318` | Page canvas, generated markdown preview background, unframed sign-off canvas |
| Secondary (30%) | `--ax-elevated` light `#ffffff`, dark `#171d24`; `--ax-sunken` light `#f1f5f8`, dark `#0b1015` | Scorecard summary bands, evidence tables, gallery rows, CI status panels, code/evidence wells |
| Accent (10%) | runtime `--ax-accent` default Cobalt `#5d79f6`; `--ax-accent-strong`, `--ax-accent-readable`, `--ax-accent-subtle`, `--ax-accent-border` | Primary sign-off action, active scorecard filter, selected gallery row, evidence link, focus ring, current verification step |
| Destructive | `--ax-danger` `#d64b4b`; danger surfaces through `--ax-status-danger-*` | Blocking regressions, failed guardrails, destructive or blocking sign-off states only |

Accent reserved for: primary CTA, active filter/view, selected row, visible focus ring, evidence links, command/result links, current verification step, and final sign-off action.

Color rules:
- Use status role pairs for pass, warning, blocked, info, neutral, and destructive states. Color alone is never the state; every badge/table row needs text.
- Blocking regressions use danger semantics and must remain visually distinct from advisory findings.
- Advisory visual/brand/microcopy findings use warning or info semantics until they become a structured regression.
- CI guardrail success uses success semantics; skipped, unavailable, or advisory evidence uses neutral/info with explicit copy.
- Overlay/layer tokens remain `--ax-z-dropdown` 200, `--ax-z-popover` 300, `--ax-z-drawer` 400, `--ax-z-modal` 500, `--ax-z-toast` 600. No ad-hoc z-index literals.

## Copywriting Contract

Use Accrue voice: measured, exact, native, durable. The sign-off surface is for operators and maintainers; it must name the artifact, evidence lens, cell, route, CI job, or regression being discussed. Do not use vague pass/fail copy without naming what passed or failed.

| Element | Copy |
|---------|------|
| Primary CTA | Approve milestone sign-off |
| Empty state heading | No regressions recorded |
| Empty state body | The final comparison found no cell downgrade or new regression row. Review CI guardrails and the curated gallery before approving sign-off. |
| Error state | Final scorecard could not be generated. Re-run the failed evidence command, then regenerate `final.cells.json`, `scorecard.delta.json`, and `regressions.ndjson`. |
| Destructive confirmation | Block sign-off: Record the blocking regression ID, affected cell, evidence ref, and required repair before rerunning the scorecard. |

Required copy for generated proof surfaces:

| Surface | Copy contract |
|---------|---------------|
| `192-SCORECARD.md` executive status | State pass/fail, final cell count, comparable cell count, regression count, coverage downgrade count, CI guardrail status, and sign-off state. |
| Baseline comparison | Use `Final score >= Phase 187 baseline for every comparable cell` only when every structured row proves it. |
| Regression rows | Name cell ID, surface, state, dimension, baseline score, final score, coverage change, severity, evidence refs, and required repair owner. |
| CI guardrail rows | Use concrete command names: `baseline:parse`, `verify_phase191_ax187_coverage`, `e2e:group-contracts`, `e2e:phase191`, `e2e:a11y`, `reduced-motion`, and component-lab coverage. |
| Screenshot gallery rows | Name `who`, `job`, route/surface, state, theme, viewport, and why the screenshot matters. |
| Maintainer checklist | Approve JTBD clarity, domain vocabulary, microcopy recovery, brand fit, accessible focus/contrast, mobile usability, dark-mode role clarity, and absence of backend-guts presentation. |

Domain vocabulary:
- Use customer, subscription, invoice, charge/payment, webhook, event, recovery, Connect account, owner scope, inspect, filter, replay, refund, void, recover, clear filters.
- Use artifact terms consistently: final cells, baseline cells, delta, regression, evidence ref, artifact manifest, curated gallery, guardrail, sign-off.
- Avoid "looks good", "all green", "LLM passed", "no issues" unless paired with structured evidence counts.

## Scorecard And Sign-Off Interaction Contract

Phase 192 produces a maintainer-readable package over canonical structured evidence.

Required artifact package:

| Artifact | Role | Interaction contract |
|----------|------|----------------------|
| `192-SCORECARD.md` | Readable summary | First screen shows executive pass/fail, regression count, coverage downgrade count, CI guardrail state, and sign-off state without requiring the maintainer to open raw JSON. |
| `final.cells.json` | Canonical final matrix | Machine-readable source for every final score, coverage status, dimension, state, theme, viewport, and evidence ref. |
| `scorecard.delta.json` | Canonical comparison | Every comparable Phase 187 cell maps to its final cell and records score/coverage changes. |
| `regressions.ndjson` | Canonical blockers | Empty file or zero rows means no regressions. Any row blocks sign-off unless explicitly reclassified with structured correction notes. |
| `artifacts.manifest.json` | Evidence index | Links screenshots, traces, command logs, reports, and checksums without committing bulky binary artifacts. |
| `192-SIGN-OFF.md` | Maintainer decision surface | Contains executive status, curated gallery index, CI guardrail status, evidence manifest links, and a checklist with explicit approve/block outcome. |

Interaction rules:
- The first maintainer read is status-first: pass/fail, what changed from baseline, what remains blocked, and what evidence proves it.
- Every summary number links or references the structured artifact that produced it.
- Every blocking row includes a direct evidence ref. No blocker may rely only on prose, screenshots, or model judgment.
- Filters/views for surface type, state, dimension, severity, and evidence lens are allowed, but filtered views must never hide blocking regressions from the top-level status.
- Aggregate scores are summary-only. A high aggregate score cannot mask one failing cell, coverage downgrade, or regression row.
- The sign-off checklist is explicit: unchecked or blocked rows keep sign-off pending.

## Adversarial Judge Evidence Contract

The judge is a layered evidence system, not an LLM-only visual score.

| Lens | Required evidence | Gate role |
|------|-------------------|-----------|
| Correctness/browser behavior | Playwright reports, command status, page-flow/group/component traces | Required for final comparison and CI guardrails |
| Axe/WCAG accessibility | `e2e:a11y` output in light and dark | Required but not sufficient for accessibility |
| Reduced motion | `reduced-motion.spec.js` output | Required deterministic guardrail |
| Component/group/page coverage | Baseline manifest, component lab coverage check, group contracts, Phase 191 coverage verifier | Required for coverage and no-downgrade proof |
| Interaction traces | Focus trap, focus restore, Escape, outside click, scroll reachability, LiveView patch focus, actionability | Required for interaction-integrity claims |
| Visual/brand/microcopy | Advisory `score-visuals` findings plus curated screenshot review | Advisory or subjective unless normalized into structured regressions |
| Maintainer screenshot review | `192-SIGN-OFF.md` checklist and curated gallery | Required for VER-04 final sign-off |

Evidence presentation:
- Raw lens outputs stay separate until a pure reducer normalizes them to canonical cell IDs.
- Every final score, downgrade, regression, and sign-off row cites evidence refs from `artifacts.manifest.json` or generated output roots.
- Do not ask the maintainer to infer focus, actionability, or scroll behavior from still screenshots; link the trace or deterministic browser assertion.
- Screenshots are curated, JTBD-first, and representative. They do not replace the full structured matrix.

## CI Guardrail UI Contract

Deterministic PR gates and final/manual evidence runs must be visually and semantically distinct.

Merge-blocking guardrail status must cover:
- `cd accrue_admin && npm run baseline:parse`
- `node scripts/ci/verify_phase191_ax187_coverage.mjs`
- `cd accrue_admin && npm run e2e:group-contracts`
- `cd accrue_admin && npm run e2e:phase191`
- `cd accrue_admin && npm run e2e:a11y`
- `cd accrue_admin && npx playwright test e2e/reduced-motion.spec.js --workers=1`
- component-lab structural coverage through the existing registry, ExUnit, or verifier path

Final or advisory evidence, not required on every PR:
- screenshot capture
- trace capture
- baseline/final regeneration
- `score-visuals`
- full broad `npm run e2e`
- maintainer sign-off

Status copy:
- `Required guardrail passed` for deterministic blocking checks.
- `Required guardrail failed` for deterministic failures that block merge/sign-off.
- `Final evidence only` for screenshot/trace/full rerun/model-scored evidence.
- `Advisory finding` for model or subjective visual/brand/microcopy findings not normalized into structured regressions.

## Curated Gallery Contract

The curated gallery must be small enough for maintainer review and broad enough to cover JTBD/risk categories.

Required categories:
- dashboard health scan
- customer inspection
- subscription triage/detail
- invoice/payment review
- webhook/event debugging
- recovery campaign
- component lab
- modal, drawer, dropdown, and command/open states
- empty, error, permission-denied, disconnected/reconnecting states
- historical-risk controls: command palette, dropdowns, drawers, modals, mobile nav, destructive confirmations, disabled/read-only actions

Each gallery row must include:
- who
- job
- route or surface
- state
- theme
- viewport
- evidence ref
- why this screenshot matters
- accept/block status

Coverage:
- Include light and dark screenshots for each selected flow.
- Include mobile screenshots for layout-risk flows.
- Include system-theme behavior only if the harness proves it deterministically.
- Include trace refs beside screenshots for focus trap, focus restore, Escape, outside click, scroll reachability, LiveView patch focus, and actionability.

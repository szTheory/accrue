## Spacing Scale

Declared values — **reuse the existing `--ax-space-*` ladder verbatim** (do not introduce raw px; RES-04 spacing-literal guard from Phase 193 bans raw px on padding/margin/gap outside the allowlist):

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-2xs` | 2px | Dense table rungs, in-chip gaps (exception rung) |
| `--ax-space-xs` | 4px | Icon gaps, inline padding |
| `--ax-space-sm` | 8px | Compact element spacing (attention-row internals) |
| `--ax-space-md` | 16px | Default element spacing, card padding |
| `--ax-space-lg` | 24px | Section padding, zone gaps (`ax-home-section`) |
| `--ax-space-xl` | 32px | Layout gaps between zones |
| `--ax-space-2xl` | 48px | Major section breaks |
| `--ax-space-3xl` | 64px | Page-level spacing |

Exceptions: the `2xs` (2px) rung is an intentional, pre-existing exception to a strict 8-point scale, reserved for dense table/chip density. Any *new* literal px introduced for the KPI-demotion or empty-state polish must be annotated with an `ax-spacing-exception` comment (the Phase-193 guard convention) or it fails CI.

## Typography

Reuse the composed `--ax-type-*` role bundles. **The phase's only typographic move is demotion** (D-03): the KPI cluster steps *down* the scale and the attention-rail heading/rows hold or step *up* their weight relative to KPIs, so "exceptions read as higher-signal than KPIs" (SPEC-OVERVIEW judge cell). Two weights only — 400 (regular) and 600 (semibold).

| Role | Token | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Display (page `<h1>`) | `--ax-type-display` | 2.25rem / 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |
| Heading (zone `<h3>`) | `--ax-type-heading` | 1.75rem / 28px (`--ax-type-2xl`) | 600 | 1.2 |
| Metric (KPI value) | `--ax-type-metric` | 1.75rem / 28px (`--ax-type-2xl`) | 600 | 1.2 |
| Title / Label | `--ax-type-title` / `--ax-type-label` | 1.25rem / 16px·sm | 600 | 1.2 / 1.4 |
| Body | `--ax-type-body` | 1rem / 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Eyebrow / KPI label | `--ax-type-eyebrow` | 0.75rem / 12px (`--ax-type-xs`) | 600 | 1.4, `--ax-tracking-caps` |

**Demotion contract (the load-bearing typographic delta):** after this phase the KPI cluster's *visual* weight (effective type step + contrast) must read as subordinate to the attention rail. KPI values may stay on `--ax-type-metric` but the cluster's framing (card weight, label contrast via `--ax-muted`) drops; do NOT promote KPIs to `--ax-type-display`. Bounded by "light polish" (D-03) — no broad type-scale rework (deferred).

## Color

Custom semantic token system, theme-aware (light default + `[data-theme="dark"]` + `[data-theme="system"]`). The 60/30/10 split maps onto the existing tokens — **reuse them; introduce no new hues** (CONTEXT: zero new tokens):

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (light `#f…paper` / dark `#0f1318`) | Page background (`ax-page`, `ax-home`) |
| Secondary (30%) | `--ax-elevated` (`#ffffff` / `#171d24`) + `--ax-border` | Cards (`ax-card`), launcher tiles, KPI cards, attention rail container |
| Accent (10%) | `--ax-accent` / `--ax-accent-readable` / `--ax-focus-ring` (`#174ea6` light / `#9bb5ff` dark) | See reserved list below |
| Destructive / danger | `--ax-danger` `#d64b4b`, `--ax-status-danger-*`, `--ax-money-negative` | Exception-rail danger dot/pill, "past due / at-risk" tone, Exhausted MRR sign |

Accent reserved for: **(1)** the ⌘K search trigger focus/hover affordance; **(2)** KPI-card and launcher hover/focus states (`--ax-interactive-hover` / `--ax-focus-ring`); **(3)** the "Review all signals" / quiet links (`ax-link-quiet`). Accent is NOT used to fill the healthy empty-state, NOT to color KPI values, and NOT as a general surface tint. Exception tones use the status tokens (`success`/`warning`/`danger`/`info`), not accent.

**Money + status semantics (reuse):** `--ax-money-positive` (Recovered MRR), `--ax-money-negative` (Exhausted MRR), `--ax-money-pending`; attention-dot/pill tones map to `--ax-status-{success,warning,danger,info,neutral}-*`. The healthy "all clear" empty state uses success/neutral tone — never danger, never accent-as-CTA.

## Copywriting Contract

All copy lives in `AccrueAdmin.Copy` (centralized; never inline LiveView strings — Phase 191 invariant). Brand voice: "well-made dev tooling, quiet polish," not fintech (`prompts/accrue-brand-book.md` / `admin_ui.md`). Existing dashboard copy is already on-voice and is **kept**; the empty-state copy is *elevated in hierarchy*, not rewritten wholesale (D-06).

| Element | Copy (existing `Copy.*` function, reused) |
|---------|-------------------------------------------|
| Page headline (`<h1>`) | "Billing operations" (`home_intro_headline`) |
| Page intro | "Start with what needs you, then jump straight to the task that resolves it." (`home_intro_copy`) |
| Attention-zone heading | "What needs attention now" (`dashboard_display_headline`) |
| Primary task door (recovery) | "Recover at-risk revenue" → "Work the dunning funnel and at-risk subscriptions." (`home_launcher_recovery_*`) — verb-first launcher labels are the page's CTAs |
| Empty-state heading | "You're all caught up" (`home_attention_empty_title`) — **elevate to hero weight** (D-06) |
| Empty-state body | "No billing exceptions need attention right now. Pick up a task below." (`home_attention_empty_copy`) |
| Recovery hero pair | "Recovered MRR (CUR)" / "Exhausted MRR (CUR)" (`recovery_*`) — hero metric pair stays leading (D-02) |
| Error / failure state | Resource-specific recoverable copy via `AccrueAdmin.Copy` (never raw `inspect(reason)` — Phase 191 T-191-10 invariant); not newly authored this phase |
| Destructive actions | **None in this phase.** Dashboard + Recovery are read/route-only; no destructive confirmations introduced. |

**Empty-state copy rule (CPY discipline carried forward):** first-run-empty vs healthy-clear-empty are distinct messages — this healthy "all caught up" state is the *reassurance* variant (operator has zero exceptions), not a first-run "no data yet" variant. Keep them distinct if both can occur.

## Interaction & Structural Contract (phase-specific — SPEC-OVERVIEW conformance)

This is the load-bearing section for Phase 194. These are the machine-checkable invariants the page-flow Playwright driver (`phase191-page-flow-helpers.js`: `assertTopPointerTarget` / `assertScrollReachable` / `assertNoHorizontalClip` / `assertFocusWithin`) and the RES-04 source guards enforce. Two new `surface_type:"page-flow"` cells (Dashboard + Recovery) fold into the unchanged `regressions.ndjson` zero-regression gate against `baseline.page-flow.cells.json`.

| Invariant | Contract | Verified by |
|-----------|----------|-------------|
| Exactly one `<h1>` per page | Both pages render a single `ax-display` `<h1>` (`home_intro_headline` / `recovery_index_heading`). | `page.locator('h1').count() === 1`; axe landmark check |
| ⌘K trigger present + focusable | Add **additive** `data-ax-command-palette-trigger="true"` **alongside** the existing `data-command-palette-trigger` on the `ax-input-search` button (D-04 — never rename the behavior attr; `command_palette.js`/`topbar.ex` untouched). | `locator('[data-ax-command-palette-trigger]')` is-visible + `assertFocusWithin` |
| Zone DOM-order encodes priority | Add `data-ax-zone="attention-rail \| task-launcher \| kpi-cluster \| recent-activity"` to the existing zone `<section>`s in source order. Invariant: `attention-rail` index < `task-launcher` index < `kpi-cluster` index in `querySelectorAll('[data-ax-zone]')` (D-05). Structure is NOT moved — markers only. | Playwright DOM-order index assertion |
| Healthy empty-rail is non-interactive | `.ax-attention-rail--empty` (the elevated "all clear" hero) carries **no** `cursor:pointer` and **no** `role="button"` (D-06). Elevate hierarchy/reassurance, stay non-interactive. | `assertTopPointerTarget` (not a pointer target) + `require_regex` source guard banning `cursor:pointer` on the empty selector |
| Recovery: no chart before the work-queue | Re-order so `AtRiskTable.at_risk_table` renders **above** `FunnelChart.funnel_chart` (D-01). Today `recovery_live.ex` renders funnel (≈L145) before table (≈L152) — swap them. Hero pair stays leading (D-02); funnel demoted to supporting viz below. | Judge cell ("work-queue not chart wall") + DOM-order check that no chart precedes the at-risk table |

**Discretion left to planner/executor (CONTEXT):** (a) exact `data-ax-zone` attribute placement + precise CSS deltas for KPI demotion / exception emphasis (bounded by "light polish" + committed-bundle rebuild); (b) whether the empty-rail non-interactive guard ships as a *new* `verify_package_docs.sh` `require_regex` guard (mirrored into `PackageDocsVerifierTest seed_tmp_dir!` per the D-08 coupling invariant) **or** only as a page-flow Playwright assertion — research must confirm what Phase 193 already wired vs. what 194 must add; (c) exact location of the two new page-flow cells relative to `baseline.page-flow.cells.json`.

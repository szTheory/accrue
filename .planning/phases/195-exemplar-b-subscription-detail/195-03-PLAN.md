<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LiveView render -> body portal root | Overlay markup leaves the LiveView subtree and appears under a body-level root. |
| Wrapper components -> overlay component | Existing drawer/modal call sites trust the new primitive to preserve dismissal and focus contracts. |
| Destructive StepUp modal -> canonical overlay | Fresh-auth challenge must remain modal and above its scrim. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-195-09 | Tampering | `#ax-overlay-root` | mitigate | Render exactly one body-level root in `Layouts.root/1`; component tests assert portal target. |
| T-195-10 | Elevation of Privilege | StepUpAuthModal wrapper | mitigate | Preserve `step_up_submit` and `step_up_dismiss` events; do not change StepUp verification logic. |
| T-195-11 | Spoofing | Overlay labels | mitigate | Require `aria-labelledby` and title/fallback focus ids on modal and drawer presentations. |
| T-195-12 | Denial of Service | Portal orphaning | mitigate | Use LiveView `portal/1` template with stable ids rather than imperative DOM relocation. |
</threat_model>

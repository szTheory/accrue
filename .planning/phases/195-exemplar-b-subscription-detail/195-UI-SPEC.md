## Spacing Scale

Reuse the existing `--ax-space-*` ladder. Do not introduce raw `px` values for `padding`, `margin`, or `gap`; Phase 193's spacing-literal guard must stay green.

| Token | Value | Usage |
|-------|-------|-------|
| `--ax-space-xs` | 4px | Icon gaps, row-level "Change" affordance gaps, compact inline controls |
| `--ax-space-sm` | 8px | Action-menu item internals, summary-list row micro-gaps |
| `--ax-space-md` | 16px | Default field/list spacing, drawer form rhythm, section internals |
| `--ax-space-lg` | 24px | Summary-card padding, drill-section bands, drawer padding |
| `--ax-space-xl` | 32px | Band-to-band spacing in the DETAIL vertical spine |
| `--ax-space-2xl` | 48px | Major separation before lazy Activity / Raw JSON |
| `--ax-space-3xl` | 64px | Page-level breathing room only; do not use inside dense drawer forms |

Exceptions:
- No spacing exceptions are allowed for padding, margin, or gap in this phase. Dense field-label/value rhythm, chips, and table-like rows must use the standard 4px floor via `--ax-space-xs`.
- Interactive touch targets must remain at least 44px on narrow viewports where controls are finger-tappable.
- Drawer geometry may use structural dimensions such as `width: min(34rem, 92vw)` and `translateX(100%)` / `translateY(100%)`; those are not spacing tokens.

## Typography

Use existing composed role bundles and exactly two weights: 400 regular and 600 semibold. Do not add 500 or 700.

| Role | Token | Size | Weight | Line Height |
|------|-------|------|--------|-------------|
| Field label / eyebrow | `--ax-type-xs` | 12px | 600 | 1.4 (`--ax-leading-normal`) |
| Value / metadata | `--ax-type-sm` | 14px | 400 or 600 for labels | 1.4 |
| Body / section title | `--ax-type-md` | 16px | 400 body, 600 section title | 1.4 body, 1.2 title |
| Summary object title | `--ax-type-2xl` | 28px | 600 | 1.2 (`--ax-leading-tight`) |

Typography contract:
- The subscription `processor_id` remains the single page `<h1>` in the summary-card wrapper, not a summary-list row.
- Summary-list labels use uppercase/caps tracking only where the existing `ax-field-label` pattern already does; do not apply caps to row values or action labels.
- Plumbing identifiers and raw fields use mono/small styling only in lazy Activity / Raw JSON, never as headline values.
- No viewport-based type scaling. Preserve `letter-spacing: 0` for normal text; caps labels may use the existing tracking token.

## Color

Reuse theme-aware `ax-*` semantic tokens. The phase introduces no new hues.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (`#fafbfc` light / `#0f1318` dark) | Page background, overlay shell backdrop context, lazy section background rhythm |
| Secondary (30%) | `--ax-elevated` (`#ffffff` light / `#171d24` dark), `--ax-sunken`, `--ax-border` | Summary card, summary-list rows, drill sections, drawer panel, action-menu panel |
| Accent (10%) | Runtime `--ax-accent` (fallback `#5D79F6`) plus `--ax-accent-readable`, `--ax-focus-ring` | Only the reserved elements below |
| Destructive | `--ax-danger`, `--ax-danger-readable`, `--ax-status-danger-*` | Destructive menu items, destructive step-up context, danger copy/surfaces only |

Accent reserved for:
- Filled primary `Change plan` button and the primary drawer submit action.
- Summary-list row `Change` / `View` links where they are true actions.
- Keyboard focus rings via `:focus-visible`.
- Action-menu hover/focus background for non-danger items.
- Active/selected menu state if a pending action is open in the drawer.

Accent must not be used for status badges, dunning severity, danger actions, raw JSON chrome, decorative dividers, or non-interactive summary surfaces. Status and lifecycle semantics use `--ax-status-*`; money uses `--ax-money-*`.

## Copywriting Contract

All copy changes go through `AccrueAdmin.Copy` / `AccrueAdmin.Copy.Subscription`, followed by regenerating and committing `accrue_admin/e2e/generated/copy_strings.json`.

| Element | Copy |
|---------|------|
| Page eyebrow | `Subscription detail` |
| Primary CTA | `Change plan` |
| Secondary primary action | `Cancel renewal` |
| Overflow trigger | `More actions` |
| Summary row action labels | `Change` or `View`, with visually-hidden context: `{verb} for subscription {processor_id}` |
| Empty state heading | `No dunning activity yet` |
| Empty state body | `This subscription has not entered recovery. Billing and item details remain available above.` |
| Error state | `Subscription details could not be updated. Review the action, then try again.` |
| Destructive confirmation | `Cancel immediately`: route through step-up; challenge copy stays `Confirm your identity to continue.` |
| Destructive confirmation | `Comp this subscription`: route through step-up; challenge copy stays `Confirm your identity to continue.` |

Action label relabels locked by `195-CONTEXT.md`:
- `swap_plan` -> `Change plan`
- `cancel_at_period_end` -> `Cancel renewal`
- `cancel_now` -> `Cancel immediately`
- `comp_subscription` -> `Comp this subscription`

Copy rules:
- Reversible `Cancel renewal` is visible; immediate destructive `Cancel immediately` is menu-only, danger-styled, and step-up gated.
- Provider-unavailable actions are absent, not disabled.
- Braintree limitations stay as provider-honesty guidance inside the drawer/menu empty region, not as floating page copy.
- Error copy is recoverable and resource-specific; never render raw `inspect(reason)`.

## DETAIL Structure Contract

The page must render as exactly six bands in this order. This is the visual spine every later detail page should copy.

| Band | Contract |
|------|----------|
| 1. Summary-list header | Keep `Detail.summary_card/1` as the outer framed identity header. Add `Detail.summary_list/1` inside it: GOV.UK-style key/value rows, row-level actions, no internal IDs as rows. |
| 2. Action band | `data-ax-action-band`. Shows `Change plan` and, when available, `Cancel renewal` as the only visible primary actions (`data-ax-primary-action`). Shows one `More actions` overflow (`data-ax-action-overflow-menu`) when more actions exist. |
| 3. Drill sections | Collapsible sections: `Billing & items`, `Dunning & recovery`, `Tax & compliance`. Exactly one section open by default. Open `Dunning & recovery` when a dunning campaign is active; otherwise open `Billing & items`. |
| 4. Related resources | Exactly one canonical `RelatedResources.related_resources` strip with `data-ax-related-resources`; migrate unique duplicate-card links into it. |
| 5. Lazy activity | Timeline stays collapsed and loads only on first expand. It is for operator/audit context, not headline status. |
| 6. Lazy raw JSON | Raw payload stays last, collapsed, and lazy-loaded. It uses mono/small styling and never appears above core operator state. |

Header summary rows above the fold at 1280x800:
- Status: read-only badge plus lifecycle qualifier.
- Customer: linked customer identity, no `Change`.
- Plan / price: `Change` opens the `swap_plan` drawer when available.
- Current period: read-only.
- Renews / ends: `Change` opens cancel/resume action path where applicable.
- Amount (MRR): derived, read-only.
- Seats / quantity: conditional `Change` for single-item subscriptions.
- Dunning: conditional `View` into the recovery drill when any campaign has run.

Delete or fold existing noise:
- Delete the Status KPI and Canonical predicates KPI from the page surface.
- Fold current price into the Plan / price summary row.
- Delete raw timeline-row count from the KPI grid.
- Delete the standalone dunning card; fold state into the Dunning row and drill section.
- Delete `data-role="subscription-related-billing"` duplicate card after migrating unique links.
- Flatten card-in-card content; one visible border level per band.

## Action Menu Contract

Add a distinct `DropdownMenu.action_menu/1` for LiveView actions. It is not the existing link-shaped `dropdown_menu/1`.

| Area | Contract |
|------|----------|
| Trigger | Native `<details>` disclosure with a button-like summary labeled `More actions`; `aria-haspopup="menu"`; `data-ax-action-overflow-menu`. |
| Items | Use `<button role="menuitem" phx-click>` items, not links. Each item has a plain label plus visually-hidden subscription context. |
| Grouping | Groups render in this order: `Edit billing`, `Collection`, `Danger zone`. Danger zone is last and separated by a divider. |
| Dismissal | Reuse `dropdown.js` grammar: Escape and outside click close idempotently and restore focus to the trigger. |
| Motion | Set `transform-origin: top right`; use existing `--ax-dur-2`, `--ax-ease-out`, and `--ax-rise-sm`. No new token. |
| Provider gating | Unavailable actions are absent, never disabled. Reuse `@swap_plan_available`, `!braintree_processor?/1`, `quantity_change_available?/1`, and `quantity_item_changes_available?/1`. |

Menu items:
- Edit billing: `update_quantity`, `add_item`, `update_item_quantity`, `remove_item`.
- Collection: `pause`, `resume`.
- Danger zone: `cancel_now` as `Cancel immediately`, `comp_subscription` as `Comp this subscription`.

Destructive items never execute directly from the menu. They open the step-up modal path through the existing `confirm_action` / `StepUp.require_fresh/4` route.

## Overlay And Drawer Contract

Phase 195 must ship the canonical `<.overlay>` public API and route the subscription side-drawer through it. Phase 199 sweeps all remaining overlay sites; it should not have to redesign the API.

| Primitive | Contract |
|-----------|----------|
| Root | Mount `#ax-overlay-root` as a body-level child in the root layout. Overlay shells render there, outside transformed/filtered/contained page ancestors. |
| Presentations | One primitive with `presentation={:modal | :drawer | :popover}`. Drawer and modal use `role="dialog"` and `aria-modal="true"`; action-menu popover does not use modal semantics. |
| Layers | Use existing z tokens: dropdown 200, popover 300, drawer 400, modal 500, toast 600. Scrim and panel share one isolated shell; scrim local z=0, panel local z=1. |
| Scroll lock | Add ref-counted, iOS-safe `scroll_lock.js`: save scrollY, lock body/html, restore exact scroll position, compensate gutter via CSS/custom property, and allow internal overlay scroll with `overscroll-behavior: contain`. |
| Background isolation | Toggle `inert` on `#accrue-admin-shell` while any modal/drawer overlay is open. Add `aria-hidden` only if needed as a compatibility companion. |
| Focus | Reuse the shipped `FocusTrap` hook for focus into panel, trap, Escape dispatch, and restore. Initial focus target must show an instant visible focus ring. |
| Dismissal | Backdrop click and Escape dispatch the same close event. Rapid open-close-open within 240ms must settle to the correct final state with no ghost shell. |
| Drawer geometry | Desktop/tablet: right edge-docked drawer, `inset: 0 0 0 auto`, width `min(34rem, 92vw)`, enter from right with `translateX(100%)` toward the final edge. Mobile: bottom sheet, enter with `translateY(100%)`. |
| Motion | Enter <= `--ax-dur-3` (240ms), exit `--ax-dur-exit` (140ms), curves from `--ax-ease-out` / `--ax-ease-in`. Reduced-motion inherits the existing token override; no JS `matchMedia`. |

`DetailDrawer.detail_drawer/1` becomes a thin wrapper around `<.overlay presentation={:drawer}>` and preserves its existing slot vocabulary. If plan budget is tight, `StepUpAuthModal` may temporarily remain on its current shell, but the modal presentation must exist and the new drawer path must be canonical.

Portal mechanism decision:
- Prefer LiveView `phx-portal` only after the planner confirms it exists in the pinned LiveView 1.1 line used here.
- If unavailable, implement a local portal hook behind the same `<.overlay>` API. Do not expose two public overlay paths.

## Machine-Checkable Invariants

These invariants are the minimum UAT surface for Phase 195.

| Invariant | Selector / Probe |
|-----------|------------------|
| Exactly one page heading | `page.locator("h1").count() === 1` |
| DETAIL primary actions cap | `[data-ax-primary-action]` count is `<= 2` |
| Overflow action menu exists | `[data-ax-action-overflow-menu]` count is `>= 1` when more than two actions are available |
| No pre-expanded action forms | `[data-ax-action-band] form:visible` count is `0` on initial page load |
| One related strip | `[data-ax-related-resources]` count is exactly `1` |
| Duplicate card removed | `[data-role="subscription-related-billing"]` count is `0` |
| Drawer above scrim | `assertTopPointerTarget` passes on drawer primary action and one focusable drawer control |
| Body scroll locked | Body/page scroll position is unchanged after wheel/touch over scrim; no gutter jump in a stable header bounding box |
| Background inert | `#accrue-admin-shell[inert]` is present while drawer/modal is open and absent after close |
| Focus integrity | Focus enters drawer, traps within drawer, Escape closes, focus restores to trigger |
| Mobile geometry | Drawer renders as bottom sheet below `--ax-bp-md`; desktop renders as right-docked drawer |
| Reduced motion | New overlay/drawer/menu classes inherit existing reduced-motion token override |

Judge-graded rubric checks:
- Summary-list answers "what state, what's wrong" above the fold.
- No card-in-card double border.
- Tabs are absent for primary state and critical actions.
- Action hierarchy reads as calm operator tooling: common safe action visible, dangerous immediate actions buried and gated.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filter toolbar to LiveView event | Browser filter input crosses into `data_table_filter` events and URL params. |
| DataTable state marker to user perception | State markers and copy tell operators whether data is loading, filtered away, absent, or populated. |
| CSS truncation to visible identifiers | Truncation can hide meaningful identity or expose raw IDs as primary content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-196-10 | Tampering | DataTable filter toolbar | mitigate | Preserve `phx-change` and `phx-submit` to caller-owned `data_table_filter`; do not add client-only filter state. |
| T-196-11 | Information Disclosure | FilterChipBar clear-all href | mitigate | FilterChipBar only renders caller-supplied href and tests require owner-scope preservation in Plan 04. |
| T-196-12 | Spoofing | DataTable empty/loading states | mitigate | Explicit D-12 state markers and D-14 skeleton a11y prevent ambiguous or misleading loading/empty presentation. |
| T-196-13 | Denial of Service | Loading fixture | mitigate | Fixture requires explicit test assign and includes no sleep, polling loop, or broad async rewrite per D-13. |
| T-196-14 | Information Disclosure | CSS/column truncation | mitigate | Enforce `min-width: 0` with ellipsis blocks and keep raw IDs out of primary identity in Plan 04. |
</threat_model>

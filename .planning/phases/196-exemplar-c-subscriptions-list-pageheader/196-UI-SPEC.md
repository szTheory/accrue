# Phase 196 - UI Design Contract

> Visual and interaction contract for the Subscriptions list exemplar and shared PageHeader slot API. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - custom `ax-*` CSS tokens and Phoenix components are the SSOT |
| Preset | not applicable - project is Phoenix LiveView, not React/Next/Vite |
| Component library | `Phoenix.Component` function components plus existing LiveView components (`DataTable`, `FilterChipBar`, `StatStrip`, `Breadcrumbs`, `StatusBadge`) |
| Icon library | `AccrueAdmin.Components.Icon` inline icon primitive |
| Font | Geist for UI text; Geist Mono for IDs/code |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner spacing, compact inline rhythm |
| sm | 8px | Compact controls, filter chips, breadcrumb gaps |
| md | 16px | Default control and toolbar gaps |
| lg | 24px | PageHeader slot gaps, section padding, filter chip card padding |
| xl | 32px | Page-level gaps between header, chips, and table |
| 2xl | 48px | Empty-state vertical padding |
| 3xl | 64px | Major page scroll margins and large empty-state treatment |

Exceptions: `--ax-space-2xs` / 2px is allowed only for documented dense-table hairlines and segmented-control internal thumb gaps. Icon-only controls keep the existing 44px minimum target (`2.75rem`) when used in header actions. Do not add raw px spacing outside the existing source-guard allowlist.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 24px | 600 | 1.2 |

Use only weights 400 and 600 for this phase. `PageHeader` title uses the existing `.ax-display` treatment. Table body text uses 16px/400 where space allows; dense secondary metadata and chips use 14px/600 or 14px/400 through existing role utilities. Primary plumbing IDs, if shown, use Geist Mono at the existing small/code role and must remain visually secondary.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` light `#fafbfc`, dark `#0f1318` | Page canvas and main content background |
| Secondary (30%) | `--ax-elevated` light `#ffffff`, dark `#171d24`; `--ax-sunken` for recessed controls | Header slot surfaces, filter chip bar, table shell, empty-state card, segmented/filter controls |
| Accent (10%) | `--ax-accent` bound to Accrue cobalt `#5d79f6`; readable `--ax-accent-readable`; filled `--ax-accent-strong` | Focus rings, active navigation/segmented state, At risk/All active chip treatment, links, primary CTA if rendered |
| Destructive | `--ax-danger` `#d64b4b` with `--ax-danger-readable` | Destructive actions only; none are introduced in Phase 196 |

Accent reserved for: keyboard focus rings, active filter/scope chips, active segmented controls, inline links, and a single primary CTA if the page renders one. Do not use accent as a general row hover color, decorative page wash, or status substitute. Lifecycle state uses existing semantic status colors (`moss`, `amber`, `slate`, `cobalt`) through `StatusBadge` or chip patterns.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | View all subscriptions |
| Empty state heading | No subscriptions yet. |
| Empty state body | Subscriptions appear after a customer completes checkout. |
| Error state | Subscriptions could not be loaded. Retry the request or check the organization scope. |
| Destructive confirmation | none - Phase 196 introduces no destructive actions |

Additional required state copy:

| State | Heading | Body | Required affordance |
|-------|---------|------|---------------------|
| Work queue empty | Nothing at risk. | No past-due or canceling subscriptions. View All to see every subscription. | `View all subscriptions` or an `All` chip/link to `?view=all` |
| Filtered empty | No subscriptions match these filters. | Clear filters or adjust the search to see subscriptions. | `Clear filters` / clear-all control |
| Loading skeleton | Loading subscriptions. | none visible beyond one status label | One `role="status"` label; decorative skeleton cells are `aria-hidden` |

Copy source is `AccrueAdmin.Copy`. Touched inline literals on Subscriptions must move through copy functions. Voice stays measured, exact, native, and short; no sales language, no exclamation marks, no fake totals.

## Phase Surface Contract

| Surface | Contract |
|---------|----------|
| `AccrueAdmin.Components.PageHeader.page_header/1` | Stateless Phoenix function component. Required attrs: `breadcrumbs` list and `title`. Optional attrs: `heading_id`, `class`, `component_group`, `:rest`. Slots: `:description`, `:stat_strip`, `:actions`, `:filter_toolbar`. |
| PageHeader selectors | Render `data-ax-page-header`, `data-ax-page-title`, `data-ax-page-actions` when actions exist, `data-ax-page-filter-toolbar` when filters exist, and `data-component-group="page-header-actions-breadcrumbs"`. |
| PageHeader semantics | Renders the breadcrumb trail and exactly one content `<h1>` per page. It owns layout/orientation only; it must not own filters, paths, pagination, query decoding, backend IDs, AppShell, flashes, provider gating, or resource behavior. |
| Subscriptions page grammar | `PageHeader` -> `FlashGroup` -> stat strip/filter toolbar through PageHeader slots -> chip row with result count and clear-all -> `DataTable`. Desktop is table-first; mobile degrades to stacked row cards below the existing md breakpoint. |
| Propagation boundary | Apply `PageHeader`, LIST markers, and state refinements only to Subscriptions in Phase 196. Customers, invoices, payments, coupons, promotion codes, webhooks, events, and connect move in Phase 197. |

## List Interaction Contract

| Interaction | Required behavior |
|-------------|-------------------|
| Default queue | Bare `/subscriptions` represents the operator work queue with `past_due,canceling` backend status, presented as `At risk`. The disconnected first paint must not show unrelated first-run empty copy before LiveView connect. |
| All escape hatch | `All` is one chip/click away. Removing or clearing the default queue must land on `?view=all`, preserving owner scope such as `org`. |
| Filters | Filters remain server-driven, URL-backed, and LiveView patch-based. No client-only filter state. `PageHeader` may render a `:filter_toolbar` slot, but caller-owned Subscriptions/DataTable code keeps `phx-change="data_table_filter"` and query behavior. |
| Chip row | Active filters render in one stable row with `[data-ax-filter-chips]`, `[data-ax-result-count]`, `[data-ax-clear-all]`, one removable chip per active constraint, and the work-queue/All affordance. |
| Result count | Use honest visible-row copy such as `Showing N subscriptions`. Do not imply a query-wide exact total while cursor pagination is the source. |
| Clear-all | Preserve owner scope and remove search/status/customer filters. First-run empty must not render clear filters; filtered empty must render clear filters. |
| Pagination | Do not render pagination controls when there is no next page. Keep cursor pagination; do not add infinite scroll as the main list model. |

## List State Contract

| State | Selector | Visual treatment | Notes |
|-------|----------|------------------|-------|
| Populated | `[data-ax-list="subscriptions"][data-ax-state="populated"]` | Dense table shell at md+; mobile card list below md; row rhythm stays compact enough for at least 8 rows above the fold at 1280x800 when seeded data allows. | Desktop column priority is identity -> state -> plan/amount -> renews/ends -> signals. |
| First-run empty | `[data-ax-state="first-run-empty"][data-ax-empty-reason="first-run"]` | Existing `.ax-empty` non-interactive card with no hover/cursor affordance. | No clear-filters affordance. |
| Filtered empty | `[data-ax-state="filtered-empty"][data-ax-empty-reason="filter"]` | Same empty-state structure, distinct copy, clear filters action present. | Must not share the first-run copy string. |
| Queue empty | `[data-ax-state="filtered-empty"][data-ax-empty-reason="queue"]` | Quiet positive empty state: "Nothing at risk." | Provides View All / All chip path to `?view=all`. |
| Loading skeleton | `[data-ax-state="loading-skeleton"]` | Table-shaped skeleton rows on desktop; card-shaped skeleton rows on mobile. Uses existing `.ax-skeleton`; reduced-motion is static. | Fixture/dev/test state unless a real async path exists. Production must not fake loading on every patch. |

Keep existing `data-role` and `data-phase191-focus` hooks while adding the new `data-ax-*` markers.

## Column Contract

| Priority | Column | Visual rule |
|----------|--------|-------------|
| 1 | Customer / subscription | Customer name or email is the primary scan label. Subscription processor/internal ID is secondary mono-small text only when useful. |
| 2 | State | Human lifecycle labels: `Active`, `Trialing`, `At risk`, `Canceling at period end`, `Paused`, `Canceled`. Use `StatusBadge` or existing badge/chip tones. |
| 3 | Plan / amount | Use resolver-backed plan/amount metadata when available. If exact money is unavailable, show honest plan/quantity text. Do not fake MRR. |
| 4 | Renews / ends | Current period end, cancellation boundary, or ended boundary in readable date/time copy. |
| 5 | Signals | Compact billing/tax/ownership chips. |

Raw UUIDs, raw processor IDs, raw flag names, and backend plumbing labels are not primary columns. Truncating cells must carry `min-width: 0` in the relevant CSS block and use existing ellipsis/truncation guard rules.

## Accessibility And Motion

| Area | Contract |
|------|----------|
| Heading | Exactly one content `<h1>` on Subscriptions after PageHeader adoption. |
| Breadcrumb | Use the existing breadcrumb nav with `aria-label="Breadcrumb"` and `aria-current="page"` on the current crumb. |
| Focus | All interactive chips, links, segmented controls, and clear actions expose visible `:focus-visible` styles using `--ax-focus-ring`. |
| Skeleton | Loading state uses `aria-busy`, one `role="status"` label, no focus movement, and `aria-hidden` decorative skeleton cells. |
| Mobile | Card degradation preserves the same priority facts in label/value order. Do not force unreadable desktop table scroll as the primary mobile experience. |
| Motion | Use existing duration tokens only. Skeleton shimmer respects `prefers-reduced-motion: reduce`; no row stagger or decorative motion. |

# Phase 198 - UI Design Contract

> Visual and interaction contract for Phase 198: Propagate DETAIL + analytics. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 198 is conformance propagation across existing `accrue_admin` LiveView pages. It does not create new product surface, routes, billing primitives, Tailwind config, shadcn registry usage, or a generic page DSL. The canonical behavior sources are `accrue_admin/guides/spec-detail.md`, `accrue_admin/guides/spec-overview.md`, Phase 195 subscription DETAIL exemplar, Phase 194 Recovery overview exemplar, `198-CONTEXT.md`, and `198-RESEARCH.md`.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - custom `ax-*` admin design system |
| Preset | not applicable |
| Component library | Phoenix LiveView function components: `Detail`, `DropdownMenu`, `DetailDrawer`, `Overlay`, `StepUpAuthModal`, `RelatedResources`, `Timeline`, `JsonViewer`, `AtRiskTable`, `FunnelChart`, `CampaignTimeline`, `StatusBadge`, `PageHeader`, `Breadcrumbs` |
| Icon library | Heroicons through `AccrueAdmin.Components.Icon`; icons inherit `currentColor` and use `--ax-icon-sm`, `--ax-icon-md`, `--ax-icon-lg` |
| Font | `--ax-font-sans`: Geist, system-ui, Segoe UI, sans-serif; `--ax-font-mono`: Geist Mono, SFMono, Consolas, monospace |

Source decisions:

- `components.json`, `tailwind.config.*`, and `postcss.config.*` are absent. shadcn is not initialized and is not applicable because this is an Elixir/Phoenix LiveView package, not React/Next/Vite.
- `accrue_admin/assets/css/theme.css` is the implementation token SSOT. `brandbook/tokens/README.md` documents the brand layer, but Phase 198 must consume existing admin `--ax-*` tokens.
- CSS or JS source changes in `accrue_admin/assets` must be rebuilt into the committed admin static bundle before completion.
- Copy changes belong in `AccrueAdmin.Copy` or resource copy modules, followed by any required generated copy fixture update.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--ax-space-xs`) | Icon gaps, row action gaps, compact inline controls |
| sm | 8px (`--ax-space-sm`) | Summary row micro rhythm, action menu internals, chip/control gaps |
| md | 16px (`--ax-space-md`) | Default summary-list rows, drill-section content, drawer fields |
| lg | 24px (`--ax-space-lg`) | Summary card padding, drill-section padding, drawer panel padding |
| xl | 32px (`--ax-space-xl`) | Band-to-band spacing in the DETAIL vertical spine |
| 2xl | 48px (`--ax-space-2xl`) | Separation before lazy Activity / Raw data |
| 3xl | 64px (`--ax-space-3xl`) | Page-level scroll margins and major layout breathing room only |

Exceptions:

- Existing `--ax-space-2xs` (2px) may remain only where already used by shared components for dense summary/action-menu micro gaps. Do not introduce new 2px page spacing.
- 1px borders and hairlines remain border treatment, not spacing scale.
- Touch targets for icon-only or narrow-viewport controls must stay at least 44px where finger-tappable.
- Drawer geometry may use structural dimensions such as `width: min(34rem, 92vw)` and translate percentages. Those are layout geometry, not spacing tokens.
- No new raw `px` values for padding, margin, or gap outside the existing Phase 193 source-guard allowlist.

DETAIL rhythm:

- Summary card to action band: `--ax-space-lg`.
- Action band to first drill section: `--ax-space-xl`.
- Drill sections: `--ax-space-md` internal gap, `--ax-space-lg` padding when framed.
- Related strip: once, after primary drills and before lazy bottom sections.
- Lazy Activity / Raw data: bottom of page with `--ax-space-2xl` separation from the related strip.

## Typography

Use exactly two weights for new/touched UI: 400 and 600. Do not introduce 500, 700, viewport-scaled type, or negative tracking.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Summary key / eyebrow | 12px (`--ax-type-xs`) | 600 | 1.4 (`--ax-leading-normal`) |
| Metadata / compact value | 14px (`--ax-type-sm`) | 400 or 600 | 1.4 (`--ax-leading-normal`) |
| Body / drill title | 16px (`--ax-type-md`) | 400 body, 600 title | 1.4 body, 1.2 title |
| Summary title / hero metric | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Typography contract:

- Every target page renders exactly one content `<h1>`, owned by the primary summary/header component.
- Summary-list keys may use uppercase tracking through existing `ax-*` styles; row values, action labels, and body copy use normal tracking.
- IDs, raw payload keys, and backend plumbing use Geist Mono only as secondary metadata or lazy Raw data content. They must not be the primary scan label.
- Recovery hero metric pair uses metric/display treatment but must not become a KPI wall; the work queue remains visually adjacent and above the supporting funnel.
- Long explanatory copy may use `--ax-leading-relaxed` (1.5). Dense operator detail rows use existing 1.4 body rhythm.

## Color

Use theme-aware `ax-*` semantic tokens. Phase 198 introduces no new hues.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (`#fafbfc` light / `#0f1318` dark) | Page canvas and dominant admin background |
| Secondary (30%) | `--ax-elevated` (`#ffffff` light / `#171d24` dark), `--ax-sunken`, `--ax-border` | Summary cards, drill sections, action menu panels, drawer panels, related strip, lazy sections |
| Accent (10%) | host `--ax-accent` with Accrue cobalt reference `#5d79f6`; `--ax-accent-readable`; `--ax-focus-ring` | Reserved elements listed below |
| Destructive | `--ax-danger` `#d64b4b`, `--ax-danger-readable`, `--ax-status-danger-*` | Destructive actions, danger menu group, destructive step-up context only |

Accent reserved for:

- Visible primary action buttons such as `Finalize invoice`, `Pay invoice`, `Refund charge`, `Replay webhook`, and `Edit platform fee override`.
- Summary-list row `Change` / `View` actions that are true links or LiveView actions.
- Keyboard `:focus-visible` rings and selected/active disclosure state.
- Non-danger action-menu hover/focus background.
- Recovery work-queue row links and active window selector state.

Accent must not be used for static headings, decorative dividers, inactive summary values, raw JSON chrome, status badges, money semantics, or danger actions. Lifecycle state uses `StatusBadge` and `--ax-status-*`; financial sign uses `--ax-money-*`; warning/attention uses amber; destructive/failed terminal state uses danger.

## Copywriting Contract

Voice stays measured, exact, native, and durable. Copy names the operator job and the affected object. Avoid sales language, exclamation marks, vague adjectives, backend flag names, and route/internal module names in visible UI.

| Element | Copy |
|---------|------|
| Primary CTA | Page-specific verb + noun: `Finalize invoice`, `Add line item`, `Pay invoice`, `Refund charge`, `Replay webhook`, `Edit platform fee override`. Read-only pages render no primary CTA. |
| Empty state heading | `No activity yet` for lazy Activity when no events exist after expansion; page-specific compact variants may name the object, e.g. `No invoice activity yet`. |
| Empty state body | `Open this section to load activity.` before lazy load; after load with no rows, `This record has no recorded activity yet. Core details remain available above.` |
| Error state | `Details could not be loaded. Retry the request or return to the list.` Action errors use `Action could not be completed. Review the values, then try again.` |
| Destructive confirmation | Sensitive actions route through step-up with `Confirm your identity to continue.` and resource-specific context in the drawer/modal title. |

Required destructive or sensitive action handling:

| Action | Visible label | Confirmation approach |
|--------|---------------|-----------------------|
| Invoice void | `Void invoice` | Overflow danger group only; `StepUp.require_fresh/4` before execution |
| Invoice mark uncollectible | `Mark uncollectible` | Overflow danger group only; `StepUp.require_fresh/4` before execution |
| Charge refund | `Refund charge` | One visible primary action opens drawer; submit is step-up gated |
| Webhook replay | `Replay webhook` | Visible only for failed/dead unambiguous rows; drawer confirmation plus step-up |
| Connect fee override | `Edit platform fee override` | One visible primary action opens drawer; save is step-up gated |
| Customer payment method delete | `Delete payment method` | Drawer or step-up modal after intent; never inline on initial load |
| Customer default payment method change | `Set default payment method` | Drawer after intent; server-side validity check required |

Summary row action labels:

- Use `Change` only when the row action changes that exact row.
- Use `View` when navigating to the related object or drill section.
- Every repeated `Change` / `View` label needs visually-hidden context that names the row and resource, for example `Change collection method for invoice INV-1024`.
- Unavailable actions are absent. Do not render disabled-looking-enabled controls.

## Phase Surface Contract

| Area | Contract |
|------|----------|
| In scope | Customer, invoice, charge/payment, coupon, promotion-code, connect-account, webhook, event, Recovery analytics, Campaign analytics drill-down |
| Out of scope | New billing primitives, new public routes/APIs, `accrue_portal`, Tailwind migration, Storybook completeness, global overlay sweep, transformed-ancestor audit, full microcopy sweep, fixture stress, final zero-regression sign-off |
| Runtime abstraction | Do not introduce a generic `DetailPage` or `AnalyticsPage` DSL/schema. Use page-local helpers and existing stateless components. |
| State ownership | LiveViews own URL params, active peer subview, lazy-load flags, drawer state, validation, provider/status gates, step-up, and action execution. |
| Helper shape | Prefer pure page-local helpers: `summary_rows/1`, `primary_actions/1`, `action_menu_groups/1`, `related_items/3`, `timeline_items/1`, `raw_payload/1`. |
| Copy ownership | New/touched copy goes through `AccrueAdmin.Copy` or resource copy modules. |

Every target detail page must use this visual order:

1. Breadcrumbs or existing orientation.
2. `Detail.summary_card/1` with one `<h1>`.
3. `Detail.summary_list/1` for always-visible facts.
4. `data-ax-action-band` with at most two visible `[data-ax-primary-action]` buttons and one optional `[data-ax-action-overflow-menu]`.
5. Page-specific drill sections, with the most relevant drill open/first.
6. Exactly one `[data-ax-related-resources]` wrapper around `RelatedResources.related_resources/1`.
7. Lazy `[data-ax-lazy-activity]`.
8. Lazy `[data-ax-lazy-json]`.

DETAIL prohibitions:

- No top-level KPI grids on detail pages.
- No action forms visible on initial load.
- No duplicate related-resource cards.
- No card-in-card double-border nesting.
- No tabs except Customer peer record-set links.
- No raw JSON, webhook payload, metadata dump, or event timeline above primary state.

## Per-Page DETAIL Contract

| Page | Summary rows | Drills | Actions | Lazy bottom |
|------|--------------|--------|---------|-------------|
| Customer | Owner, processor customer ID, locale/timezone, default payment method, billing health, tax risk, access headline when cheap | Payment methods; Access and entitlements; Tax and ownership; peer record-set subviews for Subscriptions, Invoices, Payments | Payment method actions open drawer/modal after intent; no broad `More` tab | Activity and Raw data |
| Invoice | Status, customer, amount due/remaining/paid, due/finalized boundary, collection method, PDF/hosted URL state, tax/finalize risk, line-item count | Collection and actions; Line items; Tax and documents | Draft: `Finalize invoice` and optional `Add line item`; collectible: `Pay invoice`; overflow groups `Collection`, `Documents`, `Danger zone` | Activity and Raw data |
| Charge/payment | Status, customer, amount, processor, inserted/created boundary, net/fee/refund signal | Fee breakdown; Refunds | One visible `Refund charge` primary action opens drawer; step-up on submit | Activity and Raw data |
| Coupon | Valid state, discount, duration, redeem-by, max redemptions, current redemptions, promotion-code count | Promotion codes; Projection details | No action band unless a real valid action exists | Activity and Raw data |
| Promotion code | Active state, code, parent coupon, expiry, redemption count/limit, customer restriction when present | Parent coupon; Redemption boundaries | No empty overflow menu; read-only unless a real valid action exists | Activity and Raw data |
| Connect account | Account readiness, owner, country, charges enabled, payouts enabled, onboarding/details submitted, override state | Capabilities/requirements; Platform fee policy | One visible `Edit platform fee override` primary action opens drawer; step-up on save | Activity and Raw data |
| Webhook | Status, processor event ID, endpoint/type, received/processed boundaries, verification, attempts, livemode, derived event count | Replay eligibility; Dispatch/retry lifecycle; Derived ledger rows | `Replay webhook` only for failed/dead replayable rows; no disabled replay button for non-replayable rows | Activity and Raw payload/metadata |
| Event | Type, actor, subject, source webhook, recorded time, livemode when available | Event details | No action band unless a real valid action exists | Activity and Raw data when payload exists |

Page-specific notes:

- Customer preserves compatibility for existing `?tab=` URLs, including `payments` as the visible label for internal `charges`.
- Customer removes the broad `More` bucket. `Payment methods`, `Entitlements`, `Events`, and `Metadata` move into summary rows, drills, lazy Activity, and lazy Raw data.
- Invoice danger actions are last in the overflow menu and never execute directly from the menu.
- Webhook non-replayable state uses precise copy in the Replay eligibility drill rather than a disabled button.
- Coupon, promotion-code, and event must not render empty action chrome.
- Compact reference pages still render lazy bottom sections. If an activity source is empty, the section shows the empty copy after expansion rather than omitting the contract marker.

## Analytics Contract

| Page | Contract |
|------|----------|
| Recovery | Recovery-specific overview, not Dashboard clone. Order is orientation/window selector, hero metric pair, at-risk work queue, supporting funnel. Work queue appears before any chart/funnel visualization. |
| Campaign | Detail drill-down opened from Recovery rows. Use `Detail.summary_card`, concise campaign facts, and `CampaignTimeline` as the primary drill. Do not add overview KPIs or chart-wall structure. |

Recovery markers and visual order:

- Root: `data-ax-overview="recovery"` or equivalent page-flow root marker.
- Hero pair: `data-ax-recovery-hero` for Recovered MRR / Lost MRR.
- Work queue: `data-ax-recovery-work-queue`, backed by `AtRiskTable.at_risk_table/1`.
- Supporting visualization: `data-ax-recovery-supporting-funnel`, backed by existing `FunnelChart.funnel_chart/1`.
- Page-flow assertions must judge Recovery by this order, not by Dashboard's literal attention-rail -> task-launcher -> kpi-cluster DOM order.

Analytics prohibitions:

- No chart before the at-risk table on Recovery.
- No new time-series chart in Phase 198.
- No `AnalyticsPage` abstraction.
- No Campaign KPI grid.
- No stale docs that describe `AtRiskTable` as below the funnel.

## Action, Drawer, And Step-Up Contract

| Area | Contract |
|------|----------|
| Primary actions | Maximum two visible buttons with `data-ax-primary-action`. Choose only the highest-frequency valid jobs for the current status/provider. |
| Overflow | Render one `DropdownMenu.action_menu/1` only when more than two valid actions exist. Group order: normal/edit, collection/documents, danger last. |
| Forms | Zero visible forms inside `[data-ax-action-band]` on initial load. Forms appear only inside `DetailDrawer` or step-up modal after operator intent. |
| Drawer | Use `DetailDrawer.detail_drawer/1` backed by `Overlay.overlay/1`. Drawer owns action form content; LiveView owns state and validation. |
| Step-up | Use `StepUp.require_fresh/4` for money-moving, destructive, replay, and fee-override actions unless a lower-risk reason is explicitly recorded in the plan. |
| Server authority | LiveView events must re-check action validity server-side. Hidden or omitted actions cannot be trusted as authorization. |
| Dismissal | Cancel/backdrop/Escape must return to the stable detail page without stale pending form state. Full cross-page overlay audit remains Phase 199. |

Do not introduce client-only action state. The canonical event shape is: open/select action, prepare/validate drawer form, confirm action, optional step-up, execute server operation, refresh record, close or show resource-specific error.

## Customer Peer Record-Set Contract

Customer is the only permitted tab-like exception in Phase 198.

| Rule | Contract |
|------|----------|
| Allowed labels | `Subscriptions`, `Invoices`, `Payments` only |
| Implementation | Link/patched subviews are preferred. Do not add ARIA `tablist` / `tab` roles unless full keyboard semantics are implemented. |
| URL compatibility | Accept existing `?tab=charges` and `?tab=payments`; visible label is always `Payments`. |
| Forbidden labels | `More`, `Payment methods`, `Entitlements`, `Events`, `Metadata` |
| Forbidden behavior | Primary state, payment method actions, access state, events, and metadata must not be hidden behind horizontal tabs. |

If a narrow reusable link-subview component is extracted, it must remain a navigation helper only. It must not own page state, data loading, or a generic detail schema.

## Interaction And Accessibility Contract

| Area | Contract |
|------|----------|
| Heading | Exactly one content `<h1>` on every target page. |
| Summary list | `Detail.summary_list/1` rows expose key/value semantics and row action hidden context. |
| Focus | Newly added links, buttons, menu items, drawer controls, and lazy section summaries use visible `:focus-visible` styles through existing focus tokens. |
| Keyboard | Disclosure menus and drawers preserve Escape/cancel behavior. Customer peer subviews remain normal links unless full ARIA tabs ship. |
| Mobile | Summary rows collapse to one column below the content breakpoint. Drawers render as mobile sheets through existing overlay CSS. No horizontal clipping or overlapping action bars. |
| Disabled state | Unavailable actions are omitted. Do not render controls that appear enabled but cannot act. |
| Non-interactive state | Empty or static state panels carry no pointer cursor, hover surface, role button, or fake affordance. |
| Raw payloads | Raw JSON is escaped, monospace, lazy, and bottom-positioned. |
| Owner scope | Related links, row actions, tab/subview links, and clear/back links preserve `current_owner_scope` through `ScopedPath` or existing route helpers. |

## Machine-Checkable Invariants

| Invariant | Selector / probe |
|-----------|------------------|
| One page heading | `page.locator("h1").count() === 1` for each target page |
| Summary list present | `[data-ax-summary-list]` count is exactly `1` on every target detail and Campaign page |
| Primary action cap | `[data-ax-primary-action]` visible count is `<= 2` per detail page |
| Overflow bounded | `[data-ax-action-overflow-menu]` count is `0` when two or fewer valid actions exist, `1` when more than two valid actions exist |
| No initial action forms | `[data-ax-action-band] form:visible` count is `0` on initial load |
| One related strip | `[data-ax-related-resources]` count is exactly `1` on every target detail page. If no links exist, render the wrapper with a quiet empty state rather than omitting the strip. |
| Lazy activity | `[data-ax-lazy-activity]` exists and does not eagerly load timeline rows before expansion |
| Lazy raw JSON | `[data-ax-lazy-json]` exists and does not eagerly render raw payload above the fold |
| No KPI-first details | Target detail pages do not render top-level `.ax-kpi-grid` as their first major content band |
| Customer peer tabs only | Customer visible peer nav labels are exactly Subscriptions, Invoices, Payments; no visible `More` bucket |
| Recovery order | hero metric pair index < at-risk work-queue index < supporting funnel index |
| Campaign detail | Campaign has `Detail.summary_card`, no top-level KPI grid, and `CampaignTimeline` visible as the main drill |

Representative deeper browser interaction coverage must include Customer, Invoice, Charge, Webhook, Connect Account, Recovery, and Campaign. The all-page smoke should cover desktop/mobile and light/dark for markers and clipping. Full exhaustive matrix and final scorecard remain Phase 200 ownership.

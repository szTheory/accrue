# Phase 199 - UI Design Contract

> Visual and interaction contract for Phase 199: Cross-cutting interaction/overlay correctness + fixture stress + microcopy. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 199 is a cross-cutting correctness pass over the already-conformed `accrue_admin` page surface. It does not redesign the admin UI, add billing primitives, add public routes, migrate Tailwind, or complete Phase 200's final Storybook/scorecard/sign-off gates. The contract is to make the existing overlay/floating primitives structurally correct on composed pages, stress real seeded flows and boundary data, and bring page-level copy into one brand voice.

Canonical sources: `199-CONTEXT.md`, `199-RESEARCH.md`, `.planning/REQUIREMENTS.md` IXN-01..04 / FIX-01..02 / CPY-01, `accrue_admin/assets/css/theme.css`, `accrue_admin/guides/spec-detail.md`, `accrue_admin/guides/spec-list.md`, `accrue_admin/guides/spec-overview.md`, `accrue_admin/guides/motion.md`, and `brandbook/voice.md`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--ax-space-xs`) | Icon gaps, inline padding, focus-ring offsets, compact action text gaps |
| sm | 8px (`--ax-space-sm`) | Dropdown rows, compact form/control gaps, summary-list action gaps |
| md | 16px (`--ax-space-md`) | Default field spacing, overlay body gaps, fixture-state content gaps |
| lg | 24px (`--ax-space-lg`) | Drawer/modal padding, section padding, empty-state rhythm |
| xl | 32px (`--ax-space-xl`) | Band-to-band spacing and drawer footer separation |
| 2xl | 48px (`--ax-space-2xl`) | Major lazy-section or stress-fixture separation |
| 3xl | 64px (`--ax-space-3xl`) | Page-level breathing room only |

Exceptions:

- Existing `--ax-space-2xs` (2px) may remain only in existing dense table/chip/underline micro spacing. Do not introduce new 2px page or overlay layout spacing.
- 1px borders and hairlines remain border treatment, not spacing scale.
- Touch targets for icon-only or narrow-viewport controls must remain at least 44px where finger-tappable.
- Overlay geometry may use structural dimensions such as `width: min(34rem, 92vw)`, `calc(100dvh - var(--ax-space-lg))`, and translate percentages. Those are geometry constraints, not spacing tokens.
- No new raw `px` values for padding, margin, or gap outside the existing source-guard allowlist.

Overlay rhythm:

- Modal/drawer shell padding: `--ax-space-lg`.
- Overlay header to body: `--ax-space-lg`.
- Overlay body field/form gap: `--ax-space-md`.
- Overlay footer separation: `--ax-space-xl` top margin with `--ax-space-md` top padding.
- Popover/dropdown internals: `--ax-space-sm`, with `--ax-space-xs` only for icon/text or dense metadata gaps.

## Typography

Use exactly two weights for new/touched UI: 400 and 600. Do not introduce 500, 700, viewport-scaled type, or new negative tracking. Existing token tracking may remain where already documented.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 20px (`--ax-type-lg`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display / modal-title maximum | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Typography contract:

- Overlay titles use Heading or smaller. Do not use hero/display type inside compact modals, drawers, dropdowns, or the command palette.
- Modal and drawer body copy uses Body or compact Body Small; labels use Label. Long guidance may use `--ax-leading-relaxed` (1.5) only for multi-line prose.
- Action labels are short visible verbs plus affected nouns where space allows. Repeated compact labels such as `Change` and `View` require visually-hidden object context.
- IDs, processor values, raw payload keys, and code-like content use Geist Mono only as secondary metadata or lazy raw-data content. They must not become the primary scan label.
- Focus rings appear instantly and remain visible around the focused control; no focus-ring animation is permitted.

## Color

Use theme-aware `ax-*` semantic tokens. Phase 199 introduces no new hues.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (`#fafbfc` light / `#0f1318` dark) | Page canvas, drawer surface, modal body background |
| Secondary (30%) | `--ax-elevated` (`#ffffff` light / `#171d24` dark), `--ax-sunken`, `--ax-border` | Cards, panels, dropdowns, command palette, filter bars, empty/error surfaces |
| Accent (10%) | host `--ax-accent` with Accrue cobalt reference `#5d79f6`; `--ax-accent-readable`; `--ax-focus-ring` | Reserved elements listed below |
| Destructive | `--ax-danger` `#d64b4b`, `--ax-danger-readable`, `--ax-status-danger-*` | Destructive action labels, danger menu group, failed/dead terminal states, destructive step-up context only |

Accent reserved for:

- Primary action buttons that initiate a valid operator job.
- Summary-list row `Change` / `View` actions and related-object links.
- Keyboard `:focus-visible` rings.
- Selected theme segment, selected filter chip, active lens, and active command-palette row.
- Non-danger dropdown/menu hover and focus background only where the element is interactive.

Accent must not be used for static headings, decorative dividers, inactive summary values, raw JSON chrome, healthy empty-state heroes, status badges, money semantics, or danger actions. Lifecycle state uses `StatusBadge` and `--ax-status-*`; financial sign uses `--ax-money-*`; warning/attention uses amber; destructive/failed terminal state uses danger.

Overlay layer colors:

- Scrims use the existing ink mix and blur only through `ax-detail-drawer-backdrop`, `ax-step-up-modal-backdrop`, or canonical overlay classes.
- A panel must always render above its scrim by local isolated stacking context (`backdrop z-index: 0`, panel z-index: 1). Do not fix stacking defects with larger global z-index values.
- Dark mode must use the existing `html.accrue-admin[data-theme="dark"]` token set. No theme-specific one-off hex values.

## Copywriting Contract

Voice stays measured, exact, native, and durable. Copy names the billing artifact, current state, and next useful action. Avoid sales language, exclamation marks, vague adjectives, backend flag names, route/module names, and generic "No results" text when the resource and state are known.

| Element | Copy |
|---------|------|
| Primary CTA | Existing page-specific verb + noun, for example `Finalize invoice`, `Pay invoice`, `Refund charge`, `Replay webhook`, `Edit platform fee override`, `Clear filters`. Phase 199 must not add generic CTAs such as `Submit`, `Continue`, or `Try again` when the object/action is known. |
| Empty state heading | Resource/state-specific, for example `No invoices yet.`, `No invoices need collection.`, `No invoices match these filters.`, `No webhook deliveries match these filters.` |
| Empty state body | State how rows arrive or what to do next: clear filters, adjust search, view all, or inspect the relevant log. First-run, queue-empty, filtered-empty, loading, error, and permission-denied states must stay distinct. |
| Error state | `Action could not be completed. Review the values, then try again.` Route-load errors use `Details could not be loaded. Retry the request or return to the list.` Search errors use resource-specific wording, not generic failure copy. |
| Destructive confirmation | Sensitive actions route through step-up with `Confirm your identity to continue.` plus resource-specific title/context from `AccrueAdmin.Copy`. |

Required destructive or sensitive action handling:

| Action | Visible label | Confirmation approach |
|--------|---------------|-----------------------|
| Invoice void | `Void invoice` | Overflow danger group only; step-up before execution |
| Invoice mark uncollectible | `Mark uncollectible` | Overflow danger group only; step-up before execution |
| Charge refund | `Refund charge` | Drawer after intent; submit is step-up gated |
| Webhook replay | `Replay webhook` | Visible only for failed/dead replayable rows; drawer confirmation plus step-up |
| Connect fee override | `Edit platform fee override` | Drawer after intent; save is step-up gated |
| Customer payment method delete | `Delete payment method` | Drawer or step-up modal after intent; never inline on initial load |
| Customer default payment method change | `Set default payment method` | Drawer after intent; server-side validity check required |

Microcopy rules:

- New/touched strings go through `AccrueAdmin.Copy` modules. Avoid new raw user-facing strings in LiveView templates except unavoidable local plumbing labels that are documented in the plan.
- Command palette no-results copy must name the search domain. Replace generic shape such as `No results found for "q"` with measured copy, for example `No billing records match "q". Adjust the search or open the customers list.`
- Summary-list row actions use `Change` only when the row changes that exact row, and `View` only when navigating or drilling into the related object.
- Every repeated `Change`, `View`, menu row, and action-menu item needs visually-hidden context naming the affected resource and next action, for example `Change collection method for invoice INV-1024`.
- Unavailable affordances are absent. Do not render disabled-looking-enabled buttons, empty pagination, or inert actions with pointer/hover treatment.

## Overlay Contract

| Area | Contract |
|------|----------|
| Root | The page renders exactly one body-level `#ax-overlay-root` after the admin shell content. Overlays portal there with `<.portal target="#ax-overlay-root">`. |
| Modal/drawer clients | Every modal and drawer routes through `Overlay.overlay/1` or named wrappers `DetailDrawer.detail_drawer/1` / `StepUpAuthModal.step_up_auth_modal/1`. Hand-rolled fixed shells are not allowed. |
| Command palette | Must either route through `Overlay.overlay/1` or remain a named wrapper that meets the same modal behavior: body-level/top-level stacking, backdrop click, Escape, focus capture/restore, no body focus, no hit-test obstruction, no viewport clipping. |
| Dropdown/action menu | Stays non-modal native disclosure via `DropdownMenu.action_menu/1` / `details.ax-dropdown`. It must not get `aria-modal`, backdrop, `data-scroll-lock`, or body inert behavior. |
| Popover/tooltip | Non-modal. It must remain adjacent to the trigger, pointer-reachable, viewport-bound, and z-layered through `--ax-z-popover`. |
| Scroll lock | Modal and drawer presentations set `data-scroll-lock="true"` and use `ScrollLock.lock()`. Popovers/dropdowns do not lock. Locking is ref-counted and restores only after the final overlay closes. |
| Background isolation | While a modal/drawer is open, `#accrue-admin-shell` is inert and not tabbable/clickable. Add `aria-hidden` fallback only if a failing browser support test proves it is needed. |
| Dismissal | Backdrop click, Escape, and explicit close use one close event/target path per overlay and settle idempotently. Rapid double-toggle and close-while-transition must leave no ghost scrim, stale inert shell, stale focus trap, or locked body. |
| Focus | Opening moves focus into the overlay, traps Tab/Shift+Tab, and restores focus to the trigger or stable fallback. If trigger disappeared, restore to a meaningful page target, never `document.body`. |
| Hit testing | The panel and its primary action are top pointer targets above the scrim at desktop and mobile viewports. Scrim is dismissible, panel is not blocked by scrim. |
| Nested flows | Nested modal/drawer/step-up flows preserve scroll position, lock count, inert state, and focus restoration through every open/close sequence. |

Stable selectors:

- `#ax-overlay-root`
- `#accrue-admin-shell`
- `[data-ax-overlay-shell]`
- `[data-ax-overlay-backdrop]`
- `[data-ax-overlay-panel]`
- `[data-presentation="modal"]`
- `[data-presentation="drawer"]`
- `[data-presentation="popover"]`
- `[data-scroll-lock]`
- `[data-focus-trap-initial]`
- `[data-focus-trap-fallback]`
- `[data-floating-panel="dropdown"]`
- `[data-ax-action-overflow-menu]`

Overlay prohibitions:

- No z-index-only fixes for modal-behind-scrim or trapped stacking contexts.
- No fixed-position overlay shell inside transformed, filtered, perspective, or contained page wrappers.
- No duplicate overlay roots.
- No action forms visible in the page action band on initial detail page load.
- No dropdown/action menu scroll lock.
- No disabled-looking-enabled close/action controls.

## Geometry And Motion Contract

| Surface | Geometry | Motion |
|---------|----------|--------|
| Desktop drawer | Right-edge docked panel, `inset: 0 0 0 auto`, `width: min(34rem, 92vw)`, full height, no page-horizontal overflow | Enters from right with `translateX(100%)` to `0`; duration `--ax-dur-3` (240ms); exit fade-only via `--ax-dur-exit` |
| Mobile drawer | Bottom sheet, full width, bottom-docked, max height `calc(100dvh - var(--ax-space-lg))` | Enters with `translateY(100%)` to `0`; duration `--ax-dur-3`; no horizontal travel |
| Step-up modal | Centered panel with bounded width/height, internal scroll if needed, visible action row | Focus appears instantly; panel/backdrop transition via existing modal/drawer token vocabulary only |
| Command palette | Centered/fixed palette, viewport-bound at phone/tablet/desktop, backdrop below panel | Existing scale/opacity entrance may remain only through motion tokens and reduced-motion collapse |
| Dropdown/action menu | Adjacent to trigger, natural origin near trigger, no offscreen panel near viewport edges | Small rise/fade through `--ax-transition-transform` / opacity tokens; Escape/outside click closes and restores trigger focus |
| Tooltip/popover | Adjacent to trigger, no viewport clipping, no overlap that hides the trigger unless intentionally anchored | Opacity/color only unless already documented in `motion.md` |

Motion rules:

- All new/touched motion composes from `--ax-dur-*`, `--ax-ease-*`, and `--ax-transition-*` tokens.
- Overlay and floating enter duration must remain within the existing band: 180ms default, 240ms max for drawer/modal travel, 140ms exit.
- Reduced motion preserves opacity state change but removes travel/scale through existing token overrides. No JS `matchMedia` special casing.
- Focus rings and roving-tabindex state changes are instant, not animated.
- No `transition: all`, raw `ms`/`s` literals in transition/animation rules, layout-property motion, per-row stagger, or decorative motion.

Transformed-ancestor audit:

- Audit `transform`, `filter`, `backdrop-filter`, `contain`, `perspective`, and `position: fixed` rules in page wrappers and shell ancestors.
- `#ax-overlay-root` must remain body-level and outside any transformed/filtered/contained page wrapper.
- If a route-specific wrapper traps fixed children, move the overlay root or remove the trapping style. Do not increase z-index as the fix.

## Affordance And Theme Contract

| Area | Contract |
|------|----------|
| Non-interactive empty/healthy heroes | No `role="button"`, `phx-click`, hover lift, pointer cursor, or pointer-target styling. They communicate state only. |
| Disabled controls | Real disabled controls use semantic disabled state, `aria-disabled` only where appropriate, and `--ax-disabled-*` visual tokens with readable labels. |
| Absent affordances | Pagination, destructive actions, replay buttons, action menus, and clear controls are omitted when unavailable. Do not render unavailable controls as enabled-looking or empty chrome. |
| Floating bounds | Dropdowns, command palette, theme picker, tooltips, and popovers stay within viewport bounds at phone-320, phone-375, tablet-768, desktop-1024, and desktop-1440. |
| Theme persistence | Production path uses `accrue_theme`, with cookie precedence over localStorage, then system/default fallback. Tests that only set `data-theme` are not sufficient for persistence/no-FOUC proof. |
| Theme flash | The root anti-FOUC script sets `document.documentElement.dataset.theme` before CSS loads. Reloads and system dark/light emulation must not flash wrong-theme styles. |
| Theme picker | Keep segmented radiogroup behavior: one tab stop, arrow-key movement, `aria-checked`, visible selected state, and persistence to cookie/localStorage. |

## Fixture Stress Contract

Use deterministic seeded route fixtures, not synthetic-only component states. Component kitchen and Storybook specimens may supplement evidence, but acceptance must pass on composed admin pages.

Required edge data:

| Fixture class | Required data |
|---------------|---------------|
| Long content | Very long customer/business names, long emails, long processor IDs, non-ASCII names, overflow payloads |
| Currency boundary | Zero-decimal JPY invoice and charge values, tabular money alignment, no accidental cents display |
| Dunning / recovery | Past-due subscription, dunning campaign started, at-risk recovery row, cancel-at-period-end subscription |
| Webhooks | Failed and dead webhook deliveries, replayable and non-replayable states, raw payload overflow |
| Connect | Account requiring attention, disabled charges/payouts, currently-due requirements, pending capabilities |
| List states | Populated, first-run empty, queue/default empty, filtered empty, loading skeleton |
| Overflow | More-than-one-page rows, one-row boundary, zero-row filter boundary, high counts |

Route-flow assertions:

- No document-level horizontal overflow or clipped visible elements.
- Long strings wrap, truncate, or break using `min-width: 0` discipline without squishing adjacent controls.
- Scroll containers are reachable to the end; overlays do not trap scroll in the page behind them.
- Focus never lands on `document.body` after route transitions, overlay close, back navigation, or nested detail drill-down.
- Browser back from nested detail/drill routes restores a stable route state without stale drawer, stale step-up, stale filter, or stale scroll lock.
- Seeds are idempotent; repeated Phase 199 e2e runs start from the same deterministic state.

Recommended seed path:

- Reuse `/__e2e__/seed/phase191-matrix`, `/operator-flows`, `/edge-states`, and `/overflow`.
- Add a narrow Phase 199 fixture extension only for missing long emails/processor IDs or nested drill-back IDs.
- Do not introduce a generic fixture DSL.

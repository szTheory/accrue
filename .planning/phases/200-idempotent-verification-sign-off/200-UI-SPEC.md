# Phase 200 - UI Design Contract

> Visual and interaction contract for Phase 200: Idempotent verification & sign-off. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 200 is a closeout and evidence phase for the already-built `accrue_admin` operator UI. It must complete PhoenixStorybook coverage/theming proof, re-score the full union baseline, run deterministic accessibility/theme/interaction guardrails, and produce one verifier-friendly maintainer ACCEPT/REJECT sign-off package.

This is not a redesign phase. Implementation is limited to Storybook completeness/theming, scorecard and artifact harnesses, deterministic guardrail wiring, evidence normalization, and narrow repairs for blocking regressions discovered by those gates.

Canonical sources: `.planning/STATE.md`, `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md` VER-01/VER-02/VER-03/STY-02/STY-03, `200-CONTEXT.md`, `200-RESEARCH.md`, `.planning/milestones/v1.53-phases/187-audit-baseline/187-RUBRIC.md`, archived baseline artifacts, Phase 192 closeout artifacts, Phase 199 verification artifacts, `accrue_admin/assets/css/theme.css`, `accrue_admin/assets/css/app.css`, `accrue_admin/lib/accrue_admin/dev/component_registry.ex`, `accrue_admin/lib/accrue_admin/dev/storybook.ex`, and `brandbook/voice.md`.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`--ax-space-xs`) | Icon-to-label gaps, compact status markers, evidence-link gaps, small checklist affordances |
| sm | 8px (`--ax-space-sm`) | Table cell controls, Storybook variation rows, scorecard row internals, checklist item gaps |
| md | 16px (`--ax-space-md`) | Default story preview padding, evidence table padding, artifact list spacing, form/control gaps |
| lg | 24px (`--ax-space-lg`) | Scorecard section padding, Storybook group sections, sign-off checklist groups |
| xl | 32px (`--ax-space-xl`) | Major proof-surface groups: coverage, a11y/theme, scorecard, judge, sign-off |
| 2xl | 48px (`--ax-space-2xl`) | Top-level breaks between Storybook coverage, scorecard, verification, and sign-off packages |
| 3xl | 64px (`--ax-space-3xl`) | Rare page-level separation only; never inside dense audit tables or compact Storybook previews |

Exceptions:

- Legacy `--ax-space-2xs` may exist in older CSS, but Phase 200 must not use it for layout spacing, gaps, padding, margins, offsets, or new/touched proof surfaces. Use `--ax-space-xs` / `4px` for compact gaps.
- 1px borders and hairlines remain border treatment, not spacing scale.
- Every interactive evidence link, Storybook control, disclosure, filter, action, or checklist row must preserve a 44px minimum touch target at 320px and 375px.
- Evidence tables, coverage matrices, and artifact lists must degrade to stacked rows/cards on mobile. Do not squeeze long artifact columns into unreadable horizontal tables.
- Long artifact paths, cell IDs, commands, checksums, Storybook story IDs, and NDJSON evidence refs must wrap with `overflow-wrap: anywhere`.
- Structural dimensions such as `width: min(...)`, viewport constraints, and `calc(...)` may be used for proof surfaces and Storybook if they preserve the `ax-*` spacing rhythm.

## Typography

Use exactly two weights for new/touched Phase 200 UI and proof surfaces: 400 and 600. Do not introduce 500, 700, viewport-scaled type, or new negative tracking.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--ax-type-md`) | 400 | 1.4 (`--ax-leading-normal`) |
| Label | 14px (`--ax-type-sm`) | 600 | 1.4 (`--ax-leading-normal`) |
| Heading | 28px (`--ax-type-2xl`) | 600 | 1.2 (`--ax-leading-tight`) |
| Display | 36px (`--ax-type-3xl`) | 600 | 1.2 (`--ax-leading-tight`) |

Required usage:

- Storybook story labels, state labels, group names, and coverage statuses use Label or Body. Storybook preview content should preserve each component's existing typography rather than adding wrapper-specific type styles.
- `200-SCORECARD.md`, `200-STORYBOOK-COVERAGE.md`, `200-VERIFICATION.md`, and `200-SIGN-OFF.md` headings use Heading for phase status and section names.
- Summary counts, baseline/final deltas, regression count, coverage totals, and final decision state may use Display only when they are the primary read in a summary band.
- Cell IDs, Storybook story IDs, artifact paths, commands, JSON keys, SHA/checksum values, and trace refs use Geist Mono via code role and must wrap.
- Final sign-off copy must be scannable: short status sentence first, supporting evidence second, exact artifact refs third.

## Color

Use theme-aware `ax-*` semantic tokens. Phase 200 introduces no new hues.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` light `#fafbfc`, dark `#0f1318` | Page canvas, Storybook sandbox canvas, scorecard/sign-off background |
| Secondary (30%) | `--ax-elevated` light `#ffffff`, dark `#171d24`; `--ax-sunken` light `#f1f5f8`, dark `#0b1015`; `--ax-border` | Storybook panels, evidence tables, status sections, artifact wells, CI rows, code/evidence blocks |
| Accent (10%) | runtime `--ax-accent` with Accrue cobalt reference `#5d79f6`; `--ax-accent-strong`; `--ax-accent-readable`; `--ax-focus-ring` | Reserved elements listed below |
| Destructive | `--ax-danger` `#d64b4b`; `--ax-danger-readable`; `--ax-status-danger-*` | Blocking regressions, failed guardrails, REJECT state, destructive/blocking sign-off states only |

Accent reserved for:

- Primary sign-off action when all blockers are clear.
- Storybook active navigation item, selected story/variation row, and selected color mode segment.
- Active scorecard filter/view, active evidence lens, selected gallery/checkpoint row.
- Evidence links, command/result links, and current verification step.
- Keyboard `:focus-visible` rings.

Accent must not be used for static headings, decorative dividers, raw JSON chrome, neutral summary counts, advisory findings, skipped checks, pending human state, or danger/reject actions.

State colors:

- Pass uses success semantics with explicit text.
- Advisory and incomplete evidence use warning/info/neutral semantics with explicit copy.
- Blocking regression, coverage downgrade, failed guardrail, unresolved `BLOCKER`, unresolved `REPAIR-IN-PHASE`, or REJECT uses danger semantics.
- Color alone is never the status; every badge/table row must name the state in text.

## Copywriting Contract

Voice stays measured, exact, native, durable, and proof-oriented. Copy must name the artifact, evidence lens, cell, story, route, guardrail, or finding being discussed. Avoid "looks good", "all green", "LLM passed", "no issues", or generic pass/fail language unless paired with structured evidence counts.

| Element | Copy |
|---------|------|
| Primary CTA | Record final decision |
| Empty state heading | No regressions recorded |
| Empty state body | The final comparison found no score downgrade, coverage downgrade, or regression row. Review Storybook coverage, deterministic guardrails, judge findings, and the maintainer checkpoint before recording the final decision. |
| Error state | Final evidence package could not be verified. Re-run the failed guardrail, regenerate the Phase 200 artifacts, then verify `baseline.union.cells.json`, `final.cells.json`, `scorecard.delta.json`, and `regressions.ndjson`. |
| Destructive confirmation | Reject sign-off: Record the blocking finding IDs, affected cells or stories, evidence refs, required repairs, and rerun command before replacing the final decision. |

Required copy for proof surfaces:

| Surface | Copy contract |
|---------|---------------|
| `200-STORYBOOK-COVERAGE.md` | State dynamic registry family coverage, entry coverage, group-contract coverage, N/A state handling, Storybook asset status, theme parity status, and `/dev/components` drift-test status. |
| `200-SCORECARD.md` | State union baseline row count, final row count, comparable row count, page-flow pending closure count, regression count, coverage downgrade count, and artifact verifier status. |
| `200-VERIFICATION.md` | State deterministic command names, pass/fail status, route/story coverage, light/dark axe status, no-FOUC/theme persistence status, reduced-motion status, Phase 199 interaction regression status, and host/adopter leak status. |
| `200-SIGN-OFF.md` | State deterministic artifact summary, four-lens judge findings, maintainer checkpoint rows, accepted/rejected blockers, and the exact final decision line. |
| Final decision line | Must start with exactly `Final maintainer decision: ACCEPT` or `Final maintainer decision: REJECT`. |
| Blocking rows | Name finding ID, severity, locked requirement/rubric/contract reference, affected route/story/cell, evidence ref, repair owner or subplan, and rerun requirement. |
| Guardrail rows | Use concrete command names such as `verify_phase200_scorecard`, `verify_phase200_admin_guardrails`, `e2e:phase199`, `e2e:a11y`, `reduced-motion`, Storybook structural/theming checks, and host leak checks. |

Destructive actions in this phase:

| Action | Visible label | Confirmation approach |
|--------|---------------|-----------------------|
| Reject final sign-off | `Reject sign-off` | Requires blocking finding IDs, affected artifacts/cells/stories, evidence refs, and required repair/rerun notes in `200-SIGN-OFF.md`. |
| Mark a finding blocking | `Mark as blocker` | Allowed only for `BLOCKER` or `REPAIR-IN-PHASE`; row must cite a locked requirement, rubric dimension, brandbook rule, component/group/page-flow contract, or Phase 199 interaction contract. |

No product destructive action UX is introduced in Phase 200. Existing admin destructive flows are verified only through the Phase 199 interaction and sign-off evidence.

## Storybook Coverage Contract

Phase 200 must make PhoenixStorybook complete and verifiable without creating a parallel design catalog.

Required behavior:

- Every family returned by `ComponentRegistry.entries/0` has at least one Storybook story generated or curated from registry data.
- Every registry entry and applicable state is represented, or documented as N/A using registry-derived `na_states` notes.
- All 8 `group_contracts/0` have Storybook coverage with group id/slug, proof id, required states, hierarchy, behavior contracts, and one representative composition marked with stable `data-component-group` or equivalent proof selectors.
- Tests must derive expected family, entry, state, and group IDs dynamically. The current 30 families, 42 entries, and 8 groups are planning context, not hardcoded test truth.
- `RegistryStory` may support state groups, stable slugified IDs, unique DOM IDs, named-slot templates, and curated wrappers. It must not duplicate registry metadata.
- Storybook story IDs and DOM IDs must be stable, slugified, unique, and safe for Playwright locators.
- Storybook must load committed `priv/static/storybook.css` and `priv/static/storybook.js` through the mounted `/dev/storybook` path.
- Storybook coverage must not break `/billing/dev/components`; registry, kitchen, and group drift tests must remain green.

Visual contract:

- Storybook preview chrome stays secondary. The component or group under review is the focal point.
- Preview wrappers use `--ax-base`, `--ax-elevated`, `--ax-border`, and the declared spacing scale.
- Dense registry stories should avoid nested cards unless the component under test is itself a card.
- Story/state labels are terse and exact: family, variant, state, and N/A reason where relevant.

## Theme And Accessibility Contract

Storybook and admin routes must prove both settled visual modes and production theme boot behavior.

| Area | Contract |
|------|----------|
| Storybook color mode | Enable PhoenixStorybook color mode and keep `color_mode_sandbox_dark_class: "ax-theme-dark-shim"` unless a verified better bridge is implemented. |
| Storybook token parity | Dark-mode Storybook sandbox must receive the same effective `ax-*` token scope as `html.accrue-admin[data-theme="dark"]`; add a parity guard so `theme.css` dark token changes cannot silently miss Storybook. |
| Settled axe scans | Run axe over all completed Storybook stories and primary admin page-flow routes in settled light and dark modes. Direct `data-theme` forcing is allowed only for these settled scans and must be labeled as a bypass. |

## Scorecard And Artifact Contract

Phase 200 must write all final artifacts under `.planning/phases/200-idempotent-verification-sign-off/` and must not mutate archived Phase 187/193/192 artifacts.

Required artifact package:

| Artifact | Role | Interaction contract |
|----------|------|----------------------|
| `baseline.union.cells.json` | Canonical union baseline | Union of archived component/group cells and page-flow cells; duplicate IDs fail generation. |
| `final.cells.json` | Canonical final matrix | Every inherited cell has final score, coverage status, dimension, state, theme, viewport, and evidence ref. |
| `scorecard.delta.json` | Canonical comparison | Every comparable baseline cell maps to final status, score delta, coverage delta, and evidence refs. |
| `regressions.ndjson` | Canonical blocker signal | Empty file or zero rows is required for ACCEPT. Any line blocks until repaired and regenerated. |
| `artifacts.manifest.json` | Evidence index | Repo-relative links to reports, traces, screenshots, logs, checksums, and generated markdown; reject absolute paths and `..` segments. |
| `200-SCORECARD.md` | Readable scorecard summary | First screen shows pass/fail, union row count, regression count, coverage downgrade count, page-flow pending closure, and artifact verifier status. |
| `200-STORYBOOK-COVERAGE.md` | Readable Storybook summary | First screen shows dynamic family/group coverage, theme parity, asset delivery, and kitchen drift-test status. |
| `200-VERIFICATION.md` | Readable deterministic guardrail summary | First screen shows deterministic commands, pass/fail state, route/story coverage, and any rerun requirements. |
| `200-SIGN-OFF.md` | Maintainer decision surface | Contains deterministic artifact summary, judge findings, maintainer checkpoint, and exact ACCEPT/REJECT final line. |

Scorecard rules:

- Canonical Phase 200 baseline is 30,348 unique rows unless implementation discovers and documents a duplicate-key proof.
- Archived baselines are immutable. Improvements are positive `score_delta` rows; invalid historical rows require explicit `baseline_correction` rows with reason and evidence.
- All `p193` page-flow pending cells must close with `coverage_status: "covered"`, deterministic evidence ref, and score floor `>= 2`.
- Aggregate scores are summary-only. One failing cell, coverage downgrade, missing evidence ref, or regression row blocks ACCEPT.

## Judge And Sign-Off Contract

The judge is bounded evidence review, not open-ended design critique.

| Lens | Allowed finding basis | Blocking conditions |
|------|-----------------------|---------------------|
| correctness | Structured artifacts, scorecard deltas, route/story smoke, CI logs | Missing artifact, malformed artifact, coverage downgrade, score regression, stale pending state, host/adopter leak |
| accessibility | axe results, keyboard/focus traces, WCAG-relevant Playwright assertions | Critical/serious contrast/name/role failure, focus trap/restore failure, keyboard unreachable action, status semantics failure |
| brand | `brandbook/voice.md`, locked copy contracts, curated maintainer checkpoint | Finding cites a locked copy/brand contract and affects required Phase 200 proof surface or admin JTBD clarity |
| interaction | Phase 199 contracts, Playwright traces, route/story interaction evidence | Overlay/focus/scroll/theme/reduced-motion behavior regresses or lacks deterministic evidence |

Severity labels:

| Severity | Meaning |
|----------|---------|
| `BLOCKER` | Must fix before ACCEPT. |
| `REPAIR-IN-PHASE` | Narrow Phase 200 repair required before rerun and ACCEPT. |
| `ADVISORY` | Record for future work; does not block ACCEPT. |
| `DEFERRED` | Outside v1.54 or future milestone; does not block ACCEPT. |

Sign-off rules:

- ACCEPT is all-or-nothing: empty `regressions.ndjson`, no coverage downgrade, all comparable cells `>=` baseline, all deterministic guardrails green, Storybook coverage/theming green, curated checkpoint rows accepted, and no unresolved `BLOCKER` or `REPAIR-IN-PHASE` findings.
- REJECT must name blocking finding IDs and required repair artifacts/tests before the final decision can be replaced.
- Final close must not leave `human_needed`, `pending`, stale requirement checkboxes, missing Phase 200 artifacts, or ambiguous partial states.
- Prefer Playwright traces or deterministic logs for interaction evidence. Screenshots can supplement visual review but cannot be the only evidence for focus, Escape, outside click, scroll lock, actionability, theme persistence, or reduced motion.

## CI Guardrail Contract

Deterministic CI guardrails and final closeout evidence must be visually and semantically distinct.

Required deterministic guardrails:

- Baseline parse and duplicate-key check for component/group + page-flow union.
- Phase 200 scorecard verifier for `baseline.union.cells.json`, `final.cells.json`, `scorecard.delta.json`, `regressions.ndjson`, and `artifacts.manifest.json`.
- Phase 200 sign-off verifier for exact final decision line, required artifacts, unresolved blockers, and state/requirements reconciliation.
- Registry/group tests and `/dev/components` drift tests.
- Storybook structural coverage and asset/theming checks.
- axe route/story scans.
- Reduced-motion behavioral checks.
- Phase 199 overlay/fixture/theme/copy regression suite.
- Host/adopter leak checks proving `/dev/storybook` is dev/test-only and absent from runtime surfaces.

Final or manual closeout evidence, not required on every PR:

- Full union scorecard regeneration.
- Four-lens judge generation.
- Maintainer photographic/interaction checkpoint.
- Curated screenshot/trace package.
- Model-dependent visual/brand scoring, if used as advisory evidence.

Status copy:

- `Required guardrail passed` for deterministic blocking checks.
- `Required guardrail failed` for deterministic failures that block merge or sign-off.
- `Final closeout evidence` for generated scorecard, judge, traces, screenshots, and maintainer checkpoint.
- `Advisory finding` for subjective or model-assisted observations not normalized into structured blockers.

<objective>
Build `accrue_admin/e2e/ratchet/ratchet-verify.mjs` — the Opus-based 3-role adversarial skeptic
panel (persona advocate, brand purist, operator-density defender) that confirms or kills each
DEDUP-03-collapsed candidate finding, and is the SINGLE writer that appends 2-of-3-confirmed
survivors directly into the committed `findings.ledger.ndjson` as `open` rows (D-35).

Purpose: this is the noisy-plane half of the ratchet's pawl — the MACHINE panel confirms (not a
human), so a finding only ever crosses into the committed, git-tracked ledger after passing a
deterministic re-gate the harness itself enforces, never trusting the LLM's own claims about
identity or admissibility.

Output: `accrue_admin/e2e/ratchet/ratchet-verify.mjs` plus two new `accrue_admin/package.json`
scripts (`ratchet:verify`, `ratchet:verify:self-test`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Screenshot (committed PNG, base64-encoded) → Opus panel prompt | In-image text is attacker-influenceable and crosses into the LLM's context as untrusted data (D-15) |
| Candidate `defect`/`suggested_fix` free-text (itself LLM-generated in Phase 205) → Opus panel prompt | Second-order untrusted prose re-enters the panel's context (D-34) |
| Opus `tool_use` JSON response → committed `findings.ledger.ndjson` write | LLM-supplied identity/token/severity fields cross into the deterministic, git-tracked ledger and must never be trusted at face value |

| T-206-02-02 | Tampering | Candidate `defect`/`suggested_fix` free-text → Opus panel prompt (2nd-order injection, D-34) | high | mitigate | Extended preamble sentence explicitly treats the candidate row's own LLM-generated free-text fields as untrusted data too, since that prose was produced by a Phase-205 model reading a possibly-injected screenshot |

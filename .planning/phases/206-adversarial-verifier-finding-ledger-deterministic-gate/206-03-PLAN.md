<objective>
Build `accrue_admin/e2e/ratchet/phase-ratchet-ledger.mjs` — the deterministic sibling gate that
folds the committed ledger, computes per-lens `confirmed_open` counts (D-24 — the closed 7-value
lens enum), asymmetrically compares them against `ledger.baseline.json` (fires only on increase),
checks `guard_ref` presence via static substring read, checks `reopen-markers.ndjson` legitimacy,
and writes `finding-regressions.ndjson`. Then commit Phase 206's own initial (empty, self-matching,
UNFROZEN) `findings.ledger.ndjson` / `ledger.baseline.json` / `reopen-markers.ndjson` /
`finding-regressions.ndjson` quadruple as the phase's gate-green-by-construction starting state.

Purpose: this is the deterministic half of the ratchet's pawl — zero network calls, zero LLM,
proven entirely by `--self-test` fixtures (D-37: this phase never runs the live LLM to satisfy its
own success criteria, mirroring the Phase-200 precedent).

Output: `accrue_admin/e2e/ratchet/phase-ratchet-ledger.mjs` plus the 4 committed data files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `guard_ref` string (stored in a committed ledger row, potentially hand-typed in a future PR) → filesystem read | A malformed or malicious `guard_ref` must not be able to read outside the intended `GUARD_HOME_SPECS` allowlist |
| `ledger.baseline.json` (committed, hand-editable in any PR) → `--freeze` write path | A PR must not be able to silently flip `frozen:true` without the explicit `--freeze` flag |
| `reopen-markers.ndjson` (committed, epoch-scoped) → illegal-reopen check | A `resolved_locked` claim must not be silently reopenable without a legitimate maintainer marker |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-206-03-01 | Tampering | `guard_ref` path traversal (e.g. `"../../../etc/passwd::@ratchet:f-..."`) | high | mitigate | `checkGuardRef()` rejects absolute paths, backslashes, `..` segments, and any path not a literal member of the closed `GUARD_HOME_SPECS` allowlist before ever calling `fs.readFileSync` |
| T-206-03-02 | Tampering | Frozen baseline silently overwritten without `--freeze` | high | mitigate | The reducer throws and refuses to write when the on-disk `baseline.frozen` is `true` and `--freeze` is absent from `process.argv` (D-37) — proven by the `--freeze`-refusal self-test fixture |
| T-206-03-03 | Tampering | `resolved_locked` claim reopened without a legitimate maintainer marker | high | mitigate | The illegal-reopen check requires a matching `finding_id` entry in the CURRENT-epoch `reopen-markers.ndjson`; absence fires a regression row (D-41) |
| T-206-03-04 | Tampering | Ledger row reordering/duplication (`seq` tamper) | high | mitigate | Delegated to `ratchet-ledger.js`'s `fold()` (206-01), which this reducer calls directly and lets its seq-monotonicity assertion propagate as a hard failure rather than swallowing it |

No new package-manager installs in this plan (Node built-ins + `ratchet-ledger.js` + `region-tags.js`
only) — no `T-206-03-SC` slop-check row applies.
</threat_model>

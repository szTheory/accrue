<objective>
Build `scripts/ci/verify_ratchet_ledger.mjs` — the independent CI re-verifier that recomputes
per-lens `confirmed_open` counts straight from the raw committed `findings.ledger.ndjson` rows
(never trusting `ledger.baseline.json`'s own stored numbers) and fails on any disagreement. Then
wire the paired `ratchet:ledger`/`ratchet:ledger:self-test` npm scripts.

Purpose: this is the "trust but verify" half of LEDGER-04 — a hand-edited baseline that disagrees
with the raw-row recompute must fail, exactly mirroring `verify_phase200_scorecard.mjs`'s
relationship to `phase200-scorecard.mjs`. This is the LAST plane the LLM is permanently kept off
of: the CI-facing script that will eventually gate merges (wired in Phase 208) never imports the
Anthropic SDK.

Output: `scripts/ci/verify_ratchet_ledger.mjs` plus two new `accrue_admin/package.json` scripts.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Committed `ledger.baseline.json` (hand-editable in any PR) → CI exit code | A malicious or careless PR could hand-edit the baseline's stored counts to mask a real regression |
| Committed `finding-regressions.ndjson` (byte-count as pass signal) → CI gate | A stale or hand-truncated regressions file could falsely report 0 bytes |
| This script's own dependency surface → whether the LLM is ever reachable from the CI gate path | The project-wide invariant "the LLM never gates CI" is enforced here, in the last file before Phase 208 wires this into GitHub Actions |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-206-04-01 | Tampering | Hand-edited `ledger.baseline.json` disagreeing with the raw ledger rows | high | mitigate | Independent recompute from raw `findings.ledger.ndjson` rows, never trusting the baseline file's own stored numbers (LEDGER-04) — any disagreement is a hard CI failure |
| T-206-04-02 | Repudiation | A stale/hand-truncated `finding-regressions.ndjson` claiming 0 bytes when real regressions exist | medium | mitigate | This script reads raw bytes off disk itself for the byte-count check AND independently re-derives whether regressions should exist via its own independent fold — it never trusts the file's byte-count in isolation |
| T-206-04-03 | Elevation of Privilege | The LLM ever becoming reachable from this CI-facing script | critical | mitigate | `verify_ratchet_ledger.mjs` never imports `@anthropic-ai/sdk` and makes zero network calls (grep-verifiable per Task 1's acceptance_criteria) — this is what keeps the LLM off the CI gate path entirely, a project-wide guardrail this file is the last line of defense for |
| T-206-04-04 | Tampering | `guard_ref` path traversal re-check | high | mitigate | Independently duplicated `GUARD_HOME_SPECS` allowlist + path-safety checks (no `..`/absolute/backslash), matching 206-03's checks as a second independent confirmation |

No new package-manager installs in this plan (Node built-ins + `region-tags.js` reuse only) — no
`T-206-04-SC` slop-check row applies.

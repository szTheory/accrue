<objective>
Land the two independent, low-risk, mechanical requirements the RESEARCH flagged as parallelizable: the `RATCHET_SURFACES` surface/slice subset filter (ORCH-08, D-52) threading through capture (`admin-visuals.spec.js`) and proposal (`ratchet-propose.mjs`'s `discoverPngs()`), with the slice list defined once as an exported `SLICES` map in `baseline-manifest.js`; and Anthropic prompt-caching `cache_control` breakpoints (ORCH-07, D-57) on the stable request prefix in both `ratchet-propose.mjs` and `ratchet-verify.mjs`. RESEARCH confirmed both requests already put the image first and `system`/`tools` already precede `messages` — no reordering is required, only adding `cache_control` markers.

Purpose: without this filter, a slice-scoped round requires hand-pruning `test-results/` PNGs (the exact footgun the Phase 205 live smoke flagged); without caching, every `ui.round` re-sends the full system+schema+screenshot prefix on all 7 calls/screenshot, needlessly inflating cost.
Output: a maintainer can scope any round to a named slice or CSV surface list, and repeated proposer/verifier runs against unchanged prefixes read from cache (provable via a documented live smoke, not a CI gate).
</objective>

# Phase 207 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope

Phase 207 has **exactly one** user-facing visual surface: the rendered HTML digest emitted by the new
`accrue_admin/e2e/ratchet/ratchet-digest.mjs` (ORCH-02), written to
`accrue_admin/test-results/ui-ratchet/round-NN/digest.html` and invoked by `mix accrue_admin.ui.round`.
It is a **maintainer-facing, offline, self-contained artifact** — not part of the `accrue_admin` LiveView
app, not admin chrome, not adopter-facing. It does not use `ax-*` tokens (those are the admin app's SSOT);
it uses the **brand-layer** `--accrue-*` tokens from `brandbook/index.html` directly, because this artifact
sits alongside the brand book as a maintainer tool, not inside the operator product surface.

Everything else in this phase (`mix accrue_admin.ui.round`/`ui.fix` CLI banners, `rounds.ndjson`,
`decisions.json`, prompt caching, the guard-mint data rows) is terminal text or machine-readable data —
not a design surface. This UI-SPEC governs `ratchet-digest.mjs` output only.

**All layout/ranking/overlay/brand decisions below are LOCKED by 207-CONTEXT.md (D-53..D-56) and are
formalized here as the executor's visual source of truth, not re-litigated.**

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-authored inline HTML/CSS, generated by a Node script, no build step |
| Preset | not applicable (not a React/Next/Vite app; no `components.json`) |
| Component library | none — plain semantic HTML (`<section>`, `<table>`, `<details>`) + inline `<style>` |
| Icon library | none — severity/status markers are Unicode glyphs (`■` `△`) styled with CSS, not an icon font/SVG sprite, to keep the artifact dependency-free |
| Font | Geist (sans) + Geist Mono, `font-family: Geist, system-ui, sans-serif;` / `"Geist Mono", ui-monospace, monospace;` — **no CDN/webfont `<link>`, no embedded font files.** Relies on system-installed Geist (as `brandbook/index.html` already does) and falls back cleanly on machines without it. This preserves the "opens locally/offline, no external deps" contract (D-53) — a webfont fetch would break offline use and violate the self-contained-artifact idiom. |

**Artifact contract (not a template category, but binding):**
- Single `.html` file, inline `<style>` block, zero external network requests (no CDN CSS/JS/fonts, no analytics).
- Screenshots and `.bbox.json` sidecars live in the same `round-NN/` directory as `digest.html` — see "Image Reference" below for the path decision.
- `ratchet-digest.mjs` twins `phase192-gallery.mjs`'s **structural idiom** (row-builder functions + a `REQUIRED_FIELDS`-style validator + `runSelfTest()`/`--self-test`), not its literal output — `phase192-gallery.mjs` renders Markdown; `ratchet-digest.mjs` is a new HTML template renderer. This UI-SPEC is the executor's primary reference for that renderer since no prior literal HTML gallery exists in-repo to copy.
- Regenerable and idempotent: running `ratchet-digest.mjs` twice against the same round inputs produces byte-identical HTML (deterministic sort keys, no timestamps embedded in body content beyond the round number already in the data).

## Layout & Structure (locked — D-53, D-56)

Single scrolling document, top to bottom, in this exact order:

1. **Summary banner** — `position: sticky; top: 0;` — always visible while scrolling. See "Summary Banner Copy" below.
2. **Worklist** — `<section id="worklist">` — ranked, auto-fixable confirmed findings (`effort_class` is `"css"` or `null`).
3. **Decisions needed** — `<section id="decisions-needed">` — IA/product-decision items (`effort_class === "ia-product-decision"`). Visually distinct from the Worklist (see Color contract) so a maintainer cannot mistake a judgment-call item for an auto-fixable one. Typically 0–2 rows.
4. **Gallery** — `<section id="gallery">` — screenshots grouped by `surface`, each with region overlays drawn over confirmed findings on that surface.

Semantic HTML only: `<section>` per block, `<table>` for Worklist/Decisions-needed rows, `<details>`/`<summary>` for per-surface gallery groups (collapsed detail, expanded overview — lets a maintainer scan surface headers first, then drill in). No `<div>` soup where a semantic element applies.

## Spacing Scale

Declared values (multiples of 4, matching `brandbook/index.html`'s own rhythm):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Chip/tag internal padding (mirrors `.milestone-tag` — `padding: 2px 8px`, rounded to the 4px grid) |
| sm | 8px | Table cell padding, inline gaps between glyph + label |
| md | 16px | Default row/section padding, gallery card padding |
| lg | 24px | Section-to-section vertical gap (Banner → Worklist → Decisions-needed → Gallery) |
| xl | 32px | Gallery group (`<details>`) top margin between surfaces |
| 2xl | 48px | Not used at this artifact's scale — no exception needed |
| 3xl | 64px | Not used — single-column report, no page-level chrome |

**Exception:** the region-overlay outline is **2px** (see Overlay spec) — an intentional off-grid value because it is a border stroke width, not a layout spacing token; it must stay visually thin so it reads as a highlight, not a box that obscures the defect underneath (D-56).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / findings prose (`defect`, `suggested_fix`, `why_this_matters`-style copy) | 16px | 400 | 1.6 (matches `brandbook/index.html` body rhythm) |
| Table / dense row text (Worklist, Decisions-needed, gallery captions) | 14px | 400 | 1.4 |
| Section heading (`Worklist`, `Decisions needed`, `Gallery`, per-surface `<summary>`) | 20px | 600 | 1.2 |
| Mono identifier (`finding_id`, `claim_key`, `region_tag`, `bundle_sha256`) | 13px (0.8125rem) | 400 | 1.4 — always `"Geist Mono", ui-monospace, monospace`, never the sans stack |

Exactly 4 sizes (16/14/20/13), exactly 2 weights (400 regular, 600 semibold) — no bold 700 in this artifact, unlike the brand book's H1, since the digest has no marketing-scale display type.

## Color

Light values from `brandbook/index.html` `:root`; dark values from `:root[data-theme="dark"]`, but **applied via `@media (prefers-color-scheme: dark)`, not a `data-theme` attribute** (D-56) — this is a standalone artifact with no theme-toggle chrome, so it must honor the OS/browser preference directly.

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `--accrue-surface-base` `#fafbfc` | `--accrue-dark-base` `#0f1318` | Page background |
| Secondary (30%) | `--accrue-surface-elevated` `#ffffff` | `--accrue-dark-elevated` `#171d24` | Summary banner, table rows, gallery cards, `<details>` panels |
| Accent (10%) | `--accrue-interactive-accent` / `--accrue-cobalt` `#5d79f6` | `--accrue-dark-info` `#4a90b8` | **Reserved for exactly:** region-overlay outline + label chip border, the `CONVERGED` badge, link color (finding_id anchors within the page, if any) |
| Destructive / severity=real | `--accrue-feedback-danger` `#d64b4b` | same hue, unchanged per brand tokens | Severity="real" marker text/border-left; the `CAP REACHED` escalation badge |
| Second semantic / severity=minor + Decisions-needed accent | `--accrue-feedback-warning` / `--accrue-amber` `#c8923b` | same hue | Severity="minor" marker text/border-left; Decisions-needed section's distinguishing left-border/background wash |
| Neutral border/divider | `--accrue-fog` `#e9eef2` | `--accrue-dark-elevated` `#171d24` (border role in dark) | Table borders, section dividers, card borders |
| Muted text | `--accrue-content-muted` `#5d6a73` | `--accrue-dark-muted` `#a8b2bc` | Secondary copy (surface/theme/viewport captions, `why_this_matters`-style annotations) |

**Accent reserved for:** region-overlay outline + label chip, the `CONVERGED (N dry rounds)` badge, and in-page anchor links. Nothing else uses the accent blue — it must not appear as a generic "primary button" color because this artifact has no buttons (see Copywriting Contract).

**Severity is never color-alone** (D-56, accessibility): every severity marker pairs a distinct **shape glyph** with the color, so the artifact remains legible under color-vision deficiency or grayscale printing:

| Severity | Glyph | Color | Label text |
|----------|-------|-------|-------------|
| `real` | `■` (filled square) | danger red | `REAL` |
| `minor` | `△` (hollow triangle) | warning amber | `MINOR` |

Same pairing rule applies to round status badges: `CONVERGED` uses a checkmark-style glyph (`✓`) + accent blue; `CAP REACHED` uses a warning glyph (`⚠`) + danger red — never a bare colored pill with no glyph/text.

## Region Overlay Spec (locked — D-55)

For each confirmed finding rendered in the gallery:

1. Read `${surface}${theme === "dark" ? "-dark" : ""}.bbox.json` from the same `round-NN/` capture directory.
2. Look up `bbox[region_tag]` (Phase 205's capture-time `boundingBox()` result: `{x, y, width, height}` in capture-viewport CSS px, or `null` if the selector was absent on that surface).
3. If **non-null**: draw an absolutely-positioned `<div>` outline over the embedded `<img>`:
   - `border: 2px solid var(--accrue-interactive-accent)` (light) / `var(--accrue-dark-info)` (dark) — **outline only, never a fill** (a filled overlay would hide the very defect it points to).
   - `scale = renderedWidth / project.viewport_width` where `project.viewport_width` is `1440` (desktop project) or `390` (mobile project) from `baseline-manifest.js` `PROJECTS`. Multiply the raw `bbox.x/y/width/height` by `scale` to get on-page CSS px against the rendered `<img>` element.
   - A small label chip (mono font, 13px, accent-colored border, `--accrue-surface-elevated`/`--accrue-dark-elevated` background) anchored at the box's top-left corner, containing the `finding_id` (or a short `region_tag`) so multiple overlapping findings stay distinguishable.
4. If **null** (selector absent on that surface/theme): draw no box. Instead, list the finding against the surface's header/caption area with a note that the region wasn't present at capture time — never render a phantom or (0,0) box.

## Ranking / Sort Keys (locked — D-56, zero non-determinism)

**Worklist sort key** (ascending unless noted): `severity` (real→0, minor→1) → `persona_frequency` desc → `effort_class` (`"css"`→0, `null`→1; cheap wins first) → `finding_id` asc (stable tiebreak).

**Decisions-needed sort key:** `severity` → `persona_frequency` desc → `finding_id` asc.

All fields already live on the ledger row (`ratchet-finding-event`) — no re-computation, no LLM call, no timestamp-based ordering. Rendering the same `findings.ledger.ndjson` twice must produce identical row order.

## Summary Banner Copy (exact templates)

The banner is sticky, always visible, and must render exactly one of these three states:

| State | Copy template | Badge |
|-------|----------------|-------|
| Normal round (not yet converged) | `Round {N} — {confirmed} confirmed, {root_cause} root-cause, {ia_decisions} IA decisions` | none |
| Converged | same headline + | `CONVERGED ({K} dry rounds)` — accent-blue background, `✓` glyph |
| Cap reached (6th round, not converged) | `CAP REACHED — 6 rounds, {open} open, not converged` | danger-red background, `⚠` glyph |
| Zero confirmed findings this round (empty state) | `Round {N} — 0 confirmed findings` | — see Copywriting Contract "Empty state" row for the accompanying body copy |

`{confirmed}` = count of `open`-lifecycle rows this round; `{root_cause}` = count of `effort_class !== "ia-product-decision"` among confirmed; `{ia_decisions}` = count of `effort_class === "ia-product-decision"`. These three numbers plus the badge state are the only dynamic content in the banner — no additional maintainer-facing prose beyond what's specified here (keeps the banner scannable at a glance, consistent with the "quiet, well-made dev tooling" voice — no exclamation points, no "Great job!" filler).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Not applicable — this artifact has no buttons.** It is a read-only report; the maintainer's action ("batch-approve" / "reject with reason") happens by editing `decisions.json` outside this HTML, then running `mix accrue_admin.ui.fix`. The digest must not render any interactive form controls that imply an in-browser action. |
| Empty state heading | `No confirmed findings this round` |
| Empty state body | `Round {N} re-verified every surface in scope and found nothing new to fix. If this continues for one more round, the loop reports CONVERGED.` |

| Destructive confirmation | **Not applicable** — the digest triggers no destructive action. Suppression/reject decisions are made in `decisions.json`, and `ui.fix`'s own pre-apply banner (`Applying N fixes, M suppressions:`) is terminal text, not part of this UI-SPEC's surface (per the phase's scope note). |

## Data Fields Rendered Per Finding (binding reference for the executor)

Each Worklist / Decisions-needed / gallery-overlay row draws from the ledger's `ratchet-finding-event` shape (`ratchet-ledger.js` `IDENTITY_FIELDS` + `CARRY_FIELDS`) — no new fields need to be invented:

- Identity/locator: `surface`, `surface_type`, `dimension`, `dimension_name`, `overlay_tags`, `region_tag`, `claim_key` (mono, muted, secondary — shown for the curious, not the primary label), `finding_id` (mono, primary identifier, also the overlay label-chip text), `viewport`, `theme`.
- Provenance/severity/prose: `severity` (`real`/`minor` glyph+label per above), `persona_frequency` (small numeric badge, e.g. `×3`), `defect` (body-text description — the primary human-readable copy per row), `suggested_fix` (body text, secondary to `defect`), `effort_class`/`effort_hint` (drives Worklist-vs-Decisions-needed routing per D-54, not separately displayed as raw enum text — expressed structurally by which section the row appears in).

## Default Resolved for Claude's Discretion Items (visual-adjacent only)

207-CONTEXT.md left a few items to discretion; the ones with visual consequence are resolved here as sensible defaults (not escalated — non-visual items like `bundle_sha256` capture point and the auto-guard marker syntax are out of this UI-SPEC's scope per the scope note):

- **Image reference: relative path, not `data:` URI.** `digest.html` references screenshots as relative paths (`./{surface}{-dark}.png` etc.) within the same gitignored `round-NN/` directory, not inlined `data:` URIs. Rationale: the PNGs already live beside `digest.html` in the same disposable directory (nothing is lost by not inlining); relative paths keep the HTML small and fast to regenerate/diff; the "self-contained" promise in D-53 is about *no external network fetch*, which relative-path-to-a-sibling-file already satisfies (this mirrors how `phase192-gallery.mjs`'s evidence refs point at sibling paths rather than embedding bytes). If a future phase needs a single-file artifact for sharing outside the repo, `data:` URI inlining is a safe, additive follow-up — not required here.

<objective>
Build the cheap, dependency-free orphan/dangling `ax-*` CSS guard (D-02) that Wave 2/3 will run to confirm the deletion is clean, and establish the two baselines Wave 4 needs to prove "no red left behind": the current `mix test` pass/fail state, and an independent automated cross-check of the RESEARCH.md census (92 named DELETE classes + 5 D-01 adjacent selectors = 97) against the guard's own extraction.

Purpose: CSS deletion is invisible to source-text CI — the guard is the only mechanical proof that a selector is truly dead, and running it BEFORE any deletion (against the unmodified `app.css`) validates the tool itself (its report must match the human-researched census) before Wave 2 trusts it as a safety net. Capturing the baseline now means Wave 4's "no red left behind" claim is measured against the real starting point, not an assumed-clean one.
Output: A working, self-tested `verify-css-census.mjs` script (+ npm aliases) and a recorded pre-Phase-211 test baseline.
</objective>

    1. `extractCssSelectors(cssSource)` — regex-extract every `\.ax-[a-zA-Z0-9_-]+` token from `accrue_admin/assets/css/app.css` (the unminified source, read via `fs.readFileSync`), returning a deduped `Set` of candidate class names actually defined as selectors.
    2. `walkFiles(rootDirs, extensions)` — a pure recursive directory walker using `fs.readdirSync(dir, { recursive: true, withFileTypes: true })` (Node 20+; confirmed available at v22.14.0 in this environment — no glob dependency needed) over `accrue_admin/lib`, `accrue_admin/storybook`, `accrue_admin/test`, `accrue_admin/e2e` filtered to `.ex`, `.exs`, `.js` extensions.
    3. `isReferenced(className, sourceText)` — apply the exact-token lookaround pattern `(?<![\w-])CLASSNAME(?![\w-])` (built per-class via `new RegExp`, escaping regex metacharacters in the class name) against each walked file's contents.
    4. Report (a) orphans: candidate CSS classes from step 1 with zero references across all walked files. Report (b) missing: literal `ax-[a-zA-Z0-9_-]+` tokens found inside `class="..."` / `class={[...]}` attribute-value strings in the walked `.ex`/`.exs` files with no matching selector from step 1 (informational only, does not affect exit code).
    5. Allowlist: support a `KNOWN_DYNAMIC_PREFIXES` array constant (seed it empty or with a documented placeholder comment — no known dynamic `ax-*` prefixes are in scope for this phase per RESEARCH.md) and an inline `/* verify-css-census:allow */` suppression-comment convention checked immediately above a flagged selector line, so a future phase can silence a known-dynamic false positive without editing this script.
    6. CLI entry: default invocation (`node e2e/verify-css-census.mjs`, no flags) runs the real scan against the live `accrue_admin/assets/css/app.css` and print a report (candidate count, orphan list, missing-rule list); exit code 1 if any orphan is found, exit 0 otherwise. `--self-test` flag skips all filesystem/CSS scanning and instead runs 3 hand-written in-memory fixture assertions mirroring `region-tags.js`'s `runSelfTest()` discipline: (i) a genuinely orphaned fixture rule is correctly flagged, (ii) a genuinely live fixture rule is correctly NOT flagged, (iii) the two exact-token boundary cases from RESEARCH.md Pitfall 1 — a fixture containing `.ax-launcher { }` alongside source text `class="ax-launchers"` must flag `ax-launcher` as orphan (not falsely matched by the substring), and a fixture containing `.ax-launcher-primary { }` alongside source text `data-ax-launcher-primary="true"` must flag `ax-launcher-primary` as orphan (not falsely matched by the data-attribute). `--self-test` exits 0 only if all fixture assertions pass, exits 1 with a diagnostic listing which assertion failed otherwise.
    Add two `package.json` "scripts" entries following the existing `ratchet:verify` / `ratchet:verify:self-test` pairing convention: `"css:census": "node e2e/verify-css-census.mjs"` and `"css:census:self-test": "node e2e/verify-css-census.mjs --self-test"`.

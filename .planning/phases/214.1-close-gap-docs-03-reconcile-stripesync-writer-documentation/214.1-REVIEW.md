## Summary

The provenance verifier correctly scopes the reconciler check to the One-way dependency documentation, and the scoped ExUnit verifier suite passes. One new regression test can pass an unmodified fixture to the verifier when its full-paragraph replacement anchor drifts, yielding a misleading failure unrelated to the behavior it claims to cover.

## Warnings

### WR-01: Writer-provenance regression mutation is not verified

**File:** `accrue/test/accrue/docs/package_docs_verifier_test.exs:850`

**Issue:** The test constructs `stale_writer_story` with a full, formatting-sensitive paragraph replacement but never asserts that the replacement occurred. If routine documentation editing changes that paragraph's wrapping or wording, `String.replace/4` returns the original valid module. The subsequent expectation (`status != 0`) then fails even though the verifier is correct, turning an obsolete test anchor into a false CI failure and no longer testing stale-provenance rejection.

**Fix:** Preserve `original`, assert the mutation occurred before writing the fixture, and preferably replace a smaller stable provenance token. For example:

```elixir
original = File.read!(stripe_sync_path)
stale_writer_story = String.replace(original, "client-backed pull refresh", "pull refresh")
assert stale_writer_story != original
File.write!(stripe_sync_path, stale_writer_story)
```

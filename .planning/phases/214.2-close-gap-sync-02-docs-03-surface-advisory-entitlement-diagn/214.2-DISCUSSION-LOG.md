## Local grants vs Stripe observation

| Option | Description | Selected |
|--------|-------------|----------|
| Layered canonical-first groups | Keep one disclosure; show Accrue access first and Stripe observation second, with explicit authority labels and no derived verdict. | ✓ |
| Comparison matrix | Pair local and Stripe values and derive match/mismatch or health. Fast to scan, but requires a nonexistent semantic crosswalk and risks treating Stripe as a gate. | |
| Raw-data only | Put Stripe evidence only in the existing debug payload. Smallest change, but keeps the promised operator observation effectively hidden. | |

**User's choice:** Research all alternatives with specialist subagents and make the coherent decision.

**Notes:** The selected layered model preserves the existing customer-detail IA and local-only
Access headline. Successful operator/observability products label provenance and missing data;
they do not turn semantically different models into a false binary verdict. Stripe remains useful
provider evidence, while Accrue’s local mapping remains the authorization answer.

## Advisory detail depth and diagnostic API

| Option | Description | Selected |
|--------|-------------|----------|
| Compact summary only | Show state/count/source/time/completeness. Highly scannable, but too weak to explain which Stripe feature keys were observed. | |
| Full key list | Show every lookup key in the primary disclosure. Diagnosable, but dense and responsive-unfriendly for larger catalogs. | |
| Raw evidence inline | Add structured/provider JSON inside the Access disclosure. Maximum detail, but leaks implementation shape and duplicates the existing Raw data grammar. | |
| Layered projection | Compact state plus bounded lookup-key preview in the primary view; full normalized evidence in existing lazy Raw data; one consumer-shaped core diagnostic seam. | ✓ |

**User's choice:** Research all alternatives with specialist subagents and make the coherent decision.

**Notes:** The selected contract follows consumer-oriented Elixir library design: core owns the
projection and returns typed domain data; the companion admin does not couple to Ecto or Stripe
payloads. It takes the strongest DX lesson from Pay/Cashier while avoiding the maintenance cost
of a dj-stripe-style full provider mirror. The visible list is capped at eight; stored evidence is
never truncated.

**User's choice:** Research all alternatives with specialist subagents and make the coherent decision.

**Notes:** No-data is not success, empty observation is not no snapshot, and old-looking data is
not formally stale without policy. Exact Copy plus non-color semantics protects accessibility and
operator psychology. Static mount output does not misuse live-region roles.

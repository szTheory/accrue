# Phase 214.2 — UI Design Contract

> Visual and interaction contract for the advisory entitlement diagnostic in the existing customer-detail disclosure.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing AccrueAdmin `ax-*` token system; no shadcn (Phoenix LiveView, not React/Next/Vite) |
| Preset | not applicable |
| Component library | Existing Phoenix components: `Detail.detail_field_list`, `StatusBadge`, `JsonViewer` |
| Icon library | Existing Heroicons via AccrueAdmin `Icon`; no new icon is required |
| Font | Geist / Geist Mono fallbacks |

Reuse the existing native `<details>/<summary>` disclosure, field-list layout, Copy module, and lazy Raw data panel. Do not introduce Tailwind, a new shared component, a new route/tab/nav item, a refresh control, or a second debug disclosure. [CONTEXT D-01, D-13, D-14, D-18]

## Spacing Scale

Use existing tokens only; maintain the dense customer-detail layout.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline label/value and badge gaps |
| sm | 8px | Compact field and preview-item spacing |
| md | 16px | Existing `ax-stack-md` gap between group heading, boundary, badge, and fields |
| lg | 24px | Section internal padding when inherited from the detail disclosure |
| xl | 32px | Existing page-layout gaps only; do not add space for this diagnostic |
| 2xl | 48px | Existing major-section separation only |
| 3xl | 64px | Existing page-level separation only |

No spacing exceptions: all phase-rendered layout, including inherited badge and field-list treatment, uses only the approved values above. Do not add or change spacing in an inherited area that cannot comply with this scale. At 360px, field-list values wrap beneath labels as the existing responsive layout dictates; never horizontally scroll or clip the advisory group. [CONTEXT D-14; `theme.css`]

## Typography

Use exactly the existing Geist role tokens and their two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / advisory boundary and field values | 16px | 400 | 1.5 |
| Label / `StatusBadge` / field labels | 14px | 600 | 1.4 |
| Group heading | 20px | 600 | 1.2 |
| Detail-page display (existing only; not added here) | 36px | 600 | 1.2 |

Use regular (400) and semibold (600) only. Long lookup keys and all diagnostic prose use `overflow-wrap: anywhere`; do not ellipsize a key, timestamp, state, or `+N more` count. [CONTEXT D-11, D-12, D-14; `theme.css`]

## Color

Use theme-aware semantic tokens; never hard-code a phase-specific color. The stated 60/30/10 allocation is inherited from the existing theme and applies in light, dark, and system modes.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` (`--accrue-paper` light; `#0f1318` dark) | Page and disclosure background |
| Secondary (30%) | `--ax-elevated` (`#ffffff` light; `#171d24` dark) | Existing cards and Raw data viewer |
| Accent (10%) | `--ax-accent` / `--ax-accent-readable` | Existing focus rings, links, and primary controls only; none created by this phase |
| Destructive | `--ax-danger` / `--ax-danger-readable` | Existing destructive actions only; none in this diagnostic |

Accent reserved for: existing keyboard focus, links, and primary actions only. Advisory state semantics use text plus `StatusBadge`: Slate/Ink for `disabled`, `not_observed`, `recorded`, and `age_unknown`; Amber for `incomplete`; error/danger treatment only for `unavailable`; Moss only for a genuine success fact and never just because a row exists. Never encode a state in color alone. [CONTEXT D-15–D-17]

## Copywriting Contract

All visible strings live in `AccrueAdmin.Copy.Entitlements`; use the exact phrases below and no grant/deny, match/mismatch, healthy, drift, freshness, cache-row, or JSONB claims for Stripe observation.

| Element | Copy |
|---------|------|
| Primary CTA | None — read-only diagnostic; do not add refresh, retry, or action CTA |
| Group boundary | `Stripe advisory snapshot — does not change access.` |
| Empty state heading | `No snapshot yet.` |
| Empty state body | `No advisory snapshot has been recorded for this customer.` No next step is offered. |
| Disabled state | `Not enabled.` / `Stripe advisory sync is off for this host. Local access above is unchanged.` |
| Recorded state | `Snapshot recorded.` / `Observed {absolute UTC timestamp}.` |
| Unknown-time state | `Snapshot time unavailable.` / `This advisory snapshot has no recorded observation time.` |
| Partial state | `Incomplete snapshot.` / `This webhook snapshot contains only the first reported entitlements. Local access above is unchanged.` |
| Error state | `Snapshot unavailable.` / `We couldn't load the Stripe advisory snapshot. Local access above is unchanged.` No retry control. |
| Entitlement count | `{count} entitlements observed`; for zero, exactly `0 entitlements observed` |
| Preview overflow | `+N more` after the first eight alphabetically sorted lookup keys |
| Destructive confirmation | None — this phase performs no destructive action |

The existing local Access headline and the first `Accrue access (canonical)` group are the disclosure's primary focal point. `Stripe observation (advisory)` is deliberately secondary: it follows the canonical group, uses the compact inherited field-list treatment, and never visually competes with or changes local facts. The summary-list Access headline remains derived from local resolution only. Do not render a reconciliation or staleness verdict. [CONTEXT D-01–D-05, D-12, D-15–D-18]

## Interaction and Content Contract

1. Append `Stripe observation (advisory)` below the canonical group inside the existing **Access and entitlements** disclosure; always render its boundary sentence and labelled state badge.
2. For `recorded`, `age_unknown`, and `incomplete`, render a compact field list in this order: state explanation, observed-entitlement count, sorted lookup-key preview, observed-at, source, completeness. Omit those metadata rows for `disabled`, `not_observed`, and `unavailable` rather than presenting invented values.
3. Show full normalized evidence only when the operator opens the existing lazy **Raw data** disclosure; reuse `JsonViewer`, escaping/redaction, and permitted payload contract. Do not show provider object IDs, Ecto fields, watermark, provider payload, payment/card PII, or a nested raw-data panel in the primary disclosure.
4. The result is static mount content: do not add `role="status"`, polling, async/loading UI, processor/network I/O, or a manual refresh. Native summary control remains keyboard-operable and focus-visible.
5. Preserve an independent advisory error: its unavailable state cannot replace canonical local facts, change local grants/headline, or crash the page.

## UI Considerations

Applicable state considerations resolved: 6 covered, 2 backstop, 2 dismissed.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Advisory observation field list | ✅ covered | `not_observed` is a distinct labelled state, while a recorded empty list renders `0 entitlements observed`; absence is never collapsed into zero results. |
| loading | Static customer-detail diagnostic | ✅ dismissed | One bounded synchronous core read occurs during mount/refresh; no async/network operation or loading surface is introduced. |
| error | Advisory observation and canonical field list | ✅ covered | Advisory read/decode failure renders the exact unavailable Copy text and retains local content; existing canonical failure remains separately contained. |
| populated | Advisory observation | ✅ covered | Recorded, age-unknown, and incomplete states use the inherited field list, semantic text badge, count, time, source, completeness, and sorted preview. |
| partial | Advisory observation | ✅ covered | `incomplete` states explicitly explain webhook partiality and use Amber plus text; no completeness or authorization inference is made. |
| overflow | Lookup-key preview and Raw data | 🧪 backstop | Focused LiveView/browser test proves only eight sorted keys render in the disclosure with `+N more`; full normalized evidence remains available in existing Raw data. |
| zero-one-many | Lookup-key collection | ✅ covered | Zero has the exact observed-count text; one/eight render naturally; nine-plus uses the deterministic eight-key preview and `+N more`. |
| long-text | Lookup keys, UTC time, status copy | 🧪 backstop | Responsive customer-detail browser test at 360px proves wrapping without clipping, overlap, or horizontal scroll; existing `overflow-wrap:anywhere` applies. |
| nav | Customer detail/navigation | ✅ dismissed | No route, tab, peer navigation item, or navigation state is added. |

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| device → authenticated host transport | Device/account claims, nonce proof, and evidence cross an untrusted client boundary. |
| server proof → device cache | Signed allow/deny material crosses into durable client state and must replace atomically. |
| Crosswake shell → Apple native APIs | An unresolved bridge could misrepresent unavailable native operations as proven. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-215-01 | Spoofing | device registration/reconnect | high | mitigate | Bind account/device/key thumbprint and nonce proof in golden vectors; reject wrong-key/device/account cases in both suites. |
| T-215-02 | Tampering | cached allow/deny replacement | high | mitigate | Enforce monotonic revision/iat/freshness and denial precedence with crash/fault vectors and atomic replacement tests. |
| T-215-03 | Information Disclosure | physical-device evidence | medium | mitigate | Commit only redacted device-class and result metadata; assert no device IDs, secrets, raw receipts/JWS, payloads, or PII. |
| T-215-04 | Elevation of Privilege | feasibility report | high | mitigate | Overall proven requires all capability lanes; missing Crosswake or device evidence deterministically yields feasibility_blocked. |
| T-215-SC | Tampering | package admission | high | mitigate | Install no package; authoritative Crosswake source remains an explicit unresolved input rather than an inferred dependency. |
</threat_model>

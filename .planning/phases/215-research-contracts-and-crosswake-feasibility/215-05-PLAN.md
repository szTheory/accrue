<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| canonical DecisionCases → offline fixture | Derived protocol cases must not gain independent IDs, versions, or dispositions. |
| signed server proof → Elixir/Swift verifier | Untrusted compact JWS input crosses a cryptographic and claim-validation boundary. |
| verified candidate → durable client cache | A crash or rollback attempt must not expose torn, stale, or resurrected entitlement state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-215-17 | Tampering | DecisionCase/vector binding | high | mitigate | `--check` and mutation-sensitive ExUnit fail closed on missing/duplicate IDs or version/disposition divergence. |
| T-215-18 | Spoofing | compact JWS verification | high | mitigate | Both suites cryptographically pin ES256/public key and reject signature, issuer, audience, type, account, device, and thumbprint mismatch. |
| T-215-19 | Elevation of Privilege | allow/deny high-water state | high | mitigate | Both suites fail on rollback/older inputs and prove equal/newer signed denial precedence without allow resurrection. |
| T-215-20 | Tampering | durable replacement | high | mitigate | Before/after fault injection proves verified candidate durability plus atomic rename, with only old-or-new complete state observable. |
| T-215-21 | Information Disclosure | deterministic fixture key/payloads | medium | mitigate | Key is explicitly test-only; automated scope checks reject production references and fixtures contain no PII/provider payloads. |

## ASVS L1 Control Mapping

| ASVS control | Applicability | Executable evidence / fail-closed gate |
|---|---|---|
| V2 Authentication | Applicable | Elixir/Swift tests require account/device identity plus key-thumbprint and nonce-bound expectations; wrong bindings fail closed (T-215-18). |
| V3 Session Management | Applicable | Reconciliation inputs require authenticated account/device binding and monotonic high-water state; replay/rollback cases fail closed (T-215-19). |
| V4 Access Control | Applicable | Only a verified newer allow or equal/newer signed denial changes cached disposition; invalid evidence cannot grant and denial precedence is automated (T-215-19). |
| V5 Input Validation | Applicable | Both parsers reject malformed compact input, unknown/duplicate security fields, wrong fixed claims, canonical-case drift, and invalid ordering (T-215-17/T-215-18). |
| V6 Cryptography | Applicable | Actual ES256 verification with a pinned P-256 public key runs in both languages; wrong algorithm/key/signature and key-fixture leakage fail automatically (T-215-18/T-215-21). |
</threat_model>

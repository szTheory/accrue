<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| persisted cache → fresh process | On-disk payload and ordering metadata are untrusted until authenticated. |
| concurrent processes → one cache path | Separate address spaces can race restore, comparison, candidate rename, and high-water adoption. |
| cache authentication key → tracer storage | Key material must be supplied by the host/device secure boundary and never persisted beside the cache or exposed in diagnostics. |

| T-215-45 | Tampering | persisted revision/disposition | high | mitigate | HMAC-authenticated versioned envelope binds payload, revision, disposition, and path context; field/key mutation tests fail closed. |
| T-215-46 | Elevation of Privilege | denial restart | high | mitigate | Fresh-process restoration precedes candidate comparison; denial-restart stale-allow regression proves access cannot resurrect. |
| T-215-47 | Tampering | interprocess replacement race | high | mitigate | Per-cache POSIX lock encloses authenticated reload through durable rename/adoption, with concurrent child-process tests. |

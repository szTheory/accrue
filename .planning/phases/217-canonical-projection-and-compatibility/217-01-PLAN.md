## Trust Boundaries

| Boundary | Description |
|---|---|
| authenticated host reference → account lookup | Host identity selects which canonical account may be read or provisioned. |
| qualified observation → projector transaction | Provider-normalized state may alter one lineage's durable authorization. |
| current grants → public snapshot/audit/telemetry | Durable provider facts are reduced into a privacy-safe decision value. |

## STRIDE Threat Register (ASVS L1; block threshold high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-217-01 | Tampering | `Projector.project/2` | high | mitigate | Task 1 locks the account, scopes mutation to one qualified lineage, uses PostgreSQL constraints, and tests duplicate/stale/concurrent-safe material revision. |
| T-217-02 | Elevation of Privilege | snapshot account lookup | high | mitigate | Task 1 accepts only an account or host-authenticated billable reference, separates provisioning, and tests that reads cannot create or cross accounts. |
| T-217-03 | Information Disclosure | snapshot/projector/audit telemetry | high | mitigate | Task 1 names all three span families, restricts each to an explicit metadata allowlist with opaque/hashed IDs, and captures start/stop/exception events to reject forbidden keys and seeded identity/evidence/JWS/token/provider-payload values. |
| T-217-04 | Repudiation | material revision | medium | mitigate | Each material change records one bounded immutable audit event in the same transaction; no-op evidence records no false authorization revision. |

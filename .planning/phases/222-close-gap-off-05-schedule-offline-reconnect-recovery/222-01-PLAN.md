<interfaces>
Use these existing contracts directly:

- `Accrue.Entitlements.Offline.ReconnectSweeper.perform(%Oban.Job{})` calls `Reconnect.enqueue_due(Accrue.Repo.repo())` and returns `:ok` after eligible durable attempts are requeued.
- `Accrue.Entitlements.Offline.ReconnectWorker.perform(%Oban.Job{args: %{"attempt_id" => id}})` calls `Reconnect.execute_attempt(id)` using `Application.get_env(:accrue, :offline_reconnect)`; a valid worker configuration must include `:source_coordinator` and `:key_provider` plus their required options.
- `Accrue.Entitlements.Offline.KeyProvider` callbacks are `sign(binary(), keyword())` and `public_keys(keyword())`.
- `Accrue.Entitlements.Offline.SourceCoordinator` callbacks are `due_sources(account, now, opts)`, `refresh(account, status, now, opts)`, and `enqueue_repair(account, status, now, opts)`.
- `Offline.reconnect_challenge/3` plus a device-signed `%Reconnect.Request{}` is the only admission path; `after_admission: fn -> :interrupted end` leaves the admitted attempt durable without permitting worker-side authentication fabrication.
- `Offline.verify/3` verifies the terminal compact proof against issuer, audience, account subject, installation ID, device thumbprint, public key, accepted revision/disposition/high-water values, and the verification clock.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| device -> reconnect admission | Untrusted device request crosses the host authorization and one-time PoP challenge boundary before any durable attempt exists. |
| Oban Cron/worker -> reconnect persistence | A scheduler trigger may duplicate or arrive late; PostgreSQL eligibility locks and execution tokens, not Cron leadership or Oban uniqueness, own advancement. |
| ReconnectWorker -> host source/key adapters | The worker may refresh provider state and request signing only through host-owned behavior modules and validated configuration. |
| signed proof -> client cache | The server emits a signed replacement outcome; client proof is never fed back as provider truth, and this phase does not change the client cache implementation. |

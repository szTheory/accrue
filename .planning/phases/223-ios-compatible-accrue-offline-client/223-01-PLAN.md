<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| host/server bytes → core verifier | Compact proof bytes and JWKS-derived public material are untrusted until strict verification succeeds. |
| verified proof → cache | Only a private verifier-created value may cross into ordering and persistence. |
| filesystem → recovered state | Cache bytes are untrusted until the canonical envelope HMAC authenticates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-223-01 | Tampering | compact JWS admission | high | mitigate | Exact ES256/profile/header/claims/P-256 signature checks in `OfflineEntitlementClient.swift`; mutation tests begin in this plan and expand in 223-02. |
| T-223-02 | Spoofing | account/device binding | high | mitigate | Compare issuer, audience, subject/account, and `cnf.jkt` against construction-time host configuration before creating `VerifiedOfflineProof`. |

| T-223-SC | Tampering | package dependencies | low | accept | No npm/pip/cargo or third-party Swift dependency install occurs; Apple system frameworks and the repository toolchain are used. |

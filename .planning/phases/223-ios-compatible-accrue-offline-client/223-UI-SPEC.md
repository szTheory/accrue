# Phase 223 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Boundary

This phase ships a SwiftPM offline-client library, not a rendered UI. It must not add SwiftUI, UIKit, web, StoreKit purchase/restore, or host-screen code. The library's public `Sendable` state, bounded reason, and bounded next-action values are the host-UI seam: they must allow a later host to render literal, accessible guidance in its own light, dark, and system themes without relying on color alone or exposing crypto, cache, transport, or backend mechanics.

The host owns all layout, fonts, colors, loading treatments, navigation, accessibility traits, localization, and content-access policy. This contract defines only the stable semantics and consumer-facing copy that a host may map to UI.

## Color

The package emits semantic state only and must never encode meaning through a color, icon, or visual severity. A host maps the four states to its own accessible semantic presentation in every supported appearance.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | host-defined | No package surface is rendered. |
| Secondary (30%) | host-defined | No package card, navigation, or sidebar is rendered. |
| Accent (10%) | host-defined | A later host may reserve it for its primary reconnect control only. |
| Destructive | host-defined | Not used by this package; no destructive operation is exposed. |

Accent reserved for: the host's primary **Reconnect** control when it chooses to render one. It must not be the sole signal for `fresh`, `stale_offline`, `denied`, or `invalid`.

## Copywriting Contract

These strings are normative host-rendering examples, not package-rendered UI. Package documentation may use them verbatim; host applications may localize them while preserving their literal state and next action. They follow the measured, exact, action-first Accrue voice. [Source: 223-CONTEXT.md D-14; `brandbook/voice.md`]

| Element | Copy |
|---------|------|
| Primary CTA | `Reconnect` |
| Empty state heading | `No offline proof is cached.` |
| Empty state body | `Connect to refresh your study state.` |
| Error state | `This offline proof could not be verified. Reconnect to request a new proof.` |
| Destructive confirmation | None — the public facade exposes no destructive action. |

State naming contract: host-visible text maps explicitly to the locked four states `fresh`, `stale_offline`, `denied`, and `invalid`. `stale_offline` must state that continuity is limited to study use and must never be presented as a new local entitlement grant. `denied` and `invalid` must retain their bounded next action; no fifth `reconnect_required` state is permitted. [Source: 223-CONTEXT.md D-02, D-14]

## UI Considerations

> Populated by the ui-phase UI-consideration probe and lifted by plan-phase's UI-considerations rule. Empty-state and error-state copy lives in the Copywriting Contract above; this section covers state coverage without restating it.

Applicable state considerations resolved: 6 covered, 0 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Host rendering of a missing cached proof | ✅ covered | The facade returns the bounded `invalid` outcome rather than rendering; host documentation maps that absence to the documented empty-state copy and `Reconnect` action. |
| loading | Host-owned reconnect flow | ✅ covered | `OfflineProofReconnectTransport.fetchOfflineProof()` is async; the host owns in-flight presentation. The package renders no spinner, overlay, or progress UI. |
| error | Proof verification, cache write/recovery, or reconnect failure | ✅ covered | The facade returns a bounded reason and next action. Hosts render the documented error copy without raw transport, cache, or crypto diagnostics. |
| populated | Four-state facade result | ✅ covered | Each successful load/apply/reconnect resolves to exactly `fresh`, `stale_offline`, `denied`, or `invalid`; values are immutable and `Sendable`. |
| partial | Cache/recovery result | ✅ covered | A failed candidate write or recovery preserves the prior complete authenticated envelope; a partial cache is never surfaced as accepted state. |
| long-text | Host-visible reason and next-action labels | ✅ covered | Public vocabulary is bounded domain values, not unbounded server error text. Hosts may localize labels but must retain explicit text and action. |
| overflow | Package UI | dismissed | No list, navigation, or static rendered surface is introduced in this phase. |
| zero-one-many | Package UI | dismissed | The facade returns one state value, not a collection or list UI. |

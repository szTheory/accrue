## Trust Boundaries

| Boundary | Description |
|---|---|
| external Crosswake source → phase execution | Source identity, revision, and diff are untrusted until the clean-checkout audit and immutable lock agree. |
| WebKit message → existing Crosswake validator | Raw browser input remains untrusted through every existing protocol/frame/origin/pack/manifest/route check. |
| validated Crosswake state → host delegate | Only the typed normalized request and cancellation context may cross; transport authority remains inside Crosswake. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-224-01 | Spoofing | Crosswake source pin | high | mitigate | `crosswake-source-lock.json` binds sanitized remote, base, reviewed patch revision, diff identity, and audit digest; the runner rejects any other checkout. |
| T-224-02 | Elevation of privilege | bridge admission | high | mitigate | Insert the tracer only after the audit-named existing validator and require exact manifest capability ∩ registry command/version before delegate invocation. |
| T-224-03 | Tampering | reply ownership | high | mitigate | Delegate types exclude WebKit/evaluator/callback/reply members and return only a closed outcome to the existing private one-shot terminalizer. |
| T-224-04 | Information disclosure | descriptor payload | medium | mitigate | Fixed no-field tracer request/response, explicit byte/field bounds, and rejection of unknown/duplicate fields prevent sensitive or ambient maps crossing the seam. |
| T-224-SC | Tampering | source/package acquisition | high | mitigate | No package-manager install occurs; source legitimacy is established by remote/base/diff review and exact revision pin before any test evidence is accepted. |
</threat_model>

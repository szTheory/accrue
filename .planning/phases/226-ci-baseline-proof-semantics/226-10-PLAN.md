<interfaces>
The collector already defines the trusted derivations that validation must independently mirror:
- staged chain jobs are those whose policy-derived `staged_critical_chain_order` is non-null;
- when every selected job has `started_at` and `completed_at`, chain seconds equal the maximum completion epoch minus the minimum start epoch;
- failing-lane pairs are sorted unique `{manifest_identity, conclusion}` values for `failure`, `timed_out`, and `cancelled` jobs;
- category is `no-failure` for an empty pair set and `failed-lane` otherwise;
- signature ID is `ci-root-v2-` plus the existing unpadded base64 encoding of `[derived_category, derived_pairs]`.

`validate_collector_record` and `validate_canonical_cohort` are the two public document paths. `validate_aggregates` may consume per-run chain values only after the shared derived-run predicate succeeds.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository refs/filesystem → preservation script | User-owned refs and artifacts enter a command that may create local preservation state. |
| private recovery capsule → committed inventory | Sensitive machine paths and recovery details must be reduced to allowlisted public evidence. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-229-01 | Tampering | `preserve_repository_state.sh` ref ordering | high | mitigate | Snapshot full object IDs, create only collision-safe preservation refs, verify the external bundle and every object, and stop before any later observation on failure. |
| T-229-02 | Information Disclosure | inventory schema and renderer | high | mitigate | Reject non-allowlisted keys, absolute/traversing paths, environment values, actors, raw logs/payloads, and external bundle locations before writing JSON or Markdown. |
| T-229-03 | Elevation of Privilege | shell arguments and git object expressions | high | mitigate | Strict option parsing, quoted argv, full-object validation, fixed preservation namespace, and no evaluated shell input. |
| T-229-04 | Repudiation | recovery proof | medium | mitigate | Record object IDs, preservation ref names, bundle digest, verification result, observation time, and restore templates in canonical evidence. |
</threat_model>

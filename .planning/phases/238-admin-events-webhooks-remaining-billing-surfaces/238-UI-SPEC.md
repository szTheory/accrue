# Phase 238 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual — existing Accrue Admin Phoenix component system |
| Preset | Not applicable |
| Component library | AccrueAdmin.Components (in-repo LiveView components; no external UI package) |
| Icon library | Existing inline Heroicons |
| Font | Geist / Geist Mono, served by Admin assets; inherit existing Admin theme |

**Visual anchor:** The owner-scoped webhook delivery table (compact cards on narrow screens) is the primary screen anchor. Draw the eye first to each delivery's status and timestamp, then to its accessible identifier and scoped event/detail evidence; keep filters and secondary billing-surface links visually subordinate.

Preserve the established Admin shell, page header, filter toolbar, DataTable desktop list/mobile cards, semantic status colors, detail sections/drawer, flash announcements, and step-up overlay. Do not introduce a new visual language or dependency. Keep Events and Webhooks as distinct evidence sources. Coupons and promotion codes remain read-only inspection surfaces. On Connect details label Stripe-observed readiness separately from the locally configured platform fee override.

## Spacing Scale

Declared values (multiples of 4); use the existing 4px-base Admin spacing tokens.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon/text gaps, compact inline grouping |
| sm | 8px | Filter and control grouping |
| md | 16px | Default content and field spacing |
| lg | 24px | Card and section padding |
| xl | 32px | Major layout grouping |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level separation |

No spacing exceptions below the 4px base grid. Interactive targets remain at least 44px high/wide on coarse pointers; keep target sizing as a control dimension, not a spacing token. Do not create page-wide horizontal overflow at 320 CSS px; tables must use the existing compact card representation or a locally contained scroll region when necessary.

## Typography

Use the existing Geist roles and monospace role for machine identifiers and payload values. These are the phase's four sizes and two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting label / dense metadata | 12px | 600 | 1.4 |
| Body / table values | 16px | 400 | 1.4 |
| Page and detail section title | 20px | 600 | 1.2 |
| Detail emphasis / summary metric | 24px | 600 | 1.2 |

Long identifiers and event types use Geist Mono at 12px/400; wrap or allow local horizontal scrolling inside the value container, never clip the only identifier. Existing Admin theme tokens define their line-height and type scale; these phase roles document the intended use, not new global tokens.

## Color

Use semantic `--ax-*` / `--accrue-*` tokens so light, dark, system, and host-forced themes continue to resolve through the existing root theme. Approximate 60/30/10 refers to visual area, not fixed hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--ax-base` / `--accrue-paper` (dark theme equivalent from theme.css) | Page canvas and broad background surfaces. |
| Secondary (30%) | `--ax-elevated`, `--ax-sunken`, `--ax-border` | Cards, table rows, detail panels, filter region and navigation. |
| Accent (10%) | `--ax-accent`, `--ax-accent-strong`, `--ax-accent-readable` | Primary “Apply filters” action, active filter/lens, focused selection affordance, and primary route/action links only. |
| Destructive | `--ax-status-danger-*` | Failed/blocked status indicators and explicitly destructive confirmation only; never use as a generic replay accent. |

Accent reserved for: primary filter submission, current filter/lens selection, keyboard focus ring, and primary links/actions. Informational, success, warning, and failure states use their dedicated semantic status tokens and visible text; color alone never distinguishes delivery state or action outcome. Do not assign Stripe readiness and local fee override the same badge or visual grouping.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | “Replay selected deliveries” (only when one or more rows are selected; disabled while submitting) |
| Empty state heading | “No deliveries to show” |
| Empty state body | “No webhook deliveries match these filters. Clear a filter or review all deliveries.” |
| Error state | “Delivery history could not be loaded. Try again; the current results are not a complete history.” |
| Destructive confirmation | Replay selected deliveries: “Replay {N} selected deliveries? Only deliveries still eligible when confirmed will be queued. Queue acceptance does not mean processing is complete.” Label the affirmative control “Queue eligible deliveries” and the dismissal control “Keep deliveries”. Require explicit confirmation, followed by fresh step-up before the server action. |

For list search with zero matches use “No results match these filters” with a clear-filters action. Keep a true zero-record state distinct from unavailable/failed evidence reads. Detail payload disclosure is labeled “Show payload”; keep it collapsed until explicitly opened and label it as event/delivery data. Never display an accepted/queued outcome as processed. Use precise result copy: “Queued {n} deliveries. {s} skipped; {f} failed.” When no rows were queued, state that plainly. Coupon and promotion-code views expose inspection and relationship links only; do not display create/edit controls. Connect copy must identify observed Stripe capabilities versus “Local platform fee override”.

### Verification seam decision (execution amendment)

The existing host fixture cannot deterministically inject database read failures or queue-interleaving outcomes. Those cases remain covered by the focused Admin ExUnit/LiveView suites, which run in required CI. The mounted Playwright shard covers the real host route, seeded record relationships, keyboard and theme behavior, rejected step-up recovery, responsive layout, and an actual local queue acceptance path. Do not add a production fault-injection hook solely to duplicate deterministic ExUnit cases in the browser.

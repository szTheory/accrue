## Key Implementation Notes

- **DataTable selection emit:** `handle_event("bulk-action", ...)` does NOT mutate the component — it `send(self(), {:data_table_bulk_action, event, MapSet.to_list(selected_ids)})` so the parent LiveView owns the confirm + side effect via `handle_info`. Primary button renders only when `bulk_action_event` set and selection non-empty.
- **selectable default flip:** `assign_new(:selectable, fn -> false end)`. Webhooks passes `selectable={true}` explicitly; the other 8 list pages drop orphaned checkboxes with zero per-page edits.
- **Owner-scoped queries:** `distinct_types/1` + `status_counts/1` added to `queries/webhooks.ex` only (admin package), using post-fetch `scope_rows/2` — matching `count/2`/`bulk_replay_count/2`. No SQL pushdown, no core `accrue` change.
- **Segmented filter primitive:** `:segmented` is a native radiogroup in the GET form (no JS for submission). New shared `.ax-segmented*` CSS modeled on the theme-picker. Registered `segmented`/`filter` family in the component lab (`ax_class: "ax-segmented ax-segmented-option"`) with a dedicated `do_render_specimen("segmented", ...)` clause rendering the variant class — satisfies the render-coverage guardrail (the generic catch-all renders `[@family/state]`, which would NOT contain the variant class).
- **`:select` extension:** honors a `disabled` option key + count-in-label, and never disables the currently-selected value even at zero count (`option_disabled?/1` + `not option_selected?`).
- **Microcopy:** all webhooks strings moved to `Copy` / `Copy.Locked`, JTBD-plain. No "DLQ", "cap", "slice", "dead-letter", "intent", or "audit event" jargon in user-facing strings. Selection action = "Retry selected"; confirm = "Retry N webhook event(s)? They failed every automatic retry — retrying runs them through processing again." (plural-aware); footer = "Showing N events".

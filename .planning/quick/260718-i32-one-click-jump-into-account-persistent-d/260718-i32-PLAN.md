# Quick Task 260718-i32: One-click "jump into account" + persistent demo account switcher

## Goal
The accrue_host demo exists to show off **billing, not login**. Make it trivial to become any
demo persona and land straight in their billing story, while keeping the real Sigra login form.
Add (1) a one-click "Enter workspace" button on each login card, and (2) a persistent "Switch
account" dropdown in the top nav (host pages).

Full approved design + rationale: `~/.claude/plans/i-m-in-users-jon-projects-accrue-current-refactored-willow.md`.

## Design (locked)
- **Genuine login, not a bypass.** "Enter workspace" / "Switch account" submit the **real**
  `/users/log-in` form pre-filled (persona email + shared `accrue-demo-password` + `return_to`).
  No dev-only auth endpoint, no impersonation backdoor — the shared password is already public on
  the page, and correct-password logins never trip Sigra lockout.
- **Safe `return_to`** added to the real login so each persona lands on its own route
  (`/app/billing`, `/billing`, `/admin`). Local-path-only guard blocks open redirects.
- Naming is "Enter workspace" / "Switch account" (never "impersonate" — these are real logins).
- Copy chips stay visible below the button (user preference).

## Tasks
1. **Safe `return_to` on login** — `controllers/user_session_controller.ex`
   - action: in the email+password `create/3`, pipe through `maybe_store_login_return_to/2` (sets the
     existing `:user_return_to` session key) before `UserAuth.log_in_user/3`; add `local_path?/1` guard.
   - verify: POST with `return_to=/app/billing` → 302 to `/app/billing`; forged `//evil` ignored.
2. **Shared `demo_login_form/1`** — `components/core_components.ex`
   - action: renders the real pre-filled login `<.form>` (email + `DemoBrand.demo_password()` +
     `return_to=persona.route`) with the caller's button in the slot; one source of truth for both surfaces.
3. **Login-card "Enter workspace" CTA** — `live/user_live/login.ex`
   - action: primary `btn btn-primary btn-sm` submit above the copy chips + "or copy to sign in manually"
     divider; chips kept.
4. **Persistent "Switch account" dropdown** — `components/layouts/root.html.heex`
   - action: daisyUI `dropdown dropdown-end` in the logged-in nav cluster listing all personas as
     `demo_login_form` POST buttons (current one highlighted); shows current persona label. Replaces the
     plain email span; Settings + Log out remain.

## Constraints
- Touch only the four files above; leave the ~10 pre-existing dirty/untracked files untouched.
- `AccrueHost.DemoBrand` unchanged. Host builds its own assets at dev time; no committed-bundle rebuild.
- Known tradeoff: the nav switcher shows on host pages, not inside the `/admin` or `/billing` package UIs
  (separate chrome).

## Verification
Playwright against the live stack — 8/8 assertions: Enter workspace → `/app/billing`; nav switcher present
+ shows current persona; switch across all 4 personas landing on `/app/billing`, `/billing`, `/admin`; forged
`return_to=//evil` stays on-site; manual password login unchanged (lands on `/`). Server-side curl confirms
302→`/app/billing`.

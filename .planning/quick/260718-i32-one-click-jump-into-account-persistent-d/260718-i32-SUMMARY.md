# Quick Task 260718-i32 — Summary

## What changed
- `controllers/user_session_controller.ex` — the email+password `create/3` now honors a **safe
  `return_to`** via `maybe_store_login_return_to/2` (sets the existing `:user_return_to` session key that
  `UserAuth.log_in_user/3` already reads) with a `local_path?/1` guard that blocks open redirects
  (`//host`, `/\host`). Backward-compatible: manual forms send no `return_to` and still land on `/`.
- `components/core_components.ex` — new `demo_login_form/1`: renders the **real** pre-filled login form
  (persona email + `AccrueHost.DemoBrand.demo_password()` + `return_to=persona.route`) with the caller's
  button in the slot. Single source of truth for both the login cards and the nav switcher.
- `live/user_live/login.ex` — each persona card gains a primary **"Enter workspace"** button above a muted
  "or copy to sign in manually" divider; the copy chips remain.
- `components/layouts/root.html.heex` — persistent **"Switch account"** daisyUI dropdown in the logged-in
  nav cluster: lists all personas as `demo_login_form` POST buttons (current one highlighted), shows the
  current persona's label. Replaces the plain email span; Settings + Log out remain.

## Verification
Playwright against the live stack — **8/8 PASS**: "Enter workspace" → `/app/billing`; nav switcher present
and shows the current persona; switching hops Program Owner→Scale Customer (`/app/billing`), →Finance Lead
(`/billing`), →Billing Operator (`/admin`); forged `return_to=//evil.example` is ignored (stays on
`accrue.localhost`); manual password login still works and lands on `/`. Server-side curl confirms a clean
`302 → /app/billing`.

## Notes
- The mechanism is a **genuine login**, not impersonation — the shared demo password is already public on the
  page, and correct-password logins never trip Sigra's lockout.
- Known tradeoff: the nav switcher renders on host pages (`/`, `/pricing`, `/app/billing`, `/users/settings`),
  not inside the `/admin` or `/billing` package UIs, which use their own chrome.
- During-connect quirk: clicking a form submit in the sub-second window before LiveView finishes its initial
  connect can drop the submit (falls back to a GET reload). This is inherent to all LiveView forms — the
  page's existing login forms included — not introduced here; real users (who read before clicking) don't hit it.
- `AccrueHost.DemoBrand` unchanged; host builds its own assets at dev time (no committed-bundle rebuild);
  pre-existing dirty/untracked files left untouched.

## Goal

Phase 1 of the approved admin re-skin gameplan
(`/Users/jon/.claude/plans/i-m-in-users-jon-projects-accrue-current-refactored-willow.md`):
three deterministic, root-cause **CSS-token corrections** in `accrue_admin`. These are the
"foundation" fixes that unblock the later ratchet-driven component pass. This is **not** a
redesign, palette change, or component restyle.

1. **Light-mode contrast pass** — the light theme reads washed-out/borderless; raise
   `--ax-border`, tighten surface layering, and confirm muted-text contrast. Token-level only.
2. **De-hardcode stray Cobalt literals** — `--ax-accent-readable`, `--ax-focus-ring`,
   `--ax-focus-shadow`, and the sidebar dark active pins bake in `#174ea6`/`#9bb5ff`/`#1f283d`
   cobalt hexes instead of deriving from `--ax-accent`. A swapped accent must follow.
3. **Single-source dark values** — the dark `--ax-*` set is triplicated across three selectors
   and hardcodes hexes that duplicate core `--accrue-*` dark tokens. Define once, bridge to core
   where it renders identically. Pure refactor: dark appearance stays pixel-identical.

Cobalt `#5D79F6` stays the interaction accent; Moss green stays success/status only. No greening.

### Task 2 — De-hardcode stray Cobalt literals so they follow --ax-accent (atomic commit)

- **files:** `accrue_admin/assets/css/theme.css`, `accrue_admin/assets/css/app.css`
- **action:** Replace hardcoded cobalt hexes with `--ax-accent`-derived `color-mix()` that
  preserves per-theme legibility AND is visually identical at the default accent (`#5D79F6`):
  - `theme.css` light block: `--ax-accent-readable: #174ea6` → derive by mixing `--ax-accent`
    toward ink for a dark-enough-to-read-on-white variant, e.g.
    `color-mix(in srgb, var(--ax-accent) 62%, var(--accrue-ink))` (tune the % so the result lands
    near `#174ea6` at cobalt). `--ax-focus-ring: #174ea6` → same derivation (can reference
    `var(--ax-accent-readable)`). `--ax-focus-shadow: 0 0 0 4px rgba(93, 121, 246, 0.24)` →
    `0 0 0 4px color-mix(in srgb, var(--ax-accent) 24%, transparent)` (rgba(93,121,246) IS cobalt).
  - `theme.css` dark blocks (all three — see Task 3; if Task 3 lands first, edit the single shared
    block): `--ax-accent-readable: #9bb5ff` → mix `--ax-accent` toward paper, e.g.
    `color-mix(in srgb, var(--ax-accent) 65%, var(--accrue-paper))` (tune near `#9bb5ff`).
    `--ax-focus-ring: #9bb5ff` → same. `--ax-focus-shadow: 0 0 0 4px rgba(155, 181, 255, 0.24)`
    (`rgba(155,181,255)` IS `#9bb5ff`, the dark periwinkle accent-readable — NOT cobalt) →
    `0 0 0 4px color-mix(in srgb, var(--ax-accent) 24%, transparent)`.
  - `app.css` sidebar dark active block (lines ~847–874, `.ax-sidebar-link-active` dark +
    `system@dark`): `background-color: #1f283d !important` (lines 865, 871) → replace the hardcoded
    hex with a `--ax-accent`-derived mix over the dark elevated surface, e.g.
    `color-mix(in srgb, var(--ax-accent) ~18%, var(--ax-elevated)) !important` (tune the % so it
    renders `#1f283d` when accent==cobalt). The `#f4f7fa` label pins at lines 851/859 equal the dark
    `--ax-primary` — replace with `var(--ax-primary)`. Keep `!important` and selectors exactly as-is.
    Do NOT touch the other `#f4f7fa`/`#1f283d` occurrences outside this window (lines 1020, 5121 etc.
    are separate scope — later ratchet pass).
  - **Correctness check (do NOT commit):** temporarily set a non-cobalt `--ax-accent` (e.g. edit the
    runtime default or a scratch `html.accrue-admin { --ax-accent: #cc5500; }`), rebuild or inspect,
    and confirm accent-readable, focus ring/shadow, and sidebar-active all shift with it. Then REVERT
    the scratch change before committing.
  - **Tolerance note:** `color-mix()` toward ink/paper/elevated lands NEAR (not exactly on) the
    hand-picked `#174ea6` / `#9bb5ff` / `#1f283d`. Expect a small delta on these 4 accent-derived
    tokens even at cobalt — prioritize legibility and a near-match over an exact hex hit. The
    "dark pixel-identical" invariant (Task 3 / Guardrails) applies to all NON-accent-derived dark
    tokens; these 4 are the deliberate exception.
- **verify:**
  - theme.css literals gone: `grep -nE '#174ea6|#9bb5ff|rgba\(93, ?121, ?246|rgba\(155, ?181, ?255' accrue_admin/assets/css/theme.css`

  - sidebar active bg de-hardcoded (line-scoped to the in-scope block):

  - At default cobalt, rendered colors match to within the small color-mix tolerance noted above.

### Task 3 — Single-source the dark --ax-* set (atomic commit)

- **files:** `accrue_admin/assets/css/theme.css`
- **action:** The dark token set is defined THREE times, identically:
  `html.accrue-admin[data-theme="dark"]` (lines ~221–280), the sub-tree pair
  `html.accrue-admin [data-theme="dark"], .accrue-admin [data-theme="dark"]` (lines ~287–347), and
  `@media (prefers-color-scheme: dark) { html.accrue-admin[data-theme="system"] }` (lines ~349–410).
  - Reduce the triplication to the CSS-minimum of **2 rule bodies** (not 1 — CSS cannot put a
    media-gated selector into a plain selector list): merge the two NON-media dark selectors
    (`html.accrue-admin[data-theme="dark"]` @221–280 and the sub-tree pair
    `html.accrue-admin [data-theme="dark"], .accrue-admin [data-theme="dark"]` @287–347) into ONE
    rule with a combined selector list authoring the dark set once. The
    `@media (prefers-color-scheme: dark) { html.accrue-admin[data-theme="system"] }` rule (@349–410)
    MUST stay inside its media query — keep it as the 2nd authored copy, pointing at the same values.
    Preserve `data-theme="light"`-stays-light-on-dark-OS behavior (do not widen the `system` guard).
  - Where a dark `--ax-*` maps cleanly to a core dark `--accrue-*` token, bridge it (brand.css
    `:root[data-theme="dark"]` defines `--accrue-ink:#ECF1F5`, `--accrue-slate:#B7C2CC`,
    `--accrue-surface:#171B20`, `--accrue-surface-muted:#10141A`, `--accrue-border:#2A333D`,
    `--accrue-shadow`). **Only bridge when it does NOT change the rendered value.** The admin's dark
    values differ from core (`--ax-primary:#f4f7fa` vs `--accrue-ink:#ECF1F5`;
    `--ax-elevated:#171d24` vs `--accrue-surface:#171B20`), so where they diverge, KEEP the admin's
    current hardcoded value. This is a de-duplication refactor first, an opportunistic bridge second —
    when in doubt, keep the exact admin hex.
  - Do NOT touch the light block or the reduced-motion block. Dark rendered appearance must be byte-identical.
- **verify:** The dark `--ax-*` set is authored in exactly **2 rule bodies**, not 3. Concretely
  `grep -c '#0f1318' accrue_admin/assets/css/theme.css` drops from **12** (4 occurrences —
  `--ax-base` + three `-on-solid` tokens — × 3 blocks) to **~8** (4 in the merged non-media rule +
  4 in the system media rule). Both dark rules still resolve to the same values; all three dark
  contexts (`[data-theme="dark"]`, sub-tree, system@dark) render identically. Rebuilt bundle diff
  (Task 4) shows no dark-mode color changes.
- **done:** Triplication reduced to the CSS-minimum of 2 rule bodies (merged non-media rule + the
  media-gated system rule); system-dark still gated by its media query; light-on-dark-OS preserved;
  dark appearance unchanged. Committed atomically
  (`refactor(260718-u1s): single-source admin dark --ax-* set`).

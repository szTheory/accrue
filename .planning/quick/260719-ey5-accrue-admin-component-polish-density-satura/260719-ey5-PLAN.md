# accrue_admin component polish — de-saturate status treatments + tighten over-padded regions

## Goal

Make the `/admin` dashboard read as calm, coherent, and on-brand ("quiet confidence"
dev-tooling voice) by a bounded, token/class-level VISUAL POLISH pass:

- **Task A — de-garish:** tone down the genuinely over-saturated status treatments
  (heavy full-bleed / solid saturated status fills → the brand's tinted-surface + border +
  strong-hue-on-text-only pattern that portal `.portal-status-*` already uses).
- **Task B — density:** tighten a handful of genuinely over-padded regions to operator-console
  density (step an existing `--ax-space-*` token DOWN; never below button min-heights).

This is **Phase 2** of the approved admin re-skin gameplan
(`~/.claude/plans/i-m-in-users-jon-projects-accrue-current-refactored-willow.md`), following the
just-shipped Phase 1 light-mode token fix (quick `260718-u1s`).

**Scope discipline (this is polish, not redesign):**
- NO palette change, NO hue change, NO "greening." Cobalt `#5D79F6` (`--ax-accent`) stays the
  interaction accent; Moss = success/status only; amber = warning; `--ax-danger` = danger.
  This pass reduces SATURATION/heaviness only.
- NO IA / layout / markup / copy restructure. The information-architecture findings are deferred
  to SEED-004 and are explicitly out of scope here.
- Edit SOURCE `assets/css/theme.css` / `assets/css/app.css` only. Prefer stepping an existing
  space/radius token down over inventing pixel values. Prefer deriving tints via
  `color-mix(<hue-token>, var(--ax-elevated))` so both light and dark auto-adapt.
- The admin has been through many ratchet rounds — **several regions are already calm / already
  tight** (e.g. `.ax-subscriptions-page .ax-data-table-grid td` is already `0.0625rem` padding-block).
  Only touch the genuinely over-saturated / over-padded ones. If a treatment is already calm, LEAVE IT.

## Tasks

### Task A — Calm the over-saturated status treatments (de-garish)

- **files:** `accrue_admin/assets/css/app.css` (and `assets/css/theme.css` only if a shared status-fill
  token is the cleanest single-source fix; prefer class-level edits in `app.css`).
- **action:** Apply the brand's quiet-confidence tinted-surface pattern to the genuinely over-saturated
  treatments listed in Grounding: emphasis = a TINTED SURFACE
  (`color-mix(<hue-token> ~12-18%, var(--ax-elevated))`) + a 1px `color-mix(<hue-token> ~40%, var(--ax-elevated))`
  border + full-strength hue ONLY on the text/icon/dot — NOT a solid full-bleed saturated fill.
  Concretely: (1) replace the SOLID `--ax-status-warning-solid` fill on the header health chip
  (`.ax-home-health-status`) with the tinted-surface treatment (keep `--ax-warning-readable` text at AA);
  (2) soften `.ax-button-primary` in DARK mode only by re-deriving the fill from
  `color-mix(var(--ax-accent) …, var(--ax-elevated))` so a row of primaries reads confident, not neon —
  do NOT change the light `--ax-accent-strong` fill and do NOT restructure the row; keep white
  `--ax-accent-contrast` at AA; (3) soften the `.ax-home-customer-search-strip` blue band (reduce the
  76% accent-subtle mix and/or 2px→1px border); (4) step down any verdict-bar/attention tint that reads
  heavy (e.g. `.ax-attention-summary-warning` 66%). KEEP all hues — reduce saturation/heaviness only.
  Leave already-calm treatments (`.ax-attention-row:first-child`, priority pills, health-summary tints,
  the dots) untouched. Any dark-scope token edit in `theme.css` MUST be mirrored into the
  `@media (prefers-color-scheme: dark) [data-theme="system"]` block. No markup/layout/copy changes.
- **verify:** `cd accrue_admin && grep -n 'ax-home-health-status\|ax-button-primary\|ax-home-customer-search-strip' assets/css/app.css`
  shows the edited selectors now use `color-mix(... var(--ax-elevated))` tinted surfaces (no bare
  `--ax-status-warning-solid` full fill on the health chip); no new solid full-bleed status fill introduced.
  Commit source-only (atomic): `git add assets/css/app.css assets/css/theme.css` (only if touched) — never `git add -A`.
- **done:** Genuinely over-saturated status treatments now use tinted-surface + border + strong-hue-on-text/dot;
  cobalt + all status hues unchanged; both light and dark still legible at WCAG AA; no markup/layout changes;
  changes committed as one atomic source commit.

### Task B — Tighten the over-padded regions (density)

- **files:** `accrue_admin/assets/css/app.css`
- **action:** For each candidate region in Grounding, grep/inspect the current padding/gap/margin and
  reduce ONLY the genuinely oversized ones (≥16px / ≥1rem where a smaller existing `--ax-space-*` token
  fits) to the tighter operator-console density by stepping DOWN one existing space token (e.g.
  `--ax-space-lg 24px → --ax-space-md 16px`, `--ax-space-md 16px → --ax-space-sm 8px`). Respect the
  "operator-density-defender" balance — dense but not airless; keep every touch target ≥ the existing
  button min-height and do NOT reduce anything already at/below `--ax-space-sm`. Targets: subscription-detail
  invoice-queue header→content padding, "Related billing" header→first-item gap, red alert/danger banner
  top/bottom padding; subscriptions MRR/signal row inter-badge horizontal padding + bottom margin, primary
  queue banner top/bottom padding, subscription table `padding-block` (skip if already `~0.0625rem`).
  No layout/structure/markup change. If a region is already tight, LEAVE IT.
- **verify:** `cd accrue_admin && git diff --stat -- assets/css/app.css` shows only spacing-token/value
  reductions on the targeted selectors (no new selectors, no layout props changed). Commit source-only
  (atomic): `git add assets/css/app.css` — never `git add -A`.
- **done:** Genuinely over-padded regions tightened by stepping down existing space tokens; touch targets
  preserved; already-tight regions untouched; no layout change; changes committed as one atomic source commit.

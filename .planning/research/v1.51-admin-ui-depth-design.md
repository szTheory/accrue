## 1. Diagnosis (why this milestone exists)

v1.50 built a strong **foundation**: the `ax-*` design-token system (`accrue_admin/assets/css/theme.css`),
Geist sans/mono self-hosted variable fonts with tabular numerals, a task-launcher Home, a regrouped nav,
shared `<.detail_section>` components, enriched seed data, a component kitchen at `/dev/components`, a
10-dimension rubric audit, and a Playwright screenshot + axe harness (`accrue_admin/e2e/`). The bones are
strong and **production-ready**.

But clicking through the screenshots, the UI feels **"disjoint"**: dropped on the default page it is not
obvious how to get to what you'd want to do, and depth is **uneven** — some screens were heavily iterated
in v1.50, many were not.

**The one-line diagnosis:** *Home is already job-shaped* (uk.gov-GDS: exceptions-first, tasks-as-doors,
KPIs demoted), *but everything after Home is entity-shaped* — a flat sidebar (`Customers · Subscriptions ·
Invoices · Payments`, all equal weight with Recovery/Developer/Catalog/Connect). The seam between a
job-shaped start and an entity-shaped interior **is** the disjoint feeling.

**The IA model, in one sentence:**
> "Home tells you where billing needs you; **Billing** is the everyday zone for the people who live here;
> **Recovery, Developer, and Catalog** are quiet rooms that light up only when they have work."

## 2. The six personas → job → entry point

| # | Persona | The one job | Frequency | Needs on arrival | Lives in |
|---|---------|-------------|-----------|------------------|----------|
| 1 | **Operator / Founder** | "Is billing healthy right now?" | Daily glance, seconds | Exceptions + 4 KPIs, nothing else | Home `/` (already right) |
| 2 | **Customer Support** | "Find ONE customer, see everything" | All day, per-ticket | Search → Customer 360 | Cmd-K → Customer detail |
| 3 | **Finance / Billing Ops** | "Work the open-invoice queue to zero" | Daily, heavy | A filtered work queue, not a raw list | Invoices as a *queue* |
| 4 | **Recovery / Growth Ops** | "Watch the dunning funnel + at-risk" | Daily/weekly | Recovery dashboard + at-risk table | `/analytics/recovery` |
| 5 | **Developer / Integration** | "Debug a failed webhook end-to-end" | Bursty (incidents) | Webhook DLQ → event ledger → JSON | Webhooks → Events |
| 6 | **Compliance / Audit** | "Who did what, when?" | Rare | Append-only event ledger by actor | Event log, actor-filtered |

Load-bearing insight: personas **1–3 share the billing entities**; **4, 5, 6 are specialist surfaces**.
So the ideal shape is **one primary Billing zone + three quiet specialist rooms** — not five equal nav
groups. (Operator and Finance Ops differ in *altitude*, glance-vs-queue, not in navigation; that's a
Home-vs-list distinction. Compliance is rare enough to be a saved lens, not a top-level slot.)

## 3. User-approved design decisions (locked)

- **Nav = cordoned hybrid.** Entities stay as nav leaves, grouped under a weighty primary **BILLING** zone
  (Customers · Subscriptions · Invoices · Payments) + visually-quieter, collapsible specialist zones
  (**Recovery · Developer · Catalog**) that surface attention-count badges when they have work
  (dead-letters on Developer, at-risk on Recovery). **Connect** stands alone (integration setup).
  **Compliance** = a saved actor-filter lens on the Event log, **not** its own nav group.
- **List screens default to the persona work-queue** (e.g. `/invoices` → open/uncollectible) with "All"
  one filter-chip away. Reduces overwhelm; serves the job. (Resolves the zen/simplification vs
  least-surprise tension in the user's favor toward the job, with the escape hatch one click away.)
- **Home refinements:** relabel the task launchers by **verb** ("Look up a customer," "Clear the invoice
  queue," "Recover at-risk revenue," "Investigate an incident"); surface **Cmd-K as a visible labeled
  search field** on Home + topbar (Support's primary entry, currently hidden behind a hotkey). The
  Attention-rail healthy empty-state ("Nothing needs attention") is the product's most important
  reassurance — keep it prominent. Home/nav/search are otherwise **frozen** (heavily iterated in v1.50).
- **Customer-360 tab tiering:** Primary (Subscriptions, Invoices, Payments) visible; recess
  Payment methods, Entitlements, Events, Metadata under a quieter **"More"** grouping.
- **Threading is mandatory + bidirectional** on all 8 detail screens via `related_resources.ex`;
  close the highest-value gap: **Webhook → Event → affected entity** (the Developer incident path,
  currently the weakest thread).
- **CSS architecture: double down on custom `ax-*` BEM-adjacent CSS + tokens.** Tailwind is configured
  but inert — **do NOT migrate to Tailwind.**
- **Mobile-first responsive** (usable @360px), restrained purposeful motion ("juice it but restrained"),
  brand = "quiet polish, well-made developer tooling, not fintech" (calm, exact, measured).

## 4. The six-phase shape (A–F), deps A→B→C→{D,E}→F

**Anti-churn guardrail (every phase):** each change must cite a justification token —
(a) a rubric dimension below bar with a before-score, (b) a named persona-job the screen fails to serve,
or (c) a concrete token bypass / hardcode eliminated. *"Looks nicer / my taste" is not admissible.*
Each phase opens by recording baseline rubric scores and closes by re-scoring; the delta is its evidence.
Frozen screens (Home, primary nav, global search) are touched only on a rubric-flagged regression or a
persona-job miss.

- **Phase A — Design-System Gap Closure & Token Completeness.** Add line-height scale, letter-spacing
  tokens (replace hardcoded `0.04/0.08em`), breakpoint tokens (replace hardcoded `600/768/1024px`),
  pre-composed transition bundles, max-width reading-measure container token. Kill bypasses
  (`dunning_banner.ex` inline-hex fallback, residual invoice inline styles). Document a
  component-variants reference in `/dev/components`. *Deps: none. Substrate for C/D/E.*
- **Phase B — Persona-Driven IA Spine.** Re-tier `nav.ex` (primary Billing + recessed specialist zones +
  attention badges); `sidebar.ex` visual hierarchy; `dashboard_live.ex` verb launchers + visible search;
  `customer_live.ex` tab tiering; mandatory bidirectional `related_resources.ex` incl. Webhook→Event→
  entity; work-queue list defaults via existing `filter_chip_bar`; route reshaping **with redirects**;
  Compliance actor-lens on `/events`. *Deps: A.*
- **Phase C — Systematic Per-Screen Rubric Uplift** (the heavy phase; wave-split per screen-group).
  Build the touchpoint matrix (every screen × 10 dimensions × {light,dark} × {desktop,mobile}); capture
  baseline; lift the under-iterated tail (charges, coupons, promotion-codes, connect, events, webhooks,
  invoice detail) worst-first; mobile-first rewrite using A's breakpoint tokens; reading-measure container
  on dense screens. *Deps: A, B.*
- **Phase D — Motion & Micro-interaction Design.** Documented interaction spec (what animates, why, which
  token, reduced-motion) + antipattern list, grounded in Emil Kowalski principles; applied to
  `detail_drawer.ex`, dropdowns, `global_search.ex`, tabs, flash/toasts, skeleton→content, badge/state
  changes via A's transition bundles; honors existing reduced-motion tiers. *Deps: A, C (stable layouts).*
- **Phase E — Seed Expressiveness & State Coverage.** Audit each screen for unreached states (empty,
  single-item, overflow/pagination, error, loading, dunning/at-risk, multi-currency, long strings,
  dark-only contrast); extend E2E seed fixtures (`/__e2e__/seed/<fixture>`) + host `seeds.exs` so every
  state is reachable on a single click-through. *Deps: B, C. Feeds F.*
- **Phase F — Screenshot-Driven Visual QA Loop & Sign-off.** Extend `e2e/admin-visuals.spec.js` to sweep
  the **full** inventory (currently 12 shots → all ~20 screens + detail pages) across {desktop,mobile} ×
  {light,dark}; LLM-analysis step scores each PNG against the 10 dimensions and emits structured findings;
  remediation loop until no dimension below bar; final scorecard + before/after evidence; axe re-run
  (light+dark) via `admin-a11y.spec.js`. Motion needs trace/video review (static PNGs can't see it).
  *Deps: A–E. Produces the milestone's "done" evidence.*

## 6. Evaluation rubric (inherited from v1.50; score each surface 0–3, pass at ≥2)

① token compliance (no literal hex/px, no inline style) · ② visual hierarchy · ③ spacing rhythm ·
④ state coverage (empty/loading/error/dense/sparse/overflow) · ⑤ responsive/mobile-first (usable @360px) ·
⑥ contrast (APCA/AA, `-readable` on tints, never color-only status) · ⑦ focus & semantics ·
⑧ brand expression (display face, tabular figures, tightened radii/shadow) · ⑨ motion (token-based,
reduced-motion, functional not decorative) · ⑩ reuse/DRY.

**Verification commands:**
- Asset build (after any CSS/JS edit): `cd accrue_admin && mix accrue_admin.assets.build` (commit `priv/static`).
- Screenshot audit loop: `cd accrue_admin && npm run e2e:visuals:png-only` → `test-results/admin-visuals/*.png`.
- Accessibility: `admin-a11y.spec.js` (axe, light+dark); keep `verify01-admin-a11y/mobile` green.
- Admin mounts at `/billing` (configurable `mount_path`). Known flaky `accrue` PdfTest — dodge with `--seed 0`.

## 7. Scope guardrails (explicitly NOT in scope)

- **No Tailwind migration** — stay on custom `ax-*` CSS + tokens.
- **No churn on frozen screens** (Home, primary nav, global search) — touch only on rubric-flagged
  regression or persona-job miss.
- **The demo/host app (`examples/accrue_host`) UI is not a design target** — it's only the seed/runtime
  substrate for screenshots.
- **No new billing primitives / domain features** — quality investment in a shipped surface only
  (consistent with the post-v1.48 stable-core posture; justified as adopter-facing operator DX, explicitly
  requested).
- **No breaking changes** — route reshaping ships with redirects; component public APIs stay
  backward-compatible; v1.50 shared components are extended, not replaced.
- **No re-doing the v1.50 foundation** — extend tokens, reuse the Playwright/axe harness.

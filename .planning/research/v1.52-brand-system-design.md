# v1.52 "Brand System" — Full GSD Milestone Plan

## Context

Accrue has a strong 437-line brand *strategy* seed (`prompts/accrue-brand-book.md`, gitignored) — positioning, palette (Ink `#111418`, Slate `#24303B`, Fog `#E9EEF2`, Paper `#FAFBFC`, Moss `#5E9E84`, Cobalt `#5D79F6`, Amber `#C8923B`), Geist/Geist Mono typography, voice, tagline ("Billing state, modeled clearly.") — but **zero committed brand artifacts**: no logo, no wordmark SVG, no `brandbook/` folder, no marketing copy blocks, no brand-level token docs. The user wants a full GSD milestone that (1) pressure-tests the seed through a 14-section critical-audit lens, (2) runs a **logo tournament** — programmatically generated SVG options the user picks from, with variation rounds on winners until happy, and (3) ships a self-contained, professional, standalone **HTML brand book** plus the full logo system, design tokens, and voice/microcopy/marketing copy — all committed in `brandbook/` at repo root, SVG-first, lean on binaries.

**Repo state confirmed:** v1.51 shipped & archived 2026-06-04; `main` is clean; next phase number is **180**. GSD config: high ceremony (research, plan_check, verifier, nyquist_validation on; auto_advance off), `branching_strategy: "none"`, planning docs committed on main.

**User decisions (ratified via AskUserQuestion):**
- **Checkpoints: full set** — audit/DNA ratification, every tournament round, derived-suite eyeball, batch copy review, final UAT.
- **Round 1: 12–16 concepts across 4 directions.**
- **Seed latitude: evidence-gated** — Geist + palette are defaults; audit may propose changes only with a cited failure (contrast, distinctiveness, 16px rendering), ratified by user at the audit checkpoint. Admin `ax-*` tokens in `accrue_admin/assets/css/theme.css` stay untouched this milestone.

**Hard logo constraints (from user, binding on every candidate):**
1. **NO rectangular background/container shape** behind the logomark — marks breathe / break boundaries.
2. Logotype sits **optically close** to the logomark — not visually separated.
3. Main lockup has **no subtitle/slogan**; a separate with-subtitle variant ships too.
4. Must include **fully-integrated custom typemark** options — motif/flourish worked into the letterforms, not just icon-left-of-text.

## Milestone Structure — Phases 180–186 (~22–24 plans)

Dependency shape: `180 → 181 → 182 → 183 → 186`, with `180 → {184, 185} → 186` as parallel side-rails (tokens/copy can execute while tournament rounds await user verdicts).

### Phase 180 — Brand Audit & DNA Lock ✋ checkpoint
Run the user's 14-section pressure-test prompt against `prompts/accrue-brand-book.md`: executive judgment, brand DNA extraction, 15-dimension scorecard, ~25-surface stress tests (GitHub header, README hero, Hex.pm, HexDocs, favicon, dark/light, social card, slides…), gaps by severity, upgrade recommendations, token spec, logo-system spec, visual-example guidance, voice/microcopy, landing/docs blueprint, repo artifact plan, prioritized actions, final quality gate. Every verdict tagged **KEEP / TIGHTEN / REWORK / ADD / REMOVE** with justification — no churn without a cited failure. Research plan studies devtool brand exemplars (Vercel, Prisma, Tailscale, Supabase, Phoenix, Oban) + antipatterns (gradient blobs, meaningless hexagons, rect-container marks).
**Outputs:** `BRAND-AUDIT.md`, locked `BRAND-DNA.md`, binding **logo design brief** (incl. the 4 hard constraints), Phase-186 quality-gate checklist.
**Checkpoint:** user ratifies verdicts, DNA, any evidence-gated palette/font tweaks, and the logo brief — the cheapest place to disagree.
~4 plans.

### Phase 181 — SVG Pipeline + Tournament Round 1 (Divergent) ✋ checkpoint
**Wave 1 — pipeline:** fetch Geist TTF from `vercel/geist` (SIL OFL 1.1); Node harness using **opentype.js** `font.getPath().toPathData()` to emit exact Geist letterform outlines (one `<path>` per glyph, with IDs); gallery renderer; automated pre-gate lints; Playwright screenshot QA (Phase 179 precedent). Fallback: convert in-repo `geist-sans-vf.woff2` → TTF via fonttools/wawoff2.
**Waves 2–3 — generation:** 12–16 candidates across 4 directions:
1. *Accumulation strata* — stacked/offset segments
2. *Stepped interval / timeline tick* — increment metaphor
3. *Layered arcs / state transition*
4. *Integrated typemarks* — motif worked into letterforms via path surgery on Geist outlines (the `cc` pair as echoed layers, stepped `e` crossbar, the `u` as a filling interval)

**Automated pre-gates before the user sees anything:** valid SVG parse; no-rect-background lint; lockup gap ratio within spec; 16px legibility screenshot; monochrome derivable; no subtitle in main lockup.
**Presentation:** self-contained `round-1-gallery.html` (file://-openable, SVGs inlined) rendering every candidate in a fixed **context matrix** — paper-light bg, ink-dark bg, 32px + 16px favicon, GitHub avatar circle-crop, mocked README header, mocked social card, monochrome row. Stable IDs (`A1`…`D4`) + one-line rationale each. Agent screenshots & self-reviews before checkpoint.
**Checkpoint:** user picks 1–3 winners, gives per-winner keep/change notes, kills directions — recorded verbatim in `TOURNAMENT.md` ledger.
~5 plans.

### Phase 182 — Tournament Convergent Refinement ✋ looping checkpoint
One plan per round, each authored from the latest `TOURNAMENT.md` ledger entry. Constraints are **monotonic** — once recorded, no later round violates or re-litigates them. Each round shows 6–9 variants of ≤2 finalists (weight, motif amplitude, lockup spacing/kerning, terminal treatments) in the same context matrix plus increasingly real contexts (actual social-card copy, actual README header). Default cap 3 rounds with an explicit "extend or settle" question; loops until the user is happy.
**Output:** one locked winner — mark + lockup geometry frozen.
2–4 plans (elastic).

### Phase 183 — Logo System Production (light checkpoint)
Mechanically derive the full suite from the locked winner into `brandbook/logo/`: primary lockup, integrated typemark, icon-only mark, monochrome (positive/negative), dark-bg/light-bg versions, favicon (SVG + .ico + PNG sizes), social card (SVG + the one required PNG), with-subtitle variant, clearspace/minimum-size spec sheet. All finals are **outlined paths** (no `<text>`, no `@font-face` dependency), svgo-optimized, with accessible `<title>`/`<desc>`. OFL provenance note + license file. Size-matrix screenshot validation.
**Checkpoint:** 10-minute eyeball of the derivative sheet — fidelity check, not a taste round.
~3 plans.

### Phase 184 — Design Tokens & Specimens (no checkpoint)
`brandbook/tokens/tokens.json` + `tokens.css` per the audit's token spec — raw palette, semantic roles, typography, spacing, radius, focus-ring, code-block, callout, and state tokens — with a **documented mapping to and automated consistency check against** the admin `ax-*` values in `accrue_admin/assets/css/theme.css` (admin stays SSOT for product UI; brandbook documents the brand layer; zero admin code changes). Palette + typography specimen SVG/HTML pages. Depends only on 180 — runs while 182 awaits verdicts.
~2–3 plans.

### Phase 185 — Voice, Microcopy & Marketing Copy (light checkpoint)
Voice principles, tone sliders, vocabulary do/don't, say-this/not-this examples, plus ready-to-paste copy blocks: GitHub repo description + topics, Hex.pm package description, HexDocs landing prose, README hero paragraph, landing-page copy (hero/problem/solution/install/benefits/comparison/CTAs per the audit blueprint), release-note + changelog voice templates, error/empty/success-state microcopy examples. Depends only on 180.
**Checkpoint:** one batch copy review.
~2–3 plans.

### Phase 186 — HTML Brand Book Assembly & Quality Gate ✋ final UAT
One self-contained professional static page at `brandbook/index.html` — inline CSS built from the Phase-184 tokens, all SVGs inlined, zero build step, zero JS frameworks — consuming 180's structure, 183's logo system, 184's tokens/specimens, 185's voice/copy. Sections frozen by the Phase-180 blueprint. Verification: Phase-180 quality-gate checklist, **`brandbook/` size budget ≤ ~2 MB**, dark/light/small-size rendering screenshots, final UAT via gsd-verify-work.
~3–4 plans.

## Key risks & mitigations (baked into phase design)

1. **AI-generic logo quality ceiling** → Geist outlines via opentype.js (never hand-drawn letterforms), geometric-only marks, encoded ban-lints (no container rects/coins/gradient blobs), 16px legibility gate, agent screenshot self-review before every checkpoint.
2. **Tournament never converges** → monotonic constraint ledger, 16 → ≤2 finalist narrowing, 3-round default cap with explicit extend-or-settle question, audit-ratified DNA as tiebreaker.
3. **Repo bloat** → SVG-first, svgo finals, PNG only where platforms demand it, exploration confined to `.planning/`, ≤2 MB budget enforced in Phase-186 verification.
4. **Brand book scope creep** → single self-contained file, no build step, section list frozen by Phase-180 blueprint.
5. **Token drift vs admin UI** → admin `theme.css` is SSOT; automated value-consistency check in Phase-184 verification; no admin code changes.

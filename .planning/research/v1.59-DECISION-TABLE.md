# v1.59 Entitlement Decision Table

**Canonical policy:** Stripe + Apple, account-scoped grants, 30-day revalidation target, stale downloaded study/progress continuity, no value expansion while stale, and **no independent 72-hour cutoff**. “Verified” always means provider signature/provenance and expected binding checks passed before projection.

## Eligibility and Aggregation Rules

| Input | Deterministic result | Test assertion |
|---|---|---|
| Same logical plan effective on Stripe and Apple | Plan appears once; feature set unions; quantity is max, not sum | Revoke either source and verify entitlement remains from survivor. |
| Distinct live logical plans | Both plans/features appear in snapshot | Order of evidence arrival does not change snapshot. |
| Equivalent active plan before new checkout/purchase | Return documented `:warn` or `:block` with redacted existing sources | No automatic lifecycle call, migration, refund, or proration. |
| Stale/repairing/ambiguous source state | Conservative result with explicit retry/support reason | Do not issue a second Stripe charge from an ambiguous prior attempt. |
| Apple client purchase completes despite preflight block | Project verified evidence diagnostically; do not auto-undo it | Support exception is visible; no automatic cancellation. |
| Legacy host with rails absent/disabled | Existing default-processor resolver and APIs remain exact | `customer/1`, association, aliases, and gate return shapes do not change. |

## Required Invariants

1. `GrantProjector` is the only writer of grants and account revision; it locks the account and computes before/after effective snapshots in one database transaction.
2. Every identity lookup/upsert predicates rail and environment. Apple sandbox and production may collide numerically.
3. Notifications prompt reconciliation; current signed provider status/history repairs state. Receipt time alone is never ordering authority.
4. A lease is output only. The server never accepts it as fresher billing evidence.
5. Preserve the last verified proof until a verified newer lease or signed denial atomically replaces it.
6. Apple cannot enter processor dunning, cancellation, retry, swap, proration, invoice, or payment-method mutation paths.

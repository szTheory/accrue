## Reuse and deliberate exceptions

- **Resolve the 2px/4px conflict once.** Phase 233 and `theme.css:25` intentionally allow a 2px tight rung for dense table/inline details. Phase 239's “only listed scale” instruction scoped its phase-owned choices; it does not retroactively invalidate the foundation. State in the new incumbent-system record that task separation uses the 4px-based larger roles, while documented dense inline uses may retain 2px. Retain structural 1px grid separators (`app.css:236,246`). Unexplained 0.5/1/3px section layout is a different case. Do not purge the global tight token or reopen archived evidence.
- **Reuse the registry and composition contracts.** The [component parity ledger](../../milestones/v1.63-phases/239-integrated-quality-handoff/239-COMPONENT-PARITY.md) and `ComponentRegistry` already own 30 families/42 variants/eight groups. Update affected shared specimens/contracts and their route consumers together. `Saving…` specimen text is not proof of `loading=true` or a real busy transition; inspect actual activation. Avoid a second inventory or universal state requirement for non-interactive primitives.
- **Keep representation fit to content.** Tables compare records; summary lists, read-only field groups, related-resource links, timelines, and payload disclosure already have different jobs. Use their existing composition vocabulary. Remove nested surfaces when they obscure task boundaries, rather than prohibiting every nested card. Preserve deliberate chart/code scrolling and useful repeated end-of-list affordances when justified.
- **Keep the existing overlay seam.** `Overlay` portals to `#ax-overlay-root` and provides focus/scroll contracts. Adding transform/filter/contain to its fixed ancestor can change containment. The full-page review capture extends below its recorded viewport; that alone does not prove a leaking scrim. Scroll, focus, inertness, competing step-up overlays and long-content reachability need mounted observation before an overlay defect is filed.

## Accessibility implications and footguns

The incumbent AA target and Phase 233 computed contrast thresholds remain binding. Retain meaningful labels, semantic headings, non-color status evidence and visible focus. Forced `data-ax-force` states and token lists are fixtures; real `:focus-visible`, actual activation, theme consumption and LiveView replacement behavior need their existing browser owners. Do not accept a prettier snapshot that loses target identity, exact money or honest action outcome.

Retain direct 320 CSS px reflow and check actual browser zoom from a normal desktop viewport. W3C identifies 1280px at 400% zoom as equivalent to 320 CSS px; tables may have a necessary two-dimensional-layout exception, but their surrounding controls must still reflow. Keep Accrue's stronger page-level overflow policy. A CSS `zoom` fixture or narrow screenshot alone should not be described as actual browser zoom proof. [W3C Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html).

For the touched dense headings, fields and drawers, include the spacing override of 1.5 line height, 2em paragraph spacing, 0.12em letter spacing and 0.16em word spacing; check content/action availability. These are override acceptance values, not mandatory default typography. [W3C Text Spacing](https://www.w3.org/WAI/WCAG21/Understanding/text-spacing.html).

The 44×44 CSS px target is WCAG 2.1's **AAA** target-size criterion, with stated exceptions. Keep it as Accrue's existing practical touch direction; do not mislabel it a newly certified AA requirement or use button height alone to claim conformance. [W3C Target Size](https://www.w3.org/WAI/WCAG21/Understanding/target-size.html).

Reuse the sibling safeguards already recorded in the stocktake: one pointer/keyboard selection authority, preserved rich control markup after busy states, stable hook IDs, accessible in-overlay errors, and source/served-asset provenance. No further sibling scan is needed.

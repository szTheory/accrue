## Remediation Applied (2026-05-29)

Both reviewable items found during the audit were fixed inline before completion.

### Phase 150 — `DOC-150-01` (documentation defect, affects BAN-03/BAN-02) — ✅ RESOLVED
`accrue/guides/dunning.md`'s `mount/3` example resolved the customer with
`AccrueHost.Billing.customer_for_scope/1`, which is **get-or-create** — the exact
side effect the surrounding pitfall warns against, and the bug already removed
from the shipped layout. **Fixed:** the example now uses the read-only
`billing_state_for_scope/1` pattern (case-match on `{:ok, %{customer:
%Accrue.Billing.Customer{}}}` else `nil`), mirroring the shipped example-host
layout, plus a note that the banner renders nothing for a nil/healthy customer.

### Phase 149 — Nyquist validation contract + missing component test — ✅ RESOLVED
Ran `/gsd-validate-phase 149`. The gap was BAN-02: the
`AccrueAdmin.Components.DunningBanner.dunning_banner/1` component had no direct
test in its owning package, and the `inner_block` slot branch was untested
anywhere. **Fixed:** added
`accrue_admin/test/accrue_admin/components/dunning_banner_test.exs` — 3 tests,
all green — covering the default-message, custom inner_block slot, and empty
not-dunning branches against the real DB-backed `requires_attention?/1` lookup.
Created `149-VALIDATION.md` (`nyquist_compliant: true`).
